# p_0.36.1 — The rule engine and the shell analyzer (SDK, plus the loading switch)

**Status:** planned  
**Milestone:** [m_0.36_tool_permissions.md](../m_0.36_tool_permissions.md)  
**Linked design:** [36-tool-permissions.md](../../../design/v1.0/36-tool-permissions.md), [08-security.md](../../../design/v1.0/08-security.md), [14-hooks-skills.md](../../../design/v1.0/14-hooks-skills.md)

## Goals

Three things, all of them in Go and all of them unit-testable without a model:

1. A **rule set** loaded from the workspace file `.anvil/permissions.json`, evaluated in
   `Registry.Execute` **before** the permission callback.
2. A **shell analyzer** that returns one of `read-only` / `not-read-only` / `cannot-prove`,
   where only `read-only` may ever be auto-allowed.
3. The **loading switch** that makes the workspace policy files real in the editor and the
   CLI — which also fixes `.anvil/hooks.json` having never been loaded by either.

No UI. No protocol revision. `editors/vscode/src/` is untouched, and the extension suite
must stay at its current 160 tests — that is part of what this phase proves.

## Tasks

1. **`internal/shellcmd`** — `Split` (quote-aware separator split), `Lex` (literal token
   split), `Analyze(command, goos) Verdict`.
2. **`internal/permissions`** — `Rule` / `Set` / `Load` / `Evaluate`, over the neutral
   `CallFacts{Tool, Command, Paths}` struct, with its own glob matcher.
3. **`Registry`** — `SetPermissionRules`, and the `Execute` insertion point
   (`deny` never asks, `allow` never asks, `ask` always asks, no callback + `ask` ⇒ deny).
4. **`Preview.Paths`** — the per-file list `apply_patch` already has in hand, instead of
   re-splitting its comma-joined `Path` in the matcher.
5. **Move the shell/write/edit file-hook denies into `SetPreExec`**, so a rule `allow`
   cannot skip them.
6. **`LocalOptions.LoadHooks` / `LoadPermissions`**, and the host + CLI defaults.
7. **`bypass` installs an always-allow callback** rather than none.
8. **Tests and docs.**

## Acceptance

- A `deny` rule produces a tool error the model can react to, with no callback installed
  and no side effect on the workspace.
- An `allow` rule executes with **zero** callback invocations; an `ask` rule consults the
  callback even for a tool the mode would not gate, and fails closed when there is none.
- A prefix rule matches on token boundaries and never across a separator: `git status:*`
  matches `git status` and not `git status && rm -rf /` nor `git statusx`.
- `readonly` never matches a command containing a redirection, a substitution, a glob the
  analyzer cannot resolve, or a command outside its allowlist.
- A path rule for `apply_patch` matches only when every touched path is covered; an empty
  path list never matches.
- A rule `allow` that meets an `.anvil/hooks.json` deny is still denied.
- Missing `.anvil/permissions.json` changes nothing; a malformed one fails `Create`.
- `go build ./... && go vet ./... && go test -count=1 ./...` green in `source/`;
  `internal/editorhost/independence_test.go` still green; `npm test` still 160 green.

## Non-goals

- Persisting approvals, per-hunk policy, and any rule that the user cannot read in a file.
- Any `src/` change, any `ProtocolVersion` bump, any webview change.
- Windows-specific shell analysis beyond refusing to prove: `cmd /C` metacharacters
  (`%VAR%`, `^`, `!`) are `cannot-prove`.
