# Milestone 0.43 — Context management

**Status:** done (2026-10-19)
**Product version:** 0.43.x

0.3 shipped history compression behind `HistoryMaxChars`, and 0.9 made it survive Resume by
persisting a summary marker. Both are real capabilities, but the editor never turned them on:
`buildOptions` sets no budget, so a session opened in VS Code has no compaction at all. 0.40.8
added a usage meter that reports what a run cost; it says nothing about what room is left, and
there is no way for a person to compact a conversation on purpose.

The consequence is the one this milestone exists to remove: **a long session walks into the
context window, and the first symptom is a provider error**. The design is chapter
[42](../../design/v1.0/42-context-management.md).

## Goals

1. **A budget in tokens, with a declared window.** Compression currently triggers on a character
   count nobody sets and nobody can reason about. The session declares its context window; the
   runtime estimates the conversation against it and compacts below the ceiling rather than at it.
2. **Compaction that cannot break a turn.** A summary keeps a safe tail: the cut never separates
   a tool call from its result. It runs before a run and again inside a long one, because one run
   with many tool calls can cross the budget on its own.
3. **Compaction on demand.** `Agent.Compact` and the editor's `/compact` compact an idle session,
   persist the same marker Resume already understands, and report what they did. A compact is
   visible in the transcript, live and replayed.
4. **A meter that counts down.** The editor shows the estimated context remaining, where
   auto-compaction will trigger, and how much of the last request the provider served from cache.
5. **A cache clock that is honest.** Cached-input tokens are parsed from every provider shape that
   reports them. A countdown is drawn only where a TTL is actually known — Anthropic prompt
   caching, which this milestone also turns on — not inferred for providers that publish none.

## Overall acceptance

1. A session with a declared window compacts before a run when its estimate crosses the
   configured fraction, and does not compact when it is below it.
2. A run that crosses the fraction mid-run compacts between steps and finishes normally; the
   provider sees a summary followed by a tail that never starts with an orphan tool result.
3. `Agent.Compact` on an idle agent persists one summary record, returns counts (messages
   summarized, estimated tokens before and after), and emits one `compact` event; it is refused
   while a run is in flight, and does nothing when there is nothing to compact.
4. Resume after a compact loads the summary plus the messages after it, exactly as it already
   does for a run-start compact; the full transcript is still readable.
5. The editor's `/compact` is handled locally, never sent to the model, and reports the result in
   the transcript; while a turn is running it is refused in words.
6. The meter shows estimated tokens used against the declared window, the auto-compact mark, and
   a countdown that decreases as the conversation grows.
7. Provider usage that reports cached input tokens lands in `Usage.CachedTokens` for OpenAI,
   Anthropic and streaming responses; the meter shows the cached share of the last request.
8. With Anthropic prompt caching enabled, the request carries `cache_control` breakpoints and the
   status bar counts the prompt cache's life down from the last request; when no TTL is known the
   countdown is absent rather than guessed.
9. `session.context` answers for an open session, and `session.compact` works against a real
   host; a compact requested during a run is refused with the host's run-in-progress code.
10. `cd source && go test ./...` green; `cd editors/vscode && npm test` green; packaging and the
    packaged smoke test green.

## Non-goals

- An exact tokenizer per model. The estimate is stated as an estimate, with a per-message
  overhead and a separate cost for images, and the window is declared by the caller.
- Hierarchical or multi-level memory, embeddings over the transcript, or retrieval of compacted
  turns. A summarized turn is gone from the model's context by design.
- Compacting a child agent's history: a child starts with an empty one.
- Rewriting the store to shrink it. Compaction adds a marker; the transcript keeps what happened.
- Discovering a provider's cache TTL over the wire. Providers do not publish one; the TTL is a
  declared value with a provider default where one is documented.
- Retrying or re-sending a request because its cache expired.
- Auto-compaction on every turn regardless of size, or compaction of a running tool call.
