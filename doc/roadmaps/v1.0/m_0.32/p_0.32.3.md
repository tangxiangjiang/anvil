# p_0.32.3 — agentd VS Code Server + ide-proxy + web auth

**Status:** planned  
**Milestone:** [m_0.32_sandbox_code_review.md](../m_0.32_sandbox_code_review.md)

## Tasks

1. agentd config: `code_server.enabled`, `bin`, `bind` (loopback), `base_port`, `proxy_listen`, `public_base`, `web_auth_url`.  
2. Spawn code-server on loopback with **`--auth none`**; RPC list/start/stop/status; start body matches worker-add; persist `.anvil/code_servers.json`; idempotent per `project_rel`.  
3. **ide-proxy** on `proxy_listen`: authenticate via **anvil-web session** (nginx `auth_request` and/or introspect `web_auth_url`), then route `/ide/{sid}/…` (HTTP + WebSocket) → `127.0.0.1:{port}`; drop map on stop.  
4. anvil-web: expose session check endpoint suitable for `auth_request` / introspect; optional short-lived IDE ticket on **Open** if cookie/WS forwarding needs it.  
5. Start/status return **public** URL `{public_base}/{sid}/`; UI never shows loopback ports.  
6. Scheduler + web BFF control routes; Clusters UI: start modal, session list, Open, Stop; worker “Edit in VS Code”.  
7. Document static nginx (per node → ide-proxy, optional `auth_request` to web).  
8. Tests: no web session → IDE 401; with session → proxy works; sandbox escape denied; stop removes route.

## Acceptance

- Operator starts VS Code Server like adding a worker; reaches it through **nginx → ide-proxy**; **same anvil-web login** authorizes IDE access; code-server has no separate password; Anvil web stays read-only for files; nginx config does not change per session.
