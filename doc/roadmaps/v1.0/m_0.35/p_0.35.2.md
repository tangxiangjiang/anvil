# p_0.35.2 — anvil-host binary + protocol core

**Status:** planned  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md)

## Goals

A stdio sidecar that drives in-process `anvil` sessions over newline-delimited JSON-RPC 2.0, with no approval or UI concerns yet.

## Scope

`Source/cmd/anvil-host/` (entry) and `Source/internal/editorhost/` (protocol types, session registry, event bridge). Both import the **public `anvil` package only** — no `internal/daemon`, `internal/scheduler`, `internal/web`, or tool-chain config.

## Tasks

1. Framing: one compact JSON object per line on stdin/stdout. Reuse the shape proven in `internal/plugin/exec.go`; add a fixture host patterned on `internal/plugin/fakecmd/`.  
2. Methods: `initialize` / `initialized`, `session.new` / `session.resume` / `session.list` / `session.close`, `prompt`, `cancel`, `models.list`.  
3. Session registry: session id ↔ `*anvil.Agent`; enforce one active run per session ([01](../../../design/v1.0/01-architecture.md) concurrency rule).  
4. Event bridge: map `anvil.Event` → the host's own `event` JSON (fields include `run_id`); terminal `anvil.RunResult` → `done` (including `usage`). Built from the **public** SDK types only; do not import `internal/daemon`.  
5. Drain `Run.Stream` into an outbound queue so a slow stdout never stalls the run and never trips `Run.emit`'s 64-slot drop path.  
6. Wire `LocalOptions`: `CWD` from `initialize`, `LoadRules` / `LoadCursorRules`, store kind, `SettingSources`.  
7. Tests: fake stdio client driving a stubbed completer; session create → prompt → events → done; resume; cancel mid-run; concurrent prompt on one session errors.

## Acceptance

- `go test ./Source/...` green including the new package.  
- A scripted client can run a full session with a stub model and observe `progress` / `assistant` / `tool_call` / `tool_result` / `done` events with the documented field names.  
- Cancel terminates a run and emits a terminal `cancelled` status with the right `code`.  
- A dependency check (test or `go list -deps`) proves neither new package imports `internal/daemon`, `internal/scheduler`, `internal/web`, or any other tool-chain package.

## Non-goals

- Approval, permissions, plan mode, diff preview, extension code.
