# p_0.35.8 — Editor surface: chat as a tab, sidebar as sessions, floating composer

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md)

## Goals

Move the extension's three surfaces apart, so each one is where the editor puts
that kind of thing:

1. The **conversation is an editor tab**, full width, alongside files — not a
   panel in a 300px sidebar column.
2. The **activity-bar view is session management** — this workspace's past
   agents, grouped by recency, one click to continue — not a second chat.
3. The **composer floats** over the transcript instead of taking a slice of the
   layout, so the conversation scrolls underneath it.

This is an extension-only phase. The host, the protocol (`ProtocolVersion = 1`),
and everything under `source/` are untouched: no SDK work, no protocol bump.

## Scope

`editors/vscode/` only: `src/chatPanel.ts`, `src/extension.ts`,
`src/sessionList.ts` (new), `src/sessionTree.ts` (new), `media/chat.css`,
`media/chat.js`, `package.json`, the layout tests, and the docs.

## Tasks

1. **The chat becomes a `WebviewPanel`.** `ChatPanelProvider` stops implementing
   `WebviewViewProvider` and owns a `WebviewPanel` instead: create-or-reveal on
   `anvil.openChat`, a serializer so a reload restores the tab, and a close that
   ends the view rather than the conversation.
2. **The sidebar becomes a tree.** A native `TreeView` over `session.list`,
   with the model in a `vscode`-free module so it can be unit-tested, and a
   lazy first load that never spawns a host at activation.
3. **The composer becomes an overlay.** One dock wrapper, absolutely positioned
   at the bottom, with the transcript reserving its measured height.
4. **Tests and docs**, including the stylesheet invariants the overlay adds and
   a cross-file check that the variable the script writes is the one the
   stylesheet reads.

## Tasks as delivered

1. **The conversation is a `WebviewPanel`.** `ChatPanelProvider` became `ChatPanel`
   and dropped `WebviewViewProvider`; it owns one `WebviewPanel`, created
   on demand by `anvil.openChat` (`ViewColumn.Active`,
   `retainContextWhenHidden: true`) or adopted from the serializer after a
   reload. The serializer is registered **synchronously, before anything in
   `activate` awaits**, because VS Code hands a restored panel to the extension
   during activation and a registration that lands after the first `await` is
   one reload too late. Closing the tab disposes the view, not the session —
   `ChatPanel` keeps the manager and the host alive, and the next `ready`
   re-announces trust, vision, mode, rules, state and every pending approval.

   Two consequences of moving into a tab are not obvious and both are handled:
   a tab can be **reopened while a turn is streaming**, and the webview's
   document may not have registered its `message` listener yet when the
   extension posts to it. `post()` therefore queues into `pending` until the
   document says `ready` (flushing the queue *before* the re-announcement, so
   arriving messages keep their order), which is also what makes
   `anvil.openSession` work — it opens the panel and posts `reset`, `session`
   and `state` in the same tick.
2. **The session sidebar is a native tree.** `src/sessionList.ts` (new,
   `vscode`-free) turns `SessionInfo[]` into groups and rows: local-recency
   buckets (Today / This week / Earlier / Undated), newest first, label = the
   short agent id, description = `model · N runs` plus an `open`/`running`
   marker, tooltip = the full id, workspace, model, timestamps, runs, status and
   tokens. `src/sessionTree.ts` (new, thin) maps those onto `TreeItem`s and
   decides *when* to ask. The load is lazy — first `getChildren` after the view
   becomes visible — so activation for a restored chat tab never spawns a host,
   and `quietReload()` (debounced 400 ms, fired by run start/finish and session
   open) declines to start one when a list is already cached. Bucket boundaries
   are computed with `setDate(getDate() - n)` rather than by subtracting
   milliseconds, so the week boundary survives a DST change.
3. **Three empty states, told apart.** Rather than `viewsWelcome`, which cannot
   carry a runtime message, the provider returns a *note* row: no workspace
   folder, an untrusted workspace (checked before the call, since asking would
   only be a spawn attempt that fails the same way), and a failure that reports
   the host's own error text — "could not start the host" and a failed digest
   check are different problems with different fixes. The note from a failed
   load offers **Retry**; the untrusted one does not, because there is nothing
   to retry. The explicit **Refresh** always asks; a Refresh that silently did
   nothing because the host was down would be indistinguishable from one that
   found no changes.
4. **The composer is an overlay.** `#status`, `#bypass` and the composer moved
   into one `#composerDock`, absolutely positioned at the bottom with
   `pointer-events: none` on the dock and `auto` on the card inside it, so the
   transcript's scrollbar stays draggable in the strip beside the card. The
   transcript reserves the composer's height, and that height is **measured**,
   not guessed: a `ResizeObserver` on the dock writes it to `documentElement`.
   It must be `documentElement` — the transcript is the dock's *sibling*, and a
   custom property set on the dock would never reach it. The pinned-at-bottom
   check runs *before* the reservation changes the layout, or the measurement
   would scroll away from the bottom it was taken at. The textarea grows to a
   `max-height` cap instead of being dragged, and the `/` palette grows the card
   upward for free because it sits above the textarea in DOM order.
5. **Two things the tab move had to fix, found in review before the code was
   written.** (a) `post()` now swallows the rejection from
   `webview.postMessage` — a panel disposed between the null check and the call
   is ordinary, not an error. (b) Reusing one tab for another session used to
   point the same document at a new agent while the old messages, tool cards,
   approval cards, chips and the `toolCards`/`approvals` maps survived, which
   reads as corruption. `reset` + `clearTranscript()` empties the DOM and every
   index before the new session marker is posted. The `Inbound` union's dead
   `restart` and `resume` members — neither of which `chat.js` has ever posted —
   were dropped in the same pass.
6. **The activity bar got its own commands.** `anvil.openSession` (arg: agent
   id, hidden from the palette), `anvil.newSession` and `anvil.refreshSessions`;
   `view/title` carries New and Refresh, plus Stop while `anvil.busy`. The
   `anvil.running` context key became `anvil.busy` (a turn is in flight, which
   is what the Stop buttons mean) and `anvil.trusted` was added. Stop moved to
   `editor/title` gated on `activeWebviewPanelId == anvil.chat` — the chat is no
   longer a view, so a `view/title` entry would have had nothing to attach to.
7. **Tests.** `test/unit/sessionList.test.ts` (new, 14 tests) pins what the
   sidebar shows and, mostly, what it refuses to invent: no title the store does
   not have, no guessed status for a value it does not recognise, and no undated
   session folded into a day it may not belong to. `test/unit/chatLayout.test.ts`
   gained six, including a **cross-file** check that every `--anvil-*` the
   script writes is one the stylesheet declares *and* reads, and the reverse —
   a rename on one side would otherwise leave the reserve at its default and
   hide the last message behind the card, silently. Suite: **135 tests**.
8. **Docs.** The extension README gained a Sessions section, a floating-composer
   description, a tab-lifetime bullet, three new troubleshooting rows and the
   refreshed module list; the root `README.md` and this phase doc follow. The
   design chapter carries the layout as `### Editor surface v2 as built
   (p_0.35.8)` — the invariants are written down rather than left to be
   rediscovered, which is what p_0.35.7's fix concluded was worth doing.

### What deliberately did not change

The host, the protocol (`ProtocolVersion = 1`), and everything under `source/`.
`resumeAgent` and `clearConversation` were reused rather than duplicated — the
sidebar's click and New Session are the same code paths the `/resume` and
`/clear` commands already used. No `workspaceState` mirror of the open agent id:
after a reload there is genuinely no session, so `Anvil` is the honest tab title
and it changes the moment one is opened.

## Acceptance

- **Anvil: Open Chat** opens the conversation as an editor tab; the same command
  reveals an existing one instead of opening a second.
- Closing the tab does not end the session: reopening re-announces the state,
  the mode, the rule files and any pending approval.
- The activity-bar view lists this workspace's sessions grouped by recency, and
  clicking one continues it in the tab.
- The composer floats over the transcript, the last message stays fully readable
  above it, and the reading column is centred in a wide window.
- Untrusted workspace, no workspace folder, and a host that will not start each
  produce a stated reason in the sidebar rather than an empty list.
- `npm test` green (compile, lint, unit, integration); `npm run smoke:vsix`
  green against the built package.

**Verified here:** `npm test` — `tsc` and `eslint` clean, 135 unit and
integration tests passing, the sidecar built. The layout invariants the tab move
depends on are asserted against the two files as text (the transcript is still
the only scroll container; the dock is out of flow; the reserved height and the
measured height are the same variable name). The new cross-file check was
**confirmed not to be a tautology**: renaming `--anvil-composer-h` in
`media/chat.js` alone fails it with "written by chat.js but never declared in
chat.css". `npm run package:vsix` + `npm run smoke:vsix` on the win32-x64
package.

**Not verifiable here:** that the tab, the tree and the floating card *look*
right. Nothing in `test/` renders a webview or an extension host, so the layout
half of this phase is the manual pass — open the tab, stream a turn, resize the
window wide and narrow, grow the composer with a long prompt and a `/` palette,
and close/reopen the tab to confirm the session and a pending approval both come
back.

## Non-goals

- Parallel chat tabs — one conversation at a time, one tab, reused.
- Transcript replay across a reload: the SDK has no transcript reader, so a
  restored tab re-announces live state and is honest about the rest.
- Renaming, deleting, pinning or searching sessions — the protocol has neither.
- Keybindings, marketplace publication, and any host or protocol change.
