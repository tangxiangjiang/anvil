# p_0.35.9 — Reasoning on the wire, and a transcript that reads like Claude's

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md), [05-llm-provider.md](../../../design/v1.0/05-llm-provider.md)

## Goals

Two things stand between the extension's transcript and the way a chat UI of this kind
reads:

1. **The model's reasoning is thrown away.** `internal/llm/types.go` has
   `type Delta struct { Text string }`, and the OpenAI-compatible SSE decoder
   (`internal/llm/openai_stream.go`) names only `content` and `tool_calls` in its delta
   struct — so a DeepSeek-family `reasoning_content` arrives on the socket and is dropped
   by `json.Unmarshal`. The content is *available and discarded*, not absent. Surface it as
   a streamed, collapsed **Thinking** block.
2. **The transcript is plain text.** Assistant prose is appended to a `pre-wrap` div with
   `textContent +=`, and a tool card appends its arguments and its result as two
   *unlabelled* `<pre>` blocks. Typeset the prose, and label the card's **IN** and
   **OUT**.

This is the first phase in this milestone to touch `source/`. The Go change is deliberately
the minimum that serves the editor, and it adds no protocol revision.

## Scope

`source/internal/llm/types.go`, `source/internal/llm/openai_stream.go`,
`source/internal/runtime/loop.go`, `source/types.go`,
`source/internal/editorhost/session.go`, `source/cmd/anvil/main.go`; and in

docs.

## Tasks

1. **Reasoning in the delta.** `llm.Delta` gains `Reasoning`; the OpenAI-compatible stream
   decoder names `reasoning_content` and `reasoning` and fills it.
2. **Reasoning as an event.** A new `anvil.EventType` value, `reasoning`, carrying its
   chunk in the existing `Text` field — so no `Event` field, no `EventParams` field, and no
   `ProtocolVersion` bump.
3. **The runtime emits it**, before the text of the same delta and coalesced, so a verbose
   reasoner cannot flood the run's event buffer.
4. **The host forwards it** by adding the type to `projectEvent`'s whitelist.
5. **A pure Markdown parser** (`media/markdown.js`) returning a block tree, loadable by the
   webview and by `node --test`.
6. **An incremental renderer** in `media/chat.js` that reconciles parsed blocks into DOM as
   chunks arrive, plus the Thinking block and the tool card's IN/OUT sections.
7. **Tests and docs.**

## Acceptance

- A reasoning model's output appears as a collapsed **Thinking** block that streams, and
  collapses when the answer starts; a provider that sends no reasoning shows no block at
  all rather than an empty one.
- Assistant prose renders as Markdown — headings, lists, code blocks, inline code, links —
  built without `innerHTML`, with only `http:`/`https:` links clickable.
- A long answer keeps auto-scrolling to the bottom while it streams, and does not repaint
  the whole message on every token.
- Tool cards show labelled **IN** and **OUT** sections; the result lands in OUT and the
  "show all" button still expands the result.
- `go build ./... && go vet ./... && go test -count=1 ./...` green in `source/`,
  `internal/editorhost/independence_test.go` still green, and `npm test` green in
  `editors/vscode/`.

**Verified here:** `go build`, `go vet` and `go test -count=1 ./...` green in `source/`
(the reasoning tests are new: a recorded SSE chunk for each provider field name, that a
reasoning delta never sets `streamed` so the fallback answer survives, that reasoning is
emitted before the text of the same round, that 500 characters in 10 chunks coalesce to
fewer events with the content intact, that a reasoning event survives `projectEvent`, and
that the **serialized request body carries no `reasoning` key** at any depth — the last one
being the cheap insurance against a later field-by-field refactor re-introducing the echo
hazard). `independence_test.go` green, as it must be: no new import. `npm test` in
`editors/vscode/` — `tsc` and `eslint` clean, **160 tests** passing. `npm run package:vsix`
+ `npm run smoke:vsix` green on the win32-x64 package, which now asserts `media/markdown.js`
is inside it.

The commit rule was checked the only way that catches it: `markdown.test.ts` walks each of
nine documents one character at a time, running the renderer's own freeze-and-re-parse on
every prefix and failing if any *frozen* block changed. That test found a real hole (see
below), which is the argument for keeping it.

**Not verifiable here:** that the transcript *reads* like the UI it was modelled on. Nothing
in `test/` renders a webview, so the visible half is the manual pass: one turn against a
reasoning model that produces a Thinking block, a Markdown reply with a code block and a
list, and at least two tool calls — checking that the Thinking block collapses when the
answer starts, that the tool cards show IN and OUT, that the prose reflows when the window
is resized, and that a long answer keeps auto-scrolling to the bottom while it streams.

## Tasks as delivered

1. **Reasoning reaches the delta, and stops there.** `llm.Delta` gained `Reasoning`; the
   OpenAI-compatible stream decoder names **both** `reasoning_content` (DeepSeek, vLLM, LM
   Studio) and `reasoning` (OpenRouter), and `firstNonEmpty` picks whichever the provider
   filled. Naming the field in the decode struct is the entire fix — `json.Unmarshal` ignores
   unknown keys, so the content was on the socket and thrown away at parse.
   `llm.Message` deliberately did **not** gain one: `openAIMessage` is shared between the
   request encoder and the response decoder, so a decode field on it is exactly how private
   reasoning would later be echoed upstream, and nothing can echo what nothing carries.
2. **Reasoning is a new event *type*, carried in the existing `Text`.** No `Event` field, no
   `EventParams` field, no `ProtocolVersion` bump: a `type` an old client does not know falls
   through every switch, so it loses the thinking rather than misreading the answer as its
   own. The `runtime`→`anvil` bridge and the worker's mirror copy `Type` and `Text` verbatim,
   so neither needed an edit.
3. **The runtime coalesces.** `Run.emit` drops events silently once its 64-deep buffer fills,
   and a dropped **text** chunk is permanent corruption — the transcript is append-only and
   never rebuilt. Reasoning therefore accumulates and flushes at 200 characters or at a round
   boundary, bounding the event count by size rather than by token rate, and a text delta
   flushes whatever reasoning is pending *before* it, so the order on the wire is the order it
   was thought and said. `streamed` stays keyed to text alone: setting it for a reasoning
   delta would suppress the non-streaming fallback and lose an entire answer on a round that
   reasoned first.
4. **One host edit, one CLI arm.** `projectEvent`'s whitelist gained the type — the only
   host-side change — and `cmd/anvil` prints `[reasoning]` as plain text with no ANSI, since
   stdout is often a pipe.
5. **`media/markdown.js` is a parser, not a renderer.** No DOM, no module system: an IIFE
   assigning `globalThis.anvilMarkdown`, because `media/**/*.js` is linted as browser code
   and an `export` there is a `no-undef` failure. Blocks: paragraph, ATX heading, fenced code
   with an info string (``` and `~~~`), indented code, ordered/unordered list nested by
   indent, blockquote, horizontal rule. Inline: code, strong, em, del, link. Every block
   records **the offset it started at**, which is the streaming contract, so the ordinal an
   ordered list starts from lives in a separate `from` field — writing it into `start` broke
   the re-parse for every list not beginning at 1, which is how the re-parse test earned its
   place.
6. **The commit rule, and the hole in it.** The renderer freezes every block before the last
   and re-parses `text.slice(offset)` next frame, where `offset` is the start of the block
   that was last. **Not** "seal on a blank line": a blank line is not a parse boundary — an
   indented code block continues across one, a blank line inside an open fence would split
   the code, `- a\n\n- b` is one loose list, and a list item's second paragraph has a blank
   line *inside* the item. The rule holds because a block can only be extended by the source
   immediately following it — and that prerequisite is precisely what a bare `-` broke: read
   as a paragraph, the next character turned it into a list, and a non-last, already-frozen
   block changed. `BULLET`/`ORDERED` now read a marker with nothing after it as an empty list
   item.
7. **The renderer batches a frame and reuses nodes.** Chunks landing in the same
   `requestAnimationFrame` reconcile once, so a fast stream costs ~60 parses a second instead
   of one per token; a block whose type/level/lang still matches keeps its node and only its
   inline children are reconciled; the growing tail is one `Text` node extended with
   `appendData` rather than `textContent = whole` (O(n) per chunk, and the thing that causes
   visible churn and lost selection). Every mutation replicates `pinned = atBottom()` …
   `scrollIfPinned(pinned)`, because the reconciler bypasses `append()`, the only place that
   pair lived — and without it a long answer stops auto-scrolling mid-message.
8. **One reference owns a round.** `currentText` became a per-round object holding the
   wrapper, the answer and the reconciler state, and **all nine** former `currentText = null`
   sites now call `endRound()`. Reasoning and text share it because they are one round:
   without the reset, round N+1's reasoning appends into round N's block — a node sitting
   *above* the tool cards — so the transcript would show thinking before the calls it
   actually followed. The wrapper is created by whichever of the two arrives first, so the
   `anvil` label precedes the Thinking block instead of floating below it.
9. **The Thinking block.** `details.think > summary("Thinking") + div.body`, collapsed, plain
   `pre-wrap` text — reasoning is not a document, and typesetting it would invite the reader
   to treat it as one. It collapses when the answer starts *unless* the reader opened it
   themselves, which is not something to undo for them. A provider that sends no reasoning
   produces no block, not an empty one.
10. **Tool cards got labelled sections.** `IN` holds the argv, `OUT` the result. Two
    subtleties survived the split: the arguments render only when `args !== undefined`, and
    the "show all" button now targets `out.querySelector('pre')` — left pointing at the pane,
    it would have expanded the *input*.
11. **Links are spans with a role and no `href`.** A renderer over *model* output
    reintroduces the injection risk `innerHTML` was banned to avoid, because
    `<a href="javascript:…">` is live in a webview whatever the CSP says; and a real anchor
    can be middle-clicked, which navigates the webview away and takes the conversation with
    it. So a link is a `span` with `role="link"`, a `tabIndex` and **no `href` attribute at
    all**, only `http:`/`https:` targets become one, and a target that is refused stays the
    literal text it was written as. The extension re-checks the scheme before
    `vscode.env.openExternal`: the webview's check is presentation, the extension's is the
    boundary. `test/unit/linkPolicy.test.ts` reads the two files that implement it and
    asserts both still exist and still allow the same schemes — a one-sided check is not half
    the protection, it is none, because the side that keeps it is not the side an attacker
    reaches.
12. **Tests and docs.** `test/unit/markdown.test.ts` (new, 19) covers every block type,
    nesting, unterminated fences, indented code continued across a blank line, loose lists,
    underscore flanking inside an identifier, and the two streaming properties above.
    `linkPolicy.test.ts` (new, 4). `chatLayout.test.ts` gained two: the `white-space` pair
    (the body reflows, a code block does not) and **"the stylesheet has no at-rules"**, which
    is what makes reading that file as text valid in the first place. The fake host now emits
    coalesced reasoning before its assistant text, and the integration test asserts reasoning
    reaches the client, is non-empty, and precedes the answer — the wire→UI path, with no key
    and no network. `smoke-packaged.mjs` requires `media/markdown.js`, which nothing else
    would notice the absence of. Suite: **160 tests**, from 135. The extension README gained
    a bullet for the transcript and the link policy, plus the new modules in its test list;
    the design chapters (`35-vscode-extension.md`, `05-llm-provider.md`) carry the rules as
    written rather than as rediscovered.

### What deliberately did not change

`ProtocolVersion` stays 1; `llm.Message` gained no field; `capabilities()` does not announce
`reasoning` (nothing in `src/` reads that list to enable behaviour, and it is a server-wide
claim that would be false for an Anthropic session). Persisting reasoning, replaying it on
resume, and requesting it from the provider are all out.

## Non-goals

- **Anthropic extended thinking.** With tool use, the assistant's `thinking` block and its
  `signature` must be echoed back in the next request; nothing in `fromAnthropicContent` /
  `toAnthropicMessages` can carry or re-emit a signed block, and `MaxTokens` is hard-coded
  to 8192. A separate, larger change.
- **Requesting reasoning.** `reasoning_effort` / `include_reasoning` / a `thinking`
  parameter are not sent: this phase displays what the provider already sends.
- **Persisting or replaying reasoning.** The transcript has no replay and this does not add
  one.
- Markdown images, tables, HTML passthrough, footnotes, and syntax highlighting.
- Any change to `llm.Message` or the request encoders — a decode field on `openAIMessage`
  is exactly how private reasoning would later be echoed upstream.
