# p_0.35.3 — Approval round trip + permission modes

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md)

## Goals

Make the agent ask before it acts, over a channel the editor can answer. This phase carries the one **SDK change** the milestone needs.

## Scope

`source/options.go`, `source/toolfilter.go`, `source/internal/tools/`, `source/internal/editorhost/`.

## Tasks

1. **Close the SDK gating gap (additive).** Today `internal/tools/tools.go` gates only `write_file` / `edit_file` / `apply_patch` / `shell` via `IsMutating`. Add `Options.PermissionGroups []string`; **empty preserves current behaviour exactly**. Non-empty gates by the group table in `source/toolfilter.go` (`write, edit, shell, verify, web, mcp, …`). This is the milestone's **only SDK-touching change**, it is additive and public, and it is not a tool-chain dependency — the extension still consumes the SDK alone. Host-side tool wrapping was rejected as fragile.  
2. Route MCP servers, plugin tools, and `Options.Tools` handlers through the same gate — today they bypass `Registry.permission` entirely.  
3. Define semantics when the gate denies: return `Result{IsError:true}` with the decision `Message` (existing behaviour at `tools.go`), so the model can react instead of the run dying.  
4. Editor host: on a gated call emit `approval.request` and block the callback until `approval.response`. Include `request_id`, `tool`, `args`, and `preview`.  
5. `preview` per tool kind: unified diff for `write_file` / `edit_file` / `apply_patch` (reuse `source/internal/tools/patch.go` for the dry run, read the pre-image from disk); argv list for `shell` / `run_tests` / `build`; args summary otherwise.  
6. Decisions: `allow`, `deny`, `allow_session` (host remembers `(tool, scope)` and short-circuits, in memory only). Honour `PermissionDecision.Args` rewriting.  
7. Modes: `ask` / `acceptEdits` / `plan` / `bypass`. `plan` = `DisallowedTools: ["write","edit","shell","verify"]` plus a system-prompt addendum — no new SDK code.  
8. Abort an in-flight approval when the run is cancelled (`cancel`), when the session closes, and on a configurable timeout (default deny).  
9. Tests: gated vs ungated tool sets; deny surfaces as a tool error; `allow_session` suppresses the second prompt; args rewrite honoured; MCP/plugin/custom tool gating; cancel while approval pending; timeout denies.

## Tasks as delivered

Recorded because five details differ from the plan above.

- **The preview is computed inside the SDK, not the host.** Task 5 said the host should reuse `internal/tools/patch.go`, but the host's independence rule (see the package doc in `proto.go`) forbids `internal/editorhost` from importing `internal/tools`. Instead `internal/tools/preview.go` builds an `anvil.ToolPreview` at gate time and `PermissionRequest` carries it, so the host projects it field for field and imports nothing new. This is a **second additive SDK change** beyond task 1; `Options.PermissionGroups` remains the only change that alters what the SDK *does*.
- **Plan mode's addendum is a prompt prefix, not a system-prompt addition.** `Options.SystemPrompt` *replaces* Anvil's default system text, and the host cannot read text it did not write, so appending is impossible from outside. `handlePrompt` prefixes the plan directive to the user's message instead. The mode still touches no new SDK code.
- **`SessionParams` gained `test_command` / `build_command`.** Without them the host registers no `run_tests` / `build` tool at all, so the acceptance criterion below would have been unreachable through the host. They are argv arrays, never shell strings.
- **Where each acceptance case is proven.** A gated call for `run_tests`, `shell`, and `write_file` round-trips through the real host (`internal/editorhost/approval_test.go`). Egress, MCP, plugin, and caller-registered tools are proven at the SDK layer (`permission_groups_test.go`) because the host registers no search provider yet: `web_search` / `fetch_url` only exist when `Options.WebSearch` is configured, so an egress call cannot currently be made through the host at all. Wiring that configuration is a later phase's job, not this one's.
- **The group table moved to `internal/tools/groups.go`** and `source/toolfilter.go` now delegates to it, so the SDK gate and the tool filter cannot drift apart. `"test"` stays an alias for the `"verify"` group.

Also worth recording, because a client implements against it:

- External tools — MCP, plugin, and caller-registered — belong to no group. They are gated unconditionally once `PermissionGroups` is non-empty, and ungated when it is empty, which is exactly the historical behaviour. The predicate is the tool's own type: every external tool is a `*tools.FuncTool`, every built-in is a concrete type.
- `allow_session` remembers `(session, tool, scope)`. The host never interprets `scope`; it compares it verbatim, and takes it from `preview.path` on the request. A decision with no `scope` covers every scope of that tool, which is how a client offers "always allow shell" and "always allow edits to this file" with one field.
- An `approval.response` naming a request that is no longer pending — answered, expired, or aborted — is refused with the new `-32004` rather than silently dropped, so a client learns its answer did not land. A **malformed** answer (unknown `decision`) is `-32602` instead: it is the client's bug, and reporting it as "too late" would send the client looking in the wrong place.

## Acceptance

- [x] With `PermissionGroups` unset, existing tests are untouched — no behaviour change for current callers.  
- [x] A `run_tests`, a `shell`, and a `write_file` each round-trip an approval through the host; an egress call and an MCP call each round-trip one at the SDK layer (the host cannot yet make either — see above).  
- [x] No run can hang forever on an unanswered approval.

## Non-goals

- Persisting approvals to disk; per-hunk approval policy; a rules engine beyond the group set.
