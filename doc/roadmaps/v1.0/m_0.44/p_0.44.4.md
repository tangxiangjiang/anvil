# p_0.44.4 — The host exposes the runtime

**Status:** done (2026-10-20)
**Milestone:** [m_0.44_mcp_management.md](../m_0.44_mcp_management.md)
**Linked design:** [43-mcp-management.md](../../../design/v1.0/43-mcp-management.md) §4

## Goals

1. **Every session shares the host's runtime.** `buildOptions` attaches the runtime for the
   session's `(cwd, sources)`; a server that is down or a file that will not parse no longer
   refuses a session.
2. **`mcp.list` can be believed.** It returns the observed state, tool count and error beside
   the configuration, plus a `problem` when a file is malformed. It stays additive and marks
   itself with `runtime: true`.
3. **Management is one round trip.** Add, update, remove, enable/disable, reconnect, sign in and
   sign out each write/reload and return the fresh listing.
4. **Changes reach idle sessions now, running ones next turn.** State transitions are pushed as
   `mcp.status` notifications.

## Scope

`source/internal/editorhost/proto.go`, `server.go`, a new `source/internal/editorhost/mcp.go`,
`session.go`, and tests. The host may import only package `anvil`.

## Tasks

1. **Protocol.** Extend `MCPListParams` with `include_tools`; extend the result with `runtime`,
   per-server `enabled/state/tool_count/tools/error/connected_at/env_names/header_names`, and a
   `problem` object. Add methods `mcp.add`, `mcp.update`, `mcp.remove`, `mcp.set_enabled`,
   `mcp.reconnect`, `mcp.authenticate`, `mcp.sign_out` and the `mcp.status` notification.
   Capabilities gain `mcp.runtime`.
2. **Registry.** The host keeps `map[key]*anvil.MCPRuntime` with key `cwd + sorted(sources)`.
   Creation is lazy; the first session for a key calls `Reload` synchronously (bounded by the
   per-server connect timeout), while a panel asking before any session starts the connection in
   the background and returns `connecting` statuses. `closeAll` closes every runtime.
3. **buildOptions.** When at least one source is enabled, attach the runtime and do not pass
   file MCP through the ordinary path; with no sources the session stays inline-only.
4. **Handlers.** Every management call validates scope/source, delegates to the public
   `mcpconfig` writers, reloads the runtime, and refreshes idle sessions for that runtime.
   `mcp.list` reloads (a diff-only read of the files) so external edits are seen; a malformed
   file is a result with `problem`, not an RPC error.
5. **Notifications.** Runtime `OnChange` maps to `mcp.status` per affected server, carrying the
   same server object as the listing and the source set. A notification is sent for connecting,
   connected, failed and auth-required transitions.
6. **Sessions.** Record the source set and runtime key on `session`; `RefreshMCP` errors during a
   run are swallowed and retried by the next `Send`, which already refreshes.
7. **Tests.** Host tests with a temp workspace and an `httptest` Streamable HTTP server (no
   import of `internal/mcp`): session opens with a down server; listing states; add/remove/
   toggle landing in the selected file with unknown fields preserved; notification ordering;
   shutdown closes the runtime.

## Acceptance

- [x] A workspace with one broken and one good server opens a session; the good tools are
      registered; `mcp.list` reports both states.
- [x] A malformed file produces `problem` in the result and a read-only listing, not `-32000`.
- [x] `mcp.add/update/remove/set_enabled` write the requested scope and return the fresh
      listing; an idle session's tools change immediately, a running one after its turn.
- [x] `mcp.reconnect` restarts one server and reports the new state.
- [x] `mcp.authenticate` returns a URL and the completion produces `mcp.status connected`.
- [x] `independence_test.go` still passes; host shutdown closes every runtime.
- [x] `cd source && go build ./... && go vet ./... && go test -count=1 ./...` green.

## Non-goals

- Reimplementing config editing in the host; it calls the public writers.
- Multiple concurrent runs per session, or applying config changes mid-run.
- Persisting runtime state across host restarts.

## Depends-on

- p_0.44.1 (writers), p_0.44.2 (runtime), p_0.44.3 (auth).

## Implementation notes

- **One runtime per `(cwd, sorted sources)`.** `internal/editorhost/mcp.go` keeps
  `map[string]*hostMCPRuntime`, keyed by `cwd + "\x00" + joined sorted names`; the source list
  is canonicalised (sorted, de-duplicated) before the key so `["user","project"]` and
  `["project","user"]` share one runtime. Creation is lazy and never connects by itself: the
  caller picks between a synchronous `reload` (a session's first use, every management call)
  and `reloadInBackground` (a listing), which is guarded by an `atomic.Bool` so a polling panel
  cannot stack dials. `Reload` itself skips entries whose fingerprint is unchanged, so the
  background read is a file read, not a reconnect loop.
- **`mcp.list` never fails on a file it cannot parse.** The result carries `problem` with the
  path and the parser position, plus whatever the runtime last observed. To get that position,
  `ListMCPServers` now returns the SDK's `*MCPConfigError` (path, offset, line, column) where it
  used to return a plain wrapped error — `mcpParseError` was split so the reader and the writer
  describe a broken file the same way.
- **A declared server with no status yet is `connecting`.** A listing can arrive before the
  background reload it just queued has set any state; reporting an empty state would read as
  "this host has no runtime". A disabled entry with no status is `disabled`. The malformed-file
  path invents nothing: it reports only statuses the runtime actually holds.
- **Management params carry `setting_sources` and `include_tools`** in addition to the
  design's `{scope, name, server}`. The source set is what selects the runtime to reload and
  the listing to return, and a panel that just wrote a row wants the tools in the same reply.
  `mcp.status` carries the same server object and the source set, so a client showing two
  runtimes can tell their servers apart; both are additive to the design's shape.
- **An update inherits `enabled`.** `MCPServerDraft.Enabled == nil` means "on" to the SDK
  writer, which would re-enable a disabled entry whenever a form left the checkbox out. The host
  reads the file's own value (`mcpEnabledInScope`) before delegating, so an update without the
  field changes nothing about the toggle.
- **Removing deletes tokens only when nothing else declares the name.** The merged listing
  cannot answer this (it reports one entry per name), so `mcpDeclaredOutside` reads each other
  enabled layer on its own; a layer that will not parse counts as "still declared". A stdio
  server's `SignOut` fails with "not a remote server" and that error is ignored — the removal
  is still what was asked for.
- **Reconnect reports the state, not an RPC error.** `MCPRuntime.Reconnect`'s error is already
  in the returned listing's `error` and in the pushed `mcp.status`; failing the call as well
  would make a panel show a dialog over a row that already says what happened.
- **Session bookkeeping.** `session` records `settingSources` and `mcpKey`; a write refreshes
  every idle session with that key and skips one with a run in flight (its next `Send`
  refreshes). `buildOptions` takes a `ctx` now, so the first session's `Reload` is bounded by
  the caller's context as well as the per-server timeout.
- **Tests.** `internal/editorhost/mcp_management_test.go` runs against a `fakeMCPServer`
  (`httptest`, JSON bodies, `Mcp-Session-Id` on initialize, 202 for notifications) and never
  imports `internal/mcp`. `initHost` now points `HOME`/`USERPROFILE` and `MCPTokenDir` into the
  test's temp tree, so no test reads the machine's real `~/.cursor/mcp.json`. The two older
  tests that described the pre-runtime wire (`mcp.list` failing on a malformed file, a listing
  with no state) were rewritten deliberately for chapter 43.
- **Where the sign-in round trip is tested.** The authorization-code flow, the token file and
  the reconnect-on-completion are covered at the runtime layer by p_0.44.3
  (`mcpruntime_oauth_test.go`); `mcp.authenticate`/`mcp.sign_out` in the host are a validation
  and a delegation, and the host test covers their failure paths. Duplicating the fake
  authorization server in this package would test the same code through one more layer.
- `go test -race` still cannot run here (no C compiler); the background reload and the harness
  goroutines make a `-race` run worth doing where cgo is available.
