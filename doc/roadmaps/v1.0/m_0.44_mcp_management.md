# Milestone 0.44 — MCP management

**Status:** in_progress (started 2026-10-20)
**Product version:** 0.44.x

MCP has been connectable since 0.3 and visible in the editor since 0.40.6. What 0.40.6 shipped
was deliberately a **configuration viewer**: `mcp.list` reports which servers a file declares,
and the panel says nothing about whether one connected — because the SDK had no state to report.
There is no way to add, remove, disable, re-enable or reconnect a server from the editor, and a
remote server that wants a user to sign in cannot be used at all.

Worse, the SDK's per-agent start loop treats one bad entry as fatal: a single mistyped command
aborts `Create`, so a session opens with no tools and no explanation. The milestone turns MCP
into something a person can run: a host-owned runtime with observable state, a manager that
writes the config file safely, and OAuth for the remote servers that need it. The design is
chapter [43](../../design/v1.0/43-mcp-management.md).

## Goals

1. **Connection state is real.** Every declared server has a state — disabled, connecting,
   connected, failed, auth-required — with its tool list or its error. One failed server no
   longer takes the session down with it.
2. **The connection belongs to the host, not the tab.** One runtime per `(cwd, setting_sources)`
   owns the processes; sessions register tools from it and refresh on the next turn. Reconnect
   and config changes do not require closing a conversation.
3. **The manager can change the configuration.** Add, update, remove and enable/disable write
   `.cursor/mcp.json` (project or user) atomically, preserving fields this milestone does not
   know about, refusing to touch a file that does not parse, and never exposing secret values.
4. **Reconnect is one action.** A server that failed, died, or was changed can be reconnected
   without restarting the host or the session.
5. **Remote servers can ask for sign-in.** Streamable HTTP and the MCP OAuth flow (discovery,
   dynamic registration, PKCE, refresh) are supported; tokens live in a 0600 file owned by the
   host and never cross the protocol pipe.
6. **The editor shows and controls all of it.** A dedicated MCP panel, `/mcp`, a status word on
   the chat card, and backward compatibility with a host that predates the runtime.

## Overall acceptance

1. A workspace whose `.cursor/mcp.json` has one good and one broken server opens a session with
   the good server's tools registered; `mcp.list` reports `connected` for one and `failed` with
   the error for the other, and the session is not refused.
2. Adding a server through the manager writes the selected `mcp.json` (creating the directory
   when needed) without dropping unknown top-level or per-server fields; removing it removes
   only that entry; toggling writes `enabled: false` and deletes the key on re-enable.
3. A malformed file is reported as a `problem` in the listing and the panel is read-only; no
   edit replaces the file.
4. A disabled project entry shadows an enabled same-named user entry and is reported as
   disabled, not silently replaced.
5. Reconnecting a failed server starts a new process and updates its state and tools without
   closing the session; an idle session's tools change on the next turn; a running turn keeps a
   stable registry and the change waits.
6. A remote server that answers `401` is reported as `auth_required`; signing in opens the
   authorization URL in the browser, completes on the loopback callback, stores a 0600 token
   file, and reconnects. A token is never present in any status, error or protocol message.
7. A server speaking Streamable HTTP works: the session id is carried, SSE response bodies are
   parsed, and protocol version negotiation succeeds.
8. The MCP panel shows state, transport, source, tools, and the per-server actions; `/mcp` opens
   it; the chat card shows state and tool count; a host without `runtime` degrades to the
   configuration card.
9. `cd source && go test ./...` green, including `-race` for the runtime; `cd editors/vscode &&
   npm test` green; packaging and the packaged smoke test green.

## Non-goals

- MCP resources, prompts, sampling, elicitation, or completion.
- Background GET SSE and automatic `tools/list_changed` refresh.
- Parallel calls to one server, load balancing, or idle runtime shutdown.
- Device-code OAuth, token revocation endpoints, or OS keychain storage.
- Editing existing env/header values in the panel without re-entering them.
- Transports other than stdio, legacy SSE and Streamable HTTP.
- Config files other than `{cwd}/.cursor/mcp.json` and `~/.cursor/mcp.json`.
- Any token or secret header value on the protocol pipe.
- A marketplace, server installation, or sandboxing beyond the existing trust gate.
