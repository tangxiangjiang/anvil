# p_0.40.5 — Fork a session

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [39-editor-alignment.md](../../../design/v1.0/39-editor-alignment.md), [06-session-store.md](../../../design/v1.0/06-session-store.md), [38-session-identity-and-replay.md](../../../design/v1.0/38-session-identity-and-replay.md)

## Goals

1. **A conversation can branch.** Copying the records up to a chosen run boundary into a new agent
   file produces a session that resumes from there.
2. **The copy is a copy.** No record type is rewritten except the `meta` agent id, so the fork's
   history is byte-identical to the prefix it came from.
3. **Only run boundaries.** A fork mid-run would copy a `run_start` without its `run_end`.

## Scope

New `source/fork.go`, `source/internal/editorhost/` (`session.fork`), `editors/vscode/src/`
(protocol, tree and chat actions), tests.

## Tasks

1. **The public function.** `anvil.ForkAgent(ctx, agentID, runID, opts) (string, error)`: find the
   `run_end` record with that id, copy every record through it, rewrite the copied `meta`'s
   `AgentID` to the new id (and give the title a short ` (fork)` suffix when one exists), and write
   `agent-<new>.jsonl`. A missing run id or a `runID` that is not a completed run is an error, not
   a partial copy. The title suffix is **appended as one more `meta` record**, as a rename is, so
   the agent id stays the only field rewritten in the copy; the suffix is trimmed into the title
   before the listing's own cut can remove it.
2. **Identity.** The new id is generated by the same helper `Create` uses, so files, checkpoints
   and listings agree.
3. **The wire.** `session.fork` (`{agent_id, run_id}`) returning the new agent id. Additive.
4. **The client.** Tree context menu "Duplicate conversation" (forks at the last run) and a
   per-run action in the chat panel "Fork from here"; both open the new agent in a new tab, which
   p_0.40.1 already supports.
5. Tests and docs.

## Acceptance

- [x] Forking at a run id copies exactly the records up to and including that `run_end`, and the
  record count and order are asserted. (`source/fork_test.go`,
  `internal/editorhost/fork_test.go`.)
- [x] The fork resumes and its history equals the prefix's history.
  (`TestForkResumesWithThePrefixHistory`.)
- [x] The fork's `meta` carries the new agent id; the source file is unchanged.
  (`TestForkCopiesThroughTheRunEnd` compares the source before and after.)
- [x] Forking at a run that never ended is refused, and leaves no partial agent behind.
  (`TestForkRefusesAnUnfinishedRun`.)
- [x] The fork appears in `session.list` with a distinguishable title — `… (fork)`, kept inside the
  listing's length limit even for a title the store already truncated
  (`TestForkIsListedUnderADistinguishableTitle`, `TestForkTitleKeepsTheSuffixPastTheLimit`).
- [x] The sidebar's "Duplicate conversation" branches at the row's last finished run, and a run's
  end in the chat panel offers "Fork from here"; both open the new agent in a new tab
  (`test/integration/fork.test.ts`, `test/unit/fork.test.ts`).
- [x] `go test ./...` green; `npm test` green (291 tests).

## Non-goals

- Forking mid-run, or copying checkpoints to the fork (a fork is a conversation, not a workspace
  snapshot).
- Merging two branches back together.
- Rewriting record timestamps or run ids.
