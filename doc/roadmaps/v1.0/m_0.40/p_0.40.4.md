# p_0.40.4 — Checkpoints and restore

**Status:** planned
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [39-editor-alignment.md](../../../design/v1.0/39-editor-alignment.md), [04-tools-and-sandbox.md](../../../design/v1.0/04-tools-and-sandbox.md), [06-session-store.md](../../../design/v1.0/06-session-store.md)

## Goals

1. **The workspace before a run is recoverable.** Every mutating tool call that names its files has
   its pre-image captured before it executes.
2. **Restore puts those files back.** A file the run created is deleted; a file it changed is
   returned to its prior bytes.
3. **Capture happens at the one seam every call passes through**, using the same path enumeration
   the rule matcher and the approval preview use.
4. **The boundary is stated.** A shell redirection writes a file no argument names, so it is not
   captured.

## Scope

`source/options.go` (a new `CheckpointOptions`), `source/internal/tools/` (the runner seam),
`source/internal/checkpoint/` (new), new `source/checkpoints.go` (public readers),
`source/internal/editorhost/` (two methods), `editors/vscode/src/` (protocol, panel action), tests.

## Tasks

1. **Options.** `Options.Checkpoints *CheckpointOptions{Dir, Keep, MaxAge}`. Nil means off, which
   is what every existing caller gets. The host enables it per session; the directory defaults to
   `{cwd}/.anvil/checkpoints`.
2. **Capture.** In `tools.runner.run`, after the approval rewrite and immediately before
   `t.Execute`, enumerate `pathsFor(name, execArgs)` and snapshot each path through the sandbox
   resolver. Write `{dir}/<agent>/<run>/<relative path>` for files that exist, and a manifest
   recording every path with `existed` and, when present, its size and hash. A missing agent id or
   run id is a no-op, so a unit-level caller is unaffected.
3. **Prune.** On session open, keep the newest `Keep` (default 100) runs per agent and delete
   anything older than `MaxAge` (default 30 days).
4. **Public readers.** New `source/checkpoints.go`: `ListCheckpoints(cwd, agentID)` and
   `RestoreCheckpoint(cwd, agentID, runID)`. Restore resolves each path through the same
   sandbox check used by the tools and refuses a manifest entry that would escape.
5. **Wire.** `checkpoint.list` (`{agent_id}`) and `checkpoint.restore` (`{agent_id, run_id}`).
   Additive; `ProtocolVersion` does not move.
6. **Client.** Each run's end in the chat panel offers `Restore files to before this run` behind a
   modal; after a restore the changed-files list is refreshed. A run that captured nothing offers
   no action rather than an empty one.
7. **Delete integration.** `DeleteAgent` (p_0.40.2) also removes the agent's checkpoint directory.
8. Tests and docs.

## Acceptance

- [ ] An `edit_file` run captures the file's prior bytes; a `write_file` run captures an "absent"
  marker when the file did not exist.
- [ ] Restoring returns a changed file to its prior content, and deletes a file the run created.
- [ ] A manifest path that escapes the workspace is refused by restore.
- [ ] Capture happens with the **rewritten** arguments an approval produced, not the model's
  original ones.
- [ ] Pruning keeps the newest 100 runs and drops runs older than 30 days.
- [ ] Restoring a run that used `shell` redirection restores the files it can see; the UI copy says
  the redirection is not covered.
- [ ] `go test ./...` green; `npm test` green.

## Non-goals

- Capturing shell redirections, or tracking writes by watching the filesystem.
- Checkpointing the model's context; this is files only, and chapter 38 keeps the transcript
  separate.
- Restoring a checkpoint automatically when a run fails.
- Deduplication or compression of checkpoint content.

## Depends-on

- p_0.4.x (the tool runner), p_0.8.x (the sandbox resolver), p_0.40.2 (`DeleteAgent`)
