# p_0.40.2 — Rename, delete, search

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [39-editor-alignment.md](../../../design/v1.0/39-editor-alignment.md), [38-session-identity-and-replay.md](../../../design/v1.0/38-session-identity-and-replay.md), [06-session-store.md](../../../design/v1.0/06-session-store.md)

## Goals

1. **A person can name a session.** A rename is durable and survives reload; it is an appended
   `meta` record, so the store stays append-only.
2. **A person can stop keeping a session.** Delete removes the session's file, after a modal
   confirmation and after closing any tab that holds it.
3. **A person can find a session.** A QuickPick filters by title and by agent id.

## Scope

`source/internal/store/` (`Record`, `Summarize`), new `source/session_admin.go`,
`source/internal/editorhost/` (two methods), `editors/vscode/src/` (`protocol.ts`,
`hostManager.ts`, `hub.ts`, `chatPanel.ts`, `extension.ts`, new `sessionSearch.ts`),
`editors/vscode/package.json` (the commands and menus), and the tests.

## Tasks

1. **The record.** `store.Record` gains `Title string` (`json:"title,omitempty"`), written only on
   a `meta` record produced by a rename.
2. **The rollup.** `Summarize` reads `meta.title` through the existing `titleOf` normalizer and
   **replaces** whatever title it has; the first-user-message rule keeps its "only when empty"
   guard. Records are chronological, so a rename wins over the derived title and a second rename
   wins over the first. An empty or whitespace-only title is not written at all.
3. **The public commands.** New `source/session_admin.go`: `RenameAgent(ctx, agentID, title,
   opts) error` appends one `meta` record; `DeleteAgent(ctx, agentID, opts) error` removes
   `agent-<id>.jsonl` and reports `ErrNotFound` when it is already gone.
4. **The wire.** `session.rename` (`{agent_id, title}`) and `session.delete` (`{agent_id}`), both
   resolved against `s.cwdPath()` like `session.list`. Additive; `ProtocolVersion` does not move.
5. **The client.** `protocol.ts` methods, `hostManager.renameSession/deleteSession`; tree context
   menu with Rename, Delete and Open in New Tab; Rename uses `showInputBox` seeded with the current
   title; Delete uses a modal warning and closes the owning tab first.
6. **Search.** New pure `src/sessionSearch.ts` (`filterSessions(rows, query)`) and an
   `anvil.searchSessions` command backed by the existing `session.list`; results show title plus
   a short id, and picking one opens it.
7. Tests and docs.

## Acceptance

- [x] Renaming a prompted session changes its sidebar label, and the label survives a host restart.
  The first user message does not replace the new title.
- [x] Renaming to an empty string is rejected without writing a record.
- [x] A renamed session resumes with the same history as before the rename —
  `historyFromRecords` is unchanged by the extra `meta` record.
- [x] Deleting removes the file; the row disappears on refresh; deleting a session that is open
  closes its tab first. Deleting an unknown id reports not-found rather than succeeding.
- [x] Search matches a word in the title, a prefix of the agent id, and is case-insensitive.
- [x] `go test ./...` green; `npm test` green (246 tests).

## Non-goals

- Editing any record other than appending a `meta`.
- Soft delete, trash or undo.
- Sorting, tagging, folders, or a persisted search history.
- Renaming from the chat tab's heading.

## Depends-on

- p_0.38.1 (the derived title this replaces on request), p_0.40.1 (closing the owning tab)
