# p_0.40.9 — The task list

**Status:** planned
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [39-editor-alignment.md](../../../design/v1.0/39-editor-alignment.md), [04-tools-and-sandbox.md](../../../design/v1.0/04-tools-and-sandbox.md)

## Goals

1. **The model's plan is visible.** A built-in `todo_write` tool replaces the list; the panel renders
   it below the composer.
2. **The list is part of the conversation.** The call is persisted and replayed like any other tool
   call, so a reopened session shows the list it showed live.
3. **The tool does nothing else.** No files, no shell, no network.

## Scope

`source/internal/tools/` (the tool), `source/types.go` (event and item type), `source/agent.go`
(emission), the default tool set, `source/internal/editorhost/server.go` (forwarding),
`editors/vscode/media/chat.js` + `src/chatPanel.ts`, tests and docs.

## Tasks

1. **The tool.** `todo_write` with `{items: [{text, status}]}`, `status` one of `pending`,
   `in_progress`, `done`. It validates the shape, returns a short count, and is read-only with
   respect to the workspace. It is always available, and it is not gated: it changes nothing a
   permission could protect.
2. **The event.** `anvil.TodoItem` and `Event.Items`, emitted as `type: "todo"` when the tool runs.
3. **Persistence.** The call is recorded as an ordinary tool message, so replay reconstructs it;
   the panel derives the checklist from the latest `todo_write` in the transcript.
4. **The panel.** A checklist below the composer, one row per item with its status; an empty list
   removes the block; a new session clears it.
5. Tests and docs.

## Acceptance

- [ ] `todo_write` updates the list and returns the item count; an invalid status is a tool error.
- [ ] The event carries the full list; the panel replaces its checklist on each call rather than
  appending.
- [ ] A replayed session ends with the checklist from its last `todo_write`.
- [ ] An empty list hides the block.
- [ ] `go test ./...` green; `npm test` green.

## Non-goals

- A user-authored todo list, or editing items in the panel.
- Nesting, priorities, due dates, or assignment.
- Sub-agents; this is a checklist, not a delegation mechanism.
