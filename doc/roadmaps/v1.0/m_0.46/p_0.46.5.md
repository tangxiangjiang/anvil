# Phase p_0.46.5 — Pure-function tests and an `esc()` coverage assertion

**Status:** done

## Goals

Give the front end a test seam. The pure functions that are central to correctness are currently
untested, and today's HTML-escaping correctness is maintained by discipline alone with nothing that
would notice a regression.

## Scope

- A minimal, build-step-free test runner covering the pure functions.
- One jsdom smoke test that every route renders.
- An assertion over the HTML builders' `esc()` coverage.

## Non-goals

- Full end-to-end browser tests (Playwright/Cypress). The surface count does not justify the harness,
  and p_0.46.1–p_0.46.4 are verified by their acceptance checks.
- Testing anything that requires a live `anvil-web` + scheduler.
- Coverage thresholds. The goal is a regression net over the sharp edges, not a number.

## Tasks

1. **Runner.** Add `source/internal/web/static/package.json` with `node --test` (Node 20+ built-in
   runner; no bundler, no transpile) and a `test` script. Tests live beside the code as
   `*.test.js` and are excluded from the served assets by the `go:embed` pattern being
   `all:static` → add an explicit ignore or place tests under `static/js/test/` and confirm they are
   served harmlessly or excluded.
2. **Pure-function tests.** Cover the functions whose failure is silent:
   - `parseRoute` — every documented hash shape, the legacy `#/delivery/gates` rewrite, and the
     `requirements/projects` picker form
   - `parseRoadmapMsBind` — the `m/{M}/{msId}` bind, plus malformed input
   - `composeDesignMarkdown` — section composition and ordering
   - `parseGateChecklist` — checked / unchecked / text-only gates
   - `campaignPassReady` — cases + bug interplay
   - `lifecycleLabel` — every lifecycle value including an unknown one
3. **Route smoke.** A jsdom test that stubs `api.v1.delivery()` with a snapshot fixture and asserts
   each route renders without throwing and produces a non-empty `.del-body`.
4. **`esc()` coverage.** An assertion over the template builders: every interpolation of
   model/operator-supplied text passes through `esc` (or is a known-safe enum). Practical shape: a
   allowlist of interpolations that skip `esc` (numeric fields, internal enum values), so a new
   unescaped interpolation fails by default rather than passing silently.

## Acceptance

- [ ] `npm test` in `source/internal/web/static/` runs green, and is what CI runs.
- [ ] Removing one `esc()` from a sampled builder fails a test.
- [ ] Deleting a route branch from `parseRoute` fails a test.
- [ ] The test files are not served as part of the UI assets, or their presence is proven harmless.

- p_0.46.4 (the routes under test are the post-IA ones)
