# Phase p_0.46.8 — Bulk and keyboard operation on the lists

**Status:** planned

## Goals

Remove the "one form per item" tax. Several surfaces are only usable at a scale of handfuls, which
is the wrong shape for a planning console that inherits a real backlog.

The concrete cases, all reachable today: drafting ten test cases means ten chats; moving five
milestones means five Start clicks and five waits; reviewing a generation's gates means opening one
version at a time.

## Scope

- Multi-select on the milestone list, the test-case list and the design-version list.
- Batch actions on the selections, each of which already exists as a single-item action.
- Keyboard operation: arrow navigation within a list, Enter to open, `x` to toggle selection.
- Paste-a-list to create cases in bulk.

## Non-goals

- A spreadsheet/grid editor. The forms stay forms.
- Bulk *destructive* actions beyond what already confirms per item — a batch delete would need its own
  typed confirmation naming the count, and that is deliberately left out of this phase.
- Drag-to-reorder beyond what the version cards already do.

## Tasks

1. **Selection model, one implementation.** A shared `selection.js` with range (Shift), toggle (Ctrl /
   Cmd), select-all, and an escape-to-clear, used by all three lists. Selection survives a re-render
   by id, not by DOM position.
2. **Selection action bar.** When the selection is non-empty, a bar replaces the list header showing
   `N selected` and the applicable batch actions. This is also where a partial failure is reported:
   "3 of 5 started; 2 already running" rather than one aggregate error.
3. **Batch start / pause / stop** over selected milestones, driven through the existing single-item
   endpoints in order with per-item results. Sequential on purpose — the scheduler serialises anyway,
   and a burst of parallel patches against one milestone is how duplicate jobs happen.
4. **Batch case creation** from a pasted list: one case per line, `---` splits a multi-line body,
   editable before save. This is the non-chat path to the same result p_0.46.6's assistant proposes.
5. **Keyboard pass.** Arrow keys move a list cursor, Enter opens, Space toggles selection, Escape
   clears, `/` focuses search. Bindings are announced in the help dialog so they are discoverable.
6. **Tests.** The selection reducer (range across a filtered list, toggle after a re-render,
   select-all under a filter) — a pure function, so it goes in the p_0.46.5 harness.

## Acceptance

- [ ] Select five milestones and start them: one request per milestone, a result row per milestone,
      and the bar reports partial failure precisely.
- [ ] Selection survives a re-render (the reload after a batch does not clear it).
- [ ] Paste ten case bodies and save them all in one action.
- [ ] Every list is fully operable with the keyboard alone, and the bindings are documented in-app.
- [ ] No batch action can delete anything.

## Depends-on

- p_0.46.2 (single-flight and running state; a batch is a sequence of them)
- p_0.46.5 (the harness the selection reducer is tested in)
