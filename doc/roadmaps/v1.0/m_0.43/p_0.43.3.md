# p_0.43.3 — The host turns the budget on

**Status:** planned
**Milestone:** [m_0.43_context_management.md](../m_0.43_context_management.md)
**Linked design:** [42-context-management.md](../../../design/v1.0/42-context-management.md) §2–§3,
[35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md)

## Goals

1. **Editor sessions get a budget.** `SessionParams.Context` is mapped onto `Options.Context`, so
   the window the user declared (`anvil.contextWindow`) actually compacts their session.
2. **A person can ask for a compaction.** `session.compact` compacts an idle session, answers
   with counts, and tells every tab through a `compact` notification; a run in flight is refused
   with the host's existing run-in-progress code.
3. **The meter can ask.** `session.context` answers for a live session: estimate, window,
   threshold and message count, so a tab that has not run anything still shows where it stands.
4. **Usage and cache cross the wire.** `done` carries the post-run context and the last request
   time; `usage` carries cached tokens; the `event` type `compact` is forwarded like `todo`.

## Scope

`source/internal/editorhost/proto.go`, `server.go`, `session.go`, `tasks_test.go`-style host
tests (new `context_test.go`), and the fake-host harness in `editors/vscode/test` if the wire
change requires it.

## Tasks

1. **Wire types** (`proto.go`):

   ```go
   // SessionParams
   Context *ContextParams `json:"context,omitempty"`

   type ContextParams struct {
       WindowTokens  int     `json:"window_tokens,omitempty"`
       AutoCompactAt float64 `json:"auto_compact_at,omitempty"`
       KeepRecent    int     `json:"keep_recent,omitempty"`
   }

   type ContextInfo struct {
       EstimatedTokens int `json:"estimated_tokens"`
       WindowTokens    int `json:"window_tokens"`
       CompactAtTokens int `json:"compact_at_tokens"`
       Messages        int `json:"messages"`
       Compactions     int `json:"compactions,omitempty"`
   }
   ```

   - `MethodSessionCompact = "session.compact"`, `MethodSessionContext = "session.context"`,
     `NotifyCompact = "compact"`.
   - `EventParams` gains `Compact *CompactInfoWire`; `DoneParams` gains `Context *ContextInfo` and
     `LastRequestAt string` (RFC 3339, empty when unknown); `Usage` gains
     `cached_tokens` / `cache_write_tokens`.

2. **Enable it** (`server.go`): `buildOptions` sets `opts.Context` from `p.Context`. A missing
   `Context` sends the zero value, which keeps auto-compaction off exactly as today — an older
   client cannot start compacting a session it did not ask about. Negative values are normalized
   by the SDK.

3. **`session.compact`** (`server.go`): decode `{session_id}`, resolve the live session, refuse
   when a run is active (`CodeRunInProgress`, the same code `prompt` uses), call
   `agent.Compact(ctx)`, emit a `compact` notification with the same payload shape a runtime
   `compact` event produces (reason `manual`), and answer:

   ```go
   type SessionCompactResult struct {
       SessionID string       `json:"session_id"`
       Compacted bool         `json:"compacted"`
       Before    int          `json:"before,omitempty"`
       After     int          `json:"after,omitempty"`
       Summarized int         `json:"summarized,omitempty"`
       Context   ContextInfo  `json:"context"`
   }
   ```

   A session this host does not have open answers `CodeNoSession`; compaction requires the live
   history, and reading a store to compact it is not what this phase does.

4. **`session.context`** (`server.go`): resolve the live session and return `ContextInfo` from
   `agent.ContextUsage()`. The count is an estimate; the field names never say "tokens used".

5. **Projection** (`session.go`):

   - `projectEvent` maps `anvil.EventCompact` to `EventParams{Type: "compact", Compact: …}`; the
     session's agent id and depth are stamped by `drain` as for every other event.
   - `projectDone` fills `Context` from the agent's `ContextUsage` after the run and
     `LastRequestAt` from `RunResult.LastRequestAt`; `usageWire` copies the cache fields.
   - The `done` context is what the meter uses after a turn, so it must be computed after the
     loop has folded any final compaction into the history.

6. **Capabilities**: add `"session.compact"` and `"session.context"` to the capability list only
   if the existing list is method-shaped (server.go:256-258); otherwise leave it and rely on
   `-32601` as the older clients do.

7. **Tests** (`context_test.go`): a session with a tiny window compacts through a run; an idle
   `session.compact` returns counts and appends a summary record; a compact during a run is
   `-32003`; `session.context` reports the estimate; `done` carries context and
   `last_request_at`; a runtime compact event reaches the client with the session id; usage
   carries cached tokens.

## Acceptance

- [ ] `buildOptions` maps `ContextParams` onto `anvil.Options.Context`; a session created without
  `context` behaves exactly as before.
- [ ] A session whose window makes the next request cross the threshold compacts, and the client
  sees one `event` of type `compact`.
- [ ] `session.compact` on an idle session returns before/after/summarized and the next Resume
  loads the summary; a second call with nothing left says `compacted: false`.
- [ ] `session.compact` during a run answers `-32003`, and the run is untouched.
- [ ] `session.context` answers for a live session; an unknown id answers `-32001`.
- [ ] `done` carries `context` and `last_request_at`; `usage` carries `cached_tokens` and
  `cache_write_tokens` when the provider reported them, and omits them otherwise.
- [ ] `go test ./...` green, including `independence_test.go`.

## Non-goals

- Compacting a stored session this host never opened.
- A host-side timer that compacts idle sessions.
- Changing the session list's cumulative usage semantics.
- Sending the model's summary text to the client beyond the transcript record.
