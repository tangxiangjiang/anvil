# p_0.43.2 — Cache accounting and prompt caching

**Status:** done (2026-10-19)
**Milestone:** [m_0.43_context_management.md](../m_0.43_context_management.md)
**Linked design:** [42-context-management.md](../../../design/v1.0/42-context-management.md) §3,
[05-llm-provider.md](../../../design/v1.0/05-llm-provider.md)

## Goals

1. **Cache activity becomes fact.** `Usage` carries cached input tokens, parsed from every wire
   shape that reports them, in both streaming and non-streaming responses.
2. **Anthropic actually caches.** The client sends `cache_control` breakpoints when asked, so the
   cache numbers and the countdown mean something for that provider.
3. **A clock has an anchor.** A run reports the wall-clock time of its last model request; the
   client computes the remaining cache life from that and a TTL it knows. Providers that publish
   no TTL get no countdown.

## Scope

`source/internal/llm/types.go`, `openai.go`, `openai_stream.go`, `anthropic.go`,

## Tasks

1. **The shape** (`internal/llm` and public `anvil.Usage`):

   ```go
   CachedTokens     int // input tokens served from a cache
   CacheWriteTokens int // input tokens written to a cache (Anthropic only)
   ```

   Zero means "the provider said nothing"; a client must not draw it as "no cache".

2. **OpenAI-compatible parsing**:

   - Non-stream: `usage.prompt_tokens_details.cached_tokens` → `CachedTokens`.
   - Non-stream and stream, DeepSeek: `usage.prompt_cache_hit_tokens` → `CachedTokens`;
     `prompt_cache_miss_tokens` is not stored (it is `prompt_tokens - hit`).
   - Stream: parse both shapes from the chunk that carries usage. Add
     `"stream_options": {"include_usage": true}` to the streaming request so servers that follow
     the OpenAI contract actually send a usage chunk; servers that ignore unknown options keep
     working because the field is optional.

3. **Anthropic parsing** (non-stream and stream):

   - `usage.cache_read_input_tokens` → `CachedTokens`; `usage.cache_creation_input_tokens` →
     `CacheWriteTokens`.
   - `TotalTokens = InputTokens + CachedTokens + CacheWriteTokens + OutputTokens`, because
     Anthropic's `input_tokens` counts only the uncached part. OpenAI's `cached_tokens` is a
     subset of `prompt_tokens`, so its total stays the provider's `total_tokens`.

4. **Prompt caching** (`anthropic.go`, `anthropic_stream.go`):

   - `llm.Request.PromptCache bool` and `Options.Context.PromptCache *bool` (nil = on for the
     Anthropic provider, ignored by OpenAI-compatible providers).
   - When on: `system` becomes an array of text blocks whose last block carries
     `{"type": "cache_control", "cache_control": {"type": "ephemeral"}}`, and the last message's
     last content block carries the same marker. Both request builders share one helper so the
     streaming and non-streaming bodies cannot drift.
   - The declared TTL is Anthropic's documented 5 minutes; the SDK does not set a TTL on the
     breakpoint (that would require a beta header). It reports cached tokens, not the TTL.

5. **The anchor** (`runtime/loop.go`, `types.go`):

   - The loop records `time.Now()` after each successful completer call.
   - `RunResult.LastRequestAt time.Time` and `Event.LastRequestAt time.Time` (terminal events)
     carry the last one; zero when no request was made.

6. **Persistence** (`store.Usage`): add `CachedTokens` and `CacheWriteTokens` to the stored
   usage record so `session.list` and replay keep the accounting; the JSON fields are additive.

7. **Tests.** Fake HTTP servers for each provider: non-stream and stream cached fields; DeepSeek
   hit tokens; Anthropic read/write with the total; a request body with and without
   `cache_control`; `include_usage` present on the streaming request; `LastRequestAt` set; store
   round-trip.

## Implementation notes

Written back in the same commit; chapter 42 §3 is the contract.

- **One wire struct per provider, shared by both paths.** `openAIUsageWire.usage()` and
  `anthropicUsageWire.usage()` are called from `Complete` and `CompleteStream`, so a field can
  never be parsed in one path and dropped in the other. OpenAI-compatible parsing prefers
  `prompt_tokens_details.cached_tokens` and falls back to DeepSeek's `prompt_cache_hit_tokens`;
  a proxy that sends neither yields zero, not an error.
- **Totals follow each provider's own arithmetic.** OpenAI's `cached_tokens` is a subset of
  `prompt_tokens`, so the provider's `total_tokens` is kept as-is. Anthropic's `input_tokens`
  excludes the cached parts, so the total is recomputed as
  `input + cache_read + cache_creation + output` — otherwise a warmed request would look cheaper
  than the same request sent cold.
- **Zero means silence.** `CachedTokens == 0` on a response says the provider reported nothing;
  it does not say the request missed. The editor's countdown (p_0.43.4) drives off
  `LastRequestAt` and the cache counts together for exactly that reason.
- **Both request builders call one helper.** `toAnthropicMessages(messages, promptCache)` returns
  the system value and the converted messages; `markAnthropicCache` puts the marker on the last
  content block of the last message. When caching is off the system stays a plain string, so a
  request that does not ask for caching is byte-for-byte the old body.
- **The TTL is the client's knowledge, not the wire's.** The API reports cache reads and writes
  but not how long they last; the documented 5-minute ephemeral window is applied by whoever
  draws the countdown. The SDK reports facts only.
- **The anchor is set after the call returns.** `lastRequestAt = time.Now()` runs once a
  completer call succeeds, so a run that failed on its first request — DNS, auth, a bad body —
  carries a zero anchor and the client shows no countdown rather than a wrong one. Every
  terminal emit and the final result carry the same value; the error event from a first-call
  failure is covered by the same rule.
- **Run state is cleared before the result is published.** `executeRun` used to clear
  `running`/`activeRun` in its defer, which runs *after* `run.finish`. A caller that woke from
  `Wait` and sent again could race the goroutine and be told `another run is already in
  progress`. `clearRunState` now runs before `finish` and again from the defer, where the
  second call is a no-op. This was a latent race, surfaced by the new round-trip test under
  full-suite load.

## Non-goals

- Cache warm-up, cache-busting, retries for a cold cache, or TTL discovery.
- A one-hour Anthropic TTL (it needs a beta header) or breakpoints on older turns.
- Cache accounting inside the summarizer call's own usage.
- Changing how the gateway proxies responses.
