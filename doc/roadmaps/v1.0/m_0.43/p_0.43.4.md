# p_0.43.4 — The editor's countdown

**Status:** planned
**Milestone:** [m_0.43_context_management.md](../m_0.43_context_management.md)
**Linked design:** [42-context-management.md](../../../design/v1.0/42-context-management.md) §2–§3,
[39-editor-alignment.md](../../../design/v1.0/39-editor-alignment.md)

## Goals

1. **`/compact` is a command, not a prompt.** It is handled beside `/tasks`, never reaches the
   model, compacts the open session through `session.compact`, and reports the result in the
   transcript. While a turn is running it refuses in words.
2. **The meter counts down.** It shows how much estimated context is left before the window and
   where auto-compaction will fire, ticking down as the conversation grows.
3. **The cache has a clock.** When the provider reported cached tokens and a TTL is known, the
   meter counts the cache's remaining life down to zero and then says **cache cold**. With no
   TTL it shows the cached share and no countdown.
4. **A compact leaves a mark.** The transcript draws one divider for a compact, live and on
   replay.

## Scope

`editors/vscode/src/{protocol.ts,settings.ts,session.ts,chatPanel.ts,commands.ts,transcript.ts}`,
`editors/vscode/media/{chat.js,chat.css,meter.js}`, `editors/vscode/package.json`, tests under
`editors/vscode/test`, and `editors/vscode/README.md`.

## Tasks

1. **Settings** (`package.json`, `settings.ts`):

   - `anvil.autoCompactAt` (number, default `0.8`, minimum 0.1, maximum 1) — where the session
     compacts, as a fraction of the window.
   - `anvil.contextKeepRecent` (number, default `8`, minimum 2) — messages kept verbatim.
   - `anvil.cacheTtlSeconds` (number, default `0`) — 0 means the provider default: 300 for the
     Anthropic provider, no countdown for others.
   - `readSettings` resolves them; a window of 0 still disables auto-compaction, as today.

2. **They travel** (`settings.ts`, `chatPanel.ts`, `protocol.ts`): the session config gains
   `context: {window_tokens, auto_compact_at, keep_recent}`, built from the three settings. The
   fake host asserts the exact shape a real one decodes.

3. **Wire types** (`protocol.ts`): `Usage` gains `cached_tokens?` and `cache_write_tokens?`;
   `DoneParams` gains `context?: ContextInfo` and `last_request_at?: string`; `HostEvent` gains
   `compact?: CompactInfo`; `EventType` gains `'compact'`; transcript entries gain a `summary`
   kind with `content`; `Method.SessionCompact = 'session.compact'` and a
   `ContextInfo {estimated_tokens, window_tokens, compact_at_tokens, messages, compactions?}`.

4. **`/compact`** (`commands.ts`, `chatPanel.ts`, `media/chat.js`):

   - Add the built-in with a one-line description; `route` returns a `compact` action; `runAction`
     calls a new `compactSession()`.
   - `compactSession` refuses with a visible line when a turn is running, otherwise calls
     `session.compact`, posts the result (before → after, messages summarized) and asks for
     `session.context` so the meter is correct immediately.
   - The webview's palette gets the command through the existing catalogue; no extra shortcut is
     needed (`/tasks`' webview-local interception stays as it is).

5. **The meter** (`meter.js`, `chat.js`, `chat.css`):

   - `meterMath.remaining(state, contextInfo)` returns `{used, left, compactAt, leftUntilCompact,
     percent}` when a window is known, or null.
   - `meterMath.cache(state, ttlSeconds, lastRequestAt, now)` returns `{cached, ttl, remaining}`;
     `remaining` is null when `ttlSeconds <= 0`, and 0 (cold) after expiry.
   - The `context` message from the extension gains `auto_compact_at`, `cache_ttl_seconds` and the
     optional `info` a `session.context` answer produced.
   - On `done`, chat.js records `last_request_at` and the cached tokens, and renders the meter:
     `18k of 200k (9%) · 182k left · compact at 160k` plus `· cache 8.1k · 4:12`.
   - One `setInterval(…, 1000)` updates only the cache clock while a TTL is known and the tab is
     visible; it renders `cache cold` at zero and never invents a TTL.
   - The meter is text only; the countdown uses `textContent`.

6. **The divider** (`chat.js`, `chat.css`, `transcript.ts`): a `compact` event and a replayed
   `summary` entry both draw one row — `context compacted · 24 messages summarized · 41k → 12k` —
   with no markup. The replay projection maps the host's summary entry to this row.

7. **Tests**: settings resolution; the session config shape; `commands.test.ts` for `/compact`
   routing (and that it is not a prompt); `meter` math (remaining, threshold, unknown window,
   cache TTL expiry, no TTL); chat.js source assertions in the established style (countdown
   element, text-only render, no `innerHTML`); protocol shape tests; a fake-host test that
   `session.compact` is called and its result posted.

8. **Docs**: `editors/vscode/README.md` gains a short bullet — the meter counts down and
   `/compact` compacts on demand.

## Acceptance

- [ ] `/compact` is in the catalogue, routes to the host, and never appears as a prompt; while a
  turn runs it answers with a visible refusal.
- [ ] A successful compact posts the before/after counts and refreshes the meter.
- [ ] The meter shows used, left and the auto-compact mark when a window is set, and counts down
  between turns; with no window it shows counts only, exactly as today.
- [ ] A run whose usage reports cached tokens shows the cached share; with a known TTL the
  countdown ticks and reaches `cache cold`; with TTL 0 no countdown is drawn.
- [ ] A compact event draws one divider live; a reloaded transcript draws the same divider from
  the summary entry.
- [ ] Every new renderer path uses `textContent`; the existing `innerHTML` test still passes.
- [ ] `npm test` green (402 + the new tests); `package:vsix` and `smoke:vsix` green.

## Non-goals

- A `/context` panel or a dedicated context view; the meter carries the numbers.
- Changing the model picker or estimating a window from a model name.
- Per-tab TTL overrides or a cache-warm-up button.
- Compacting a child agent's conversation from the editor.
