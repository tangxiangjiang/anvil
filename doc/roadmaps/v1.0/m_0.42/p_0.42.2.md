# p_0.42.2 — Background tasks in the SDK

**Status:** planned (2026-10-19)
**Milestone:** [m_0.42_subagents_and_tasks.md](../m_0.42_subagents_and_tasks.md)
**Linked design:** [41-subagents-and-tasks.md](../../../design/v1.0/41-subagents-and-tasks.md),
[03-runtime-loop.md](../../../design/v1.0/03-runtime-loop.md)

## Goals

1. **Work that outlives a call.** `shell` can start a process and return without waiting;
   `spawn_agent` can do the same with an agent. Both are rows in one table.
2. **One table, one reader.** `task_list`, `task_output` and `task_cancel` are tools the model
   uses, and `Agent.Tasks`/`TaskOutput`/`CancelTask` are the embedder's API over the same rows.
3. **Ownership is explicit.** Tasks belong to the root agent's tree; `Agent.Close` cancels them
   and waits briefly, so a closed conversation does not leave a process writing into its
   workspace.
4. **Bounded.** `Subagents.MaxBackground` bounds concurrent tasks; a background shell is still
   bounded by its timeout; nothing here is an unbounded queue.

## Scope

`source/internal/tasks/` (new package: `manager.go`, `output.go`, `manager_test.go`),
`source/internal/tools/{tools.go,shell_unix.go,shell_windows.go,task_tool.go (new),groups.go}`,

## Tasks

1. **The manager** (`source/internal/tasks`):

   ```go
   type Kind string   // "shell" | "agent"
   type Status string // "running" | "finished" | "failed" | "cancelled"

   type Info struct {
       ID, Title, AgentID string
       Kind   Kind
       Status Status
       StartedAt, EndedAt time.Time
       ExitCode int
   }

   type Manager struct{ /* mutex-guarded map + optional change hook */ }

   func NewManager() *Manager
   func (m *Manager) StartShell(spec ShellSpec) (Info, error)
   func (m *Manager) StartAgent(spec AgentSpec) (Info, error)
   func (m *Manager) List() []Info
   func (m *Manager) Output(id string, offset, limit int) (Output, error)
   func (m *Manager) Cancel(id string) (Info, error)
   // Close cancels everything still running and waits up to grace for the
   // goroutines to observe it.
   func (m *Manager) Close(grace time.Duration)
   ```

   - `ShellSpec{Title, Command, CWD string; Timeout time.Duration; Prepare func(*exec.Cmd)}` — the
     manager builds `exec.CommandContext(ctx, shell)`, sets `Dir`, calls `Prepare` (the platform
     hook that kills the process tree), and runs `CombinedOutput` into the ring.
   - `AgentSpec{Title, AgentID string; Run func(ctx context.Context) (string, string, error)}` —
     the runner returns `(status, message, err)`. The manager files one task and records the final
     message as the task's output, so `Output` on an agent task is its result, not a byte stream.
   - A cancelled shell task's status is `cancelled`, `ExitCode` is `-1` unless the process exited
     on its own before the cancel was observed. Output ends with the same sentence the foreground
     tool writes for a kill.
   - `Start` refuses past the manager's limit (`Limit int`, set from
     `Subagents.MaxBackground`) with a sentence naming it.

2. **The output ring** (`source/internal/tasks/output.go`): at most 1 MiB per task, a
   monotonically increasing offset. `Output(id, offset, limit)` returns `Text`, `NextOffset`,
   `FirstOffset` (the oldest byte still held) and `Truncated` (true when `offset < FirstOffset`).
   A reader that fell behind is told it did, instead of receiving a gap. `limit` is capped at
   64 KiB per call.

3. **Wiring** (`source/agent.go`, `source/internal/tools/tools.go`):

   - `Options` gains an unexported `taskMgr *tasks.Manager`. `Create` leaves it nil;
     `buildRegistry` creates one when nil and stores it on the `Registry`
     (`reg.SetTaskManager(mgr)`). `createSubagent` copies the parent's manager into the child's
     options, so a child's shell job and a grandchild's subagent share one table.
   - `Agent` keeps the manager (from the registry) for `Tasks`/`TaskOutput`/`CancelTask` and
     calls `Close(twoSeconds)` in `Agent.Close`, before MCP/plugins/LSP are torn down.
   - `NewRegistry` registers `task_list`, `task_output` and `task_cancel` alongside `shell` when
     `allowShell`; `buildRegistry` additionally registers them when subagents are enabled, so a
     read-only child can still read the parent's background work.

4. **Background shell** (`source/internal/tools/tools.go`, `shell_windows.go`, `shell_unix.go`):

   - `shell` gains `"run_in_background": {"type": "boolean"}`.
   - `timeout_seconds` keeps its 1–120 s range for a foreground call. A background call accepts
     1–3600 s (default 60) and passes it as the task's `Timeout`; a job is unwaited, not
     unbounded.
   - On `run_in_background`, `Execute` starts the task and returns:
     ```
     task-… started in the background: <command>
     Read it with task_output, stop it with task_cancel.
     ```
     The permission gate already ran: `Registry.Execute` asks before `t.Execute`, so the card is
     answered before the process exists.
   - `Prepare` is the existing `configureShellCommand`, so a cancel is `taskkill /F /T` on Windows
     and the process group on Unix — the same kill the foreground timeout uses.

5. **Background subagents** (`source/subagent.go`):

   - `spawn_agent` with `"background": true` builds the child exactly as the foreground path does,
     then calls `StartAgent` with a runner that does `Create` → `Send(context.Background())` →
     `Wait` → `Close`, returning `(string(status), final message, err)`.
   - The child is not tied to the parent run's context: cancelling the turn leaves it running.
   - `SubagentEvent`s from a background child are still forwarded through `OnEvent`; their
     `ToolCallID` is the spawn call, which has already returned. That is how the editor attaches
     live steps to a card that is no longer waiting (p_0.42.3).
   - The result text is:
     ```
     task-… started in the background: subagent Find Registry.Execute callers
     Read it with task_output, stop it with task_cancel.
     ```
   - `MaxBackground` is enforced by the manager, so the refusal is one sentence regardless of
     kind.

6. **The task tools** (`source/internal/tools/task_tool.go`):

   | Tool | Arguments | Result |
   |---|---|---|
   | `task_list` | — | `id  kind  status  age  title`, one per line; `(no tasks)` when empty |
   | `task_output` | `{task_id, offset?, limit?}` | `task-… <status> (exit N)` then the chunk, then `next offset N` when more remains |
   | `task_cancel` | `{task_id}` | `task-… <status>`; cancelling an ended task is not an error |

   `task_output` on a running task returns the bytes so far and `next offset` at the current end;
   polling is the model's loop, and the tool does not block.

7. **The `agent` group** (`source/internal/tools/groups.go`): `"agent":
   {"spawn_agent", "run_workflow", "task_list", "task_output", "task_cancel"}` and
   `DefaultPermissionGroups` in the host gains `agent` in p_0.42.3. In this phase the group exists
   so a caller can name it; `AutoApproveCall` returns false for every name in it (a test pins
   that).

8. **Docs.** Chapter 41's "Background tasks" section is the contract; implementation divergence is
   written back in the same commit.

## Acceptance

- [ ] `shell {command, run_in_background: true}` returns a `task-…` id immediately; the process
  keeps running after the turn ends; `task_output` reads its output in offset order and reports
  `next offset`.
- [ ] `task_cancel` on a running shell task kills the process tree (a grandchild process is gone
  too) and the task's status is `cancelled`.
- [ ] A background shell that reaches `timeout_seconds` is `failed`, and its output ends with the
  "command killed after" sentence.
- [ ] A background subagent's final message is returned by `task_output` once; its events reached
  `OnEvent` while it ran.
- [ ] `task_list` on a parent lists a child's shell task with the child's `agent_id`.
- [ ] The `MaxBackground`-th concurrent start is refused with a sentence naming the limit; the
  tool result is an error and the run continues.
- [ ] `Agent.Close` cancels running tasks and returns within the grace period; a task cancelled
  this way is not `running` afterwards.
- [ ] `Tasks`, `TaskOutput`, `CancelTask` agree with the tools for the same ids; an unknown id is
  an error naming it.
- [ ] `AutoApproveCall` is false for `spawn_agent`, `task_list`, `task_output`, `task_cancel`.
- [ ] `go test ./...` green; `gofmt`/`go vet` clean.

## Non-goals

- Host RPCs and editor surfaces (p_0.42.3).
- Task persistence across process exits, retry, scheduling, or a queue with a producer API.
- PTY/interactive shells; stdin is closed for every background job.
- Cross-workspace tasks or tasks that outlive `Agent.Close`.
- Streaming task output as SDK events; the ring is polled.
