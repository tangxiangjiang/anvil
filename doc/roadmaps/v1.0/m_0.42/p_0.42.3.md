## Goals

1. **A child is visible where it acts.** A subagent's steps are drawn under the `spawn_agent` card
   while it runs, and its stored transcript opens from that card afterwards.
2. **`/tasks` exists.** Host RPCs and a `task` notification feed a panel, a composer command, a
   status-bar item and a nested session tree — one state, several views.
3. **The approval card names the asker.** A child's permission request reaches the same person,
   and the card says which subagent asked.
4. **The wire stays additive.** New fields and methods, no `ProtocolVersion` bump; a 0.41 client
   reads a 0.42 host and simply does not show what it does not know.

## Tasks

1. **Wire types** (`source/internal/editorhost/proto.go`):

   - `EventParams` gains
     ```go
     AgentID         string `json:"agent_id,omitempty"`
     ParentToolCallID string `json:"parent_tool_call_id,omitempty"`
     Depth           int    `json:"depth,omitempty"`
     ```
     The parent's own events carry the session's agent id; child events carry theirs plus the spawn
     call. `Depth` is 0 and omitted for the session's own agent.
   - `ApprovalRequestParams` gains `AgentID string` and `Depth int`.
   - `SessionSummary` gains `ParentAgentID string`, `Depth int`, `Subagent bool`,
     `TaskTitle string` (from the store summary added in p_0.42.1).
   - New:
     ```go
     type TaskInfo struct {
         ID, Kind, Title, Status, AgentID string
         StartedAt, EndedAt time.Time
         ExitCode int
     }
     type TasksListParams struct{ SessionID string }
     type TasksListResult struct{ Tasks []TaskInfo }
     type TasksOutputParams struct{ SessionID, TaskID string; Offset, Limit int }
     type TasksOutputResult struct{ Status string; ExitCode int; Output string; NextOffset int; FirstOffset int; Truncated bool }
     type TasksCancelParams struct{ SessionID, TaskID string }
     type TasksCancelResult struct{ Task TaskInfo }
     type TaskNotification struct{ SessionID string; Task TaskInfo }
     ```
   - `MethodTasksList = "tasks.list"`, `MethodTasksOutput = "tasks.output"`,
     `MethodTasksCancel = "tasks.cancel"`; `NotifyTask = "task"`.

2. **Host plumbing** (`source/internal/editorhost/server.go`, `session.go`):

   - `buildOptions` sets `Subagents: anvil.SubagentOptions{Enabled: true, OnEvent: ...,
     OnTask: ...}` when a new session parameter `subagents *bool` is not false. The default is on
     for the editor; `localProjection` carries it.
   - `OnEvent` projects the child event through `projectEvent` with `AgentID` and
     `ParentToolCallID` filled from the envelope and notifies `event`. It does not go through the
     parent's `drain`, because the parent's run is blocked on the card and its channel is not the
     right owner.
   - `OnTask` notifies `task` with the session id; a task that ends after the session closed is
     dropped (the session lookup fails), which is the same rule late events follow.
   - The approval hook adds `AgentID: req.AgentID` and `Depth: req.Depth` to the notification. The
     `run_id` stays the session's active run, so `session.cancel` still withdraws the prompts that
     belong to the turn; a background child's approval while the session is idle has an empty
     `run_id` and is withdrawn by `session.close` and by `tasks.cancel` for its task.
   - Register the three handlers beside `session.cancel`. Each resolves the session first
     (`CodeNoSession`), then the task (`CodeNoTask`, a new code), then delegates to the SDK.
     `tasks.output` on an ended agent task returns its final message once and then an empty chunk
     at the same offset.
   - `session.list` passes the new summary fields through.

3. **Extension protocol** (`editors/vscode/src/protocol.ts`): the mirrors of the above —
   `Method.TasksList/TasksOutput/TasksCancel`, `Notify.Task`, `HostEvent.agent_id/
   parent_tool_call_id/depth`, `ApprovalRequest.agent_id/depth`, `SessionSummary.parent_agent_id/
   depth/subagent/task_title`, and `TaskInfo`, `TasksListResult`, `TasksOutputResult`.

4. **Host manager and session** (`hostManager.ts`, `session.ts`):

   - `hostManager` gains `listTasks(sessionId)`, `taskOutput(...)`, `cancelTask(...)`.
   - `ChatSession.handle` routes `Notify.Task` to a new `onTask?: (task: TaskInfo) => void`
     handler. Every event, including a child's, keeps routing by `session_id`; the panel decides
     where to draw it using `parent_tool_call_id`.
   - The session keeps no task state of its own: the Tasks panel and status bar read from the host,
     so a closed and reopened panel shows the truth rather than what it remembered.

5. **Nested cards** (`editors/vscode/media/chat.js`, `chat.css`):

   - A `tool_call` named `spawn_agent` creates a card with a header (status, description, child
     agent id once known) and a collapsible body.
   - A child event (`parent_tool_call_id` set) is appended to that call's body with the same
     primitives the parent transcript uses: assistant text, reasoning, tool cards, errors. No
     second renderer, no `innerHTML`.
   - The spawn `tool_result` sets the card's terminal state and keeps the child's steps; the
     result's first line supplies the agent id, so a replayed tab can offer **Open subagent
     transcript** without having seen a child event.
   - Replay: a stored `spawn_agent` call+result renders collapsed with a summary line and the
     open-transcript action; it does not pretend the steps are present.
   - A background spawn's card says *running in the background* and links to the Tasks panel.

6. **Tasks panel** (`editors/vscode/src/tasksPanel.ts`, `media/tasks.js`, `media/tasks.css`):

   - One document per window (`anvil.tasks`), revealed like the permissions manager; trusted
     workspaces only (`HostManager.assertTrusted()` before the first host call).
   - Rows: kind, title, status, elapsed, agent id, actions — **Open transcript** (agent tasks),
     **View output** (shell tasks; a `<pre>` fed by `textContent` with a Refresh action), **Cancel**
     while running.
   - `ready`/`refresh` call `tasks.list`; a `task` notification on the owning session triggers a
     re-list while the panel is visible. No timer when the panel is hidden.
   - Output is read in offset order; `truncated` shows the "older output dropped" note rather than
     a silent gap.

7. **Composer `/tasks`** (`media/chat.js`, `chatPanel.ts`, `hub.ts`):

   - A send whose trimmed text is exactly `/tasks` posts `{type:'openTasks'}` and sends no prompt.
     The composer's slash list gains `/tasks — show background tasks and subagents`.
   - `chatPanel` forwards it to `hub.openTasks()`; unknown `/` text is still sent to the model (it
     may be a path or prose), so only the exact known command is intercepted.

8. **Status bar** (`editors/vscode/src/statusBar.ts`): a second item shows `$(tasklist) N` while
   the session has running tasks; clicking opens the panel. It is updated from `task`
   notifications and cleared when the count reaches zero, independently of the run indicator.

9. **Session tree** (`editors/vscode/src/sessionTree.ts`):

   - A session with `subagent: true` is a child of its `parent_agent_id`; children are collapsed
     under the parent and drawn with their `task_title` (falling back to the derived title).
   - Opening a child opens its transcript tab through the existing resume/replay path.
   - Deleting a parent says how many child sessions go with it; the host's `DeleteAgent` is what
     actually removes them (p_0.42.1).

10. **Commands and docs.** `anvil.openTasks` in `package.json` and `extension.ts`; the extension
    README gains a subagents/background paragraph and a `/tasks` line. Root `README.md` gains the
    0.42 row when the milestone is done.

## Acceptance

- [ ] A session opens with subagents enabled; a scripted spawn produces an `event` notification
  with `agent_id` and `parent_tool_call_id`, and the webview draws the child's steps under the
  spawn card.
- [ ] The spawn card's *Open subagent transcript* opens the child's stored conversation in a tab.
- [ ] A child's `write_file` in `ask` opens a card whose payload names the child (`agent_id`,
  `depth: 1`); answering it resolves the child and the parent's card completes.
- [ ] `tasks.list` returns shell and agent tasks from the session's tree; `tasks.output` pages a
  long output by offset and reports `truncated` when it has fallen behind; `tasks.cancel` stops a
  running task and answers with its final state.
- [ ] The `task` notification fires on start and on end; a closed session drops it rather than
  throwing.
- [ ] Typing `/tasks` opens the panel and sends nothing to the model; `Anvil: Open Tasks` does
  the same; the status bar shows the running count and clears it.
- [ ] The session tree nests a child under its parent; deleting the parent names the child count.
- [ ] A 0.41-shaped client still opens, prompts and renders parent events against a 0.42 host
  (`ProtocolVersion` unchanged).
- [ ] `go test ./...` and `npm test` green; packaging and the packaged smoke test green.

## Non-goals

- Task output streaming as it is produced; the panel refreshes on demand and on lifecycle change.
- A separate window/tab per task, drag-and-drop ordering, or task history across host restarts.
- Editing a child's prompt or re-running a child from the UI (beyond opening its transcript).
- Changing Stop's meaning: it still cancels the turn, not the tasks.
