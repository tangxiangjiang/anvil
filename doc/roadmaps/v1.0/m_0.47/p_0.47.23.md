## Goals

The dock holds two facts about the session — the folder the conversation belongs to and
what the session has spent — and one fact about the run in flight. In the DOM they are
ordered root, status, meter, so a turn in flight inserts the working line between the two
session facts and pushes the meter away from the root it belongs with. Seen at the bottom of
a long conversation, the two lines read as if they had drifted apart, and the growing dock
moves under the transcript as it runs.

1. **The two session facts stay together.** The root line and the token/context meter are
   adjacent, in that order, whether or not a run is in flight.
2. **The working line sits nearest the composer.** It is about the run, not about the
   session; directly above the input is where a reader looks for it. The finished run's
   summary inherits the same place.
3. **Spacing follows the grouping.** The root line's foot returns to 6px so it reads with
   the meter beneath it; the working half keeps its 10px above the composer.

## Scope

`editors/vscode/src/chatPanel.ts` (one element moved in the dock template), `media/chat.css`
(the root line's foot and the comments that describe the order) and `test/unit/working.test.ts`
(the dock's order). No protocol field, no host change, no setting, no change to the mark or
the verbs.

## Decisions (before any change)

- **Order is meaning.** The root and the meter describe the session; the status describes one
  run. A DOM order that interleaves them says the opposite, and no amount of spacing fixes a
  sentence written in the wrong order.
- **The working line belongs at the bottom.** It replaces itself with the run's summary, and
  a summary is read just above the input. Putting it there also keeps the two session facts
  still while the dock grows during a turn.
- **The root line tightens, the status line does not.** p_0.47.21 gave both 10px while they
  were adjacent. With the meter between them, 10px would separate the pair the change is
  meant to join, so the root returns to the rhythm it had before and the working line keeps
  the room it was given.

## Implementation notes

### The order

`#composerDock` now reads root, meter, status, bypass, dontAsk, composer. The status element
kept its id, its two halves and every helper that writes it — `setStatus`, `startWorking`,
`stopWorking`, `finishRun` — because only its place in the template changed. The `#status`
comment in the template says why the place is what it is; the stylesheet's root and status
comments say the same from the layout side.

### The feet

`.root` returns to 6px, as it had before p_0.47.21, so the root line reads with the meter
directly beneath it. `.status` keeps 10px, now above the composer. Nothing else in the dock's
spacing moved, and the measured dock height (`--anvil-composer-h`) still covers all of it.

## What was not walked

No real window here. The grouping was checked in the template's order and the stylesheet's
feet; how the pair reads under a long root path, and whether the working line at the very
bottom draws the eye too late in a tall panel, were reasoned from the layout.

## Non-goals

- Merging the two facts into one line; they are two values with two sources and different
  alignments.
- Moving either line into the transcript.
- Changing the mark, the verbs, the colours or the clock.
- A protocol change, a host change, a version bump, a branch, or a push.
