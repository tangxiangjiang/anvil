# p_0.47.15 — A result finds its call, and a window starts at a turn

**Status:** done (2026-10-20)
**Milestone:** [m_0.47_editor_polish.md](../m_0.47_editor_polish.md)
**Linked design:** [44-editor-polish.md](../../../design/v1.0/44-editor-polish.md) §17,
[35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md) (history replay)

## Goals

Opening a stored conversation showed a large orange block containing a whole tool result,
drawn as an error. It was not an error: it was a result whose call was not on screen. Three
defects met at that block, and each is fixed here.

1. **A window can open mid-run.** The host keeps the newest 200 stored entries and moves the
   window forward to the first user turn it contains. When the window contains no user turn
   at all — a long run of calls and results — it stayed where the cap fell, so the replay
   began with a result whose call had been cut. The window now moves back to the user turn
   that opened the run.
2. **A result without a card was drawn as an error.** The webview's fallback called
   `addNotice`, which styles the block as `.msg.error` and prints the result in full. A
   result is information the model already acted on; it is not a failure. The fallback now
   draws the row the result should have had, then fills it through the normal path.
3. **The replay did not synthesize the call.** A stored tool record whose call fell outside
   the window replayed as a lone `tool_result`. `replayOf` now emits a `tool_call` for a
   `tool_call_id` it has not seen, carrying the stored name, before the result.

## Scope

`source/transcript.go` and `source/transcript_test.go`; `editors/vscode/src/transcript.ts`
and `editors/vscode/test/unit/replay.test.ts`; `editors/vscode/media/chat.js` and

the change. No protocol field, no store change, no setting.

## Tasks

1. **Move the window back to its turn.** In `transcriptFromRecords`, when the capped window
   contains no user entry, find the last user entry before it and start there. When it does
   contain one, the existing forward alignment is unchanged.
2. **Draw an unseen call.** `replayOf` tracks the call ids it has emitted; a tool record
   whose id is new gets a synthetic `tool_call` (id, stored name, no arguments) immediately
   before its `tool_result`.
3. **Draw a missing call live.** `addToolResult` calls `addToolCall` for a result whose card
   is not in `toolCards`, then continues through the normal result path. A result with no id
   at all gets a compact note with the tool name and the output caption, never the full text
   as an error.
4. **Share the caption.** The output caption is built by one `outputNote` helper used by a
   settled card and by the id-less note.
5. **Tests.** A Go case for a cap that lands inside a run (and one for a store with no user
   turn); a replay case for a synthesized call and for an already-seen id; a renderer case
   that the fallback draws a row rather than a notice.
6. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Decisions (before any change)

- **The turn is the unit a window must not cut.** The cap is a bound on what one render
  costs, but a render that starts with an OUT whose card was never drawn is not a smaller
  conversation, it is a wrong one. Moving back can make the window longer than the cap when
  a single turn is longer than the cap; showing that turn whole is the only honest option,
  and the alternative — a broken row — is worse than a large render.
- **The synthesized call has no arguments.** The store keeps the result's tool name, not the
  call's JSON, so an empty IN is what is known. Inventing arguments or hiding the row would
  both claim more than the store holds.
- **A missing call is drawn, not reported.** `.msg.error` says the run failed. This run did
  not: the model received the result and continued. The renderer draws the same row a live
  call gets, so the transcript shows a step rather than a defect.
- **One renderer for both paths.** The live fallback reuses `addToolCall`; the replay emits
  the event shape `addToolCall` already consumes. No second card renderer and no special
  case in the webview's event table.
- **The id-less result is a note.** Without an id there is nothing to attach a card to, so
  the block names the tool, says a line about the result, and offers the output tab. It is
  not styled as an error either.

## Implementation notes

`transcriptFromRecords` slices the newest `limit` entries as before. It then looks for a
user turn in that window: found after index 0, the window moves forward to it (the existing
behaviour); not found at all, `lastUserTurnBefore` scans the entries before the window and
the window moves back to that index. The scan is bounded by the store's own length, and the
result reports the extra entries in `Dropped`.

`replayOf` keeps a `Set` of emitted call ids. An assistant record's `tool_calls` fill it as
their events are emitted. A tool record whose `tool_call_id` is absent from the set is
preceded by a `tool_call` event with that id, the record's `name`, and no `args` key — which
is what the renderer reads as "no IN pane" — and the id is added so a second result cannot
synthesize a second call.

In the webview, `addToolResult` keeps its map lookup. When the lookup misses and the event
has an id, it calls `addToolCall` with `{ type: 'tool_call', tool_call_id, name, args:
undefined }`, reviewable false, and then looks the card up again. The normal body of the
function is unchanged: state word, review, rule references, OUT, and the output caption. The
id-less branch builds a `.msg.result-note` with the tool's title and an `output-link` inside
it, so the text is reachable without being printed.

`outputNote(name, event, content)` returns the caption button or null, and both callers use
it. A caption's click still posts `openOutput` with the call id and the untruncated text.

The Go window now keeps the full slice in `all` and reports `all[dropped:]`; the forward
alignment reads the window, and `lastUserTurnBefore` extends it back when the window's first
entry is not a user turn. `isUserTurn` is shared by both scans. A store with no user turn at
all keeps the cap's tail: there is no boundary to move to, and moving either way would invent
a start the store does not have.

## What was not walked

No real window here. The window move-back was read through the store's own JSONL in the
recorded case, but the panel's rendering of a synthesized row — a card with an empty IN and a
full OUT — was not opened; nor was the id-less note, which the host is not expected to
produce.

## Non-goals

- Backfilling the call's arguments from anywhere; the store does not keep them.
- Changing `DefaultTranscriptLimit`, paging the transcript, or adding a second request.
- A protocol change, a store change, or a new setting.
- Re-fetching a result the window already carries.
