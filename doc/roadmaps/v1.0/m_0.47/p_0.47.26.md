# p_0.47.26 — A count that says it landed, says "not yet", and stops where it should

**Status:** done (2026-10-21)
**Milestone:** [m_0.47_editor_polish.md](../m_0.47_editor_polish.md)
**Linked design:** [44-editor-polish.md](../../../design/v1.0/44-editor-polish.md) §29

## Goals

Four defects reported from one window, all on the composer's session line or the rail that
ends a reply.

1. **The session total lost two of its three counts.** `renderMeter` drew `in` and `out`
   behind `if (!context)`, so a workspace that declared a context window saw only
   `cache 742k`. The counts are a sentence about the session; a window is a separate fact.
2. **Nothing on the line said that a number had arrived.** The session counts land once per
   run; the step counter advances once per step. Both changed silently.
3. **The line vanished for a conversation's whole first turn.** A count is only known once a
   run has ended, so `usageTotals` was empty, every node rendered as the empty string,
   `meter.hidden` became `true`, and the composer showed no meter at all — which reads as
   "this build has no meter", not as "nothing has been counted yet".
4. **A stub of rail hung below a reply's last block.** `rail-down` reaches 10px past its own
   box to meet the next segment across the reply body's 12px gap. The reply's **last** block
   has no next segment, so at the bottom of a scrolled conversation the reach painted a
   hairline into the space the dock reserves for the composer.

Every value drawn is the one the host reported, and the step is the loop's own counter: the
pulse is added to real numbers, never in place of them.

Reviewing that first draft found six more defects in it, all of the same shape — a fact that
was computed and never reached the node that shows it, or a comparison made against the wrong
thing. They are fixed in this phase rather than left to the next one.

5. **The cache count pulsed every second.** `setNumber` compared the node's `textContent`,
   and the clock is a node inside the cache count: every tick rewrote the text and fired the
   pulse. The last value a node was told is now kept beside it, so a rewrite and a change are
   different questions.
6. **The window's share was never drawn.** `meterMath.label`'s share was collected into the
   string behind `meter.title` and never into a node, and it was gated on the host's context
   estimate. It is a node now, and it is drawn whenever a last run can be measured.
7. **Two dots could not separate four counts.** Hiding `out` left `5k in cache 4k`, because
   each dot looked only at the pair around it. A dot now belongs to the count in front of it
   and is shown only while another count still follows, so each pair of visible counts gets
   exactly one dot.
8. **A reader was pulled to the bottom once a second.** `renderMeter` pinned the transcript
   on every render, including the cache tick. Only the root line's own change pins it now.
9. **The footprint led the conversation in the document.** The flex `order` drew it last, but
   entries were appended after it, so a copy or a screen reader read the session lines before
   the conversation. Entries are inserted in front of it.
10. **The chat's fix could still be served from cache.** The content digest was applied in
    `chatPanel.ts` only; the four manager panels kept the plain URL. One builder now serves
    all five documents.

## Scope

`editors/vscode/media/chat.js` (the meter's nodes, `setNumber`, `pulseNumber`,
`stepLabel`, `countText`, the step node and its pulse on advance, the node-assembled line,
`addToEnd`), `media/chat.css` (an inline-block box per count and for the step; the last-block
rail rule), `src/webviewAsset.ts` (new; the fingerprinted asset URL), the five panel sources
that build a webview document, `test/unit/usageMeter.test.ts`, `test/unit/working.test.ts`,
`test/unit/chatLayout.test.ts`, `test/unit/replies.test.ts` and
`test/unit/chatFontSize.test.ts`. No protocol field, no host change, no setting, no new
timer.

## Tasks

1. **Draw all three counts.** `in`, `out` and `cache` each render whenever the provider
   reported them; `meterMath.label`'s window share is added on top, not instead.
2. **One node per count.** `#meter` holds `meterIn`, `meterOut`, `meterShare`, `meterCache`
   and `meterClock` with three separator nodes between the counts, so each can be shown,
   hidden or animated on its own.
3. **Hide the separators with the counts.** A dot with nothing on one side of it is
   punctuation about a number nobody reported. A dot belongs to the count in front of it and
   is shown only while another count follows, so hiding the middle count leaves exactly one
   dot between the two visible ones rather than two dots in a row.
4. **Stand in, do not vanish.** While nothing has been counted, each count renders an em
   dash — the one spelling that cannot be mistaken for a count — so the line keeps its place
   and its height.
5. **Placeholders are for "not yet", not for "never".** Once anything has been reported, an
   absent count is absent rather than a dash.
6. **Assemble the line from its nodes.** `parts` reads the count nodes rather than recomputing
   their text, so a count hidden for one reason cannot appear in the line through another.
7. **Write numbers through `setNumber`.** Compare before writing, against the value the node
   was last told and not against its text: the cache count owns the clock node, so its text
   changes every second while its number does not. An unchanged value is not written, so a
   pulse always means "this changed", and the first value or a reset is drawn without one.
8. **Pulse from script.** `pulseNumber` runs a 520ms WAAPI animation — scale to 1.18, back to
   1, with an opacity dip — cancelling any animation already on the node.
9. **Give the step its own node.** `stepLabel` holds the spelling; `renderWorkingMeta`
   appends `workingStepNode` so the counter can pulse while the parenthetical keeps one
   truncation box around it.
10. **Pulse the step on advance only.** `progress` may restate the current step; only a
    differing `e.step` pulses.
11. **Keep the clock out of the counts.** The cache countdown is written into `meterClock`,
    appended to the cache node, so a per-second tick cannot pulse the number beside it.
12. **Stop the rail at the reply.** `.reply-body > :last-child.rail-down::after { bottom: 0 }`.
13. **Keep motion a preference.** `pulseNumber` returns early on `reduceMotion` and when
    `Element.prototype.animate` is absent; the number is still drawn.
14. **Draw the window's share.** `meterShare` is set from `meterMath.label` whenever there is
    a last run to measure, whether or not the host sent an estimate.
15. **Keep the placeholder's count's name.** `cache —`, not a bare dash, so the line says
    which fact is not known yet.
16. **Put entries in front of the footprint.** `addToEnd` inserts before `#footprint` for the
    transcript, so the document order matches the drawn order.
17. **Let only a change pin the transcript.** `renderMeter` compares the root line before
    writing it, and pins nothing else: the per-second tick cannot undo a scroll.
18. **Keep the separator out of the pulsable node.** The step's `·` is a text node beside
    `workingStepNode`.
19. **Fingerprint every document's assets.** `src/webviewAsset.ts` builds one digest URL per
    media file, and all five panels link through it.
20. **Test.** Counts drawn unconditionally; the placeholder's condition and its name; the
    node-assembled line; the derived separators; `setNumber`'s stored-value comparison; the
    pulse's shape and guards; the step's advance-only pulse and its separator; an inline-block
    box per count and for the step; the last-block rail rule; the footprint's place in the
    document; the fingerprinted link in all five panels; no at-rule in `chat.css`.
21. **Verify.** Compile, lint, the unit suite, the Go suite, packaging and the packaged smoke
    test.

## Decisions (before any change)

- **The pulse is state, not celebration.** One scale and one opacity dip, 520ms, nothing
  left behind. A longer or coloured animation would read as an event rather than as a value
  arriving.
- **Compare before write.** `renderMeter` is called on the cache tick and on every root
  update; without a comparison the cache count would pulse once a second and the pulse would
  mean nothing.
- **Compare the stored value, not the text.** The cache count holds the clock as a child, so
  its `textContent` changes on every tick even when the number does not. The value each node
  was last told is kept in a `WeakMap` beside it, so "the count changed" is not confused with
  "the node was rewritten".
- **The share is a node.** A fact that exists only in `title` and `aria-label` is not drawn.
  It is drawn for every declared window with a last run to measure, whether or not the host
  sent an estimate — the composer line is then the only place that can say it.
- **A dot belongs to the count before it.** Two dots between three counts cannot separate
  four, and asking "is there a visible count on either side" shows two dots in a row when the
  count between them is hidden. A dot is shown only while its own count is visible and another
  count follows it, so each pair of visible counts gets exactly one dot.
- **Only the root line pins the transcript.** It is the one thing `renderMeter` writes that
  lives in the scroll container, and it pins only when its text changes. The composer cannot
  move the transcript at all.
- **The footprint is last in the document, not only in the layout.** `order: 1` draws it
  last; inserting entries in front of it makes the copy and screen-reader order agree.
- **One fingerprinted asset builder.** The digest lived in `chatPanel.ts` while four sibling
  panels kept the cached URL. The builder is shared so a panel cannot keep the old behaviour.
- **The step's spelling leaves `renderWorkingMeta`.** `stepLabel` is a function so the node
  can be appended, and so the assertion that pins the spelling follows one name rather than
  a string inside a longer body.
- **Script, not `@keyframes`.** `chat.css` may carry no at-rule — `chatLayout.test.ts`
  enforces that so the file stays parseable as text — so the pulse uses the Web Animations
  API, the same reason the hammer swings from script.
- **`inline-block` per count.** A transform has no effect on a non-replaced inline box; this
  is the one line of CSS the animation requires.
- **No new timer.** The clock that already exists (one second, while a cache is live) drives
  the countdown; nothing new was added for the pulse, which is event-driven.
- **An em dash, not a zero.** `0 in` is a claim about a run that spent nothing; the truth is
  that no run has finished. The dash says the second thing.
- **The placeholder expires.** It is drawn only while *nothing* has been reported — the
  first-turn case. A conversation that has finished one run shows real counts and no dashes,
  which is what keeps the dash meaning "not yet".
- **The line is not hidden to save space.** Its disappearance was the bug: a reader looking
  for the meter concluded the build did not have one.
- **The rail's 10px overlap stays.** Removing it entirely would put a visible break in the
  rail at every block boundary inside a reply. Only the reply's end is wrong, so only the end
  is fixed.
- **The rail rule names the last child of the reply body, not the run.** `syncRail` already
  declines to mark a run's last block `rail-down`; the class reaches other producers — an
  interrupted run, a replayed turn — and a segment that stops at its own box is correct for
  all of them, so one selector covers every producer.

## Implementation notes

### The renderer

`renderMeter` now writes four count nodes instead of one string. The counts go through
`countText`, which draws the number when the provider reported one, an em dash while nothing
has been reported at all, and nothing in between; `setNumber` then compares against the value
the node was last told, so a redraw that does not move a count does not pulse it — and a
per-second clock write inside the cache node does not even reach the comparison. The line
itself is assembled by walking `meterCounts`, and each separator is hidden from the counts on
either side of it. The clock is written into `meterClock` and appended to `meterCache`, so
appending it does not disturb the count's own text. The untruncated line is still assembled
into `meter.title` and `aria-label`, unchanged from p_0.47.24.

`renderMeter` pins the transcript only around a change to the root line. The composer's line
is outside the scroll container, and the function runs once a second while a cache is live:
pinning on every render would drag a reader who had scrolled up within the 60px tolerance back
to the bottom, once a second, for a countdown.

`addToEnd` is the one way a block reaches the end of the transcript: it inserts before
`#footprint` when the target is the transcript, so the document order matches what `order: 1`
draws. The reply opener and an approval card with no reply open both go through it.

`src/webviewAsset.ts` builds a media URI with a twelve-character sha256 of the file in its
query, and the five `renderHtml` functions call it. A file that cannot be read still yields a
plain URI rather than failing the panel.

`pulseNumber` cancels every animation on the node first (`node.getAnimations()`), so two
landings inside 520ms restart the pulse rather than queueing, and no cancelled animation is
left in `getAnimations()`.

`renderWorkingMeta` writes the escape and the clock as text, appends `workingStepNode` when a
step exists, and appends the closing parenthesis as a text node. The `progress` branch records
whether the step actually advanced before it overwrites `workingStep`, and pulses only then.

### The stylesheet

`.composer .meter > span` and `.status .working-step` are both `display: inline-block`, with
`span[hidden] { display: none }` under the meter's rule so the counts can be hidden against
the author display rule. `.reply-body > :last-child.rail-down::after { bottom: 0 }` stops the
last block's segment at its own box.

## What was not walked

No real window here. The pulse's 1.18 scale was chosen as the smallest change that is
noticeable at `0.8em` and `0.85em`; whether it reads as "a value arrived" rather than as "a
jitter" needs a window. The placeholder's width under `anvil.chatFontSize` was not measured —
it is three characters and one word at `0.8em`, narrower than any real total. The rail stub
was reported from a screenshot showing a hairline above the composer and was reasoned from
the 10px overlap against an empty reply body, not from scrolling a live panel.

The window share lengthens the composer's line — `in · out · last N of M (P%) · cache ·
clock` — and how much of its tail a narrow panel ellipsises is unmeasured; the full line stays
in the tooltip. The DOM order under the footprint has no visual effect at all, so its only
evidence is a copy or a screen reader, and neither was run here. The asset digest is read once
per document open (five files for the chat) and no measurement was taken; that cost is
invisible beside starting a webview.

## Non-goals

- Sending per-step token usage. `internal/runtime/loop.go` emits `progress` without `Usage`
  on purpose ("a token count is a fact about a completed exchange, not a running estimate"),
  and this phase does not overturn that. The counts therefore land once per run.
- Animating the context line, the root line, or the cache countdown.
- A new setting for motion; the existing `prefers-reduced-motion` covers it.
- Changing `syncRail`'s run detection, or the reply's 12px rhythm.
- A protocol change, a host change, a version bump, a branch, or a push.
