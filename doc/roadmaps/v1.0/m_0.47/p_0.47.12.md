# p_0.47.12 — A dot, more air, and text the reader can size

**Status:** done (2026-10-20)
**Milestone:** [m_0.47_editor_polish.md](../m_0.47_editor_polish.md)
**Linked design:** [44-editor-polish.md](../../../design/v1.0/44-editor-polish.md) §15,
[35-vscode-extension.md](../../../design/v1.0/35-vscode-extension.md) (the chat view)

## Goals

p_0.47.10 made the transcript a list of rows. Run against a real conversation, the rows
were still not the shape the reader had in mind: a caret says "there is more to read" before
every call, the rows sit closer together than the words justify, and an edit is compared in
a pane that is quieter than the thing it describes. Text size was whatever the editor's UI
font happened to be, and there was no way to ask for larger.

1. **A dot, not a caret.** A tool row and a Thinking row lead with a small round dot. It
   carries state: filled while a call runs, muted when it is done, red when it failed, a
   ring when its result never arrived, and a ring while the row is open.
2. **More air.** Rows gain vertical padding, the gap between rows grows, and the panes
   under a row are indented to the name they belong to.
3. **An edit reads as a comparison.** The pane keeps the two sides, gains a path line with
   the number of added and removed lines, a looser line height, and wider cells. Nothing
   in the markup changes shape, so the narrow fallback still works.
4. **The reader sizes the text.** A new `anvil.chatFontSize` setting (number, default 15,
   10–24) sets the chat document's base size. It applies live, without restarting the
   host: it is display-only and never reaches a session.

## Scope

`editors/vscode/media/chat.css`, `media/chat.js`, `media/tokens.css`; `package.json`

## Tasks

1. **The dot.** Replace the `\25B8`/`\25BE` caret on `.tool > summary::before` and
   `.msg .think > summary::before` with an empty pseudo-element styled as a 6px circle.
   State colours come from the row's existing classes; open is a ring.
2. **The air.** Raise `--ui-gap` to 12px and `--ui-gap-tight` to 8px in `tokens.css`,
   give the summaries `6px` vertical padding, the panes `0 0 10px 22px`, and loosen
   `.msg`'s margins and the gaps between sections.
3. **The comparison.** Give `.edit-diff .path` a flex row with the file name and a
   `+n −m` stat, raise the diff's line height, and widen the cell padding and gutter.
   The stat is computed in `renderEditDiff` from the rows it already has.
4. **The size.** Declare `anvil.chatFontSize`; read and clamp it in `readSettings`;
   render it into the document as `data-font-size` and re-announce it at `ready`;
   `chat.js` writes it to `--anvil-font-size`, which `body` uses with the editor's own
   font size as the fallback.
5. **Live, without a restart.** The window's configuration listener compares the new
   reading with the previous one; a change that touches only the text size is posted to
   every open tab and does not restart the host. A change to anything else keeps the
   existing restart.
6. **Tests.** Pin the dot, the spacing and the font-size chain in source, and pin the
   setting's shape in `package.json`.
7. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and
   the packaged smoke test.

## Decisions (before any change)

- **State in the dot, not in another colour word.** The row already says `done` /
  `failed` / `stopped` in its state column. The dot repeats that once, at the start of the
  row, where the eye lands; it does not introduce a second vocabulary.
- **A ring means "open" and "unknown".** Both are "there is more here than the row says":
  a row that is open has its body below it, and a stopped call has a result the transcript
  never saw. The same shape for both keeps the dot set small.
- **Keep the caret's affordance in the pointer and the hover.** The caret was the only
  thing saying the summary toggles. The summary keeps `cursor: pointer` and its hover
  background; the open ring is the state cue.
- **Display-only settings must not reach the host.** A restart for a font size would end
  a run in progress to change a number of pixels. The listener compares readings rather
  than naming every key, so a future display setting inherits the same treatment by being
  compared rather than by being listed.
- **The setting is an absolute size, not an offset.** `--vscode-font-size` is the UI font
  and the webview may be zoomed independently; adding two to a number the extension cannot
  see would make the default depend on a setting the user did not touch.

## Implementation notes

### The dot

Both summaries are flex rows with a 6px `::before`. Each state sets `--dot`, and the base
rule fills with it; the stopped and open rules replace the fill with an inset ring, so the
colour survives either shape. High contrast raises the opacity to 1, the same rule the
caret had.

### The air

`--ui-gap` and `--ui-gap-tight` live in `tokens.css`, so the manager panels gain the same
breathing room. The transcript's own spacing is the gap plus `.msg`'s margins; the dot and
its gap set the pane's indent, so the output starts under the tool's name rather than under
the dot.

### The comparison

`renderEditDiff` counts the add and del rows it already built and writes them beside the
path. The diff keeps its two columns, its per-side backgrounds and its 24-row cap; the
change is line height, cell padding, gutter width, and the path line's layout. The narrow
fallback is untouched, except that the width at which it fires now scales with the text
size (`DIFF_SIDE_MIN × fontSize / 15`): two columns stop paying for themselves sooner at
20px than at 15, and a threshold fixed in pixels would keep showing them long after each
column had lost its readable width.

### The size

`settings.ts` reads `anvil.chatFontSize`, rounds and clamps it, and exposes it as
`fontSize` on the resolved settings. `renderHtml` writes it to `data-font-size` on the body;
`chat.js` copies it to `--anvil-font-size` before the first paint and again on a `fontSize`
message, and re-runs the diff width check because the geometry changed with the type. The
`--anvil-font-size` declaration in `:root` carries the editor's own UI font as its value, so
a document whose script has not run yet is already the right size. The configuration
listener compares `settingsKey`, which is every field except `fontSize`, to decide whether
a restart is needed; the font itself reaches open tabs through `Hub.setFontSize`.

### What was not walked

No real window here. The dot's size, the new spacing and the stat line should be looked at
in light, dark and high contrast, at a wide and a narrow width, and at both ends of the
font-size range — the composer's floating height and the diff's threshold are the two
places a larger base size changes geometry. The live path (change the setting with a run in
flight, in one tab of several) is pinned at the source level only.

## Non-goals

- A font family setting, a zoom level, or per-conversation sizes.
- Applying the size to the four manager panels; they follow the editor's UI font.
- Changing the diff algorithm, the pairing, the 24-row cap or the narrow fallback.
- A version bump, a branch, or a push.
