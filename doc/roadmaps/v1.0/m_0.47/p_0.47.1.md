# p_0.47.1 — LSP and test/build wiring

**Status:** in_progress (2026-10-20)
**Milestone:** [m_0.47_editor_polish.md](../m_0.47_editor_polish.md)
**Linked design:** [44-editor-polish.md](../../../design/v1.0/44-editor-polish.md) §2–§3

## Goals

1. **A configured language server becomes tools.** `session.new` carries an `lsp` block, the
   host maps it to `anvil.LSPOptions`, and the session registers `lsp_*` tools. A language
   server that cannot start is a missing tool, not a failed conversation.
2. **A configured test or build command becomes a tool.** The extension sends the
   `test_command` and `build_command` the protocol has accepted since 0.18.
3. **Nothing configured changes nothing.** With empty settings, the wire message and the tool
   list are exactly what they are today.

## Scope

`source/internal/editorhost/proto.go`, `server.go`; `editors/vscode/package.json`,
`src/settings.ts`, `src/protocol.ts`, `src/hostManager.ts`; tests on both sides;
`editors/vscode/README.md`.

## Tasks

1. **Protocol.** Add `lsp: {enabled, servers: [{language, pattern, command, args}]}` to
   `SessionParams`. Keep `Required` unset (the host passes `false`); reject a server entry
   with an empty command or with neither language nor pattern.
2. **Host.** In `buildOptions`, map the block to `anvil.LSPOptions`, clamping timeouts to the
   package defaults. Validate `test_command` / `build_command` shape (non-empty first word;
   empty array = unset) and keep the existing `opts.Test` / `opts.Build` mapping.
3. **Settings.** `anvil.lsp.enabled` (default `false`), `anvil.lsp.servers` (array of
   objects), `anvil.testCommand` and `anvil.buildCommand` (string arrays) in `package.json`.
4. **Extension.** Read and shape-check the settings in `src/settings.ts`; add the fields to
   `SessionNewParams`; send them from `hostManager.startSession` only when enabled or
   non-empty, so the unset case stays byte-identical.
5. **Docs.** `editors/vscode/README.md`: settings table, one paragraph on the trust posture
   (workspace values are accepted because the extension refuses untrusted workspaces; commands
   and arguments are never joined into a shell string), and what to do when a server fails.
6. **Tests.** Go: the mapping, an unstartable server not failing the session, and the command
   tools appearing. Extension: an integration test pinning the exact wire message with
   nothing configured (must match today) and with each setting configured.

## Acceptance

- [ ] With no settings, `session.new` params deep-equal today's (integration test).
- [ ] `lsp.enabled` with one server yields `lsp_*` tools in the session's tool list; a bad
      command leaves the session alive with the other tools.
- [ ] `test_command` / `build_command` yield `run_tests` / `build`.
- [ ] `go build/vet/test` green from Git Bash; `npm test` green; `package:vsix` and
      `smoke:vsix` green.

## Non-goals

- Discovering language servers automatically, or pushing LSP diagnostics to the Problems
  panel.
- Lazy start per file, or multiple servers per language.
- A `Required` setting in the editor.

## Depends-on
