# Phase p_0.6.1 — Progress events and limit UX

**Status:** done

## Goals

Callers can observe which step the run is on versus MaxSteps, and detect step-limit failures reliably.

## Scope

- Public stream event `progress` (`EventProgress`) with `Step` and `MaxSteps` on `Event`
- Emit once per LLM round (before Complete / CompleteStream) from `internal/runtime`
- MaxSteps exceeded: `RunResult.Status=error`, stable message containing the limit; public helper/constant for detection (e.g. `ErrMaxSteps` / `IsMaxStepsExceeded`)
- SDK default MaxSteps when unset: **128** (was 32)
- Update design 03 / 07

## Non-goals

- Automatic task splitting / sub-agents
- Changing MaxWallTime semantics

## Tasks

1. Extend runtime `Event` + public `anvil.Event` / `EventType`.
2. Emit progress in the loop; map in `agent.go`.
3. Change default MaxSteps to 128 in agent + runtime.
4. Add `IsMaxStepsExceeded` (or equivalent) + unit tests.
5. Refresh design chapters.

## Acceptance

- [x] Mock loop test receives increasing `progress` events with correct MaxSteps.
- [x] After MaxSteps exceeded, Wait/result is detectable as a steps limit (not a generic opaque error only).
- [x] Default MaxSteps is 128 when Options.MaxSteps is 0.
