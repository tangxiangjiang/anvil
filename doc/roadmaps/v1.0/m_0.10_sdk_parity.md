# Milestone 0.10 — Cursor SDK local parity

**Status:** planned  
**Product version:** 0.10.x

## Goals

Close remaining **API / options / config-layer** gaps versus Cursor SDK’s *local* agent surface, so Anvil is capability-aligned for hosts that would otherwise call `@cursor/sdk` / `cursor-sdk` with `local: { cwd }`.

This milestone is about **surface parity** (Create/Prompt/Resume/Send/Stream/Wait/Cancel/Close and the local knobs around them). It does **not** claim behavioral parity with Cursor’s proprietary agent runtime (semantic search, Composer models, IDE harness).

## Overall acceptance

1. A host can opt into loading `.cursor/mcp.json` (and documented rule layers) via `settingSources`, matching Cursor’s inline vs project vs user idea without requiring the Cursor app.
2. Callers can replace the main system prompt and allow/deny built-in tool groups without forking Anvil.
3. Busy-run `Force`, config `Reload`, and run listing work for local stores.
4. At least one file-based hook path can deny or annotate shell (or equivalent mutating) tool calls.
5. Design + roadmap explicitly list remaining intentional non-goals (cloud, Bridge, sub-agents as Cursor ships them).

## Non-goals

- Cursor Bridge / embedding Cursor runtime
- Cloud agents (`bc-` ids, dashboard MCP)
- Pixel-perfect event schema compatibility with `@cursor/sdk`
- Matching Cursor IDE / Composer exploration quality (0.7–0.9 and later quality work)
- OAuth browser flows for MCP (headers-only is enough for 0.10 unless a phase expands it)
