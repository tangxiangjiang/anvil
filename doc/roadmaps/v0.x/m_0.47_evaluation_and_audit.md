# Milestone 0.47 — Evaluation baseline and audit

**Status:** planned
**Product version:** 0.48.0

Milestone 0.45 carries the editor-host smoke tests and the anvil-web polish, so this line starts at 0.46.
continues the numbering from it.

0.46 closed the editor polish line. What comes next — reasoning effort, retries, role prompts,
and the Single / Multi / Complex ladder — changes what the SDK sends to a model and how many
agents a request creates. None of it can be judged by the six scripted fixtures in
`source/eval`, which call `runtime.Loop` directly, ignore the request they are answering, and
record nothing but pass or fail. This milestone delivers the measurement first, so that every
phase of 0.48, 0.49 and 0.50 can say "no regression" against a number recorded before the change.
The design is chapter [47](../../design/v0.x/47-evaluation.md).

This milestone changes no behaviour a caller sees. The SDK is the deliverable; the host, the
worker and the editor are untouched.

## Goals

1. **Read the agent path once, with a test per finding.** `agent.go`, `run.go`, `subagent.go`,
   `workflow.go`, `internal/runtime`, `internal/llm`, `internal/tools`, `internal/permissions`.
   Every finding has a reproducing test; a finding without one is listed as a suspicion.
2. **Make `source/eval` a harness.** Three tiers — scripted, recorded replay, live — sharing
   one task shape and one scorer; replays run through the public `Agent`, and an unmatched
   request fails with a diff rather than being answered.
3. **Record the baseline.** `eval/baseline.json`, a compare rule that fails on a gated field
   moving the wrong way, `scripts/eval.sh`, and an `invariants` suite that names Anvil's own
   capabilities and must stay at 100%.

## Overall acceptance

1. `audit.md` exists; every finding marked *confirmed* has a test in the tree that failed
   before its fix and passes after, or is marked *open* with the test still failing and
   skipped by name.
2. `go test ./eval/...` runs three tiers; a recorded fixture whose request digest matches
   nothing fails with a diff of the nearest recorded request.
3. `eval/baseline.json` holds a score for every task; `go test ./eval/...` fails when a gated
   field regresses and passes with a note when it improves; `-update` is the only way the file
   changes.
4. The `invariants` suite lists at least the eight tasks of chapter 45 §6.1 and passes at
   100%.
5. `cd source && go build ./... && go vet ./... && go test -count=1 ./...` green (run from
   Git Bash) at the end of every phase.

## Non-goals

- Fixing audit findings as phases of this milestone: a bug is fixed in a plain commit with
  its test.
- Any change to `Options`, the request shape, the system prompt, or the tool set.
- A live-provider gate. The live tier is a report.
- Host, worker, CLI or editor changes.
