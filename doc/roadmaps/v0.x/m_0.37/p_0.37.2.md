# p_0.37.2 — Where the starting mode comes from, and saying so

**Status:** done  
**Milestone:** [m_0.37_permission_modes.md](../m_0.37_permission_modes.md)  
**Linked design:** [37-permission-modes.md](../../../design/v0.x/37-permission-modes.md), [35-vscode-extension.md](../../../design/v0.x/35-vscode-extension.md), [08-security.md](../../../design/v0.x/08-security.md)

## Goals

1. **A workspace can declare the mode its sessions start in.** `"defaultMode"` in
   `.anvil/permissions.json` — the file a team already commits and the editor already opens.
2. **The host resolves it, in one place.** The mode the client sent, else the file's, else
   `ask`. A client that has no opinion sends none; it does not have to know the file exists.
3. **A project file may not grant `bypass`.** Refused, and *said*: both the session result and
   `permissions.get` report the value that was refused, so nothing is silently dropped.
4. **The composer offers `dont_ask`, and says when the mode in force came from the file** —
   the same "say why" that 0.36.2 gave a call that ran without a prompt.
5. **Writing a rule does not delete the declaration.** `AddPermissionRule` rebuilds the file
   from what it parsed; the declaration has to be carried through it explicitly.

## Scope

`source/internal/permissions/` (`File`, `Set`, `Parse`), `source/permissionrules.go` (the public
reader and the write path), `source/internal/editorhost/` (resolution, protocol),
`editors/vscode/src/` and `editors/vscode/media/`, its tests, and the docs.

## Tasks

1. **The file** — `File.DefaultMode`, carried onto `Set` with an accessor. `Parse` checks the
   *shape* (a bare lowercase word, and a place to point at when it is not); the *vocabulary*
   and the `bypass` ban stay in the host, which is where the ladder lives.
2. **The reader** — a public way to read the file whole: its rules and its declaration. The
   host may import the public package only, and a second parser of the same file is how two
   answers to "what does this file say" start disagreeing.
3. **The resolution** — `resolveMode` in the host, beside `permissionMode`, returning the mode,
   where it came from, and what was refused.
4. **The protocol** — `permissions.get` gains `default_mode` / `default_mode_refused`; the
   session result gains `permission_mode_source` / `permission_mode_refused`.
5. **The client** — `dont_ask` in the mode list, the select, the labels and the banner; no
   `permission_mode` sent when the workspace has no stored choice; the mode the host resolved
   reported back to the composer; one notice per session when the file decided the mode or had
   a declaration refused.
6. **Version** — `editors/vscode/package.json` to `0.37.2` (the phase, as with 0.36.2) and
   `editorhost.Version` to `0.37.0-dev` (the milestone). The drift check compares minor lines,
   so they move together.
7. Tests and docs.

## Tasks as delivered

Four details the task list does not carry, and one sentence in it that needed saying better.

- **The refusal has one wording, used twice.** `refusedMode` returns the sentence and both
  surfaces — the session result's `permission_mode_refused` and `permissions.get`'s
  `default_mode_refused` — carry it verbatim. A second phrasing for the same refusal is how a
  user ends up reading two different explanations of one problem. The two fields answer
  different questions, which is why they are not folded into one: "why is this session not in
  the mode my file names" and "what does this file say".
- **`honouredMode` is the single answer to "would the host take this?"** The resolution
  decides with it and `permissions.get` reports through it, so the panel cannot be told a
  declaration is fine and then find its session started somewhere else.
- **A malformed declaration fails the session, an unknown one does not.** The *shape* check
  lives in `internal/permissions`, so `session.new` refuses a `defaultMode` that is not a bare
  lowercase word with the file and the line — the same treatment a misspelled effect gets —
  while a well-formed word the ladder does not have opens the session in `ask` and is reported
  in words. The split is deliberate: a file that will not parse is a file nobody can trust for
  anything, and a word the host happens not to know is one line of it.
- **"No opinion" had to be representable at every step, not just at the end.** The select
  gained an entry that is not a mode (empty value), choosing it deletes the stored key rather
  than storing `""`, the client then sends no `permission_mode` key at all, and the `mode`
  message carries the stored choice *and* the resolved mode because the select and the banner
  are not driven by the same value. Each of those is the state surviving one more hop.
- **Said better:** task 5 listed `dont_ask`'s banner and the "came from the file" notice as
  two pieces of composer work. They are one mechanism, not two — `announceSessionMode` keys on
  the whole resolved picture (`mode`, `source`, `refused`) and is the only thing that speaks,
  so a session re-opened by a skill or a model call does not repeat itself. The task list reads
  as though the banner and the notice could drift apart; in the code there is one place that
  decides what to say about a mode.

## Acceptance

- [x] A file declaring `"defaultMode": "accept_edits"` makes a session start in it when the
  client sends no mode, and the session result says the mode came from the file.
  (`TestSessionModeComesFromTheFileWhenTheClientSendsNone`.)
- [x] A mode the client sends beats the file's. (`TestAnExplicitModeBeatsTheFile`.)
- [x] A file declaring `bypass` starts the session in `ask` and reports the refusal in words,
  on both the session result and `permissions.get`.
  (`TestBypassCannotBeDeclaredByAWorkspaceFile`.)
- [x] A `defaultMode` that is not a mode at all is reported the same way, and the session
  still starts. (`TestUnknownDefaultModeIsRefusedAndReported`.)
- [x] A `defaultMode` that is not a bare lowercase word is a file problem with a place, the
  way a misspelled effect is. (`TestMalformedDefaultModeIsAFileProblemWithAPlace`.)
- [x] `session.new` with `load_permissions: false` ignores the declaration as well as the
  rules. (`TestLoadPermissionsOffIgnoresTheDefaultMode`.)
- [x] Appending a rule keeps the declaration. (`TestAddPermissionRuleKeepsTheDefaultMode`.)
- [x] The extension sends no `permission_mode` for a workspace it has no stored choice for,
  and shows the mode the host resolved. (`test/integration/modeResolution.test.ts`,
  against the scripted host, which resolves the mode the way the real one does.)
- [x] The mode list and the mode labels cannot drift between `protocol.go`, `protocol.ts` and
  the panel's markup and labels — one test reads all four as text
  (`test/unit/permissionModes.test.ts`), because a mode the Go side renames is a silent
  `undefined` here and a mode with no `<option>` is a mode nobody can choose.
- [x] `go test ./...` green; `npm test` green (181, up from 171); `npm run smoke:vsix`
  green against `anvil-vscode-0.37.2-win32-x64.vsix`.

## Non-goals

- A graphical mode picker beyond the existing select; a per-project mode editor.
- Any change to the decision order, or to what the rules themselves mean.
- User-level or managed defaults. The declaration lives in the workspace file, which is the
  file a reader can find; a precedence chain above it is a later question.
- `auto`. See the milestone.
