# p_0.37.1 — The two decisions the ladder was missing

**Status:** done  
**Milestone:** [m_0.37_permission_modes.vscode.md](../m_0.37_permission_modes.vscode.md)  
**Linked design:** [37-permission-modes.vscode.md](../../../design/v0.x/37-permission-modes.vscode.md), [36-tool-permissions.vscode.md](../../../design/v0.x/36-tool-permissions.vscode.md)

## Goals

Two changes to what a mode *means*, both in the host, both decidable without a model:

1. **`dont_ask`** — a fifth mode that never prompts: every gated call the workspace's rules do
   not already allow is refused. It is `bypass`'s mirror image.
2. **An `ask` rule outranks `bypass`.** "Do not ask me" is a statement about everything; a rule
   is a statement about one tool, written down, whose only effect is to interrupt. The rule
   wins, and the card that appears says which rule it was.

No client change, and none is needed: a mode is a composition of public SDK options, so this
phase is `source/internal/editorhost/` only. `editors/vscode/src/` is untouched and the
extension suite stays at its current 171 tests — that is part of what this phase proves.

## Scope

`source/internal/editorhost/proto.go`, `source/internal/editorhost/server.go`, its tests, and
the docs. No SDK file changes: `PermissionRequest.Rule` (p_0.36.2) is what makes the second
decision expressible, and a callback that always says no is what the first one is.

## Tasks

1. `ModeDontAsk` and its place in `permissionMode`'s accepted set.
2. `permissionHookForMode(mode, sess, timeout)` — one switch that maps a mode to the callback
   it installs, sitting beside `groupsForMode`, which maps a mode to its gates. Today that
   choice is an `if` in `buildOptions`, which is how a mode gets added to one list and not the
   other.
3. `dontAskHook` — the always-no callback, honouring a session allowlist entry (a session-wide
   "always allow" is a pre-approval the user gave), and naming the rule when a rule is what
   asked.
4. `bypassHook` — always yes, **except** when `PermissionRequest.Rule` is an `ask` rule, where
   it delegates to the ordinary approval hook.
5. Tests and docs.

## Tasks as delivered

Three details worth recording, and one that corrects the design chapter.

- **`permissionHookForMode` is a method on `*Server`; `groupsForMode` is a free function.** The
  pair is still adjacent in `server.go` and still read together, but building a callback needs
  the broker and the server, so only one of the two could be a plain function. A mode is
  therefore added to the two switches at two places in the same file rather than to two
  signatures of the same shape.
- **`dont_ask` gates what the client asked for, not the literal default six.** In delivery it
  falls through `groupsForMode` exactly as `ask` does, so an explicit `permission_groups`
  narrows or widens it. That is the useful reading — a client that has named its gates has
  named them for every mode — and ch37 now says so under the table rather than leaving the
  column to imply otherwise.
- **The session-allowlist branch is unreachable through the protocol.** The allowlist's only
  writer is the ordinary approval hook, and `dont_ask` installs its own instead; a mode is
  fixed when the session opens, and even `session.resume` mints a fresh session id, so an
  allowance can never exist for a session running in this mode. The branch is kept because the
  invariant is the right one — a mode must not overrule an approval a person gave — and
  `TestDontAskHonoursASessionAllowance` exercises the callback directly so that the invariant
  is proven rather than assumed. ch37 records both the reason and what would make it
  reachable.
- **Corrected while delivering:** the acceptance list named p_0.36.1's deny test as
  `TestRuleDenyHoldsInBypass`. It is called `TestBypassStillHonoursADenyRule`; the phase doc
  now names it correctly. No test was renamed.

## Non-goals

- A workspace declaring its starting mode, and the resolution order — p_0.37.2.
- Any `src/` or `media/` change; any `ProtocolVersion` bump (`dont_ask` is a new accepted
  value of an existing field, which is additive).
- A mode that decides by model. See the milestone's non-goals.
