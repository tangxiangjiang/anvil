# p_0.60.2 — VS Code execution and live projection

**Status:** planned
**Milestone:** [m_0.60_worktree_execution_control.vscode.md](../m_0.60_worktree_execution_control.vscode.md)
**Linked design:** [60-worktree-execution-control.vscode.md](../../../design/v0.x/60-worktree-execution-control.vscode.md)

## Goals

Expose an explicit, understandable Worktree execution flow in the Workflow view.

## Scope

Run command, preflight modal, settings diagnostics, live state, task/checkpoint evidence, review
handoff, command gating, accessibility, and fake/real-host tests.

## Tasks

1. Add **Run in isolated Worktree** only to approved dependency-ready items.
2. Show item, base, model profile, root, and attempt in a native confirmation.
3. Nest operation, Worker, run, task, checkpoint, and terminal evidence under the item.
4. Route Review/Discard/Cleanup to the exact returned Worker revision.
5. Prove all read/open/restore interactions issue no execution mutation.

## Acceptance

- Canceling the modal sends zero mutation RPCs; confirmation sends exactly one.
- Live and restored views render the same identity and state.
- Missing/invalid setup yields actionable settings guidance.
- Keyboard, screen-reader, stale-state, and reconnect tests pass.

## Non-goals

- Retry/restart policy, PR/CI, or automatic integration.
