# p_0.60.1 — Coordinator execution transaction

**Status:** planned
**Milestone:** [m_0.60_worktree_execution_control.vscode.md](../m_0.60_worktree_execution_control.vscode.md)
**Linked design:** [60-worktree-execution-control.vscode.md](../../../design/v0.x/60-worktree-execution-control.vscode.md)

## Goals

Create one durable operation that validates an approved work item, prepares its Worktree, starts
the routed Worker, and records one execution identity.

## Scope

Protocol, artifact/dependency gate, attempt reservation, Worktree preparation, durable run
creation, routed start, atomic failure projection, and audit records.

## Tasks

1. Define `workflow.execute_worktree` request/result and structured stale/policy errors.
2. Bind artifact/item revision, Worker, execution, run, model profile, and Worktree manifest.
3. Serialize duplicate starts and make retries idempotent by operation identity.
4. Clean only coordinator-owned preparation on pre-start failure.
5. Add JSONL/SQLite and adversarial repository tests.

## Acceptance

- Duplicate, stale, denied, dependency-blocked, or topology-mismatched starts create no Worker run.
- A successful request produces one consistent identity tuple in every store.
- A post-start failure is durably terminal/interrupted rather than reported as not started.
- The primary checkout remains unchanged.

## Non-goals

- Editor UI, automatic retry, integration, publication, or remote execution.
