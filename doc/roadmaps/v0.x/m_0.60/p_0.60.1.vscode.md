# p_0.60.1 — Requirement artifact and durable lifecycle

**Status:** planned

## Goals

Add the authoritative revisioned product-requirement contract used by every later stage.

## Scope

- Define Requirement identity, content, provenance, revision, lifecycle, supersession, and audit.
- Bind optional Git document path/commit/digest without making an uncommitted file authoritative.
- Add expected-revision/idempotency transitions for submit, approve, reject, and supersede.
- Import existing Delivery requirements with quarantine for invalid or ambiguous records.
- Add snapshot/event-cursor APIs, authorization, pagination, and redacted audit export.

## Tasks

1. Implement Requirement schemas, persistence, revision transitions, and audit events.
2. Add Git binding/import validation and legacy quarantine migration.
3. Test stale/idempotent writes, reconnect, authorization, and deterministic export.

## Acceptance

- Stale/duplicate writes cannot create a second revision or approval.
- Approval binds actor and exact content/provenance revision and starts no downstream work.
- Git/service drift is detected rather than silently accepted.
- Restart/reconnect yields the same lifecycle and audit sequence.
- Legacy invalid records remain auditable without becoming approved artifacts.

## Non-goals

- VS Code UI, AI Chat, design/roadmap planning, or execution.

## Depends-on

- Delivered Workspace domain and audit/event stores.
