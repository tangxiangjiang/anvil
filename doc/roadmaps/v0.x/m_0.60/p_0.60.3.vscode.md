# p_0.60.3 — Web Chat and requirement cutover

**Status:** planned

## Goals

Make VS Code the sole requirement/AI interaction client and reduce Web to requirement audit.

## Scope

- Remove Web prompt submission, tool approvals, requirement create/edit/approve, and related UI.
- Reject legacy Web mutation requests with a stable read-only error; hiding controls is insufficient.
- Keep bounded read-only requirement/transcript history, search, audit, export, and Open in VS Code.
- Add migration parity, authorization, reconnect, accessibility, fault, package, and smoke gates.
- Document the client boundary and mark older multi-mutating-client plans superseded.

## Tasks

1. Remove Web Chat/requirement controls and reject their legacy mutation requests.
2. Preserve read-only history, export, and signed Open in VS Code handoff.
3. Run migration, parity, authorization, accessibility, package, and smoke gates.

## Acceptance

- Automated route/UI tests prove Web cannot Chat or mutate requirements.
- Existing Web records remain searchable/exportable and hand off to VS Code.
- VS Code passes clean-install, reload, stale-revision, and real-service tests.
- Removing Web controls does not remove service authority or audit history.

## Non-goals

- Removing later Web workflow controls before their VS Code replacements land.

## Depends-on

- p_0.60.1 and p_0.60.2.
