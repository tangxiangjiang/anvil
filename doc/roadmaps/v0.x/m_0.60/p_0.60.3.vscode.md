# p_0.60.3 — Cancellation, retry, restart, and release gates

**Status:** planned
**Milestone:** [m_0.60_worktree_execution_control.vscode.md](../m_0.60_worktree_execution_control.vscode.md)
**Linked design:** [60-worktree-execution-control.vscode.md](../../../design/v0.x/60-worktree-execution-control.vscode.md)

## Goals

Close lifecycle gaps under cancellation, lost hosts, retries, and packaging.

## Scope

Terminal finalization, cancel races, lost-owner reconciliation, new-attempt retry, retained prior
attempts, fault injection, version bump, VSIX packaging, and smoke tests.

## Tasks

1. Make cancel wait for a durable terminal boundary before Worktree finalization.
2. Reconcile lost owners without adopting unproven processes.
3. Make retry create a new Worker/branch/execution while preserving previous evidence.
4. Add crash points around preparation, start, terminal append, and review handoff.
5. Complete the exact one-patch visible delivery and documentation synchronization.

## Acceptance

- Cancel/start/finish races have one durable outcome.
- Restart never silently resumes or reroutes a lost Worker.
- Retry cannot reuse or overwrite an earlier attempt.
- Full Go/VS Code, fault, package, and VSIX smoke suites pass.

## Non-goals

- Automatic retry or cleanup based solely on disconnect.

## Depends-on

- p_0.60.1 and p_0.60.2.
