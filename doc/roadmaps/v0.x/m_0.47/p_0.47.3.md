# p_0.47.3 — The baseline, the compare rule, and the invariants suite

**Status:** done
**Milestone:** [m_0.47_evaluation_and_audit.md](../m_0.47_evaluation_and_audit.md)
**Linked design:** [47-evaluation.md](../../../design/v0.x/47-evaluation.md) §6

## Goals

Record the numbers every later phase is measured against, make the comparison a test, and
name the suite that proves Anvil's own capabilities are intact — permission rules, loop guard,
checkpoints, plan-mode read-only, the subagent invariants — so that no phase in 0.48, 0.49
or 0.50 can weaken one of them without a red test.

## Scope

`source/eval/baseline.json` (new), `source/eval/compare.go`, `source/eval/eval_test.go`,
`source/eval/invariants_test.go`, `scripts/eval.sh` (new).

## Tasks

1. **`baseline.json`.** One entry per task name: the `Score` and the list of gated fields.
   Written by `go test -tags anvileval ./eval/... -update`, which refuses to run under `CI=1`.
2. **The compare rule.** For each task: a gated field that moved the wrong way fails with
   both numbers; one that improved passes with a `t.Log` note; a task absent from the
   baseline fails with "record it first"; a baseline entry with no task fails with "stale".
3. **Gating per task.** Behaviour tasks gate `Completed` and `Steps`; invariant tasks gate
   `Refused` and `LoopStops` exactly.
4. **The `invariants` suite**, tier 1 or tier 2 as each needs, all under `-run
   TestInvariants`: `inv_permission_deny`, `inv_permission_ask`, `inv_loop_guard`,
   `inv_checkpoint_restore`, `inv_sandbox_escape`, `inv_plan_readonly`,
   `inv_child_never_widens`, `inv_child_result_only`. Each gates its field exactly (a deny is
   refused **once**, not "at least once").
5. **`scripts/eval.sh`.** `go test -tags anvileval ./eval/... -count=1` with `--update`, `--live` and
   `--suite <name>` passed through; prints the compare table at the end. Runs from Git Bash.
6. **Record.** Run `-update` once on the tree as it stands at the end of this phase; commit
   the file.
7. **Verify.** The script; the Go suite from Git Bash.

### Gate

- 命令：`./scripts/eval.sh` （等价于 `cd source && go test -tags anvileval -count=1 ./eval/...`）
- 通过条件：退出码 0；输出的对比表中每个任务的受控字段 `=` 或改善；`--suite invariants` 单独运行时八个任务全部通过且每个任务的 `Refused`/`LoopStops` 与基线**相等**。
- 失败条件：任一受控字段劣化；任一任务不在基线中；`invariants` 中任一任务的精确字段与基线不等（多一次拒绝和少一次一样是失败——多出的拒绝意味着一个本该允许的调用被挡）；`-update` 在 `CI=1` 下未被拒绝。
- 基线条目：`baseline.json` 全文——这是此线所有后续 Gate 的基线。

## Delivery evidence

- `source/eval/baseline.json` records 19 tasks: the six scripted fixtures, five synthetic
  public Agent scenarios and the eight invariants. Behaviour tasks gate `completed` and
  `steps`; invariants gate `completed`, `refused` and `loop_stops` exactly. Scenarios that
  expect a refusal or loop stop add those two fields. `request_bytes` is recorded, not gated.
- `compare.go` implements the rule (regression fails with both numbers, improvement passes with a
  note, a missing task says "record it first", a baseline entry with no task is stale, changed
  gating needs `-update`), unit-tested in `compare_test.go`.
- `-update` under `CI=1` fails; `scripts/eval.sh` supports `--update`, `--live`, `--suite invariants`.
- The baseline scores come from scripted and synthetic fixtures. They guard the SDK, not model
  quality, and are not provider recordings.
- `inv_plan_readonly` is modelled as a tool set without write tools (`unknown tool: write_file`),
  because the SDK has no separate plan mode before 0.50.

## Non-goals

- A mode dimension on the invariants (p_0.50.3).
- Any threshold other than "not worse": the baseline is the only target.
- A CI workflow file; the script is what one would call.
