# p_0.47.2 — The harness: three tiers, a digest, a scorer

**Status:** done
**Milestone:** [m_0.47_evaluation_and_audit.md](../m_0.47_evaluation_and_audit.md)
**Linked design:** [47-evaluation.md](../../../design/v0.x/47-evaluation.md) §4, §5

## Goals

Turn `source/eval` from six request-blind fixtures into a harness: scripted request
predicates, digest-matched recorded replay through the public Agent, an opt-in real
provider recorder, and one score per task. Real provider recordings must be distinguished
from synthetic integration data.

## Scope

`source/eval/`: task, script, digest, replay, recorder, Agent/live runners and tests.
One narrow exception to the original eval-only scope is `source/eval_bridge.go`, behind
`//go:build anvileval`: it assigns the existing private `Options.completer` and delegates to
real `Create`. The default SDK gains no exported testing API or behaviour change.
`scripts/eval.sh`, baseline comparison and invariants remain p_0.47.3.

## Tasks

1. **Task and Reply.** Keep the six existing checks and eight-step default. A `Reply` holds
   an `llm.Message` and optional `Expect func(llm.Request) error`. Predicate failures include
   the request and remain harness failures even when the task expects a runtime error.
2. **Digest.** SHA-256 canonical request JSON, with copied data and JSON object keys sorted
   without losing integer precision. Clear model; normalize the actual Anvil introductory cwd
   line, valid RFC3339 timestamps only inside `# Session notes`, and recognized temporary
   workspace prefixes in tool results. Recognition uses a portable request-only grammar,
   never the loading machine's `os.TempDir`: POSIX `/tmp`, `/var/tmp`, `/private/tmp`, standard
   Windows user/system temp paths and macOS `/private/var/folders/.../T`. Nonstandard temp
   paths stay significant. Retain user text, prompt layers, schemas and cache flag.
3. **Necessary additional volatility.** Sort tool definitions by name (`Registry.Defs` reads
   a map). Normalize generated child IDs only in a `spawn_agent` success/failure/cancellation
   heading or initial workflow table (including rows without child IDs), not file contents or
   child bodies. Recover missing tool names from preceding invocations even when a later turn
   reuses an ID. Normalize elapsed seconds on Go package summary lines inside `run_tests`,
   and their exact copies in the generated failed list corroborated by `logTail`.
   Changes to status/package/output and adjacent workspace-relative subpaths remain visible.
4. **Replay.** Versioned JSONL records include explicit `synthetic`/`provider` provenance and
   a verified digest. Match by digest, not position. Identical duplicates have finite occurrence
   counts; conflicting responses are rejected. A miss/exhaustion prints a unified diff against
   the nearest request (message-count distance, digest prefix, then stable record order).
   Unconsumed calls and sticky auxiliary-call failures fail the task.
5. **Recorder.** Snapshot before calling the provider; serialize whole lines safely under
   concurrent calls. Exclusively create `<name>.live.jsonl` with restrictive permissions and
   never truncate a committed or previous live file. Propagate write, sync and close failures.
   Reject conflicting responses for an already recorded digest before writing the ambiguous
   line; the Complete error and Close outcome remain sticky. Identical concurrent responses
   retain finite duplicate occurrences. Only typed `llm.Request`/`Response` are stored:
   no provider config or HTTP headers.
6. **Public Agent.** Tagged replay tests run `Create` + `Send`, drain immediately, `Wait` and
   `Close`. Verify root tool-event coverage against the persisted transcript: buffer loss fails
   scoring rather than producing misleading counts. Child events use the synchronous callback.
7. **Score.** `Completed`, root `Steps`, `ToolErrors`, `Refused`, `LoopStops`, `Retries`,
   `RequestBytes`, `Agents`. An expected loop-guard stop can complete its task. Refusal uses
   rule decisions, narrow SDK refusal formats and an eval-controlled callback-denial marker,
   not arbitrary error text. Retries/Agents remain zero placeholders. RequestBytes counts
   original provider-neutral request JSON across root/child calls, not HTTP-wire bytes.
8. **Existing fixtures.** Add sandbox-prompt and `edit_file` definition predicates; preserve
   the six behavioural checks.
9. **First five recordings.** Two-file edit + configured test, child read/report, sequential
   two-step workflow, permission deny with no callback, loop guard. Offline tests currently
   capture and replay **synthetic** answers in different temporary workspaces. Genuine provider
   recordings must still be captured, reviewed and committed; synthetic data does not satisfy
   that delivery item.
10. **Live report.** Require `-live` and `ANVIL_EVAL_LIVE=1`; provider/model/base URL/key come
    from configuration. Use controlled fresh fixture workspaces, restricted tools and bounds.
    No executable hooks, MCP, shell or model-chosen commands are enabled. The test-command
    scenario runs only `BuildVerifier`'s fixed program: it ignores `os.Args` (the model controls
    `run_tests` `extra_args`), reads only `a.go` and `b.go`, and is the single command `RunLive`
    accepts. Any other test or build command is rejected, so no OS sandbox is needed. Real `go test`
    of model-written code stays out of the live tier. Remote outcomes are reports, never gates.

### Gate

- 命令：`cd source && go test -tags anvileval -count=1 ./eval/...`
- 通过条件：六个原有脚本 fixture、五个合成的 public Agent 捕获/回放场景及 digest、
  predicate、scorer、JSONL 和 recorder 的正反向测试全部通过；真实 provider 录制的五个
  fixture 在录制并审阅提交后也全部通过。后者尚未完成，不能仅凭合成测试将本阶段标为 done。
- 失败条件：有语义变化却 digest 不变；应忽略的波动导致回放未命中；丢失的事件被作为完整
  score；录制失败被吞掉；合成数据被当成真实 provider 录制；默认测试触发真实 provider。
- 基线条目：每个任务的 Score 全部字段（先打印，p_0.47.3 再落盘）。

## Acceptance

- [x] Tier 1 Expect fails with the request; errors cannot be hidden by an expected runtime stop.
- [x] Digest preserves meaningful changes and handles documented volatile fields.
- [x] A miss/exhaustion fails with a real unified diff; stale expected calls fail verification.
- [x] Provider configuration/HTTP headers are not serialized into recordings.
- [x] Tagged tier 2 runs through the public Agent and exercises the five scenarios synthetically.
- [x] Every offline fixture prints one Score; refusal and ordinary tool errors are distinguished.
- [x] Recorder never overwrites an existing file; concurrent identical/conflicting calls and write/close failures are tested.
- [x] Genuine provider recordings are captured, reviewed and committed for four of the five
      scenarios: `permission_deny_no_callback`, `spawn_read_report`, `two_file_edit_test`,
      `workflow_two_steps` (`source/eval/recordings/<task>.jsonl`, provenance `provider`).
- [x] The fifth scenario, `loop_guard`, is a **known limit**: it has no genuine recording. In three
      attempts, with and without an explicit instruction, the real model changed strategy after
      the guard's warning, so it never reached the stop. That is the behaviour a good model should
      have, so no model choice can be relied on to trigger it. The guard is covered by the
      synthetic scenario and the `inv_loop_guard` invariant (warn on the third identical call,
      stop on the fourth, `loop_stops` exact). It is not counted as a genuine recording.
- [x] Live test-command scenario uses only the fixed, argument-ignoring verifier; other commands are rejected (tested).
- [x] Default build, vet and Go suite are green from Git Bash; tagged eval tests/vet are green.

## Non-goals

- A baseline file, compare rule, invariants suite or eval script (p_0.47.3).
- A tokenizer or provider-wire byte counter.
- Streaming reasoning capture: `llm.Response` has no reasoning field. The plain Complete
  recording boundary neither stores nor reconstructs reasoning deltas.
- MCP/LSP/web/git-remote fixtures; background-task replay and truncated child-output ID
  normalization. Unsupported metadata changes still fail replay visibly.
- Resolving audit #10 or changing SDK command-environment policy. The offline two-file
  scenario runs a controlled precompiled test executable that reads the edited files, avoiding
  Windows Go cache environment requirements inside the scrubbed verification environment.

## Genuine recordings — 2026-10-23

- Made through an OpenAI-compatible gateway with a configured model; the endpoint, key and
  user name do not appear in the files (checked by search). Workspaces were the fixed paths
  `C:\anvil-eval\<task>`, because a real model copies the workspace path into its own prompts
  (a workflow step, a child task); that text is user content the digest must not normalize. A
  recording that embeds such a path therefore replays only on the OS that made it
  (`TestReplayProviderRecordings` skips it elsewhere).
- Replay needed three things that a synthetic capture hid: `Context.PromptCache` taken from the
  recording (it depends on the provider), the live tier's fixed verifier, and a verifier whose
  output order does not depend on map iteration.
- Replay scores are in `baseline.json` as `provider_<task>` entries. Model quality is not
  gated; these entries gate the SDK's behaviour on real model output.
