# p_0.32.1 — agentd sandbox read + git RPC

**Status:** done
**Milestone:** [m_0.32_sandbox_code_review.md](../m_0.32_sandbox_code_review.md)

## Goals

- Expose sandbox-confined directory listing and text-file reads over the authenticated agentd → scheduler path.
- Expose fixed, read-only `git status` and `git diff` operations for an assigned worker repository.
- Keep node identity, workspace admission, worker ownership, and advertised capabilities consistent across the full route.

## Scope

- `cluster.sandbox_list` and `cluster.sandbox_read`, bound to a selected node and worker project.
- `cluster.git_status` and `cluster.git_diff`, with fixed arguments and bounded output.
- Scheduler methods and authenticated HTTP routes for those RPCs.
- Canonical path resolution on Windows and Unix, including symlink/junction/reparse-point confinement and post-open validation.
- Stable error codes for invalid scope, escape, missing paths, binary/invalid UTF-8, non-repository paths, limits, timeout, and unavailable nodes.

## Non-goals

- File writes, delete/rename, terminal access, or arbitrary command execution.
- Git mutation or caller-supplied git command-line arguments.
- VS Code Server, ide-proxy, or any p_0.32.3 capability.

## Tasks

1. Add protocol bodies/results and capability declarations for bounded list/read/status/diff.
2. Route requests through scheduler by node + worker; derive the repository root from the assigned worker rather than trusting a browser-supplied host path.
3. Replace lexical-only sandbox resolution with canonical confinement that rejects `..`, absolute paths, drive/UNC ambiguity, and symlink/junction/reparse-point escape; revalidate opened files to reduce TOCTOU exposure.
4. Read text as UTF-8 without newline rewriting; report binary/invalid UTF-8 without returning content. Cap file size, directory entries, status entries, diff bytes, and operation duration, and return truncation metadata.
5. Run only fixed read-only git invocations with argument terminators/config hardening; handle non-repositories, renames, untracked/binary files, submodules, and oversized diffs.
6. Add protocol, daemon, scheduler HTTP, Windows path, and local scheduler↔agentd integration tests.

## Acceptance

- An authenticated scheduler request bound to an online node and its worker can list/read files and obtain status/diff without mutating the tree.
- Requests outside that worker repository or sandbox, including link/reparse escapes, fail with a stable error code and return no host data.
- Limits, binary handling, UTF-8/newline preservation, non-repository behavior, timeout, and unavailable-node behavior are covered by tests.
- A real local scheduler → agentd RPC test proves the transport; daemon-only fakes are insufficient.

## Depends-on

- p_0.29 sandbox workers and filesystem confinement.
- p_0.28 cluster node/worker routing and workspace admission.

## Delivery status

Delivered: `cluster.sandbox_list`/`sandbox_read` and `cluster.git_status`/`git_diff` over the
authenticated daemon ↔ scheduler path, with canonical confinement, bounded output and fixed
read-only git invocations.

**A worker repository is untrusted content.** It is written by the agent under review, so git
must not run anything the repository names:

- `gitRepo.run` overrides the keys that make git start a program (`core.fsmonitor`,
  `core.hooksPath`, `core.attributesFile`, `diff.external`), passes `--no-pager`, disables the
  system and global config scopes and the system attributes file, strips every inherited `GIT_*`
  variable, and pins `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR` to the validated repository.
  Without the overrides a repository config executed a program on the agentd host.
- A filter driver is selected through `.gitattributes` and its command comes from config, so its
  name is not known in advance and cannot be overridden on the command line. The resolved local
  config (includes and worktree config included) is scanned with `git config --list`; a non-empty
  `filter.*.clean|smudge|process` or `core.alternateRefsCommand` refuses the request with
  `unsafe_repository`, and a config listing that hits the output cap is refused rather than
  trusted.
- Repository metadata must resolve inside the worker repository: the `.git` file's gitdir line,
  `commondir`, object store, refs, index, config and `objects/info/alternates` are checked before
  git runs, and `GIT_WORK_TREE` stops `core.worktree` from moving the worktree out. A crafted
  repository that pointed git at a host repository previously returned that repository's status
  and diffs.
- Windows junctions are reparse points, and `filepath.EvalSymlinks` can leave one unresolved when
  Go reports it as `ModeIrregular` instead of `ModeSymlink`. `canonicalExisting` resolves every
  reparse point with `os.Readlink` first, so junctions are confined the same way symbolic links
  are, for list/read as well as for the metadata checks.

**Credential-bearing paths are hidden consistently.** Status entries and whole-repository diffs
exclude the names the viewer refuses (`.env`, `.env.*`, `.netrc`, `.ssh`, `.aws`, `.gnupg`,
`credentials`); an explicit credential path is already refused. Staged and unstaged diffs apply
the same exclusion, so the Changes list and the diff agree.

**Stable error codes added:** `invalid_repository` (metadata outside the repository, or an
unreadable/oversized config), `unsafe_repository` (config that would run a program),
`git_unavailable` (git not on `PATH`) and `git_timeout` (the pinned timeout expired).

**Tests.** `sandbox_review_test.go` covers repository-configured execution (a control proves
plain git would run it), all three filter-config sources (local, included, worktree), `.git`-file
and worktree redirection, alternate object stores, credential hiding in status and in staged and
unstaged diffs, renames and submodule gitlinks, diff and status caps, missing git, timeout, and a
Windows junction escape alongside an in-repository symlink that must stay readable.

**Known limit.** The config scan and the git command are separate processes, so an agent that
rewrites `.git/config` in between is not prevented. The agent already controls this repository
and has shell access to it; the scan removes the ordinary path, not a racing adversary.
