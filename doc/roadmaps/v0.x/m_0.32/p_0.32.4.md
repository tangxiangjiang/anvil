# p_0.32.4 — Shared workflow clients over WebSocket

**Status:** planned
**Milestone:** [m_0.32_sandbox_code_review.md](../m_0.32_sandbox_code_review.md)
**Linked design:** [32-sandbox-code-review.md](../../../design/v0.x/32-sandbox-code-review.md)

## Goal

Connect desktop/hosted VS Code and Flutter to the same database-backed Workspace workflow without
building a second workflow state machine in any client.

## Scope

- Define versioned HTTP bootstrap and short-lived WebSocket connection tickets.
- Define idempotent commands, sequenced events, resume cursors and snapshot recovery.
- Connect the Anvil extension running in desktop VS Code and hosted VS Code Server.
- Keep Flutter compatible with the same protocol as its separate client iteration proceeds.
- Keep anvil-web read-only for workflow review/audit and use it to launch hosted VS Code.

## Acceptance

- [ ] The service database is the only durable source for Workspace structure and run state.
- [ ] Reconnecting a client resumes without duplicating commands or losing approvals.
- [ ] Desktop and hosted VS Code use the same extension workflow implementation.
- [ ] Flutter can consume the same event contract without VS Code-specific fields.
- [ ] Web contains no second workflow authoring or execution state machine.
