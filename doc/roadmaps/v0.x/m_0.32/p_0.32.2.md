# p_0.32.2 — Web BFF + read-only review UI

**Status:** done
**Milestone:** [m_0.32_sandbox_code_review.md](../m_0.32_sandbox_code_review.md)

## Goals

- Provide an authenticated Web BFF and responsive, accessible, read-only review workbench over the p_0.32.1 RPC chain.
- Make scope, loading, empty, error, truncation, and disconnected-node states explicit.

## Scope

- Safe fleet/node/worker selection using current cluster inventory.
- Worker-relative file tree and text viewer.
- Git status/changes list and bounded unstaged/staged diff viewer.
- Refresh and route state without exposing host paths or scheduler credentials.

## Non-goals

- Editing, file writes, terminal access, arbitrary command execution, or Git mutation.
- VS Code Server or ide-proxy controls from p_0.32.3.
- Rendering repository HTML/Markdown as trusted markup.

## Tasks

1. Mirror bounded scheduler tree/file/status/diff routes through the authenticated Web BFF, validating fleet/node/worker route segments and preserving structured upstream errors.
2. Add a **Review** action for project-bound workers and a route-scoped workbench.
3. Render file tree, escaped plain-text viewer, Changes list, and escaped diff using shared action/error helpers.
4. Represent refresh/loading/empty/error/truncated/disconnected states and keep selection safe when fleet/node/worker scope changes.
5. Apply responsive and keyboard/focus semantics from shared UI styles; show a read-only banner with no edit/terminal controls.
6. Add BFF, pure-function/DOM, and real Chrome smoke tests, including a Browser/Web → scheduler → agentd → sandbox path.

## Acceptance

- An authenticated operator can select an assigned worker, browse files, open UTF-8 text, inspect status, and view staged/unstaged or untracked diffs.
- Route scope changes cannot reuse data from another fleet/node/worker, and unauthenticated or invalid scope requests fail closed.
- Repository content is always rendered as text; XSS fixtures cannot create executable DOM.
- Narrow-screen, keyboard, truncation, empty, loading, and node-unreachable states are usable and explicit.
- A real local Browser/Web → scheduler → agentd → sandbox smoke test passes; fake-BFF-only coverage is insufficient.
- No Web API or UI in this phase writes files, mutates Git, opens a terminal, or executes caller-selected commands.

## Depends-on

- p_0.32.1 agentd sandbox read + Git RPC.
- Existing cluster inventory, shared action/error helpers, auth middleware, and browser smoke harness.
