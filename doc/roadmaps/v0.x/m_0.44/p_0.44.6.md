# p_0.44.6 — The MCP manager panel

**Status:** done (2026-10-20)
**Milestone:** [m_0.44_mcp_management.md](../m_0.44_mcp_management.md)
**Linked design:** [44-mcp-management.md](../../../design/v0.x/44-mcp-management.md) §7

## Goals

1. **One place to see and change every server.** A webview document lists each server with its
   state, transport, source, tools and error, and offers enable/disable, reconnect, delete,
   sign in/out, add and edit.
2. **Editing is safe by construction.** The form maps to the host's writers; a malformed file
   makes the document read-only with the parser error, exactly like the permissions manager;
   secret values are never shown.
3. **The entry points are where a person looks.** `anvil.openMcp`, `anvil.openMcpFile`, and
   `/mcp`.

## Scope

New `editors/vscode/src/mcpPanel.ts`, `media/mcp.js`, `media/mcp.css`; `src/commands.ts`,
`chatPanel.ts`, `extension.ts`, `package.json`, `editors/vscode/README.md`, and tests.

## Tasks

1. **Panel shell.** One document per window, reveal rather than duplicate, nonce + CSP,
   `localResourceRoots`, disposal unsubscribes from `hub.onMcpStatus`.
2. **Messages.** Inbound: `ready`, `reload`, `add`, `update`, `remove`, `setEnabled`,
   `reconnect`, `authenticate`, `signOut`, `openFile`, `scopeChanged`. Outbound: `state`,
   `saving`, `saved`, `error`, plus `state` re-renders on `mcp.status`.
3. **Rendering.** Per row: name, state dot/word, transport, source, tool list (collapsible),
   error line; actions: toggle, reconnect, delete (confirm), Sign in / Sign out. Add/edit form:
   scope (project/user), name, transport, command/args/env or URL/headers, enabled. Every value
   via `textContent` or input value; no `innerHTML`.
4. **Read-only states.** A `problem` or a listing error disables the form and shows the parser
   message and path; the "Open mcp.json" button remains.
5. **OAuth.** `authenticate` calls the host, opens the returned URL with
   `vscode.env.openExternal`, shows "waiting for the browser", and updates from `mcp.status`;
   an openExternal failure is shown as text.
6. **Commands and slash.** `anvil.openMcp` / `anvil.openMcpFile` contributed and registered;
   `/mcp` routes to `{kind:'mcp'}` in `commands.ts` and opens the panel from the composer; the
   builtin-order test is updated.
7. **Docs.** `editors/vscode/README.md` settings/commands/feature sections; update chapter 43's
   delivery row; the milestone and its index flip to done. Root README and design cutoffs move
   to 0.44.
8. **Tests.** Unit source assertions for the panel (text-only, CSP, read-only-on-problem,
   commands), integration for each wire call, and the fake host's management/status behavior.

## Implementation notes

- **The manager lists both layers, always.** Unlike a session — which reads the layers its
  settings enable — the document asks for `['project', 'user']` on every call. The manager is
  where those files are edited, and a layer the settings exclude is exactly the one a person
  opens it to look at or to add a first server to. The scope select decides which file a write
  lands in; a banner says `anvil.mcp.<layer> is off`, so nobody adds a server and then wonders
  why the session does not have it. The fixed set also keeps the runtime key stable: every
  `mcp.status` belongs to the listing on screen, and a status naming another set is dropped.
- **Two renders, because a write and a notification mean different things.** `state` and
  `saved` rebuild the document — the answer to a write is the host's reading of a new file, so
  the form resets — while `rows` repaints only the banners and the rows. `mcp.status` schedules
  a `rows` refresh through a 150 ms timer, which coalesces a connect's burst of transitions
  into one listing and lets a half-typed form survive. The listing is re-read rather than
  patched from the notification because a status carries no tool catalogue.
- **A blank env/header section means keep, and the form says so.** `draftFromForm` omits the
  map when nothing is typed, which the host reads as nil = keep; an empty map would erase
  values the form never showed. Switching transport does not clear the other half for the same
  reason. Because the values are never sent back to the editor, an edit form prefills key names
  and leaves the values blank, with the hint naming the keys that would be replaced.
- **Read-only has one definition.** `editable()` is `runtime && no problem && no listing
  error`; it gates the row actions, the form and Save alike. A listing that could not be
  fetched at all still posts its envelope — with `runtime: false` and the reason — so the
  document degrades the same way as for a host that predates `runtime`. Open mcp.json stays
  live: a person with a broken file still has an editor.
- **Delete confirms in the document.** The first click arms the button for four seconds; the
  host does not ask twice, and the entry may be the only record of a server's configuration.
- **The sign-in URL is never written down.** The panel hands it to `vscode.env.openExternal`
  and nothing else — no log, no output channel, no postMessage — because it carries the flow's
  `state`. Completion arrives as `mcp.status`, so the request that starts the flow returns
  immediately.
- **`openMcpFile` resolves the path locally.** `mcp.list` reports a path only after it has
  parsed the file, so asking the host would fail precisely when the file is the problem. The
  panel computes the same paths the host uses (first folder's `.cursor/mcp.json`,
  `~/.cursor/mcp.json`) and seeds a missing file with `{"mcpServers": {}}` — the smallest
  document the writer accepts.
