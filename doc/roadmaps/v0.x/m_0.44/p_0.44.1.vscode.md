# p_0.44.1 — A config the manager can write

**Status:** done (2026-10-20)
**Milestone:** [m_0.44_mcp_management.vscode.md](../m_0.44_mcp_management.vscode.md)
**Linked design:** [44-mcp-management.vscode.md](../../../design/v0.x/44-mcp-management.vscode.md) §3

## Goals

1. **The file model can say what the manager needs to say.** A server entry gains `enabled` and
   an explicit `transport`, without breaking the Cursor-compatible shape.
2. **Writes preserve what they do not understand.** Adding, updating, removing or toggling one
   server must not delete another server's unknown fields, nor top-level fields this milestone
   knows nothing about.
3. **A broken file is never overwritten.** Every write refuses to parse-loss a file; the caller
   gets the parser error and the file keeps its bytes.
4. **The listing can feed a manager without leaking secrets.** `ListMCPServers` reports the
   enabled flag, the launch fields a form needs, and env/header **names** only.

## Scope

`source/internal/settings/mcpjson.go`, `source/settings.go`, `source/options.go`, `source/mcp.go`,
a new `source/mcpconfig.go`, and their tests. No runtime, no host, no extension.

## Tasks

1. **Parser fields.** `settings.MCPServer` gains `Enabled *bool`, `Transport string` and
   `Type string` (legacy alias). `mcpFromSettings` prefers `transport`, falls back to `type`, and
   carries `Enabled` into `MCPServerConfig.Enabled *bool` (public, additive).
2. **Disabled means not started.** `mergeMCPFromSources` skips an entry whose `Enabled` is
   explicitly false. Inline `Options.MCPServers` entries are not filtered: an inline config is
   the caller's direct intent. A disabled entry still shadows a same-named entry from a lower
   layer.
3. **Listing.** `MCPServerInfo` gains `Enabled`, `Command`, `Args`, `URL`, `EnvNames` and
   `HeaderNames` (sorted). Values are never returned. `ListMCPServers` reports the effective
   entry (project over user) and keeps its existing order and source semantics.
4. **Writers.** New `source/mcpconfig.go`:
   - `MCPConfigPath(cwd, source) (string, error)`;
   - `MCPServerDraft{Name, Transport, Command, Args, Env, Headers, URL, Enabled}`;
   - `AddMCPServer`, `UpdateMCPServer`, `RemoveMCPServer`, `SetMCPServerEnabled`, each returning
     the fresh `MCPListing` for the same sources;
   - raw-map read/modify/write preserving unknown fields, deterministic key order;
   - validation (see below), directory creation, temp-file + rename atomic write;
   - a typed `MCPConfigError` carrying path, message and byte offset/line where the parser
     provides one.
5. **Validation.** Name non-empty and free of path separators or control characters; transport
   in `stdio|http|sse|streamable-http`; `stdio` requires `command`; remote requires an absolute
   `http`/`https` URL; command and URL are mutually exclusive; env/header keys non-empty; add
   refuses an existing name, update and remove require one.
6. **Tests and docs.** New `source/mcpconfig_test.go`; extend `source/mcp_test.go`,
   `source/settings`-level tests where the parser lives. Update chapter 43 if an implementation
   decision narrows it.

## Acceptance

- [x] An added server survives a round trip with its unknown per-server field, and every other
      server's unknown fields are byte-for-byte still present in the rewritten file.
- [x] Add/update/remove/toggle on a malformed file returns an error and leaves the file's bytes
      unchanged.
- [x] `enabled: false` is written by `SetMCPServerEnabled(..., false)` and removed by enabling;
      a disabled entry is listed as disabled and is not started by the non-runtime merge.
- [x] A disabled project entry shadows a same-named enabled user entry.
- [x] `ListMCPServers` exposes env/header names but no values.
- [x] `cd source && go build ./... && go vet ./... && go test -count=1 ./...` green.

## Implementation notes

- `settings.MCPServer` also **rejects a file that spells the transport twice with different
  values** (`transport: "http"` + `type: "sse"`) at parse time. `streamable-http` folds to
  `http` in `TransportName`, so the listing and the client agree on one name.
- The raw editor keeps unknown fields **inside the edited entry** too, not just elsewhere: an
  update unmarshals the entry, changes the fields the draft names, and writes it back. The
  non-goal about formatting therefore holds — the file is re-indented — while field
  preservation is strictly better than the phase asked for.
- `UpdateMCPServer` writes `transport` or `type` depending on which spelling the entry already
  used, so the writer does not migrate a file to a shape its owner did not choose.
- `MCPConfigError` carries the path, the parser message and, for syntax/type failures, the
  byte offset with a 1-based line and column; the host's `problem` object reads them directly
  (p_0.44.4). Every writer error is an `*anvil.Error` wrapping it, so `errors.As` finds it.
- A write that succeeds but whose fresh listing fails says so explicitly ("mcp.json was written,
  but listing the servers failed") — reporting only the listing error would invite a retry that
  then answers "already exists".
- Validation additionally rejects env names containing `=` or NUL, because they cannot be passed
  to a child process intact.

## Non-goals

- Starting or observing a server (p_0.44.2).
- Writing `transport`/`type` in a different shape than the file already uses.
- Editing any file other than the two Cursor paths.
- Preserving formatting or key order exactly; the contract is field preservation, not byte
  preservation (except when refusing).
