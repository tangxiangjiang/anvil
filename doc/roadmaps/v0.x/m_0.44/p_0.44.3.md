# p_0.44.3 — Streamable HTTP and sign-in

**Status:** done (2026-10-20)
**Milestone:** [m_0.44_mcp_management.md](../m_0.44_mcp_management.md)
**Linked design:** [44-mcp-management.md](../../../design/v0.x/44-mcp-management.md) §5–6

## Goals

1. **`http` means what remote servers actually speak.** Streamable HTTP: `Mcp-Session-Id`, SSE
   response bodies, protocol version negotiation, and a JSON response still accepted.
2. **A 401 is a typed fact.** The client reports `*AuthRequiredError` with the challenge; the
   runtime maps it to `auth_required` instead of a string that only looks like an error.
3. **The host can sign in.** Discovery, dynamic registration, PKCE, the loopback callback and
   the token exchange live in the SDK; tokens are persisted 0600 and refreshed.
4. **No secret leaves the process except to the server it belongs to.**

## Scope

`source/internal/mcp/remote.go`, new `source/internal/mcp/streamable.go`, `oauth.go`,
`tokenstore.go`, and `source/mcpruntime.go` for the `Authenticate`/`SignOut`/refresh surface.
Tests use `httptest` only.

## Tasks

1. **Streamable HTTP.** POST with `Accept: application/json, text/event-stream`; capture
   `Mcp-Session-Id` from the initialize response and send it on every later request; parse JSON
   or SSE bodies looking for the matching JSON-RPC id; notifications accept 202/204 and treat
   other non-2xx as errors; initialize sends `2025-06-18`, records the negotiated version, sends
   `MCP-Protocol-Version` afterwards, and retries once with `2024-11-05` when the server rejects
   it. `streamable-http` normalises to `http`. Legacy `sse` is untouched.
2. **Typed failures.** `*AuthRequiredError{Challenge, ResourceMetadataURL}` on 401;
   `*SessionExpiredError` on 404 with a session id. Other non-2xx stay ordinary errors.
3. **Discovery.** `WWW-Authenticate` parsing; protected resource metadata (RFC 9728) with the
   derived well-known fallback; AS metadata (RFC 8414, then OpenID); validation that the
   advertised `resource` matches the configured URL.
4. **Registration and authorization.** Dynamic client registration (RFC 7591) when needed and
   no cached client id; `oauth.client_id`/`oauth.client_secret` in the entry as a manual
   alternative; PKCE S256 and constant-time `state`; loopback listener on `127.0.0.1:0` with a
   five-minute lifetime; authorization URL includes `resource` (RFC 8707).
5. **Tokens.** Store under `~/.anvil/mcp/oauth/` (0700), file 0600, hashed name; refresh 60 s
   before expiry with `resource`; `invalid_grant` or a missing refresh token clears the tokens
   and returns `auth_required`; `SignOut` deletes the file. Tokens and client secrets never
   appear in errors or logs; URLs are redacted of query strings.
6. **Runtime surface.** `MCPRuntime.Authenticate(ctx, name) (MCPAuthentication, error)` returns
   the URL and starts the pending flow; a second call while pending returns the same URL;
   completion reconnects and calls `OnChange`. `SignOut(name)`.
7. **Tests.** Fake AS (`httptest`) covering metadata, registration, PKCE verification, exact
   redirect URI, `resource`, code exchange, refresh and `invalid_grant`; fake MCP server that
   answers 401 until it sees the bearer; token file mode on non-Windows; a test that no token
   appears in any returned error.

## Acceptance

- [x] A Streamable HTTP server sees the session id on every request after initialize, and an
      SSE response body is parsed.
- [x] A legacy JSON-responding HTTP server keeps working.
- [x] `401` produces `auth_required`; `Authenticate` returns an authorization URL whose
      `redirect_uri`, `code_challenge` and `resource` the fake AS validates.
- [x] Completing the callback stores a token file (0600 where the OS supports it), reconnects,
      and reports `connected`.
- [x] An expired token is refreshed once and the new token is persisted; `invalid_grant` yields
      `auth_required` without a retry loop.
- [x] No token or client secret is present in any status, error or log line the tests capture.
- [x] `cd source && go test -count=1 ./...` green.

## Non-goals

- Device-code flow, revocation endpoints, OS keychain.
- Manual callback-code paste (the remote/SSH caveat is documented, not solved here).
- Background GET SSE, `tools/list_changed`.
- OAuth for stdio servers.

## Depends-on

- p_0.44.2 (the runtime entry and reconnect path), p_0.9.x (remote client).

## Implementation notes

- **One request path for both shapes.** `requestStreamable` decides by response `Content-Type`:
  `text/event-stream` goes through `parseSSEResponse`, anything else is read as a JSON body. A
  legacy HTTP server that answers plain JSON needed no change; the old HTTP branch in
  `remote.go` now calls this function.
- **Protocol fallback is one retry, not a negotiation loop.** `initialize` opens with
  `2025-06-18`; only an error that names the protocol or version (JSON-RPC error message, or
  HTTP 400) triggers the single retry with `2024-11-05`. Auth failures and network errors are
  never mistaken for a version rejection.
- **Notification bodies are read and discarded.** `notifyStreamable` accepts any 2xx, which
  covers 202 and 204 as the design says; a non-2xx is an `httpStatusError`.
- **Discovery follows the design's chain and validates its own input.** The challenge's
  `resource_metadata` wins over the derived RFC 9728 path; a protected-resource document whose
  `resource` names a different URL is refused rather than followed, which keeps a hostile
  challenge from redirecting the flow to another server.
- **The token record carries more than the tokens.** `token_endpoint` and
  `registered_redirect_uri` are persisted so a refresh needs no rediscovery (the server may be
  offline for everything except `/token`) and a re-sign-in can reuse the registration. This
  adds two fields beyond the phase's wording; both are host-local and never leave the file.
- **Manual registration is configured, not inferred.** `oauth.client_id`,
  `oauth.client_secret` and `oauth.scope` in a server entry; a configured client id skips DCR.
  Without one and without a cached registration, a server that offers no registration endpoint
  fails with "set oauth.client_id in mcp.json".
- **Cancellation is a first-class state.** `cancel` closes the listener once and wakes `Wait`,
  so a runtime shutdown (or a retire) does not leave a goroutine blocked until the five-minute
  timer fires.
- **Runtime mapping.** `connect` stores the challenge from a 401 and reports
  `auth_required`; `Call` does the same for a 401 that arrives mid-session (for example after a
  token was revoked). `Authenticate` holds `authMu` only around `Begin`, so a second call
  during a pending flow returns the same URL; completion runs in a goroutine bounded by the
  runtime's lifetime and reconnects on success. `SignOut` deletes the file and retires the
  session back to `auth_required`.
- **Tests.** `internal/mcp/oauth_test.go` (fake AS plus a 401-until-bearer MCP server, public
  API only) and `mcpruntime_oauth_test.go` (runtime-level sign-in/out) cover the acceptance
  list; `streamable_test.go` covers the transport. Error strings are asserted to contain no
  token. `go test -race` still cannot run on this machine (no C compiler), same limitation as
  p_0.44.2; the runtime OAuth test uses a background goroutine, so a `-race` run is worth doing
  where cgo is available.
