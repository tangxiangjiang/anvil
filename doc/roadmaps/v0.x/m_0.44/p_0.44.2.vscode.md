# p_0.44.2 — A runtime that owns the connections

**Status:** done (2026-10-20)
**Milestone:** [m_0.44_mcp_management.vscode.md](../m_0.44_mcp_management.vscode.md)
**Linked design:** [44-mcp-management.vscode.md](../../../design/v0.x/44-mcp-management.vscode.md) §2

## Goals

1. **One owner for MCP connections.** A public `anvil.MCPRuntime` opens, tracks, retires and
   reconnects servers; agents borrow its tools instead of spawning their own processes.
2. **Failure is data.** A server that will not start becomes a `failed` status with its error;
   the rest of the session works.
3. **Tools follow the runtime.** Reconnect and config reload replace the process; tool handlers
   resolve the current session by name, so a registry refresh is safe at any later turn.
4. **A run never sees its registry change under it.** Tools refresh before `running` is set and
   never during a turn.

## Scope

New `source/mcp_runtime.go`; `source/agent_options.go`, `source/agent.go`, `source/subagent.go`,
`source/internal/mcp/client.go` (pagination only), and tests. No host or extension changes.

## Tasks

1. **Runtime API.**
   - `MCPState` (`disabled|connecting|connected|failed|auth_required`);
   - `MCPServerStatus{Name, Transport, Source, Enabled, State, Error, ToolCount, Tools,
     ConnectedAt}`;
   - `MCPRuntimeOptions{CWD, SettingSources, Inline, TokenDir, ConnectTimeout, OnChange}`;
   - `NewMCPRuntime`, `Reload`, `Reconnect`, `Statuses`, `Status`, `Tools`, `Version`, `Call`,
     `Close`.
2. **Connections.** `Reload` reads config (file layers plus inline), diffs by a normalised
   config hash, starts changed servers in parallel with `ConnectTimeout` (default 15 s), retires
   removed ones after their in-flight calls finish, and returns an error only for a config that
   cannot be read. A malformed file keeps the last good sessions and statuses and is reported.
3. **Ownership.** Each entry has a read/write lock; `Call` holds the read lock, retirement holds
   the write lock. Sessions are closed by the runtime only.
4. **Agent integration.** `Options.MCPRuntime *MCPRuntime` is the sole source of MCP when set:
   `createAgent` skips `mergeMCPFromSources`; `buildRegistry` registers `mcp_*` tools from
   `runtime.Tools()` with handlers that call `runtime.Call`; the agent records the snapshot
   version; `Close` and `Reload` do not close runtime sessions.
5. **Refresh.** `Agent.RefreshMCP()` unregisters and re-registers only `mcp_*` names. `Send`
   calls it under `a.mu` when the runtime version moved, before setting `running`. A running
   turn is never touched; the next turn picks the change up.
6. **Children.** A subagent inherits the runtime only when its selectors include `mcp`;
   otherwise the child gets `MCPRuntime = nil` and no file MCP.
7. **Pagination.** `tools/list` follows `nextCursor` until exhausted. Duplicate registered tool
   names (two servers sanitising to the same prefix) are detected and the loser is reported
   `failed` rather than silently overwriting.
8. **Tests.** Runtime tests with the existing `fakecmd` fixture, a second fixture that records
   its PID for retirement checks, and a broken command; `-race` for concurrent call/reload.

## Implementation notes

- **A start timeout must not own the process.** `startStdio` used `exec.CommandContext(ctx)`
  with the caller's context, so a runtime that bounded `Start` with
  `context.WithTimeout` killed the server the moment the handshake finished — the next call
  read EOF. `Session` now keeps its own `cancel` (`context.WithCancel(context.WithoutCancel(ctx))`):
  the caller's context still bounds `initialize` and `tools/list`, and only `Session.Close`
  stops the child. This also fixes the same latent issue for any caller that cancels a context
  after `Start` returns.
- **Two different fixtures.** `internal/mcp/fakeruntime` is new (the old `fakecmd` speaks only
  well enough for the client tests): it writes its PID to `$FAKE_MCP_PIDFILE`, and exposes
  `echo`, `pid` and `slow` (sleeps `ms`, then echoes `text`). The tests build it with
  `go build -o <tmp> ./internal/mcp/fakeruntime` in the package directory, the same pattern the
  existing tests use.
- **Collision policy.** `resolveCollisions` runs after a reload or reconnect and marks the
  alphabetically later server `failed` with `tool <registered> collides with server <first>`,
  retiring its session. The alternative — letting the registry reject the second registration —
  would leave a server listed `connected` whose tools were never registered.
- **Status vs. removal.** A removed entry is deleted from `entries` (the listing omits it); a
  *disabled* entry stays, with `State: disabled`, because the file still declares it and a
  manager must show it. `retire(entry, nil)` is the "leaving, no status" path; every other
  transition goes through a status so `OnChange` fires.
- **Version.** `Version()` moves on every connect, retire-with-status, and removal. `Send`
  compares it under `a.mu` before `running = true`; `RefreshMCP` refuses while a run is in
  flight rather than queueing.
- **Subagents.** `childOptions` copies `MCPRuntime` only in the `hasMCPSelector` branch, so a
  child without the `mcp` selector gets neither files nor runtime.
- **`-race`.** Not executed: `go test -race` fails with `-race requires cgo`, and this machine
  has no `gcc`/`clang`. `TestMCPRuntimeConcurrentCallsAndReloads` exists and passes in the
  normal build; it should be run under `-race` on a machine with a toolchain.
- **Verification.** `go build ./...`, `go vet ./...`, `go test -count=1 ./...` all green.

## Non-goals

- OAuth or remote transport changes (p_0.44.3).
- Parallel calls to one server.
- Idle shutdown or connection reuse across different source sets.
