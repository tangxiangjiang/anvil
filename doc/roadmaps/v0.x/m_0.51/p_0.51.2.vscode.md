# p_0.51.2 — Host approval integration

**Status:** done

## Goals

Integrate protected shell-path findings into the editor-host approval flow so risky or ambiguous
commands require informed, explicit approval.

## Scope

- Invoke the p_0.51.1 analyzer before the host authorizes a shell tool call.
- Require approval when a finding targets a protected path or cannot be safely classified.
- Include affected path, operation, and analyzer reason in the approval request and transcript.
- Preserve existing permission behavior for commands classified as not affecting protected paths.
- Keep denial and cancellation durable across live rendering and replay.

## Acceptance

- [x] A host integration test proves an otherwise allowed shell command that writes a protected
  path pauses before execution and runs only after explicit approval.
- [x] Denial and cancellation tests prove the command is not started and the reason remains in
  the transcript after reload.
- [x] Ambiguous-command tests prove the host requests approval rather than silently allowing it.

- Changing approval policy for non-shell tools.
- Assigning the future patch number in this planned document.
