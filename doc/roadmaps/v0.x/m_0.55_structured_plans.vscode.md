# Milestone 0.55 — Structured plans

**Status:** planned

Turn plans into one shared, versioned data model that can be read before execution, approved in
parts, and tracked through dependencies from a VS Code control center. This milestone provides
human-controlled execution; it does not add an automatic reviewer or autonomous re-planning
loop. The design is chapter
[55](../../design/v0.x/55-structured-plans-and-workflow-control.vscode.md).

## Goals

1. Define one plan schema and validation contract across SDK, host, stores, and VS Code.
2. Support partial approval while preserving dependency and denial semantics.
3. Make the editor a read-first control center for inspecting and controlling plan execution.
4. Apply the VS Code patch policy per user-visible implementation batch from the then-current
   package version; 0.55 itself is not the plugin patch version.

## Ordering

p_0.55.1 fixes the persisted and wire representation. p_0.55.2 adds state transitions over that
schema. p_0.55.3 is last because its controls and projections must use, rather than redefine,
those transitions.

## Overall acceptance

1. Schema fixtures round-trip byte-stable semantic content through SDK, host protocol, JSONL,
   SQLite, and VS Code, and reject unknown schema versions without executing.
2. Dependency tests prove only approved, dependency-ready items can start; denying a prerequisite
   blocks dependents with an explicit reason.
3. VS Code tests prove opening a plan performs no mutation, approvals require an explicit action,
   and reconnect/reload preserves the authoritative plan state.
4. No test path invokes an automatic reviewer or generates a replacement plan after failure.
5. `cd source && go test -count=1 ./...` and `cd editors/vscode && npm test` pass; each
   user-visible delivery also verifies an exact one-patch extension version increment and all
   synchronized version declarations.

## Non-goals

- Automatic reviewer agents, automatic approval, or autonomous re-planning after failure.
- A general workflow language or arbitrary executable code in plan nodes.
- Collaborative multi-user plan editing.
