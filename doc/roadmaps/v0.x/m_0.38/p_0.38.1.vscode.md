# p_0.38.1 — A session's title

**Status:** done  
**Milestone:** [m_0.38_session_identity.vscode.md](../m_0.38_session_identity.vscode.md)  
**Linked design:** [38-session-identity-and-replay.vscode.md](../../../design/v0.x/38-session-identity-and-replay.vscode.md), [35-vscode-extension.vscode.md](../../../design/v0.x/35-vscode-extension.vscode.md), [06-session-store.md](../../../design/v0.x/06-session-store.md)

## Goals

1. **A row says what the session was about.** The first `role: "user"` message in the store,
   on one line, cut at a fixed length.
2. **Derived where the store already is, not where it is displayed.** `Summarize` is the one
   rollup every consumer reads a session's metadata from; the title is metadata, so it belongs
   there and nowhere else.
3. **The title never replaces what identifies the session.** The agent id is what a command
   takes and what `resume` needs; it stays in the tooltip. A title is a label, not a key.
4. **Absent when there is nothing to say.** No user message means no title — and then the row
   falls back to the shortened id, exactly as every row does today.

## Scope

`source/internal/store/` (`Summary`, `Summarize`), `source/session_list.go` (`AgentInfo`),
`source/internal/editorhost/` (`SessionInfo` on the wire, one line of projection),
`editors/vscode/src/` (`protocol.ts`, `sessionList.ts`), and the tests and docs on both sides.

## Tasks

1. **The derivation** — `store.Summarize` learns `TypeMessage`. The first user-role record
   wins; a second is not a better title. Add `Summary.Title`.
2. **Normalization** — an unexported helper: drop control characters, fold every run of
   whitespace (including newlines) to a single space, trim, cut at 80 **runes**, and append an
   ellipsis only when something was actually cut.
3. **The public field** — `anvil.AgentInfo.Title`, mapped in `loadInfo`.
4. **The wire** — `SessionInfo.title` on `session.list`, `omitempty`, one line in
   `handleSessionList`. `ProtocolVersion` does not move: the field is optional, which is the
   p_0.36.2 rule.
5. **The client** — `title?: string` in `protocol.ts`; the sidebar labels a row with its title
   and falls back to `shortId`; the tooltip is unchanged in shape and still names the agent id.
6. Tests and docs.

## Tasks as delivered

Four details the task list does not carry, and one sentence in it that needed saying better.

- **Trimming is not a step, it is what the whitespace rule already does.** The normalizer holds a
  pending space instead of writing one: a run of spaces and newlines collapses to a single space
  because only the first is remembered, a *trailing* run collapses to nothing because the held
  space is only flushed when a real character follows, and leading whitespace produces nothing
  because the hold is set only once something is already in the buffer. Three behaviours that
  read as three steps in the task list ("fold, trim, cut") are one mechanism, and the tests pin
  each of them separately because that is how they will break — one at a time.
- **A control character is dropped, not folded into a space.** A tab or a newline is a break in
  the text and becomes the space it stands for; `\x00` and its neighbours are not breaks, they
  are bytes no sidebar can render, so folding them to a space would invent a word boundary that
  was never typed. The two rules are `unicode.IsSpace` and `unicode.IsControl`, in that order.
- **The ellipsis is decided by the rune that was refused, not by the length that was kept.** The
  cut is checked as the *next* rune arrives, so a title of exactly `titleLimit` runes ends
  without a `…` — the mark means "there is more", and a title that fits has no more. Pinned by
  its own test, because the off-by-one here is silent in every case but the boundary.
- **`omitempty` needed a test of its own, and the field it guards is not just an optimization.**
  `TestSessionListOmitsAnAbsentTitle` asserts the `title` *key* is absent from the JSON, not
  that its value is empty: the client's fallback keys on `undefined`, so a host that sent
  `"title": ""` would be a host whose rows lose their label to a title nobody wrote. Two
  client-side behaviours follow from the same place — `sessionLabel` trims before it decides, so
  a whitespace-only title falls back to the id even if some host ever sends one.
- **Said better:** task 5 read as though labelling were a formatting change. It is a rule about
  what a label is and what a key is, and it is why the tooltip did not change: the agent id stays
  there in full, and the title is deliberately *not* repeated beside it. A row is found by the
  thing a person recognises and resumed by the thing a command takes, and the two are on
  different surfaces in every case. That rule now lives in one function with the reason written
  above it, rather than in the two call sites it would otherwise have been spread across.

## Acceptance

- [x] A store whose first user message is `Fix the flaky test` reports that title, and a second
  user message does not replace it. (`TestSummarizeTitlesASessionFromItsFirstUserMessage`.)
- [x] A prompt that spans lines and contains a tab and a control character yields one line with
  no control characters. (`TestSummarizeMakesATitleOneLine`.)
- [x] A title of more than 80 runes is cut at 80 runes with an ellipsis; 80 CJK characters are
  not split into mojibake — 80 `测` plus the mark, and the result is asserted to be valid UTF-8.
  (`TestSummarizeTruncatesATitleAtEightyRunes`, and `TestSummarizeDoesNotMarkATitleThatFits`
  for the boundary that must *not* gain the mark.)
- [x] A session with no user message has an empty title, and the wire carries no `title` key —
  the key's absence is asserted, not its emptiness. (`TestSummarizeHasNoTitleWithoutAUserMessage`,
  `TestSummarizeHasNoTitleForAWhitespaceOnlyPrompt`,
  `TestSummarizeDoesNotTitleASessionFromToolOutput`, `TestSessionListOmitsAnAbsentTitle`.)
- [x] `session.list` returns the title for a session that was prompted through the host.
  (`TestSessionListCarriesTheTitle`, and the integration test
  `'a prompted session is listed under the first thing that was typed'` over the real pipe.)
- [x] The sidebar shows the title as the row's label, and the full agent id in its tooltip —
  which is also asserted *not* to restate the title. (`sessionList.test.ts`.)
- [x] A row with no title is labelled with the shortened id, as before, and so is a title of
  nothing but whitespace. (`sessionList.test.ts`.)
- [x] `go test ./...` green; `npm test` green (184, up from 181).

## Non-goals

- Any model call, and any stored title field. The title is derived on read, every read.
- A title editor, a rename command, or a title in the chat tab's heading.
- Changing what the row's description or icon carry.
- Searching or filtering sessions by title.
