# Milestone 0.11 — Worker daemon & agent-worker

**Status:** done  
**Product version:** 0.11.x

## Goals

Add a **per-machine worker-daemon (`agentd`)** and **agent-worker** processes so hosts can assign, stream, and cancel Anvil Local jobs without embedding the SDK in every controller. Local IPC is required; cluster join/forward is designed and stubbed or minimally wired after local works.

## Overall acceptance

1. A controller can connect to local agentd, assign a job to an allowlisted cwd, receive streamed events, and cancel.
2. Workers run Anvil Local (Create/Prompt or Send path); daemon does not implement the tool loop.
3. Capacity limits are enforced; overload rejects or queues per documented policy.
4. Cluster plane is specified; at least join+forward or a documented stub with clear non-goals.
5. Public in-process `anvil` API remains intact; daemon is additive (`cmd/agentd`, `cmd/agent-worker`).

## Non-goals

- cloud-agent Gateway/App replacement
- Model gateway
- Cursor Bridge / Cloud agents
- In-library multi-agent graph inside `anvil.Create`
- Public TCP daemon without explicit config

## Depends-on

- Milestone 0.10 done (stable local agent surface)
- Prefer 0.7–0.8 error/cancel and security behavior for worker runs
