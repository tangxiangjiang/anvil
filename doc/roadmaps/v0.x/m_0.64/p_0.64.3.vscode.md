# p_0.64.3 — Remote Git, pull request, CI, and Web cutover

**Status:** planned

## Goals

Deliver only the exact reviewed commit through explicit recoverable provider operations in VS Code.

## Scope

- Add provider-neutral repository/target/publication/PR/check records and first GitHub adapter.
- Add allow-listed identity/OAuth and short-lived Git credentials; tokens are absent from prompts,
  stores, Worktrees, Git config, output, persistent helpers, and inherited environments.
- Bind push and PR create/update/comment/close to previewed revision/idempotency and drift checks.
- Add webhook/subscription or bounded-poll CI state, bounded redacted logs/artifacts, and an
  explicit previewed revision-bound idempotent Retry checks operation.
- Reuse the explicit 0.57 integration command for the exact reviewed Worktree/base revision.
- Route approved CI repairs through 0.62–0.64 with fresh reviewed commits and deterministic bounds.
- Remove Web review/Git/PR/CI/repair/merge controls/routes; retain read-only audit/export.

## Tasks

1. Implement provider-neutral publication/PR/check records, credentials, drift, and idempotency.
2. Add VS Code integration, publication preview, PR lifecycle, CI evidence, Retry checks, and repair.
3. Remove Web delivery mutations and run provider/security/reconnect/route/package gates.

## Acceptance

- Only the reviewed commit reaches the approved remote/ref and credentials never leak.
- Cancel writes nothing; retries/reconnect cannot duplicate remote mutation.
- Drift, SSO/scope/protection/rate-limit/unknown outcomes fail closed or recover explicitly.
- Viewing failed CI starts no rerun/Agent; Retry checks is explicit and automatic merge is absent.
- Web cannot review, publish, mutate PR/CI, repair, or merge.

## Non-goals

- Automatic merge/release or first-release multi-provider parity.

## Depends-on

- p_0.64.1, p_0.64.2, and milestone 0.63.
