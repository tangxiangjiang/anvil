# p_0.40.3 — Per-hunk accept and reject

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.vscode.md](../m_0.40_editor_alignment.vscode.md)
**Linked design:** [40-editor-alignment.vscode.md](../../../design/v0.x/40-editor-alignment.vscode.md), [35-vscode-extension.vscode.md](../../../design/v0.x/35-vscode-extension.vscode.md), [36-tool-permissions.vscode.md](../../../design/v0.x/36-tool-permissions.vscode.md)

## Goals

1. **A change can be accepted in parts.** The reviewer selects hunks; only those are applied.
2. **The accepted content is computed against the file, not the diff.** Selected hunks are applied
   to the preview's whole `before` text, so untouched lines come back byte-identical.
3. **The decision reuses the existing channel.** The result is an `allow` with rewritten arguments,
   which the host already turns into `PermissionDecision.Args`.
4. **It fails closed.** If a hunk cannot be proven to apply, partial mode is unavailable for that
   approval and the card offers Allow/Deny only.

## Scope

New `editors/vscode/src/hunks.ts` (pure), new `src/reviewPanel.ts`, new `media/review.js` /
`media/review.css`, `src/chatPanel.ts`, `media/chat.js`, and the tests.

## Tasks

1. **`hunks.ts`** — `parseDiff(diff)` into hunks (header, old range, new range, lines);
   `applyAccepted(before, hunks, accepted) → string | undefined`; `rewriteArgs(tool, args,
   before, after, acceptedText)`. Matching compares line content only; each emitted line keeps the
   source line's own terminator. Any selected hunk whose old side does not match returns
   `undefined`.
2. **The rewrite.** `write_file` → `{path, content}`; `edit_file` → `{path, old_string: before,
   new_string: accepted}`; anything else → `undefined`. A file that changed since the preview
   fails the tool's own single-occurrence check and is reported, not silently applied.
3. **The review panel.** A webview (`anvil.review`) listing each hunk with a checkbox, the file
   path, and Accept selected / Reject all / Cancel. Rendered with `textContent` only. It is
   scoped to one approval at a time and closes when answered.
4. **The approval card.** When `preview.kind === "diff"` and both `before` and `after` are present
   (and the tool is `write_file` or `edit_file`), the card gains a `Review changes…` action next to
   Allow/Deny. It opens the review panel for that request.
5. **Answering.** `chatPanel.ts` sends `session.respond(requestId, "allow", { args })` for a
   partial accept, and `deny` when every hunk was rejected. The card then shows the familiar
   settled state.
6. **Fake host.** Record the `args` received on an approval so the round trip is asserted.
7. Tests and docs.

## Acceptance

- [x] Applying a subset of hunks to a `before` text produces exactly the expected content —
  multi-hunk, non-adjacent hunks, and a selection of the first and last only.
- [x] A CRLF `before` with a `\n`-joined diff yields CRLF on every untouched line and on
  synthesized lines; the result is byte-comparable to the original where untouched.
  (`hunks.test.ts`.)
- [x] A hunk whose context no longer matches makes partial mode unavailable rather than producing
  a guessed file.
- [x] `edit_file` partial acceptance answers `allow` with `{path, old_string, new_string}` and the
  host executes the rewritten call; the fake host asserts the exact arguments.
- [x] Rejecting all hunks sends `deny` and leaves the file untouched.
- [x] `apply_patch` shows no `Review changes…` action.
- [x] The review webview contains no `innerHTML`.
- [x] `npm test` green (271 tests).

## Non-goals

- Line-level selection inside a hunk. A hunk is the unit.
- Editing the proposed lines before accepting.
- A diff renderer in the chat panel itself; the review panel is the surface.
- `apply_patch` splitting, and rewriting shell commands.
