# p_0.40.7 — Web search and fetch

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [40-editor-alignment.md](../../../design/v0.x/40-editor-alignment.md), [15-web-search.md](../../../design/v0.x/15-web-search.md), [08-security.md](../../../design/v0.x/08-security.md)

## Goals

1. **The tools 0.15 built are reachable from the extension.** A setting turns them on and configures
   the provider.
2. **The key follows the model key's discipline.** SecretStorage only; injected as
   `ANVIL_WEB_SEARCH_API_KEY`; never in settings, logs or the protocol.
3. **Off means absent.** When disabled, the tools are not registered at all.

## Scope

`editors/vscode/package.json`, `editors/vscode/src/settings.ts`, `editors/vscode/src/extension.ts`
(two key commands), `source/internal/editorhost/` (`buildOptions`), the panel status row, tests.

## Tasks

1. **Settings.** `anvil.webSearch.enabled` (default false), `anvil.webSearch.provider`
   (`http` | `mcp`), `anvil.webSearch.baseUrl`, `anvil.webSearch.maxResults` (0–10, 0 meaning the
   provider default). The pure `webSearchParams` in `src/webSearch.ts` turns them into the session
   field and returns nothing when off, so the request is exactly what it was before the settings
   existed. An unrecognised provider falls back to `http`; `base_url` is sent only for `http`,
   since the mcp provider would otherwise carry a field nothing reads.
2. **The key.** Commands `anvil.setWebSearchKey` and `anvil.clearWebSearchKey`, with their own
   SecretStorage key (`anvil.webSearchKey`). `childEnv` now takes both credentials and writes
   `ANVIL_WEB_SEARCH_API_KEY` beside `ANVIL_API_KEY`; an absent key is deleted from the inherited
   environment as well, so "cleared" cannot silently mean "the shell still had one".
3. **The host.** `buildOptions` maps the request field through `webSearchFrom`: presence is the
   switch, `APIKeyEnv` is the constant `ANVIL_WEB_SEARCH_API_KEY`, and `AllowFetchURL` is on
   because the phase is search *and* fetch. An http provider with no endpoint and an unknown
   provider are both invalid params naming the field, rather than an SDK error at `session.new`.
   `AllowPrivateURLs` stays false.
4. **The panel.** When enabled, one compact row says the tools are on and whether a key is stored —
   present or absent, never the value; the `mcp` provider is drawn as "no built-in web tools".
   When disabled nothing is posted. The row follows the restore, like the MCP card. The `web`
   permission group gates the calls.
5. Tests and docs.

## Acceptance

- [x] Enabled with a provider and key: the host options carry `WebSearch.Enabled` and the env var
  name; the tool list a session can call includes the web tools.
  (`TestBuildOptionsCarriesTheWebSearchConfiguration`, `TestSessionWithWebSearchAdvertisesTheWebTools`.)
- [x] Disabled: no `WebSearch` option is set and the tools are absent.
  (`TestBuildOptionsLeavesWebSearchOffUnlessAsked`, `TestSessionWithoutWebSearchAdvertisesNoWebTools`,
  `test/unit/webSearch.test.ts`.)
- [x] The key is never present in settings JSON, the log, or a protocol payload — asserted by a
  test that greps what the fake host received. (`TestWebSearchParamsHasNoKeyField`;
  `test/integration/webSearch.test.ts` starts the host with both credentials in its environment
  and finds neither in the record; `test/unit/webSearch.test.ts` pins that no key field exists in
  the params and that the key is written only to the child environment.)
- [x] The panel row appears only when enabled. (`reportWebSearch` returns before posting when the
  setting is off; `test/unit/webSearch.test.ts`.)
- [x] `go test ./...` green; `npm test` green (318 tests).

## Non-goals

- A built-in search backend or a proxy.
- Relaxing `AllowPrivateURLs`, or a per-URL allowlist UI.
- Caching results across runs.
