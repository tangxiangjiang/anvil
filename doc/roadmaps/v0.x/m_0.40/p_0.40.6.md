# p_0.40.6 — MCP: turn the workspace config on

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.md](../m_0.40_editor_alignment.md)
**Linked design:** [40-editor-alignment.md](../../../design/v0.x/40-editor-alignment.md), [09-extensibility.md](../../../design/v0.x/09-extensibility.md), [36-tool-permissions.md](../../../design/v0.x/36-tool-permissions.md)

## Goals

1. **A `.cursor/mcp.json` in the workspace is honoured.** The SDK already parses it; the host must
   pass the setting source that selects it.
2. **Reading the user's home config is opt-in.** Two settings with deliberately different defaults.
3. **The panel lists what will load**, and says nothing about connection state it cannot observe.
4. **MCP calls stay behind the `mcp` permission group.**

## Scope

`editors/vscode/src/settings.ts`, `editors/vscode/package.json`, `source/internal/editorhost/`
(`buildOptions`, a new method), `editors/vscode/src/chatPanel.ts` + `media/chat.js`, tests.

## Tasks

1. **Settings.** `anvil.mcp.project` (boolean, default **true**) and `anvil.mcp.user` (boolean,
   default **false**). Mapped in `settings.ts` to `setting_sources` through the pure
   `settingSourcesFor` in `src/mcp.ts`; both off sends no key at all.
2. **The host.** `buildOptions` sets `LocalOptions.SettingSources` from that field
   (`SettingSourceProject` / `SettingSourceUser`). Empty means today's inline-only behaviour. Both
   `buildOptions` and `mcp.list` validate the enum through one helper, so the session and the card
   always agree about which layers exist.
3. **The listing.** `mcp.list` returns the servers the selected sources declare: name, transport
   kind and source file, parsed with the same parser the SDK uses (`anvil.ListMCPServers`, public
   because the host may import nothing else). The result carries no connected field — the wire has
   no place for a false one. Each layer is also reported with its path and whether the file exists,
   so the panel can tell "off" from "on with nothing there"; a file that will not parse fails the
   call rather than yielding an empty listing.
4. **The panel.** A read-only MCP card listing the servers, shown only when at least one source is
   enabled; a note when the project file is absent. Posted after the document's conversation is
   restored, so it never races the replay.
5. **Security copy.** The design and README state that the project file can start commands, which
   is why it is workspace-scoped and why the extension refuses untrusted workspaces.
6. Tests and docs.

## Acceptance

- [x] With a `.cursor/mcp.json` declaring one server and `anvil.mcp.project` on, a new session's
  host options carry `SettingSourceProject`, and `mcp.list` names the server and its source.
  (`TestBuildOptionsCarriesTheSelectedSettingSources`, `TestMCPListReportsTheProjectFile`,
  `TestListMCPServersReadsTheProjectFile`.)
- [x] With the setting off, no source is passed and `mcp.list` is empty.
  (`TestBuildOptionsCarriesTheSelectedSettingSources`, `TestMCPListReadsNothingWhenNoSourceIsAsked`,
  `test/unit/mcp.test.ts`.)
- [x] `anvil.mcp.user` is off by default and, when on, adds `SettingSourceUser`. (Defaults in
  `package.json` and `settings.ts`, asserted in `test/unit/mcp.test.ts`;
  `TestListMCPServersLetsTheProjectOverrideTheUserFile` covers both layers.)
- [x] A malformed project file produces an error in the listing, not a silently empty one.
  (`TestMCPListFailsOnAMalformedFile`, `test/integration/mcp.test.ts`.)
- [x] The panel shows the card only when enabled. (`reportMcp` returns before asking when both
  layers are off; `test/unit/mcp.test.ts`.)
- [x] `go test ./...` green; `npm test` green (304 tests).

## Non-goals

- OAuth or credential storage for MCP servers.
- Remote transports the SDK does not support.
- A connect/disconnect UI, or per-server enable toggles inside a file.
- Editing `.cursor/mcp.json` from the panel.
