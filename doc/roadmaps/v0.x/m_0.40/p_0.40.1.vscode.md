# p_0.40.1 — Parallel chat tabs

**Status:** done (2026-10-19)
**Milestone:** [m_0.40_editor_alignment.vscode.md](../m_0.40_editor_alignment.vscode.md)
**Linked design:** [40-editor-alignment.vscode.md](../../../design/v0.x/40-editor-alignment.vscode.md), [35-vscode-extension.vscode.md](../../../design/v0.x/35-vscode-extension.vscode.md), [38-session-identity-and-replay.vscode.md](../../../design/v0.x/38-session-identity-and-replay.vscode.md)

## Goals

1. **Two conversations at once.** Each editor tab holds one session; a second tab does not steal
   the first one's events, approvals or change list.
2. **One host process.** Sessions are multiplexed over the existing JSON-RPC connection; no second
   child, no second handshake.
3. **A reload restores the tabs it had.** Each tab remembers its agent id in the webview's own
   state, and the serializer resumes and replays it — the same path a tab that was never closed
   takes.
4. **The sidebar knows what is open.** Clicking a session with a live tab reveals it; clicking one
   without opens a tab; `anvil.openChat` always opens a new one.

## Scope

`editors/vscode/src/` (`hostManager.ts`, `chatPanel.ts`, `extension.ts`, `sessionTree.ts`, new
`hub.ts`), `editors/vscode/media/chat.js`, `editors/vscode/package.json`, and the test harness.

## Tasks

1. **`HostManager` becomes a session factory.** Replace the single `session` field with
   `sessions: Map<sessionId, ChatSession>`. `open(options, listener)` starts a session and
   registers it when the host answers with its id; `close(id)` unregisters it. The notification
   handler routes by `params.session_id`; an unknown id is logged and dropped. Catalogue calls
   (`models.list`, `skills.list`, `rules.list`, `session.list`) keep using the client directly and
   remain independent of any session.
2. **Per-session listener bundles.** A `ChatPanel` passes its own `onEvent` / `onApproval` /
   `onDone` / `onState` when it opens its session, so no state is shared by accident. The
   `resolvedMode` value becomes per-panel rather than per-manager.
3. **`ChatPanel` holds its session.** It calls `hub.manager.open(...)` instead of `ensure()`, owns
   the returned `ChatSession`, and closes it on disposal. `open()` always creates a panel;
   `reveal(agentId)` finds and reveals the panel already showing that agent.
4. **`src/hub.ts`.** One per window: the manager, the model catalogue and the rules cache, plus
   `panels: ChatPanel[]` and `findByAgent(agentId)`. `extension.ts` constructs it and passes it to
   every panel.
5. **Serializer.** `deserializeWebviewPanel(panel, state)` builds a new `ChatPanel` for that panel,
   reads `state.agentId`, and resumes/replays. `media/chat.js` calls `vscode.setState({ agentId })`
   whenever it learns the id (session opened, resumed, or reattached).
6. **Sidebar.** `SessionTreeProvider` marks rows that have a live panel and emits
   `onDidChangeTreeData` when a tab opens or closes. Clicking a row reveals or opens as above; add
   `anvil.openSessionInNewTab` for the explicit case.
7. **Fake host.** `startFakeHost` must serve several sessions concurrently and record which
   session each approval belonged to, so the cross-talk test is meaningful.
8. Tests and docs.

## Acceptance

- [x] Two tabs are open at once and each shows only its own session's events, including streaming
  text from both at the same time.
- [x] An approval raised in tab A appears only in tab A; answering it in tab A does not settle
  anything in tab B. (`tabs.test.ts`, over the fake host with two sessions and interleaved
  approvals.)
- [x] `session.close` is sent for a tab that is disposed, and not for the other tab's session.
- [x] A window reload restores both tabs; each resumes its own agent and replays its own
  transcript.
- [x] `anvil.openChat` creates a tab; clicking a sidebar row with a live tab reveals it instead of
  creating a second one; `anvil.openSessionInNewTab` always creates.
- [x] `npm test` green (239 tests).

## Non-goals

- Splitting one tab into panes, dragging tabs into groups, or a custom tab renderer.
- A second host process, or a pool of hosts.
- Sharing a session between two tabs. Two tabs are two agents; a viewer that wants the same
  conversation twice opens it twice and resumes it twice.
- Changing the store, the protocol or the host.
