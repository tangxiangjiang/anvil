# p_0.61.2 — Pull-request lifecycle and VS Code surface

**Status:** planned
**Milestone:** [m_0.61_remote_git_pr_ci.vscode.md](../m_0.61_remote_git_pr_ci.vscode.md)
**Linked design:** [61-remote-git-pr-ci.vscode.md](../../../design/v0.x/61-remote-git-pr-ci.vscode.md)

## Goals

Create and update pull requests through explicit, reviewable, idempotent actions.

## Scope

PR records, generated/editable title/body, create/update/comment/close confirmations, stale provider
revision, read-first Workflow projection, browser links, auth/rate-limit errors, and tests.

## Tasks

1. Add PR list/get/create/update/comment/close provider contracts.
2. Bind writes to repository, refs, head commit, review digest, and provider revision.
3. Preview editable content before one confirmed provider request.
4. Add Workflow PR group and read-only restore/reconnect.
5. Handle pushed-but-unlinked and unknown outcomes by read-after-write lookup.

## Acceptance

- Opening or refreshing PR state performs no remote write.
- Canceling confirmation sends zero writes; confirmation is exactly once/idempotent.
- Remote head/provider revision drift blocks mutation.
- Content and error rendering leak no credentials or unsafe provider payload.

## Non-goals

- Automatic approval/merge, CI repair, or bypassing repository policy.
