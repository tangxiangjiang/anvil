# p_0.61.2 — Structured plan and execution policy

**Status:** planned

## Goals

Produce a validated, reviewable implementation plan and policy without executing it.

## Scope

- Define work dependencies, acceptance/evidence, budgets, ownership, completion, and rollback.
- Declare repository/base, Worktree, integration, delivery, and release targets.
- Declare model/tool/permission, sandbox/network/secret/browser/desktop capability requirements.
- Add impact diffs for dependency, acceptance, policy, budget, and release-target changes.
- Add revision-bound submit/approve/reject and capability/readiness validation.

## Tasks

1. Extend structured plans with evidence, budget, capability, delivery, and rollback policy.
2. Implement readiness/capability validation and revision-bound decisions.
3. Generate and test complete structured impact diffs.

## Acceptance

- Missing acceptance, cycles, stale revisions, or unavailable required capabilities block approval.
- Policy cannot silently select weaker isolation or broader permissions.
- Every invalidated approval appears in the impact diff.
- Approval starts no Worker, test, provider, or release mutation.

## Non-goals

- Worktree/sandbox execution or external writes.
