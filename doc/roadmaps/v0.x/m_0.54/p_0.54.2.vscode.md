# p_0.54.2 — Task persistence semantics

**Status:** done
**Milestone:** [m_0.54_durable_agent_runs.vscode.md](../m_0.54_durable_agent_runs.vscode.md)
**Linked design:** [54-durable-agent-runs.vscode.md](../../../design/v0.x/54-durable-agent-runs.vscode.md)

## Goals

Define the task persistence boundary precisely: task handles, process control, output rings, and
cancellation functions remain in memory; durable run state records the consequence when their
host owner is lost.

## Scope

Host/task ownership, run leases, restart classification, live-host cancellation, lost-handle
behavior, interruption reasons, and the separation between task truth and durable run truth.

## Tasks

1. Specify which run facts persist and which task/process fields must never be persisted.
2. Record host incarnation and lease evidence on runs; never treat a PID as proof of control.
3. On host restart, expose no former task handle and reconcile unfinished owned runs to
   `interrupted` after the defined lease/ownership check.
4. Preserve normal cancellation only while the original host still owns the process handle.
5. Apply the exact one-patch VS Code version bump only if this implementation batch is
   user-visible, using the then-current package version.

## Acceptance

- `cd source && go test -count=1 ./... -run 'Test(TaskPersistenceBoundary|RunLease|LostHost|ProcessHandle)'`.
- Restart fixtures prove `tasks.list` is empty for the new host, no task is recreated, and an
  unfinished run owned by the lost host becomes `interrupted` with the documented reason.
- While the original host remains live, cancellation still terminates the process tree; after
  handle loss, Cancel is unavailable and no signal is sent to a discovered or guessed PID.
- Store fixtures prove process handles, cancellation functions, environment snapshots, and raw
  task output rings are absent from durable records.

## Non-goals

- Persisting or respawning tasks, adopting arbitrary OS processes, or claiming control after
  supervisor loss.
- Editor rehydration.
- Cross-machine task migration.
