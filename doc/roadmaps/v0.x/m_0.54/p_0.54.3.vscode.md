# p_0.54.3 — VS Code rehydrate and reconcile

**Status:** planned
**Milestone:** [m_0.54_durable_agent_runs.vscode.md](../m_0.54_durable_agent_runs.vscode.md)
**Linked design:** [54-durable-agent-runs.vscode.md](../../../design/v0.x/54-durable-agent-runs.vscode.md)

## Goals

Restore run UI from the journal, then reconcile once with the authoritative live host without
duplicate cards, stale running state, or invented task/process ownership.

## Scope

Host snapshot/reconcile protocol, replay watermark, extension activation and reconnect,
run projections, live task controls only when the same host retains their handles,
stale-state replacement, and user-visible interrupted states.

## Tasks

1. Define snapshot plus journal-watermark wire fields and mismatch errors.
2. Rehydrate local projections before or during reconnect without enabling mutating controls early.
3. Reconcile durable runs by host lease; expose task controls only from the live task table.
4. Deduplicate replayed/live events and cover repeated activation.
5. Before packaging this user-visible batch, bump the current extension patch exactly once and
   synchronize package lock, host version, and shipped-version documentation references.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestHost(Rehydrate|Reconcile|Watermark)'`.
- `cd editors/vscode && npm test -- --runInBand` includes activation/reload fixtures proving one
  card per event, stable ordering, no enabled cancel button before reconciliation, and identical
  state after a second reload.
- A restarted-host fixture renders an unfinished run `interrupted`, imports no task, and offers
  no Cancel; an extension-only reconnect to the same live host may recover its live controls.
- `cd editors/vscode && npm run package` and the packaged smoke test pass after the policy-driven
  patch bump; no version is derived from roadmap number 0.54.

## Non-goals

- Recovering control of an unowned OS process.
- Search UI, plan UI, or worktree workers.
- Replacing the journal with editor workspace state.
