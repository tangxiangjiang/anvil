# p_0.54.1 — Event sequence and journal

**Status:** planned
**Milestone:** [m_0.54_durable_agent_runs.vscode.md](../m_0.54_durable_agent_runs.vscode.md)
**Linked design:** [54-durable-agent-runs.vscode.md](../../../design/v0.x/54-durable-agent-runs.vscode.md)

## Goals

Define the authoritative ordered journal from which a run can be reconstructed after restart.

## Scope

Sequence allocation, journal records and schema version, append/flush boundaries, replay,
tail-corruption handling, compaction boundaries, and equivalent JSONL/SQLite behavior.

## Tasks

1. Specify sequence uniqueness, monotonicity, run ownership, and durable-ack semantics.
2. Add versioned journal encode/decode and explicit unknown-version errors.
3. Define replay and safe truncated-tail recovery without accepting interior corruption.
4. Build a shared conformance corpus for JSONL and SQLite.
5. For any user-visible implementation batch, read `editors/vscode/package.json`, bump its patch
   exactly once, and synchronize every required shipped-version declaration before packaging.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestJournal(Sequence|Replay|Tail|Conformance)'`
  proves sequences remain strictly increasing across restart, duplicate append is detected,
  a partial final record is handled as specified, interior corruption fails, and both stores
  replay identical records.
- A crash-boundary test proves no event acknowledged durable disappears after reopen.
- Unknown journal schema versions fail before replay mutates reconstructed state.
- Version-policy tests, when this phase has a user-visible delivery, compare against the
  pre-change package version and require exactly `patch + 1`; they do not derive a version from
  `0.54.1`.

## Non-goals

- Task restart semantics or VS Code rendering.
- Exactly-once external side effects.
- Recovering control of an OS process.

## Depends-on

- Session store and run identity contracts.
- Milestone 0.53 host lifecycle.
