# p_0.66.2 — Remote source, execution, and result transport

**Status:** planned
**Milestone:** [m_0.66_remote_workers.vscode.md](../m_0.66_remote_workers.vscode.md)
**Linked design:** [66-remote-workers.vscode.md](../../../design/v0.x/66-remote-workers.vscode.md)

## Goals

Execute immutable approved source in a remote sandbox and return verifiable result evidence.

## Scope

Commit/patch source bundle, scoped fetch credentials, remote checkout/Worktree, 0.63 sandbox,
durable events, logs/artifacts, result manifest/signature, upload, cancellation, unknown state.

## Tasks

1. Define immutable source and signed result manifests with content digests.
2. Materialize source without arbitrary filesystem synchronization.
3. Run the bound model/profile/policy in a remote sandbox.
4. Stream sequenced events and upload bounded encrypted logs/artifacts/results.
5. Reconcile cancellation, node loss, duplicate result, and interrupted upload.

## Acceptance

- Source/result/environment/policy identity verifies at both ends.
- Remote Worktree/sandbox cannot access control-plane or unrelated workload secrets.
- Duplicate/reassigned attempts cannot both become accepted.
- Local primary checkout remains unchanged until normal review/integration.

## Non-goals

- VS Code controls, shared mutable filesystems, or direct remote integration.

## Depends-on

- p_0.66.1, 0.60, 0.61, and 0.63.
