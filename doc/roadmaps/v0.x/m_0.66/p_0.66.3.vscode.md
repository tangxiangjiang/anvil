# p_0.66.3 — VS Code remote operations and release gates

**Status:** planned
**Milestone:** [m_0.66_remote_workers.vscode.md](../m_0.66_remote_workers.vscode.md)
**Linked design:** [66-remote-workers.vscode.md](../../../design/v0.x/66-remote-workers.vscode.md)

## Goals

Expose remote execution, queueing, evidence, cancellation, retry, and recovery without weakening
local review gates.

## Scope

Local/remote selector, pool capability/budget preflight, queue/run stream, reconnect, logs/artifacts,
cancel, new-attempt retry, unknown/interrupted state, review handoff, fault/soak/package gates.

## Tasks

1. Add explicit remote execution selection with pool/policy/budget explanation.
2. Render durable queue/assignment/run/upload/review states and evidence.
3. Make cancellation acknowledged and retry a new attempt.
4. Surface node/lease/unknown/revoked states with operator recovery links.
5. Run disconnect, split-brain, outage, scale, security, and packaged smoke campaigns.

## Acceptance

- Viewing/reconnecting starts no duplicate execution.
- Cancel and retry bind the exact displayed execution revision.
- Unknown or lost-node state cannot be accepted as success.
- Returned changes enter 0.64 review/PR delivery and 0.65 release workflows.
- 0.65 release/security gates pass for the supported control plane and Worker matrix.

## Non-goals

- Direct SSH UI, automatic remote retry, or bypassing local review/publication.

## Depends-on

- p_0.66.1, p_0.66.2, and 0.65.
