# p_0.66.1 — Control-plane identity, pools, and scheduling

**Status:** planned
**Milestone:** [m_0.66_remote_workers.vscode.md](../m_0.66_remote_workers.vscode.md)
**Linked design:** [66-remote-workers.vscode.md](../../../design/v0.x/66-remote-workers.vscode.md)

## Goals

Establish authenticated remote Worker identity, enrollment, capability pools, leases, policy, and
durable scheduling.

## Scope

Mutual authentication, node enrollment/revocation, capability inventory, pools, placement,
quotas, queue/assignment leases, idempotency, split-brain prevention, and operator records.

## Tasks

1. Define remote Worker/execution/pool records and signed protocol.
2. Add enrollment, key rotation, revocation, and lease expiry.
3. Match platform/runtime/toolchain/network/data policy without model-selected nodes.
4. Enforce queue/runtime/resource/artifact/model/retry quotas.
5. Test replay, stale lease, duplicate assignment, revocation, and scheduler restart.

## Acceptance

- Unauthenticated/revoked/stale/mismatched nodes cannot receive or publish work.
- One execution attempt has at most one accepted assignment/result authority.
- Scheduling decisions and quota refusals are durable and auditable.

## Non-goals

- Source transfer, remote sandbox execution, or VS Code UX.

## Depends-on

- 0.63 and 0.65 foundations.
