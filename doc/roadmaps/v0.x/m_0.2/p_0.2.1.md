# Phase p_0.2.1 — JSONL store and Resume

**Status:** done

## Goals

Implement local JSONL persistence and `anvil.Resume`.

## Scope

- `{cwd}/.anvil/agents/<agentID>.jsonl` layout per design 06
- Append-only writes; reload history on Resume
- Re-apply LocalOptions / model from caller on Resume (MCP/custom tools not restored from disk)

## Finalized JSONL schema

Each line is one JSON object with `"type"` and `"ts"` (RFC3339 UTC).

| type | Fields |
|------|--------|
| `meta` | `agent_id`, `cwd`, `provider`, `model`, `max_steps`, `allow_shell` (no API key) |
| `message` | `role`, `content`, `tool_call_id`, `name`, `tool_calls[]` (`id`,`name`,`args`), optional `run_id` |
| `run_start` | `run_id` |
| `run_end` | `run_id`, `status`, `steps`, `usage` |

Crash-safe read: stop at first invalid / truncated line; keep prior valid records.

## Non-goals

- Cancel / MaxWallTime (later 0.2 phase)
- Encryption at rest
- MCP

## Notes from oneshot self-test (keep)

An early experiment asked `oneshot` to implement this phase itself. Useful outcomes:

1. **Large coding tasks burn MaxSteps** — default 32 is fine for small edits, not for multi-file features; oneshot exited with `max steps exceeded`.
2. **Half-finished work is common** — the agent left a usable `store` + `Resume` draft but skipped tests, phase status, and left a run-id inconsistency between loop and agent.
3. **Rules help humans more than the local agent** — `.cursor/rules` (phase-first) are for the IDE agent workflow; oneshot does not read those rules unless they are in its system prompt / cwd docs it chooses to open.
4. **Drafts can still accelerate** — cleaning the oneshot diff was faster than greenfield, once reviewed.
5. **Do not treat oneshot output as phase-done** — status/`Acceptance` updates and tests remain human (or Cursor-session) gates.
