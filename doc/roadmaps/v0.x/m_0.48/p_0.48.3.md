# p_0.48.3 — Stop reasons, output limits, error kinds

**Status:** done
**Milestone:** [m_0.48_llm_calls.md](../m_0.48_llm_calls.md)
**Linked design:** [48-llm-effort-and-retry.md](../../../design/v0.x/48-llm-effort-and-retry.md) §5

## Goals

Let the SDK say why a completion ended and why a request failed. `Response.StopReason` from
both wires; a `truncated` event and `Result.Truncated` when the provider cut the answer;
`Request.MaxOutputTokens` on both wires; and `HTTPError.Kind` mapped to codes — `provider`,
`provider_busy`, `request_rejected`, `auth` — so a container can tell "the model is busy" from
"this model does not accept that parameter" without parsing a message.

## Scope

`source/internal/llm/types.go` (`StopReason`, `Request.MaxOutputTokens`, `HTTPError.Kind`),
`errors.go` (`Kind` classification), the four adapter files (read `finish_reason` /
`stop_reason`; send `max_completion_tokens` / `max_tokens`), `source/internal/runtime/loop.go`
(the `truncated` event, `Result.Truncated`, code mapping), `codes.go`, `source/options.go`
(`Options.MaxOutputTokens`), `source/types.go`, tests beside each.

## Tasks

1. **`StopReason`.** `end | tool | length | other`, projected from `finish_reason` and
   `stop_reason` on plain and streaming paths; absent maps to `other`.
2. **`truncated`.** When the last assistant message's reason is `length`, the loop emits
   `Event{Type: "truncated"}` and `Result.Truncated = true`. The run still finishes; nothing
   is re-requested.
3. **`MaxOutputTokens`.** `Options.MaxOutputTokens` → `Request.MaxOutputTokens`. OpenAI sends
   `max_completion_tokens` when non-zero; Anthropic sends the larger of it and the effort
   floor from p_0.48.1 (8192 when no effort). Zero keeps today's bodies, pinned by the
   p_0.48.1 golden.
4. **`Kind`.** `KindTransport | KindRateLimited | KindServer | KindRejected | KindAuth` set
   in `mapHTTPStatus` and the nine explicit `HTTPError{}` sites; `Retryable` becomes derived
   from `Kind` (one function) so the two cannot disagree.
5. **Codes.** `CodeProviderBusy`, `CodeRequestRejected`, `CodeAuth` added; the loop maps
   `Kind` to code after retries are exhausted. The provider's message text is kept verbatim.
6. **Eval.** One tier-1 task scripts a `length` stop and gates `Completed` with
   `Truncated == true` recorded; one scripts a 400 naming `reasoning_effort` and gates the
   code `request_rejected`.
7. **Re-baseline.** `./scripts/eval.sh --update` once, since `Score` gained nothing but the
   two tasks are new; commit the file.
8. **Verify.** Go suite from Git Bash; the script.

### Gate

- 命令：`cd source && go test -count=1 ./internal/llm/... -run 'TestStopReason|TestMaxOutputTokens|TestErrorKind' && go test -count=1 ./internal/runtime/... -run 'TestTruncated|TestProviderCodes' && ./scripts/eval.sh`
- 通过条件：两个 adapter、plain 与 stream 四条路径各自将 `stop`/`end_turn`、`tool_calls`/`tool_use`、`length`/`max_tokens` 映射到 `end`/`tool`/`length`，缺省映射到 `other`；`MaxOutputTokens: 0` 时请求体等于 p_0.48.1 golden，非零时 OpenAI 带 `max_completion_tokens`、Anthropic 的 `max_tokens` 为 `max(MaxOutputTokens, effort floor)`；`TestErrorKind` 枚举 0/401/403/429/500/400 六种状态各得正确 `Kind`，且 `Retryable` 与 `Kind` 一致；`TestTruncated` 证明 `length` 产生一个 `truncated` 事件、`Result.Truncated == true`、且只发出一次模型请求；eval 不劣化。
- 失败条件：任一映射错误；`Retryable` 与 `Kind` 不一致（两者可独立设置即算失败）；`length` 之后出现第二次模型请求（自动续写）；eval 任一受控字段劣化。
- 基线条目：更新后的 `baseline.json`（新增两个任务）；p_0.48.1 的 golden 保持不变。

## Non-goals

- Automatic continuation.
- A context-overflow handler; `request_rejected` is the signal chapter 42's compaction can
  act on later.
- Host or editor display of `truncated`.

## Delivery evidence — 2026-10-27

- `StopReason` (`end | tool | length | other`) is read on all four paths: OpenAI `finish_reason`
  (the streaming path keeps the last non-empty one) and Anthropic `stop_reason` (top level, or
  `message_delta` when streaming). An absent value is `other`, never `end`.
- `Result.Truncated` and a `truncated` event are produced when the final answer's reason is
  `length`; exactly one model request is made. A `length` stop on a round that went on to call a
  tool does not mark the run.
- `Options.MaxOutputTokens` reaches both wires (`max_completion_tokens`; `max_tokens`). Zero is
  byte-identical to the p_0.48.1 goldens. With thinking on, Anthropic is never sent less than the
  effort's default, because the provider refuses a limit under the thinking budget; without
  thinking the ceiling is sent as given.
- `HTTPError.Kind` is set once by `NewHTTPError`, which also derives `Retryable`, so the two
  cannot disagree. Every adapter error is built through it (the nine literal sites are gone).
  `KindCode` maps a kind to `provider`, `provider_busy`, `request_rejected` or `auth`; the
  provider's text stays verbatim in `Err`.
- Eval: `length_stop_truncated` (one request, `Truncated`) and `effort_rejected` (a 400 naming
  `reasoning_effort` becomes `request_rejected`, with `Retries == 0` gated exactly). A task can
  declare the single upstream failure it expects (`ExpectProviderError`); any other upstream
  failure is still a harness error.
- Checked by mutation: a wrong length mapping, an absent reason read as `end`, a 429 that is not
  retryable, a dropped floor, a dropped `max_completion_tokens` on the stream path, and a lost
  Anthropic stream stop reason each turn a test red.
- A 429 that is not retried (`MaxAttempts: 1`) is now `provider_busy`, not `provider`. No host,
  worker or CLI branches on the old code.
