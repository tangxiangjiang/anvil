# p_0.48.2 — Retry with backoff

**Status:** planned
**Milestone:** [m_0.48_llm_calls.md](../m_0.48_llm_calls.md)
**Linked design:** [48-llm-effort-and-retry.md](../../../design/v0.x/48-llm-effort-and-retry.md) §4

## Goals

Make `HTTPError.Retryable` mean something. A transport failure, a 429 or a 5xx is retried with
exponential backoff and jitter, up to a bound, honouring `Retry-After`; a request that is
wrong is not; a stream the user has already seen is not. Usage is counted once, and each
attempt is an event the container can show.

## Scope

`source/internal/llm/retry.go` (new: `RetryPolicy`, `WithRetry`), `retry_test.go`,
`source/options.go` (`Options.Retry`), `source/agent.go` (wraps the completer once),
`source/internal/runtime/loop.go` (the `retry` event type, `CodeProviderMidStream`),
`source/internal/runtime/codes.go`, `source/types.go` (the public event fields),
`source/eval/score.go` (`Retries`).

## Tasks

1. **`RetryPolicy`** with `MaxAttempts` (0 → 3, 1 → off), `BaseDelay` (0 → 500ms),
   `MaxDelay` (0 → 8s). `Options.Retry`; the zero value is on.
2. **`WithRetry`** returns a `Completer` that is also a `StreamCompleter` when the inner one
   is. Decision table from §4.3: retry on `Status: 0`, 429, 5xx; not on other 4xx; not after
   the first delta reached `onDelta`; not when `ctx.Err() != nil`.
3. **Backoff.** Exponential from `BaseDelay`, full jitter, capped at `MaxDelay`;
   `Retry-After` (seconds or HTTP-date) replaces the computed delay when present and parseable,
   still capped. The sleep is `ctx`-aware.
4. **Usage once.** Only the successful attempt's `Response` is returned; a failed attempt's
   usage block is dropped. A test with a 5xx body that carries usage proves the count.
5. **The event.** `Event{Type: "retry", Attempt, Delay, Text}` emitted through the emitter
   the runtime threads in the context; the final failure's message names the attempt count.
   A mid-stream failure ends the run with `CodeProviderMidStream`.
6. **Wire it.** `agent.go` wraps the completer with `WithRetry(c, opts.Retry)` once, at
   construction; children inherit through `Options.completer` and are not wrapped twice (a
   test asserts a 429 under a subagent is retried three times, not nine).
7. **Eval.** `Score.Retries` is filled from `retry` events; one tier-1 task scripts a 429
   then a 200 and gates `Retries == 1` and `Completed`.
8. **Verify.** Go suite from Git Bash; the script.

### Gate

- 命令：`cd source && go test -count=1 ./internal/llm/... -run 'TestRetry' && go test -count=1 ./ -run 'TestSubagentRetryOnce' && ./scripts/eval.sh`
- 通过条件：`TestRetry429ThenOK`：两次请求、一个 `Response`、`Usage.InputTokens` 等于成功那次的值、一个 `retry` 事件；`TestRetry400NoRetry`：一次请求；`TestRetryMidStreamNoRetry`：首个 delta 送出后的失败不重发，结果码为 `provider_mid_stream`；`TestRetryCtxCancel`：取消后 10ms 内返回；`TestRetryAfterHeader`：延迟等于头部值（受 `MaxDelay` 上限）；`TestSubagentRetryOnce`：子 agent 下的 429 重试 3 次而非 9 次；eval 新任务 `Retries == 1`。
- 失败条件：以上任一断言不成立；或 `Usage` 被累加（证明失败尝试的 usage 泄漏）；或 eval 任一受控字段劣化。
- 基线条目：eval 对比表；新任务的 `Retries` 记录为 1 写入基线。

## Acceptance

- [ ] `RetryPolicy` defaults as documented; `MaxAttempts: 1` restores today's behaviour.
- [ ] The decision table holds for every row, by test.
- [ ] `Retry-After` is honoured and capped.
- [ ] Usage is counted once.
- [ ] `retry` events reach the stream; the final error names the attempts.
- [ ] A subagent's completer is wrapped once.
- [ ] `./scripts/eval.sh` not worse than baseline; `invariants` 100%.
- [ ] `cd source && go build ./... && go vet ./... && go test -count=1 ./...` is green (run
      from Git Bash).

## Non-goals

- Retrying tool calls, subagents, workflow steps.
- A circuit breaker or a per-provider rate limiter.
- Surfacing the retry in any UI; the event is the interface.
