# p_0.48.1 — Effort on both wires, and the reasoning test split

**Status:** in_progress
**Milestone:** [m_0.48_llm_calls.md](../m_0.48_llm_calls.md)
**Linked design:** [48-llm-effort-and-retry.md](../../../design/v0.x/48-llm-effort-and-retry.md) §2, §3

## Goals

Add `Options.Effort` as an SDK interface — three named levels and an empty default — carry it
to both adapters, and send it as each provider spells it. Keep today's request exactly when
nothing is configured. Split the reasoning test so that the leak guard gets stricter and the
effort field gets its own assertion, and settle whether Anthropic tool use with thinking
enabled needs a run-scoped provider block.

## Scope

`source/options.go` (`Effort`, `Options.Effort`), `source/agent.go` (threading),
`source/internal/runtime/loop.go` (`Config.Effort` → `Request.Effort`),
`source/internal/llm/types.go` (`Request.Effort`, possibly `Message.ProviderState`),
`openai.go`, `openai_stream.go`, `anthropic.go`, `anthropic_stream.go`,
`reasoning_test.go` (split), new `effort_test.go`, golden files under
`internal/llm/testdata/`, `subagent.go` (a child inherits the parent's effort).

## Tasks

1. **The type.** `type Effort string` with `EffortDefault`, `EffortLow`, `EffortMedium`,
   `EffortHigh`; `Options.Effort`; validation at `Create` refuses any other string.
2. **Thread it.** `Options.Effort` → `runtime.Config.Effort` → `llm.Request.Effort`.
   `childOptions` copies the parent's.
3. **OpenAI.** `reasoning_effort` as a top-level field, `omitempty`, both the plain and the
   streaming request struct.
4. **Anthropic.** `thinking: {type: enabled, budget_tokens}` with the §3.3 table; `high`
   raises `max_tokens` to `budget + 8192`. Both request structs.
5. **Golden files.** Record both adapters' request bodies for a three-message history with
   one tool, effort empty, before any change; the test compares against them after.
6. **Split the test.** `TestOpenAIStreamRequestCarriesNoReasoning` becomes
   `TestRequestNeverEchoesReasoning` (both adapters, history with streamed reasoning, no
   reasoning-text key anywhere, with and without effort) and `TestRequestEffortField` (field
   present iff configured, correct value, empty effort equals golden).
7. **Settle §3.4.** Capture one live Anthropic tool-use exchange with thinking enabled using
   the 0.47 live tier. If the provider requires the signed thinking block on the next request,
   add `Message.ProviderState []byte`, encode it only in the Anthropic adapter, never persist
   it, and extend `TestRequestNeverEchoesReasoning` to assert the block is the provider's own
   bytes with a signature and nothing else. If it does not, record that in chapter 48 §3.4 and
   add no field.
8. **Rejection is visible.** A 400 whose body names the effort parameter surfaces as the
   provider's message; a test asserts the adapter does not strip the field and resend.
9. **Eval.** Add an `Expect` to one tier-1 task asserting `reasoning_effort` is absent with
   effort empty; re-run `./scripts/eval.sh`.
10. **Verify.** Go suite from Git Bash; the script.

### Gate

- 命令：`cd source && go test -count=1 ./internal/llm/... -run 'TestRequestNeverEchoesReasoning|TestRequestEffortField|TestEffortGolden' && ./scripts/eval.sh`
- 通过条件：`TestEffortGolden` 证明 effort 为空时两个 adapter 的请求体与 `testdata/*.golden` 逐字节相同；`TestRequestEffortField` 证明三档各自产生正确字段与数值，且 Anthropic `high` 的 `max_tokens` 为 24576；`TestRequestNeverEchoesReasoning` 在历史中含流式 reasoning 的情况下，`messages[]` 任一消息不含 `reasoning` / `reasoning_content` / `thinking` 文本键；eval 对比表不劣化。
- 失败条件：golden 不等（说明空 effort 改变了请求）；任一档位字段缺失或数值错误；任一消息携带 reasoning 文本；adapter 在 400 后剥离字段重发（用计数 server 证明请求数为 1）；eval 任一受控字段劣化。
- 基线条目：两个 golden 文件；`./scripts/eval.sh` 的对比表（0.47 基线）。

## Non-goals

- A per-`Send` effort.
- Any provider-capability table; a wrong configuration is reported, not corrected.
- Host, worker, CLI or editor plumbing for the option.

## Delivery status — 2026-10-27

Done: the `Effort` type and `Options.Effort` (refused at `Create` when unknown), threading to
`llm.Request` and to children, `reasoning_effort` on both OpenAI request structs, `thinking` and
the `max_tokens` rule on both Anthropic ones, four golden bodies recorded **before** any change,
`TestEffortGolden`, `TestRequestEffortField`, `TestRequestNeverEchoesReasoning` (the old test is
gone), the rejection test (one request, the provider's message), and an eval predicate that the
request carries no effort when none is configured. `Request.Effort` is `omitempty`, so a request
recorded before this phase keeps its digest and the genuine provider recordings still replay.

Open: **task 7 (§3.4)** is not done. Whether Anthropic requires the signed thinking block on the
next request of a tool loop needs one real exchange from the live tier, and none was captured.
`Message.ProviderState` is therefore **not** added. This phase stays `in_progress`: with effort
enabled on Anthropic and a tool call, the next request may be refused by the provider until this
is settled. Nothing sets effort by default, so no current request is affected.
