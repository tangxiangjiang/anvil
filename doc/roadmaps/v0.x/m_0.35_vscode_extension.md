# Milestone 0.35 — VS Code extension + editor host

**Status:** done  
**Product version:** 0.35.x

## Goals

- New **`anvil-host`** sidecar binary: stdio, newline-delimited JSON-RPC 2.0, in-process `anvil` SDK — **standalone**, no tool-chain coupling.
- **Editor host protocol**: sessions, prompt, events (built from the public `anvil.Event` / `anvil.RunResult` types), cancel, models, and a bidirectional **approval** round trip on `Options.Permission`.
- Close the SDK approval gap: group-based gating so `run_tests` / `build` / egress / MCP / plugin / custom tools can be approved (today only four builtins are).
- First-party **VS Code extension** at `editors/vscode/`: chat panel, streaming, tool cards, approval prompt, diff review, context injection, sessions, plan mode.
- Platform packaging: VSIX with bundled host binaries.

## Overall acceptance

1. A trusted workspace with the extension installed streams assistant output and tool cards from a real model.
2. Every gated tool class prompts — edit, shell, `run_tests`, egress, MCP — and deny surfaces as a tool error the model can react to.
3. Diff review shows the post-edit result before it is applied.
4. Session history lists past agents and resumes one.
5. Plan mode performs no writes.
6. Untrusted workspace refuses to start; the API key is only in SecretStorage and the child env.
7. `go test ./...` green in `source/`; extension tests green; one end-to-end test against a stub host.

**As delivered:** the phases above are complete, and the deliverable is a per-platform VSIX (`anvil-vscode-0.35.9-<target>.vsix`) that carries a cross-compiled `anvil-host` verified against the digest recorded when it was built — so nothing in this milestone needs a Go toolchain on the machine that installs it. The checks that run without a window (160 extension tests, the real-sidecar integration tests, `go test ./...`, and `npm run smoke:vsix` against a built package) are green; the checks that need a window — a real model turn, each of the four non-host platforms, and the layout itself — are listed as the manual pass in [p_0.35.7](m_0.35/p_0.35.7.md), [p_0.35.8](m_0.35/p_0.35.8.md) and [p_0.35.9](m_0.35/p_0.35.9.md). Those manual passes changed the product three times: the first install of the 0.35.7 package turned up a transcript that shrank its items instead of scrolling (fixed, and now guarded by a stylesheet test), [p_0.35.8](m_0.35/p_0.35.8.md) moved the three surfaces apart — the conversation into an editor tab, the activity bar onto session management, and the composer into a card floating over the transcript — and [p_0.35.9](m_0.35/p_0.35.9.md) closed the last gap between the transcript and the kind of UI it was modelled on: the model's reasoning now reaches the wire and is shown in a collapsed Thinking block, assistant prose is typeset as Markdown by a hand-written parser that builds no HTML, and a tool card labels what went in and what came out.

## Non-goals

- Replacing or bundling VS Code Server ([32](../../design/v0.x/32-sandbox-code-review.md)) — a tool-chain line.
- Becoming a language server or DAP debugger; LSP stays agent tools ([16](../../design/v0.x/16-lsp.md)).
- Any scheduler / `agentd` / cluster execution path from the extension — deliberately absent, not deferred.
- Notebook editing, multi-root panels, checkpoints/rewind, marketplace publication.

## Depends-on

- **Public SDK only**: `anvil.Event` / `anvil.RunResult`, `Options.Permission`, `BuiltinTools` / `DisallowedTools`, `LocalOptions` (rules, setting sources, store), vision attachments, skills.
- **No tool-chain milestone is a dependency.** Scheduler, `agentd`, clusters, anvil-web, and the delivery pipeline are unrelated to this milestone and must not be imported from `anvil-host`.
