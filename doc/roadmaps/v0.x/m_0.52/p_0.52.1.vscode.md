# p_0.52.1 — Mode protocol and host bridge

**Status:** planned

## Goals

Carry Single, Multi, and Complex mode values and mode-specific events through the editor-host
protocol without changing SDK orchestration semantics.

## Scope

- Add explicit mode fields to session create/resume messages with Single as the absent default.
- Validate mode values at the protocol boundary and pass them into SDK options.
- Project delegate briefs, Complex stages, dependencies, and acceptance reports onto stable wire
  events suitable for live use and replay.
- Preserve compatibility for clients that do not send or understand the new fields.

## Tasks

- [ ] Define protocol messages and compatibility rules for modes and stage metadata.
- [ ] Bridge session creation/resume and SDK events in the host.
- [ ] Persist the event data required for deterministic replay.
- [ ] Add codec, host integration, compatibility, and replay tests.

## Acceptance

- [ ] Protocol round-trip tests cover absent/Single, Multi, Complex, and unknown mode values.
- [ ] Host tests assert the selected mode reaches SDK creation/resume and cannot mutate an active
  run.
- [ ] Live/replay fixtures preserve stage identity, parent/dependency relations, brief fields,
  and per-item acceptance states.
- [ ] A legacy session fixture with no mode field decodes as Single and retains its prior event
  representation.
- [ ] Run `cd source && go test ./...`.

## Non-goals

- Implementing or modifying SDK mode orchestration.
- Mode selection UI or extension-side persistence.
- Reconstructing structured events by parsing model prose.
