# p_0.52.2 — VS Code mode selection and persistence

**Status:** planned

## Goals

Let a user choose Single, Multi, or Complex for a conversation and restore that choice
consistently without changing the mode of an in-flight run.

## Scope

- Add a mode selector to the composer using the p_0.52.1 protocol values.
- Persist mode per conversation and restore it after reload or window restart.
- Snapshot the selected mode when creating/resuming the session used by the next turn.
- Explain mode cost/behavior briefly and disable or defer changes that cannot safely affect an
  active run.
- Migrate conversations with no stored mode to Single.

## Tasks

- [ ] Implement the accessible mode selector and mode descriptions.
- [ ] Add per-conversation persistence, restore, and legacy migration.
- [ ] Connect turn/session lifecycle behavior to the host bridge.
- [ ] Add state, reload, queue/lifecycle, and accessibility tests.

## Acceptance

- [ ] Extension tests select each mode, reload the webview/window state, and observe the same
  mode only in the originating conversation.
- [ ] A legacy conversation fixture with no mode opens as Single without rewriting history.
- [ ] Lifecycle tests prove changing the selector during a run does not mutate that run and the
  next eligible session/turn receives the selected mode.
- [ ] Keyboard and screen-reader tests can identify the current mode and each option's concise
  description.
- [ ] Run `cd editors/vscode && npm test`; before this user-visible batch ships, increment the
  current `editors/vscode/package.json` patch exactly once, then package and run the packaged
  VSIX smoke test.

## Non-goals

- Automatic mode selection based on prompt complexity.
- Persisting mode inside transcript message content.
- Assigning the future patch number in this planned document.
