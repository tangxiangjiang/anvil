# p_0.52.3 — Complex stages, briefs, and acceptance UX

**Status:** done

## Goals

Present Complex execution as a comprehensible hierarchy of stages and worker briefs, with
acceptance outcomes visible in both live runs and replay.

## Scope

- Render Decision, Analyze, and Worker stages with status and parent/dependency relationships.
- Show each structured worker brief's goal, files, ordered plan, and acceptance list.
- Render acceptance states as met, not met, or unreported without treating model claims as host
  verification.
- Provide compact and expanded views that remain readable under worker fan-out.
- Use the same structured wire data for live updates and restored transcripts.

## Tasks

- [x] Add stage and fan-out view models keyed by stable protocol identities.
- [x] Build brief and acceptance renderers with accessible status labels.
- [x] Handle partial, failed, cancelled, and out-of-order stage events.
- [x] Add live/replay equivalence, fan-out, accessibility, and visual regression fixtures.

## Acceptance

- [x] A fixture containing Decision → Analyze → three dependent Workers renders the correct
  hierarchy and dependency order during live updates and after reload.
- [x] Brief fixtures display goal, files, plan, and every acceptance item without parsing prose.
- [x] Acceptance fixtures distinguish met, not met, and unreported and label them as worker
  reports rather than independently verified facts.
- [x] Failed/cancelled/partial fixtures preserve completed stage details and expose the terminal
  reason.
- [x] Run `cd editors/vscode && npm test`; before this user-visible batch ships, increment the
  current `editors/vscode/package.json` patch exactly once, then package and run the packaged
  VSIX smoke test.

## Non-goals

- Editing or re-running a brief from the transcript.
- Adding a reviewer stage or changing workflow scheduling.
- Assigning the future patch number in this planned document.
