# Milestone 0.53 — Model capabilities

**Status:** done
**Product version:** 0.52.25. The Agent SDK, built-in Host, and VS Code extension share this
release version.

## Goals

1. Describe model capabilities explicitly and derive provider request behavior from that profile.
2. Carry retry and truncation state across the editor-host wire without collapsing either into
   generic progress or failure.
3. Give users a model-aware output ceiling and a safe, explicit continuation action.

## Ordering

p_0.53.1 makes model support and output constraints authoritative. p_0.53.2 exposes runtime
outcomes to the host and extension. p_0.53.3 consumes both: its limits come from the capability
profile, and Continue generating appears only for a terminal truncation event.

## Overall acceptance

1. Capability-profile tests cover absent, supported, unsupported, adaptive-thinking, and
   bounded-output models, including deterministic fallback behavior.
2. Provider request fixtures prove adaptive thinking is emitted only for profiles that support
   it and legacy request bodies remain unchanged otherwise.
3. Protocol tests round-trip retry attempt/delay and terminal truncation distinctly through
   live and replay paths.
4. Extension tests prove output limits are validated against the selected model and Continue
   generating is offered only after truncation, creates an explicit new turn, and cannot replay
   a prior tool call automatically.
5. Run `cd source && go test ./...` and `cd editors/vscode && npm test`; before each actual
   user-visible delivery batch, bump the current plugin patch once, then package and run the
   packaged VSIX smoke test.

## Non-goals

- Inferring capabilities from model-name substrings at request time.
- Exposing or persisting private chain-of-thought content.
- Automatically continuing truncated output or retrying after visible stream output.
- Assigning a VS Code plugin patch while this milestone remains documentation-only.
