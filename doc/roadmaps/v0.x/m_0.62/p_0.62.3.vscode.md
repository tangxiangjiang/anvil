# p_0.62.3 — Opt-in desktop interaction

**Status:** planned
**Milestone:** [m_0.62_browser_computer_use.vscode.md](../m_0.62_browser_computer_use.vscode.md)
**Linked design:** [62-browser-and-computer-use.vscode.md](../../../design/v0.x/62-browser-and-computer-use.vscode.md)

## Goals

Provide a narrowly confined desktop tier for approved applications without weakening browser or
workspace permissions.

## Scope

OS capability detection, window/process selection, capture masking, focus confinement, pointer/key
actions, emergency stop, protected applications/regions, durable evidence, packaging, and tests.

## Tasks

1. Define platform-neutral desktop observation/action contracts and unavailable states.
2. Require explicit window/process selection and separate opt-in permission.
3. Cancel on focus loss, target replacement, privilege elevation, or emergency stop.
4. Block terminals, password managers, security settings, and protected regions.
5. Add Windows/macOS/Linux capability matrix and per-platform package gates.

## Acceptance

- Input cannot escape the selected current window/process.
- Protected applications/regions are neither captured nor operated.
- Desktop permission is never inherited from browser or shell modes.
- Unsupported platforms report unavailable capability without fallback.

## Non-goals

- General remote desktop, privilege elevation, or unrestricted OS automation.
