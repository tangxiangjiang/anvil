# p_0.62.3 — VS Code execution, recovery, and Web cutover

**Status:** planned

## Goals

Operate Worktree/sandbox execution from VS Code with durable cancel, retry, and restart behavior.

## Scope

- Add revision-bound preflight and explicit Run confirmation.
- Project queue/run/sandbox state, logs, events, checkpoints, files, and terminal manifest.
- Add Stop, Retry, Review Worktree, Discard, Cleanup, and recovery diagnostics.
- Ensure retry creates a new Worker/branch/Worktree/execution/attempt and retains old evidence.
- Remove Web start/stop/retry/interactive workbench controls/routes; retain audit/export.
- Add race/fault/reconnect/accessibility/adversarial runtime/package/smoke gates.

## Tasks

1. Build execution preflight, live evidence, lifecycle actions, and recovery diagnostics.
2. Implement retry/restart invariants and remove Web execution mutations.
3. Add race, fault, reconnect, accessibility, route, package, and smoke tests.

## Acceptance

- Canceling confirmation writes nothing; confirmation targets exactly the displayed execution.
- Viewing/reconnecting starts no work and live/restored state agrees.
- Restart never adopts an unproven process; retry never overwrites an earlier attempt.
- Web cannot execute or configure work.

## Non-goals

- Verification, review, publication, integration, or automatic retry.

## Depends-on

- p_0.62.1 and p_0.62.2.
