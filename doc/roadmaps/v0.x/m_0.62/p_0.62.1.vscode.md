# p_0.62.1 — Coordinator execution transaction

**Status:** planned

## Goals

Atomically turn one approved dependency-ready work item into one isolated durable attempt.

## Scope

- Add `workflow.execute` with exact artifact/policy/base revisions and idempotency.
- Validate approval, dependencies, topology, model, budgets, runtime, Worktree root, and capabilities.
- Create Worker branch/Worktree, execution/run, manifest, and shared identity tuple.
- Bind events, tasks, checkpoints, diffs, logs, and terminal evidence to that tuple.
- Clean owned pre-start failures and durably terminalize every post-start failure.

## Tasks

1. Implement `workflow.execute` validation, idempotency, and coordinator transaction.
2. Bind Worktree/Worker/execution/run/evidence identities across stores and events.
3. Add duplicate, stale, dependency, topology, and partial-failure fault tests.

## Acceptance

- Duplicate/stale/blocked/mismatched starts create no run.
- A successful request produces one identity tuple in every store.
- Post-start failure is terminal/interrupted/recovery-required, never “not started.”
- Primary checkout remains unchanged.

## Non-goals

- Sandbox adapter, VS Code UX, retry, publication, or remote execution.

## Depends-on

- Milestone 0.61 and delivered 0.54/0.57 primitives.
