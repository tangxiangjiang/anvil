# p_0.50.1 — Multi: `Options.Mode` and `delegate`

**Status:** done
**Milestone:** [m_0.50_agent_modes.md](../m_0.50_agent_modes.md)
**Linked design:** [50-agent-modes.md](../../../design/v0.x/50-agent-modes.md) §3, §4

## Goals

Give the main agent a structured way to hand off well-specified work: a `delegate` tool whose
brief is validated before a child starts, whose `files` become a deny rule for everything else,
and whose result reports against each acceptance item. Add `Options.Mode` as the session
property that turns the tool and the matching main-role paragraph on.

## Scope

`source/options.go` (`Mode`, `Options.Mode`), `source/agent.go` (mode validation; registers
`delegate` in Multi and Complex; plan mode removes it), `source/delegate.go` (new: the brief,
validation, the child, the report), `delegate_test.go`, `source/internal/prompt/prompt.go`
(the Multi paragraph on the main role), `source/internal/tools/groups.go` (`delegate` in
`agent`), `source/subagent.go` (shared child creation refactored, not changed in behaviour),
the meta record (`brief`), `source/eval` (two tier-2 tasks).

## Tasks

1. **`Mode`.** `ModeSingle | ModeMulti | ModeComplex`; `Options.Mode`; `Create` and `Resume`
   validate; not a `SendOption`; not persisted.
2. **The brief.** The §4.2 struct; `validateBrief` refuses with every problem listed: empty
   goal, `plan`/`acceptance` outside 1–20, `files` outside 1–64 or any path outside the
   workspace (`ResolveInRoot`), unknown tool selectors. A directory entry ends with `/`.
3. **The child.** Created through the same path `spawn_agent` uses, with `Role: RoleWorker`,
   the brief rendered as L3 by the SDK, the parent's effort unless the brief sets one, and
   `PermissionRules` extended with a generated deny on `write`/`edit`/`apply_patch` for every
   path not under `files`, appended **after** the parent's rules.
4. **The report.** Parse the child's trailing acceptance block (`[met]`/`[not met]` lines)
   into one line per item; missing → `[unreported]`; `changed:` from the child's checkpoint
   captures. Prepend to the child's final message as the tool result.
5. **Meta.** The validated brief written to the child's meta record under `brief`; `/tasks`
   title is `goal`.
6. **The prompt.** The main role gains the Multi paragraph when `Mode != Single`; the
   `delegate` and `spawn_agent` descriptions say which is for what.
7. **Plan mode.** `delegate` joins the set plan mode removes (the host's
   `planDisallowedTools` is the host's; the SDK's own `DisallowedTools` handling must drop it
   when a caller lists it, and the tool description says it is editing).
8. **Eval.** Tier-2: a Multi task where the main agent delegates one item and the child
   meets both acceptance lines; a Multi task where the child tries a file outside `files`,
   is refused, and the parent's result shows `[not met]`. Gate `Refused == 1` exactly on the
   second.
9. **Verify.** Go suite from Git Bash; the script.

### Gate

- 命令：`cd source && go test -count=1 ./ -run 'TestDelegate|TestModeOption' && ./scripts/eval.sh`
- 通过条件：`TestDelegateRefusesBadBrief` 对缺 `files`、缺 `acceptance`、`files` 含 `../x`、21 条 plan 四种输入各返回错误且**不创建 agent**（用预算计数证明 `used` 不变）；`TestDelegateAllowlistIsARule` 证明子 agent 对 `files` 外路径的 `edit_file` 被规则引擎拒绝（结果含规则名，不是 prompt 拒绝），且父 agent 自己的 deny 规则仍先于生成规则生效；`TestDelegateReport` 证明 `[met]`/`[not met]`/`[unreported]` 三种行与 `changed:` 行按设计出现；`TestModeOption` 证明 `Mode: "weird"` 被 `Create` 拒绝、`ModeSingle` 下注册表无 `delegate`、`ModeMulti` 下有；`TestDelegateChildNeverWidens` 证明 `tools: [read]` 的子 agent 对 `edit_file` 得到 `unknown tool`；eval 两个新任务通过，第二个 `Refused == 1`。
- 失败条件：任一断言不成立；一个被拒的 brief 消耗了预算；生成规则排在父规则之前（用父 deny + brief allow 同一路径的用例证明父规则赢）；eval 任一受控字段劣化。
- 基线条目：`baseline.json` 新增两个任务；`invariants` 仍为 100%。

## Delivery status

Implemented: `Mode` (`ModeSingle`, `ModeMulti`; `ModeComplex` is refused until p_0.50.2),
`Options.Mode` validated by `Create` and `Resume`, the `delegate` tool (registered only in Multi,
in the `agent` group, removed by `DisallowedTools` like any tool, always reaching the approval
card), the validated `Brief`, the worker role with the brief rendered as L3, the generated write
allowlist, the acceptance report with a `changed:` line from the child's checkpoint record, the
brief in the child's meta record, and the Multi paragraph on the main role.

**The allowlist needed an engine change the design did not name.** The rule engine had no way to
say "deny a write outside these paths": a deny rule matches paths inside its pattern. The engine
gained `Rule.Unless`, a deny that covers a write when any touched path is outside the listed
globs, or when the paths cannot be read (a malformed patch fails closed). It is code-only: the
public `PermissionRule` does not carry it, and the workspace and user rule files reject the key
(`json:"-"` with strict parsing). It is only valid on a deny and cannot combine with a pattern.
The generated rules are appended after the caller's own, so a path the parent denies stays
denied, and a `spawn_agent` child of a worker inherits them, so the allowlist cannot be left by
spawning.

**Decisions and limits.**
- `changed:` reads the child's checkpoint record, so it is `not recorded` (not "nothing") when
  checkpoints are off.
- `background: true` on a brief is refused for now ("not supported yet"); a background worker
  needs the task table path and is left for a later phase.
- The eval digest normalizes a `delegate` heading's agent id exactly as it does `spawn_agent`'s,
  and nothing under it.
- Two tier-2 tasks are in `baseline.json`: `multi_delegate_met` and `multi_delegate_refused`
  (`refused` gated exactly at 1). They are scripted replays, not genuine provider recordings.
- The `plan` mode row of the gate (the host's `planDisallowedTools`) is the host's; the SDK side
  is that `DisallowedTools` drops `delegate`, which `TestModeOption` proves.

## Acceptance

- [x] `Options.Mode` validates at `Create`/`Resume`; Single registers no `delegate`.
- [x] A bad brief is refused with every problem named and no agent created.
- [x] The allowlist is a generated rule after the parent's rules.
- [x] The report has one line per acceptance item and a `changed:` line.
- [x] The brief is in the child's meta; `/tasks` can title by `goal`.
- [x] Plan mode has no `delegate`.
- [x] `./scripts/eval.sh` not worse; `invariants` 100%.
- [x] `cd source && go build ./... && go vet ./... && go test -count=1 ./...` is green (run
      from Git Bash).

## Non-goals

- Changing `spawn_agent`.
- A plan file in the workspace.
- A mode switch within a session.
- Host or editor cards for the brief; the meta record and the events are the interface.
