# p_0.50.3 — The invariants under three modes

**Status:** planned
**Milestone:** [m_0.50_agent_modes.md](../m_0.50_agent_modes.md)
**Linked design:** [50-agent-modes.md](../../../design/v0.x/50-agent-modes.md) §6

## Goals

Prove that what Anvil has and Codex does not — the rule engine, the loop guard, checkpoints
and rewind, plan mode, the subagent invariants — is as true in Multi and Complex as in Single,
by running the 0.47 invariants suite once per mode and gating each field exactly. Fix the one
place it is not true today: a child's checkpoint is keyed by its own run, so restoring the
parent's run misses what its children changed.

## Scope

`source/eval/invariants_test.go` (a `--mode` dimension), `scripts/eval.sh` (`--mode`),
`source/checkpoints.go`, `source/internal/checkpoint/*.go`, `source/internal/tools/tools.go`
(`SetCheckpointRun` takes the tree's root run and the agent id), `source/subagent.go`,
`source/delegate.go`, `source/workflow.go` (children capture under the root run),
`source/eval/baseline.json`.

## Tasks

1. **The mode dimension.** Every `inv_*` task runs under `ModeSingle`, `ModeMulti` and
   `ModeComplex`; the baseline keys by `task@mode`. For Complex, the task's prompt is what
   the Decision stage receives, and the invariant is asserted on the whole tree.
2. **Per-mode expectations.** `inv_plan_readonly@multi`: no `delegate` in the registry.
   `inv_plan_readonly@complex`: `Send` refused. `inv_child_never_widens@multi`: a `delegate`
   child with `tools: [read]`. `inv_child_result_only@complex`: no stage message in the
   root's history. `inv_loop_guard@complex`: a looping Worker fails its item and the other
   item finishes.
3. **Tree-keyed checkpoints.** A child's captures are written under
   `<root run>/<child agent id>/…`; `ListCheckpoints` shows the root run once with the files
   of the whole tree; `RestoreCheckpoint(root run)` restores every file any agent in the tree
   changed. A child's own run id is still recorded in the capture so a per-child restore
   remains possible later. Existing single-agent trees are unchanged (a test restores a
   0.46-shaped checkpoint directory).
4. **`inv_checkpoint_restore@multi` and `@complex`.** A worker edits two files; restoring the
   root run puts both back.
5. **`--mode`.** `scripts/eval.sh --suite invariants --mode single,multi,complex`.
6. **Re-baseline.** The mode-keyed entries are new; `--update` once; commit.
7. **Verify.** Go suite from Git Bash; the script in all three modes.

### Gate

- 命令：`./scripts/eval.sh --suite invariants --mode single,multi,complex && cd source && go test -count=1 ./ -run 'TestTreeCheckpoint'`
- 通过条件：八个不变量任务 × 三个模式 = 24 项全部通过，且每项的 `Refused` / `LoopStops` 与基线**相等**；`TestTreeCheckpointRestoresChildren` 证明 Multi 下子 agent 改的两个文件在对根 run 调用 `RestoreCheckpoint` 后恢复；`TestTreeCheckpointLegacyLayout` 证明 0.46 形状的检查点目录仍能列出和恢复；`inv_plan_readonly@complex` 的 `Send` 返回错误且 `Agents == 0`。
- 失败条件：24 项中任一失败或精确字段与基线不等；根 run 恢复漏掉任一子 agent 的文件；旧布局不能恢复；`invariants` 的单模式结果与 p_0.47.3 的记录不等（说明 0.48–0.50 的某处削弱了 Single）。
- 基线条目：`baseline.json` 中 24 个 `inv_*@<mode>` 条目；完整的 `./scripts/eval.sh` 对比表作为 0.50 的收尾基线。

## Acceptance

- [ ] 24 invariant runs pass with exact fields.
- [ ] Tree-keyed checkpoints restore children's edits from the root run.
- [ ] Legacy checkpoint layout still lists and restores.
- [ ] `--mode` runs the suite per mode from Git Bash.
- [ ] Single-mode results equal the 0.47 record.
- [ ] `cd source && go build ./... && go vet ./... && go test -count=1 ./...` is green (run
      from Git Bash).

## Non-goals

- A per-child restore in the UI; the capture keeps the child's run id for a later phase.
- New invariants beyond the eight; this phase proves the existing ones per mode.
- Host or editor changes to the checkpoint list.
