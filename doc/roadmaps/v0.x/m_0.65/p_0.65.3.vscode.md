# p_0.65.3 — Release, migration, provenance, and rollback gates

**Status:** planned
**Milestone:** [m_0.65_production_hardening.vscode.md](../m_0.65_production_hardening.vscode.md)
**Linked design:** [65-production-hardening.vscode.md](../../../design/v0.x/65-production-hardening.vscode.md)

## Goals

Make release artifacts reproducible, version-consistent, upgrade-tested, and safely recoverable.

## Scope

Per-platform builds, hashes/provenance, clean install, N-2 upgrade, persisted schema migration,
downgrade refusal, rollback, marketplace/package metadata, gate freshness, and release reports.

## Tasks

1. Produce reproducible signed Host/VSIX artifacts and provenance manifests.
2. Test clean install and N-2 upgrade for all persisted/configured domains.
3. Make migrations restart-safe and incompatible downgrade refusal explicit.
4. Add rollback drills that preserve user data.
5. Block publication on missing/stale/failed required gates or unaudited waivers.

## Acceptance

- Artifact hashes, embedded Host, extension, SDK, docs, and metadata versions agree.
- Upgrade/rollback fixtures preserve or explicitly refuse every schema.
- Clean packaged smoke passes on each supported platform.
- A release report proves source commit, matrix, provenance, migrations, and waivers.

## Non-goals

- Supporting arbitrary downgrade or silently rewriting incompatible state.
