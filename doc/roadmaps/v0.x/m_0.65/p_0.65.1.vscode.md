# p_0.65.1 — Platform matrix, fault injection, soak, and scale

**Status:** planned
**Milestone:** [m_0.65_production_hardening.vscode.md](../m_0.65_production_hardening.vscode.md)
**Linked design:** [65-production-hardening.vscode.md](../../../design/v0.x/65-production-hardening.vscode.md)

## Goals

Turn cross-platform, crash, duration, and scale behavior into required automated release evidence.

## Scope

OS/architecture/Git/VS Code/store/model matrices, named failpoints, protocol/store corruption,
network/provider faults, long sessions, large repos/diffs, parallelism, and resource budgets.

## Tasks

1. Declare supported matrix and capability exclusions.
2. Add test-only failpoints around every durable/mutating boundary.
3. Build crash/network/disk/lock/truncation/cancellation campaigns.
4. Add multi-hour and scale scenarios with leak/growth/latency budgets.
5. Publish deterministic reports and waiver records.

## Acceptance

- Every failpoint has a completed or recoverable/blocked invariant.
- Required matrix cells run from clean machines.
- Soak leaves no unbounded processes, handles, goroutines, temp files, memory, or store growth.
- Performance regressions fail without an audited waiver.

## Non-goals

- Diagnostics/telemetry UI or release publication.

- 0.60–0.64.
