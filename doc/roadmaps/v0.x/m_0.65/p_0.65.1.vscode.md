# p_0.65.1 — Release candidate, promotion, and rollback

**Status:** planned

## Goals

Turn the approved reviewed delivery into one explicit, traceable configured release outcome.

## Scope

- Add immutable candidate manifest from requirement through PR/CI, artifacts, target, and rollback.
- Define common candidate lifecycle and adapter-specific merge/tag/package/deploy handoffs.
- Add expected-revision/idempotency, preview, explicit approval, promotion, recovery, revoke, rollback.
- Persist partial/unknown outcomes and use read-after-write recovery.
- Add VS Code provenance graph, missing/stale gate diagnostics, actions, and immutable report.

## Tasks

1. Implement candidate manifest/lifecycle, adapters, expected revision, and idempotency.
2. Build VS Code provenance, preview, approval, promotion, recovery, revoke, and rollback UX.
3. Add duplicate/restart/partial/unknown outcome and waiver tests.

## Acceptance

- Opening/refreshing/green CI performs no release mutation.
- Duplicate/restarted requests yield one authoritative adapter outcome.
- Partial release and rollback intent remain durable and recoverable.
- Waivers bind actor/reason/expiry/gate/candidate revision.

## Non-goals

- Automatic release, production qualification, or remote Worker execution.

- Milestone 0.64.
