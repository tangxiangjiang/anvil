# p_0.65.2 — Local diagnostics and opt-in telemetry

**Status:** planned
**Milestone:** [m_0.65_production_hardening.vscode.md](../m_0.65_production_hardening.vscode.md)
**Linked design:** [65-production-hardening.vscode.md](../../../design/v0.x/65-production-hardening.vscode.md)

## Goals

Make failures diagnosable without exporting user content or enabling telemetry by default.

## Scope

Health/version/capability/resource diagnostics, structured errors, support bundle preview/export,
redaction, opt-in aggregate telemetry, local event preview, retention/delete, and privacy tests.

## Tasks

1. Define forbidden support/telemetry content and machine-checkable schemas.
2. Add local diagnostics for Host, stores, queues, resources, capabilities, and package integrity.
3. Add attachment-by-attachment support bundle preview.
4. Add off-by-default aggregate telemetry with retention/delete controls.
5. Fuzz/redact prompts, paths, commands, source, credentials, cookies, headers, and environment.

## Acceptance

- Default operation sends no telemetry.
- Bundles/events contain no forbidden fixtures or absolute user paths.
- The user can preview, omit, export, inspect, and delete local data.
- Diagnostics remain useful under Host/store/package failure.

## Non-goals

- Automatic crash upload or collecting prompts/responses/source.
