# p_0.65.2 — Qualification, diagnostics, and telemetry

**Status:** planned

## Goals

Prove the complete 0.60–0.65 path under supported platforms, faults, scale, and privacy policy.

## Scope

- Define Windows/macOS/Linux, architecture, Git, VS Code, store, provider, model, and runtime matrix.
- Add failpoints at durable/external mutations and crash/network/disk/lock/cancel/truncation campaigns.
- Add multi-hour soak and large repo/diff/session/workflow tests with resource/latency bounds.
- Add local diagnostics and previewable redacted support bundles useful under startup/store failure.
- Add off-by-default content-free telemetry with retention/inspection/export/deletion controls.

## Tasks

1. Build supported-platform matrix, failpoints, fault campaigns, soak, scale, and budgets.
2. Implement local diagnostics and previewable forbidden-content-checked support bundles.
3. Add opt-in telemetry controls and clean-machine privacy/performance gates.

## Acceptance

- Every failpoint ends completed or durably recoverable/blocked.
- Required clean-machine matrix cells pass.
- Soak leaves no unbounded memory/process/handle/temp/store growth.
- Bundles/telemetry contain no prompts, responses, source, secrets, credentials, or absolute paths.
- Performance or privacy failures block release absent an audited allowed waiver.

## Non-goals

- Automatic crash upload or arbitrary user-content telemetry.

## Depends-on

- p_0.65.1 and milestones 0.60–0.64.
