# p_0.56.2 — Cursor protocol and pagination

**Status:** done
**Milestone:** [m_0.56_session_search.vscode.md](../m_0.56_session_search.vscode.md)
**Linked design:** [56-session-search-and-history.vscode.md](../../../design/v0.x/56-session-search-and-history.vscode.md)

## Goals

Provide opaque, validated pagination cursors with deterministic traversal and identical behavior
for JSONL and SQLite.

## Scope

Cursor envelope/version, query binding, sort anchor, snapshot boundary, page limits, expiry/error
semantics, host RPC fields, cancellation, and parity fixtures.

## Tasks

1. Encode only server-owned traversal state in an opaque versioned cursor.
2. Bind cursors to normalized query, ordering, store identity, and snapshot boundary.
3. Define insert/delete behavior and stable tie-breaking across pages.
4. Reject tampered, mismatched, expired, and unknown-version cursors without fallback.
5. Follow the one-patch extension policy from the current version for any user-visible delivery.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestSession(Cursor|Pagination|PageParity)'`.
- Shared tests traverse the same corpus in page sizes 1, 2, and 50 against both stores with no
  duplicate or skipped IDs inside the defined snapshot.
- Invalid signature/encoding, changed query, wrong store, expiry, and unknown version produce
  typed errors and no partial result.
- Concurrent insert/delete fixtures produce the documented stable outcome in both stores.

## Non-goals

- Client-decoded offsets, infinite retention of cursors, or cross-workspace cursors.
- UI virtualization and search input behavior.
- Relaxing local privacy.
