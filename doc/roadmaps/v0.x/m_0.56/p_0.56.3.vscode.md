# p_0.56.3 — Sessions full-text UI

**Status:** done
**Milestone:** [m_0.56_session_search.vscode.md](../m_0.56_session_search.vscode.md)
**Linked design:** [56-session-search-and-history.vscode.md](../../../design/v0.x/56-session-search-and-history.vscode.md)

## Goals

Add local full-text search to the VS Code Sessions surface using the shared query/cursor contract,
with cancellable requests and accessible result navigation.

## Scope

Search input, debounce/cancellation, filters, snippets/highlights, paging, loading/empty/error
states, keyboard/accessibility behavior, session opening, and reconnect.

## Tasks

1. Send normalized local queries through the host contract and cancel superseded requests.
2. Render escaped snippets and metadata without evaluating stored transcript content.
3. Page with opaque cursors and reset traversal when query/filter/sort changes.
4. Keep search terms and transcript bodies out of telemetry and remote services.
5. Bump the current extension patch exactly once before packaging this user-visible batch and
   synchronize package lock, host version, and shipped-version references.

## Acceptance

- `cd editors/vscode && npm test -- --runInBand` covers typing/debounce, stale-response
  suppression, filters, next page, cursor reset, empty/error states, keyboard navigation, and
  opening the selected session.
- A malicious snippet fixture renders as text; no command, HTML, or script is executed.
- Host integration runs the same UI cases over JSONL and SQLite and compares ordered visible
  results.
- Privacy tests observe no search text or transcript body in telemetry/provider requests.
- `npm run package` and packaged smoke tests pass after the exact one-patch bump.

## Non-goals

- Cloud/global search, semantic search, or model-assisted query rewriting.
- Persisting search history outside explicitly local editor state.
- Different capabilities for JSONL and SQLite.
