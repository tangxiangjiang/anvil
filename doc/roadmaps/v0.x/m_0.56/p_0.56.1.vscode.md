# p_0.56.1 — JSONL/SQLite query contract

**Status:** planned
**Milestone:** [m_0.56_session_search.vscode.md](../m_0.56_session_search.vscode.md)
**Linked design:** [56-session-search-and-history.vscode.md](../../../design/v0.x/56-session-search-and-history.vscode.md)

## Goals

Define one local session-query contract whose filters, text matching, ordering, snippets, and
errors are observably equivalent in JSONL and SQLite.

## Scope

Query fields, normalization, literal/full-text rules, metadata filters, deterministic sort keys,
snippet boundaries, limits, cancellation, store adapters, and local privacy boundaries.

## Tasks

1. Specify normalization and matching without store-specific syntax leaking into the API.
2. Implement equivalent query execution for JSONL and SQLite.
3. Build one golden corpus covering Unicode, punctuation, deleted sessions, subagents, and ties.
4. Ensure queries and transcript bodies never enter provider, telemetry, web, or MCP requests.
5. Apply an exact one-patch extension bump only when the batch becomes user-visible.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestSessionQuery(JSONL|SQLite|Parity|Privacy)'`.
- For every golden query, both stores return identical ordered IDs, snippets, match fields, and
  typed errors.
- Tests cover empty text, Unicode normalization, deterministic ties, cancellation, malformed
  limits, and records appended during a query.
- A network-spy test observes no query/transcript content on provider, telemetry, web, or MCP
  paths.

## Non-goals

- Pagination cursors or VS Code UI.
- Remote indexing, semantic/vector search, or model-generated summaries.
- Store-specific search features that break parity.
