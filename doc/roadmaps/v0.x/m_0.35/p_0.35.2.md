# p_0.35.2 — anvil-host binary + protocol core

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v0.x/35-vscode-extension.md)

## Goals

A stdio sidecar that drives in-process `anvil` sessions over newline-delimited JSON-RPC 2.0, with no approval or UI concerns yet.

## Scope

`source/cmd/anvil-host/` (entry) and `source/internal/editorhost/` (protocol types, session registry, event bridge). Both import the **public `anvil` package only** — no `internal/daemon`, `internal/scheduler`, `internal/web`, or tool-chain config.

## Tasks

1. Framing: one compact JSON object per line on stdin/stdout. The line shape follows `internal/plugin/exec.go` (`{"jsonrpc":"2.0","id":…,"method":…,"params":…}`).  
2. Methods: `initialize` / `initialized`, `session.new` / `session.resume` / `session.list` / `session.close`, `prompt`, `cancel`, `models.list`, `shutdown`.  
3. Session registry: session id ↔ `*anvil.Agent`; enforce one active run per session ([01](../../../design/v0.x/01-architecture.md) concurrency rule).  
4. Event bridge: map `anvil.Event` → the host's own `event` JSON (fields include `run_id`); terminal `anvil.RunResult` → `done` (including `usage`). Built from the **public** SDK types only; `internal/daemon` is not imported.  
5. Drain `Run.Stream` into an **unbounded outbound queue** written by a dedicated goroutine, so a slow client never stalls the run and never trips `Run.emit`'s 64-slot drop path.  
6. Wire `LocalOptions`: `CWD` from `initialize`, `LoadRules` / `LoadCursorRules`, store kind, `SettingSources`.  
7. Credentials never cross the pipe: the client sets `ANVIL_API_KEY` / `ANVIL_BASE_URL` / `ANVIL_MODEL` / `ANVIL_PROVIDER` in the child environment, which the SDK already reads.

## Tasks as delivered

Recorded because two details differ from the plan above:

- The test client is **in-process** — it drives the real `Server` over `io.Pipe` with a scripted OpenAI-compatible SSE stub behind `httptest`, rather than a separate fixture binary patterned on `internal/plugin/fakecmd/`. This exercises the production code path instead of a stand-in. The public SDK has no completer-injection point, so the stub is an HTTP endpoint.
- The **SDK's own `done` event is not forwarded**. The runtime emits it carrying the final assistant text, which has already reached the client as `assistant` deltas (streaming path) or one `assistant` event (non-streaming path). The terminal signal is the `done` notification built from `RunResult`, emitted exactly once per prompt.

## Acceptance

- [x] `go test ./source/...` green including the new package.

- [x] Cancel terminates a run and emits a terminal `cancelled` status with `code: cancelled`.

- [x] `session.resume` continues a persisted agent; `session.list` reports it.  
- [x] An import-guard test fails the build if either new package reaches into the tool-chain (verified against a deliberate violation).  
- [x] The built binary runs end to end over a real pipe: protocol on stdout, diagnostics on stderr only.
