# p_0.35.5 — Context injection + diff review

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.vscode.md](../m_0.35_vscode_extension.vscode.md)  
**Linked design:** [35-vscode-extension.vscode.md](../../../design/v0.x/35-vscode-extension.vscode.md)

## Goals

Give the agent what the editor knows, and give the developer the change before it lands.

## Scope

Host `prompt.context` handling; extension webview + native diff editors.

## Tasks

1. **`@` mentions**: file and folder picker in the composer; resolved to workspace-relative paths in `context.mentions`; host injects contents with sane size caps.  
2. **Selection**: active file + selected range/text in `context.selection`.  
3. **Diagnostics**: current file diagnostics in `context.diagnostics` (reuses the 0.16 language-tooling direction, read-only).  
4. **Image paste**: pasted images become `attachments`, routed to the 0.19 vision path; honour `Vision.Enabled` and the downscale budget.  
5. **Diff review before apply**: render the `diff`-kind approval preview. Accept → allow; reject → deny. Use VS Code's diff view against the pre-image.  
6. **Changed files list**: after a turn, list files touched by `write_file` / `edit_file` / `apply_patch`; clicking opens a native diff.  
7. Tests: mention resolution and size caps; attachment plumbing; diff preview rendering for create / modify / delete; a rejected diff leaves the file untouched.

## Tasks as delivered

1. **Mentions.** `mentions.ts` (pure: relative-path resolution, labels, dedupe, and the paths a tool call's arguments name) + `editorContext.ts` (a `workspace.findFiles` quick pick). The composer opens the picker on a typed `@` or the `@` button; chips hold workspace-relative paths. The host resolves each one against the session cwd, cleans it, re-checks after symlinks, and refuses `..`, absolute, and symlink escapes as `-32602`; caps are 32 mentions, 64 KiB per file, 256 KiB total, 200 listing entries, with omissions and truncations announced in the block.
2. **Selection** is read when Send is pressed, not when the panel opened, and its path is deliberately *not* required to be inside the workspace: no file is read on its account and the text is already in hand.
3. **Diagnostics** are taken from the language server, sorted worst-first and capped at 100 *after* sorting, so a file full of hints cannot crowd out the error that matters. The host renders a compact block and computes nothing.
4. **Image paste.** The webview reads the pasted `File` and posts a `data:` URL; `attachments.ts` (pure, `vscode`-free) converts it to `{data, mime}`, refusing non-images, non-base64, empty, and over-bound payloads. `anvil.vision` (off by default; p_0.46.9 makes the editor ask for vision by default, leaving the SDK default off) sets `vision: true` on `session.new`; the host refuses an attachment on a session without it, naming the setting.
5. **Diff review.** `anvil.ToolPreview` gained `Before` / `After`, lifted with one shared 512 KiB cap in the SDK's public path — past it both bodies are dropped together and `truncated` is set, because a clipped post-image rendered as the whole file is worse than the diff text. `review.ts` serves both sides through a read-only content provider and opens `vscode.diff`; the review is closed when its question is answered, withdrawn, or the run ends.
6. **Changed files.** `changes.ts` snapshots the pre-image at the `tool_call` event and again before an approval is answered (first touch wins per turn), covering auto-allowed modes too; after the turn each snapshotted path is re-read, unchanged ones dropped, and the rest listed with a diff against the snapshot. A `shell` redirect is out of reach of this design and documented as such.
7. **Tests.** Extension: mention resolution and escapes, tool-call path extraction (including the patch headers), attachment conversion and refusals, what a prompt actually carries on the wire, vision opt-in, and the four diff scenarios (bodies present, deny leaves the file byte-identical, allow writes what was shown, an empty pre-image for a create). Go: `TestPreviewCarriesBothBodies`, `TestPreviewCreateHasAnEmptyPreImage`, `TestPreviewDeleteHasAnEmptyPostImage`, `TestPreviewBodiesAreDroppedTogetherWhenTooLarge`, and `internal/editorhost/context_test.go` (composition order, plan-mode ordering, verbatim prompts, caps, escape refusals, and the four attachment paths against a real 1×1 PNG).

## Acceptance

- A prompt with an `@`-mentioned file and an active selection reaches the model with both.  
- A pasted screenshot is understood by a vision-capable model.  
- An edit is shown as a diff before it is applied, and rejecting it leaves the file byte-identical.

**Verified by tests:** the first and third, at the protocol level (what the prompt carries; what a denial leaves on disk). The second and the window-level halves — the quick pick rendering, the diff editor opening, a screenshot actually being described — need a VS Code window and a model key, so they are for the p_0.35.7 acceptance pass.

## Non-goals

- Per-hunk accept/reject; inline decorations in the editor gutter.
