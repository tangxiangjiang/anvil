# p_0.35.6 — Sessions, plan mode, slash commands, rules

**Status:** done  
**Milestone:** [m_0.35_vscode_extension.md](../m_0.35_vscode_extension.md)  
**Linked design:** [35-vscode-extension.md](../../../design/v0.x/35-vscode-extension.md)

## Goals

Turn a single conversation into a resumable, steerable workspace assistant.

## Scope

Session history and resume; the mode switcher and plan mode; the slash catalogue; the rules the session loads and a way to see them.

## Tasks

1. **Session history**: `session.list` → past agents with runs, status, and usage from the store; click to `session.resume`.  
2. **Resume**: continue a prior conversation; the extension treats it as the same chat session.  
3. **Usage display**: show `JobDoneBody.usage` at the end of a turn. A live context meter is **not** in scope — usage is terminal-only today.  
4. **Plan mode**: UI toggle → host sets `DisallowedTools: ["write","edit","shell","verify"]` plus a system-prompt addendum; the turn produces a plan and stops. Switching back restores the toolset via `Agent.Reload` semantics.  
5. **Slash commands**: built-ins `/plan`, `/model`, `/resume`, `/clear`; plus commands contributed by **skills** (`.anvil/skills/<id>/SKILL.md`, [14](../../../design/v0.x/14-hooks-skills.md)) surfaced through the skill list.  
6. **Rules**: host sets `LoadRules` + `LoadCursorRules` so `AGENTS.md`, `.anvil/rules/*.md`, and `.cursor/rules/*` apply; surface which rule files were loaded.  
7. **Mode switcher**: `ask` / `acceptEdits` / `plan` / `bypass` in the panel, with `bypass` visibly flagged.  
8. Tests: resume round trip; plan mode issues no write/mutate call; slash command dispatch; skill-derived command listing.

## Tasks as delivered

1. **Session history.** `session.list` now fills `SessionInfo.usage` — the cumulative tokens of the stored runs, which is the only thing that makes a row worth picking — and `/resume` (or the same command with no argument, or nothing at all) opens a VS Code quick pick over it: agent id, run count, last status, model, and when it was updated. There was **no public transcript reader** in the SDK at the time, so a resumed conversation could not be replayed into the webview; the panel said "Continuing session …" and moved on rather than printing an invented history. **(p_0.38.3 added the reader and the replay** — see [38](../../../design/v0.x/38-session-identity-and-replay.md).)
2. **Resume.** `ChatSession` keeps the agent id in a field of its own, separate from the live session. `close()` deliberately keeps it, so `session.close` + `session.resume` re-opens the *same* agent under *new* options — one mechanism, used by every mode switch, model change, and skill selection. `continueWith(id)` adopts a stored agent; `reset()` forgets it so the next prompt starts a fresh one.
3. **Usage.** `done.usage` is rendered as `N steps · 1.2k tokens (1.0k in / 180 out)`. A live context meter remains out of scope, as planned.
4. **Plan mode** is a UI toggle and a `/plan` command, both of which set `permission_mode: 'plan'` and re-open the session. The withholding itself is the SDK's (`DisallowedTools` + the plan prompt prefix) and was already pinned by `TestPlanModeWithholdsWriteTools`; what is new here is that the panel can turn it on and off without losing the conversation. `/plan <text>` sends the text as the request once the mode is on.
5. **Slash commands.** `commands.ts` is pure and `vscode`-free: the catalogue (built-ins first — a skill never shadows a built-in, since a command that did something other than its name says is worse than a missing one), a parser that considers only the first token, and `route()`, which decides *what* a line means. Executing it — quick picks, re-opens, the transcript — stays in `chatPanel.ts`, which is where a window is. `/model` lists the provider's models (or takes an id); `/resume` lists stored agents (or takes an id); `/clear` ends the conversation without killing the host; `/help` prints the catalogue. The `/` palette is a UI affordance only: it inserts a command name and never dispatches anything itself.
6. **Rules.** `anvil.rules` and `anvil.cursorRules` (both on) set `load_rules` / `load_cursor_rules` on the session, so `AGENTS.md`, then `.anvil/rules/*.md`, then optionally `.cursor/rules/*.md|.mdc` apply under the SDK's 24 KiB budget. `rules.list` reports, per file, whether its body reached the prompt and whether the budget cut it short. The panel shows that list behind a `Rules (n)` button, and speaks up unbidden only when a file was skipped or truncated — a silently ignored rule file is the one state the user cannot see for themselves.
7. **Mode switcher.** `ask` / `acceptEdits` / `plan` / `bypass` in a select above the composer, remembered per workspace in `workspaceState` (not in settings: `extension.ts` restarts the host on any `anvil.*` change, which would drop the conversation). `bypass` is flagged in the notice, on the strip above the composer, and on the composer's own border. A change is refused mid-turn — checked before the re-open rather than by it, so the refusal is reported as a refusal and the recorded option is put back rather than left to take effect on the next session. The select is disabled while a turn runs and is driven only by what the extension says is in force.
8. **Tests.** Extension: `test/unit/commands.test.ts` (11: parsing, catalogue precedence, case rules, palette matching, every route, paths that are not commands), `test/unit/session.test.ts` (re-open keeps the agent and applies new options; a pre-prompt change opens nothing; a refusal changes nothing; `continueWith`; `reset`), `test/integration/sessions.test.ts` (5, against the scripted host: a resumed conversation keeps its agent and takes a second prompt, a mode change reaches `session.resume`, the listing carries runs/status/usage, `skills.list` → commands → a route, `rules.list` honours the layers asked for, `included`/`truncated` survive), and `realHost.test.ts` now asserts the `skills` and `rules` capabilities and calls both against the real sidecar. Go: `ListSkills` / `ListRuleFiles` gained `sessions_test.go`, `skills_api_test.go`, `rules_api_test.go`.

### Additive SDK surface

`internal/skills` and `internal/rules` are unreachable from `anvil-host` (that is the independence rule), so "what rule files were loaded" and "what skills exist" needed new *public* APIs: `anvil.ListRuleFiles` and `anvil.ListSkills`. `internal/rules` was refactored onto a single `discover()` pass that yields both the prompt text and the per-file report, so the listing and the prompt cannot drift apart — and `TestListRuleFilesMatchesWhatLoadInjects` asserts they agree.

## Acceptance

- Past sessions are listed and resumable, and the resumed conversation retains prior context.  
- Plan mode completes a turn with zero mutating tool calls.  
- Repo rules (`AGENTS.md` / `.cursor/rules`) visibly influence output.

**Verified by tests:** the resume round trip end to end — `TestResumeContinuesTheConversation` (the model request of the second turn contains what the first turn was told, and the listing's cumulative usage is non-zero) and the extension-side resume over the real pipe; plan mode's zero mutating calls (`TestPlanModeWithholdsWriteTools`, whose result is asserted to come back as an error); and the rules surface (`TestRulesListReportsWhatWasLoaded`, `TestListRuleFilesReportsTheBudget`, `TestListRuleFilesMatchesWhatLoadInjects`).

**Not verifiable here, for the p_0.35.7 acceptance pass:** that a rule file *changes what the model writes* (needs a key and a model), and the window-level halves — the quick pick, the mode select rendering, the palette's keyboard handling, and the honest limit that a resumed conversation shows no prior messages because the SDK exposed no transcript reader (that limit was removed in p_0.38.3).

## Non-goals

- Checkpoints / rewind, conversation branching, exporting transcripts.
