# p_0.53.2 — Retry and truncation wire events

**Status:** planned

## Goals

Carry provider retry progress and terminal output truncation through the host protocol so VS Code
can distinguish waiting, failure, normal completion, and a length-limited answer.

## Scope

- Define versioned wire events for retry attempt, maximum attempts, delay, and safe provider
  summary text.
- Define a terminal truncation marker tied to the assistant turn/run that was cut.
- Preserve both event types in persisted session replay.
- Keep truncation distinct from cancellation, transport failure, and ordinary completion.
- Avoid serializing private reasoning or provider state.

## Tasks

- [ ] Extend protocol codecs and compatibility behavior.
- [ ] Map SDK retry/truncated events through the editor host.
- [ ] Persist and restore the event data needed by the extension.
- [ ] Add live, replay, compatibility, ordering, and privacy fixtures.

## Acceptance

- [ ] Protocol round-trip tests preserve retry attempt/max/delay and truncation run/turn identity.
- [ ] Host integration tests show retries before the terminal result and exactly one terminal
  truncation marker for a length-limited response.
- [ ] Replay tests produce the same retry/truncation state as the recorded live event sequence.
- [ ] Cancellation, mid-stream provider failure, ordinary completion, and truncation fixtures
  remain four distinguishable outcomes.
- [ ] Serialization tests prove reasoning content and opaque provider state are absent.
- [ ] Run `cd source && go test ./...` and `cd editors/vscode && npm test`.

## Non-goals

- Changing retry policy or retrying after visible stream output.
- Automatically continuing a truncated answer.
- Rendering final output-limit controls.
