# p_0.53.4 — Per-model provider routing

**Status:** done

## Goal

Let one Session use an Anthropic-native main model while selected Subagents use
OpenAI-compatible or Anthropic routes according to their configured model.

## Scope

- Add an SDK model-route map containing provider, endpoint, credential source,
  and explicit capabilities.
- Resolve a fresh child completer when a Subagent selects a different model;
  never reuse the parent protocol client for that model.
- Carry model routes through the editor-host session protocol without putting
  API keys on the JSON-RPC wire.
- Persist per-model routes in VS Code Model Manager, with protocol-specific
  SecretStorage keys and compatibility fallback to the existing default key.
- Preserve the existing Single-mode form and behavior.

## Acceptance

- [x] A root Anthropic agent can spawn an OpenAI-compatible child model.
- [x] Anthropic and OpenAI child routes emit their native request shapes.
- [x] Missing routes retain the existing inherited-provider behavior.
- [x] Route credentials come from environment variables populated from
      SecretStorage and never appear in settings, profile files, or JSON-RPC.
- [x] Model Manager can edit and remove a route for every curated gateway model.
- [x] Single mode requires no route configuration.
- [x] SDK, host, extension, packaged VSIX, and smoke tests pass.
