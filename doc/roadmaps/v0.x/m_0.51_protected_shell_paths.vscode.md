# Milestone 0.51 — Protected shell paths

**Status:** planned
**Product patch:** none. This roadmap milestone is not the VS Code plugin patch version. Each
actual user-visible delivery batch must increment the then-current
`editors/vscode/package.json` patch by exactly one; these planned documents do not select or
reserve that patch.

## Goals

1. Define one conservative policy for detecting shell commands that can modify protected paths.
2. Apply that policy at the editor-host approval boundary so a protected operation cannot be
   hidden inside an otherwise permitted shell command.
3. Keep analysis deterministic, explainable, and fail-safe when a command cannot be classified.

## Ordering

p_0.51.1 defines the analyzer result and test corpus. p_0.51.2 consumes that contract at the
host approval boundary; it must not duplicate or reinterpret command parsing in the extension.

## Overall acceptance

1. Analyzer tests cover direct writes, redirection, deletion, moves, interpreter wrappers,
   quoted paths, relative paths, mixed command chains, Windows and POSIX spellings, and
   unclassifiable input.
2. A host integration test proves a shell command affecting a protected path requires explicit
   approval even when the ordinary shell permission would otherwise allow it.
3. Approval text identifies the protected path and reason without claiming the command is safe.
4. Commands proven not to affect a protected path preserve existing permission behavior.
5. Run `cd source && go test ./...` and `cd editors/vscode && npm test`; before any actual
   user-visible delivery, bump the current plugin patch once, then package and run the packaged
   VSIX smoke test.

## Non-goals

- A complete shell parser or an OS-level process sandbox.
- Automatically approving an ambiguous command.
- General secret scanning, malware detection, or organization policy distribution.
- Assigning a VS Code plugin patch while this milestone remains documentation-only.

## Depends-on

- Existing tool permission rules and editor-host approval flow.
- Existing workspace containment and protected-path semantics.
