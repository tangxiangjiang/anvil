# Milestone 0.60 — End-to-end Worktree execution control

**Status:** planned

Turn the delivered 0.57 Worktree primitives into one explicit VS Code flow from an approved
structured work item to an isolated durable Worker and review-ready result. Design:
[60](../../design/v0.x/60-worktree-execution-control.vscode.md).

## Goals

1. Add one host-owned operation that atomically validates, prepares, routes, and starts a Worker.
2. Project durable execution, checkpoints, cancellation, and terminal evidence under the work item.
3. Add explicit one-click VS Code execution, retry, and recovery without implicit starts.

## Ordering

The coordinator transaction lands first. The editor may expose Run only after the operation has a
durable identity. Restart/retry gates close the milestone after real-host integration exists.

## Overall acceptance

- An approved, dependency-ready item starts exactly one routed Worker in its owned Worktree.
- Every event, task, diff, and checkpoint carries the same item/Worker/execution/run identity.
- Opening, expanding, approving, or restoring a plan never starts execution.
- Cancellation, stale state, restart, and retry preserve evidence and never touch the primary
  checkout.
- Go and VS Code suites include end-to-end real-host coverage and package/smoke gates.

## Non-goals

- Automatic integration, retry, conflict resolution, remote execution, PR, or CI.
- Running unstructured prose as a Worktree item.
