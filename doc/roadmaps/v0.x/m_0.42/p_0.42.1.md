## Goals

1. **An agent inside an agent.** A `spawn_agent` built-in tool creates a second `anvil.Agent`,
   sends it one brief, and returns its final message as the tool result.
2. **A child is not a stranger.** The store's meta record, the session listing and the permission
   request all carry the parent's identity, so a child is attributable, replayable and deletable
   with its parent.
3. **The child's work is visible while it runs.** Every event a child emits reaches an optional
   `SubagentOptions.OnEvent` callback, keyed by the spawn call, so a host can draw it under the
   card that is waiting.
4. **Nothing widens.** The child inherits the workspace, the sandbox, the rules and the permission
   callback; its tool set is a deliberate subset; depth and an agent budget bound recursion.

## Tasks

1. **`SubagentOptions` and public types** (`source/options.go`, `source/types.go`):

   ```go
   type SubagentOptions struct {
       // Enabled registers spawn_agent. Off by default: a tool that creates agents
       // and spends tokens is an opt-in, like WebSearch.
       Enabled bool
       // MaxDepth bounds nesting. Default 2 means a root (0) and its children (1);
       // a child at the last depth has no spawn_agent in its registry.
       MaxDepth int
       // MaxAgents bounds how many agents one root run tree may create. Default 8.
       MaxAgents int
       // MaxBackground bounds concurrent background tasks. Read by p_0.42.2; stored
       // here so a caller configures one struct.
       MaxBackground int
       // OnEvent, when non-nil, receives every event a child emits.
       OnEvent func(SubagentEvent)
   }

   type SubagentEvent struct {
       ParentAgentID string
       ParentRunID   string
       ToolCallID    string // the spawn_agent call
       AgentID       string
       RunID         string
       Event         Event
   }
   ```

   `Options.Subagents SubagentOptions`. Zero values resolve to the defaults above; `Enabled` is
   the only switch and is false unless set.

2. **Identity in the store** (`source/internal/store/store.go`, `source/agent.go`):

   - `store.Record` and `store.Summary` gain `ParentAgentID`, `ParentRunID`,
     `ParentToolCallID`, `Depth`, `Kind`, `TaskTitle` (all `omitempty`; `Depth` omitted at 0).
   - A new internal creation path carries them:
     ```go
     // In package anvil (unexported): the identity Create/Resume stamps onto meta.
     type subagentIdentity struct {
         ParentAgentID, ParentRunID, ParentToolCallID, TaskTitle string
         Depth int
     }
     func createSubagent(ctx context.Context, opts Options, id subagentIdentity) (*Agent, error)
     ```
     `Create` calls the same constructor with a zero identity, so the top-level meta record is
     unchanged. `createSubagent` writes `Kind: "subagent"` and the identity fields.
   - `Create` computes `agentID` **before** `buildRegistry` and passes it to the registry
     (`reg.SetIdentity(agentID)`), so the permission wrapper can name the agent that is asking.
     `Resume` does the same with the id it was given. This is a reorder inside `Create`, not a
     behaviour change.

3. **The tool call id in the context** (`source/internal/runtime/loop.go`,
   `source/internal/tools/tools.go`):

   - In `runToolCalls`, both the sequential and the parallel path call
     `registry.Execute(tools.WithCallID(ctx, tc.ID), tc.Name, tc.Args)`.
   - `tools.WithCallID(ctx, id) context.Context` and `tools.CallID(ctx) string` (unexported key).
     The spawn tool reads it to key its `SubagentEvent`s. No public API change.

4. **`spawn_agent`** (`source/subagent.go`, registered in `buildRegistry`):

   ```go
   // Register only when opts.Subagents.Enabled && depth+1 < MaxDepth.
   {
     "type": "object",
     "properties": {
       "prompt":       {"type": "string"},
       "description":  {"type": "string"},
       "tools":        {"type": "array", "items": {"type": "string"}},
       "model":        {"type": "string"},
       "max_steps":    {"type": "integer", "minimum": 0},
       "background":   {"type": "boolean"}
     },
     "required": ["prompt", "description"]
   }
   ```

   - `tools` defaults to `[]string{"read", "search", "skills", "git", "vision"}`; a selector that
     names no known group and is not a registered built-in is a tool error listing the accepted
     selectors, not a silently narrower child.
   - Child options are built by `(*Agent).childOptions(params, selectors, depth)`: the whitelist
     in the design chapter, `SystemPrompt` = the fixed subagent brief, `Local.CWD` = the parent's,
     `PermissionRules`/`PermissionGroups`/`Permission` inherited, `Checkpoints` inherited.
     `MCPServers`, `LSP`, `WebSearch`, `Test`/`Build`, `Vision` are copied **only** when the
     selector names `mcp`, `lsp`, `web`, `verify`, `vision` respectively. `Local.SettingSources`
     is inherited (it also carries rules and hooks), so a child without the `mcp` selector sets
     an unexported `skipFileMCP` flag that makes `Create` drop servers loaded from
     `.cursor/mcp.json` after the merge. The child reuses the parent's provider client
     (`a.complete`) instead of building a second one.
   - `max_steps` clamps to the parent's non-zero `MaxSteps`; a clamped value adds one sentence to
     the result (it does not fail the call).
   - Foreground (`background: false`, the default in this phase): `Create` → `Send(ctx, prompt)`
     with the parent run's context → `Wait`. The result is:
     ```
     agent-… finished in N steps.
     <final message>
     ```
     A failed child returns `Result{IsError: true}` with the child's status and `Err`. The child is
     closed in a `defer` after the result is captured.
   - Background is refused in this phase with a clear "not yet" error; p_0.42.2 implements it.
   - The tool is a `tools.FuncTool{Builtin: true}`. `FuncTool` gains that field and
     `IsExternalTool` returns false for it, so the group table, `Options.BuiltinTools` and
     `Options.DisallowedTools` treat `spawn_agent` as a built-in rather than as a caller-supplied
     tool that no filter may remove. `run_workflow` (p_0.42.4) uses the same field.
   - The depth/budget closure: `maxDepth` and a `*subagentBudget` (mutex + count + limit) are
     passed through the child's `SubagentOptions` so grandchildren share the same counter. The
     root creates the counter at `Create` (and `Resume`), and `executeRun` resets it when a depth
     0 agent starts a run, so one root run is one tree.

5. **The subagent brief.** A fixed, short system prompt, in the same voice as `prompt.System`:

   ```text
   You are a subagent. The conversation that created you gave you one task and is waiting for
   your answer. Work with the tools you have; do not ask a question and stop — if something is
   missing, say what you could not determine. Your final message is the entire result; write it
   for the agent that called you, not for a person.
   ```

   The brief is a constant in `source/subagent.go`. It does not include the parent's prompt or
   skills.

6. **Permissions carry identity** (`source/types.go`, `source/agent.go`):

   - `PermissionRequest` gains `AgentID string`, `RunID string` and `Depth int` as designed. The
     wrapper in
     `buildRegistry` fills them from the registry's identity and the context value for the current
     run (`tools.CallID` is not the run; the run id is a registry field set by
     `SetRunContext`). `Depth` is a registry field set by `createSubagent`.
   - `registry.SetIdentity(agentID string, depth int)` is the internal method; `executeRun`
     continues to call `SetRunContext(agentID, runID)`, and `Registry.RunID` reads the run id the
     wrapper reports.
   - A child that inherits the parent's `Permission` closure therefore produces requests naming
     the child. No host change in this phase; the host's card shows the fields in p_0.42.3.

7. **Event bridge** (`source/subagent.go`, `source/agent.go`):

   - `executeRun` gains an optional child-event forwarder: when `a.opts.Subagents.OnEvent != nil`
     **and** this agent is a child (it has an identity), the run's event callback calls
     `OnEvent(SubagentEvent{...})` in addition to `run.emit`. The parent's own events are not
     forwarded, so `OnEvent` is exactly "events from children".
   - `ToolCallID`, `ParentAgentID` and `ParentRunID` come from `ctx` values set by the spawn tool
     before `Send`: `withSubagentOrigin(ctx, parentAgentID, parentRunID, toolCallID)`. The spawn
     tool reads them from its own ctx (the runtime's call id, the parent agent's active run).

8. **Delete with the parent** (`source/session_admin.go`):

   - `DeleteAgent` loads the store's ids, finds every agent whose meta `ParentAgentID` is the
     deleted id (transitively), deletes those files and their checkpoints, then the parent's.
     A child's delete failure after the parent's succeeds is reported; no file is left silently.
   - This requires listing ids, which `store.ListIDs` already provides for JSONL; SQLite's
     backend exposes the same through the store interface (`Backend` gains `ListIDs` if it does
     not already). Tests cover both backends where the suite already runs both.

9. **Docs and version.** Update `doc/design/v0.x/README.md` and `doc/roadmaps/v0.x/README.md`
   with the 0.42 row and chapter 41; root `README.md` stays at "0.41 delivered" until the
   milestone is done. Chapter 41 is the contract; a divergence found during implementation is
   written back into it in the same commit.

## Acceptance

- [x] With `Subagents.Enabled: true`, a scripted model can call `spawn_agent`; the child's model
  call is a second conversation whose first user message is the `prompt`, and its final message is
  the tool result's second paragraph.
- [x] The child's store file has one meta record with `parent_agent_id`, `parent_run_id`,
  `parent_tool_call_id`, `depth: 1` and `kind: "subagent"`; `store.Summarize` carries them.
- [x] `anvil.List` reports the child with `ParentAgentID`, `Depth: 1`, `Kind: "subagent"` and
  `TaskTitle`; `DeleteAgent` on the parent removes the child's file and checkpoints too. (The
  host wire fields and the editor's session tree are p_0.42.3.)
- [x] At `MaxDepth`, the child's `Registry.Defs()` has no `spawn_agent`; a direct call returns the
  registry's `unknown tool` error.
- [x] The ninth spawn of one run tree returns a tool error naming `MaxAgents`; the counter resets
  on the next run.
- [x] A child's `write_file` reaches the inherited permission callback with `AgentID` = the
  child, `Depth` = 1; denying it makes the child's tool result an error and the parent's run
  continues.
- [x] `OnEvent` receives the child's `assistant`, `tool_call` and `tool_result` events with the
  parent's id, the spawn call id and the child's agent id.
- [x] A child model error yields `is_error: true` on the spawn result and a finished parent run.
- [x] `Subagents.Enabled` false registers no tool and changes no existing test's tool list.
- [x] `go test ./...` green; `gofmt`/`go vet` clean.

## Non-goals

- Background subagents and any task table (p_0.42.2).
- Host RPCs, event-wire fields and editor rendering (p_0.42.3).
- Workflows (p_0.42.4).
- Plugin tools, caller `Options.Tools`, skills, or a different cwd in a child.
- A model-driven choice of subagent: the model calls the tool, as with every tool.
