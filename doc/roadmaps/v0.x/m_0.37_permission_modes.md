# Milestone 0.37 — Permission modes (a complete ladder)

**Status:** done  
**Product version:** 0.37.x

Both phases are delivered — `p_0.37.1` the two decisions the ladder was missing, `p_0.37.2`
the resolution and the surfaces that report it. The problem statement below is the state this
milestone was planned against, kept as the record of why these are the changes being made.

Two things the milestone did *not* build, recorded so the omissions stay decisions. `auto` is
a non-goal, argued under Non-goals below. A user-level or managed default mode is a non-goal
of p_0.37.2: the declaration lives in `.anvil/permissions.json`, the file a reader can find,
and a precedence chain above it is a later question — the resolution has one step from the
file, and `resolveMode` is the single place a second step would go.

## Goals

0.36 gave a session a rule table and a shell analyzer, so *what a call may do* is written down
in a file and a decision can name the rule that made it. What is left is the layer above:
the **mode**, which decides only whether to ask. That layer has four values today and three
defects.

1. **No mode answers no.** `ask`, `accept_edits`, `plan` and `bypass` are all satisfied by a
   person at a keyboard. A run with nobody watching — a script, a job, an agent left running —
   has no way to say "do only what the workspace's rules already allow". `bypass` is the
   closest thing to it and it is the opposite.
2. **`bypass` overrules a rule that asked.** The mode is supposed to skip the *asking*, not the
   policy — and the policy includes an `ask` rule, which has no other purpose than to
   interrupt. Because `bypass` installs an always-allow callback, `{"effect":"ask","tool":
   "shell","pattern":"git push:*"}` is silently answered yes. Claude Code resolves this the
   other way: an explicit ask rule still prompts in `bypassPermissions`.
3. **A workspace cannot say which mode its sessions start in.** The choice is remembered per
   workspace by the *client* (`workspaceState`), so it is a habit of one machine rather than a
   property of the repository. A team that wants "edits are fine here, nothing runs without a
   prompt" has nothing to commit.

The milestone is therefore not "add modes". It is: **the ladder becomes complete, and every
way into a mode becomes sayable.**

## Overall acceptance

1. `dont_ask` refuses every gated call no `allow` rule covers, quotes the rule when a rule is
   what asked, and never shows an approval card.
2. Under `dont_ask`, an `allow` rule still runs the call with no prompt, and a `deny` rule
   still refuses with its reason.
3. Under `bypass`, a matching `ask` rule opens the card and its answer is honoured; a call no
   rule mentions still runs unprompted; a `deny` still holds.
4. `.anvil/permissions.json` may carry `"defaultMode"`. A client that sends no mode gets the
   one the file declares; a client that sends one gets what it asked for.
5. A `defaultMode` the host will not honour — `bypass`, or a word the ladder does not have —
   starts the session in `ask` and is reported in words, on the session result and on
   `permissions.get`, naming the value.
6. A rule written from the approval card leaves the file's `defaultMode` alone.
7. `load_permissions: false` ignores the file's `defaultMode` as well as its rules.
8. `go test ./...` green in `source/`; `npm test` green in `editors/vscode/`;
   `npm run smoke:vsix` green.

## Non-goals

- **A mode that decides by model.** Claude Code's `auto` reviews each call with a classifier
  model, degrades to Manual after repeated blocks, and temporarily suspends broad allow rules
  while it is on. It is the one mode that is not deterministic, and 0.36's whole premise is
  that an automatic decision must be one the user could have predicted from the file — a
  classifier review is not in any file. It would also need a second model call per gated
  action, and its own model requirements. Named here so the omission is a decision rather than
  an oversight; it is not planned.
- **OS-level enforcement** (containers, seccomp, filesystem isolation). Mode selects whether
  to ask; [32](../../design/v0.x/32-sandbox-code-review.md) is the isolation layer.
- **Modes per tool, or per rule.** One mode governs a session.
- **A mode's own rule set.** A mode composes options; it does not carry policy.
