# Milestone 0.57 — Worktree workers

**Status:** in_progress

Run selected workers in isolated Git worktrees, attribute their checkpoints to the correct
worker and branch, and bring results back through explicit merge/conflict review. This is a
high-risk capability: validation, routing, merge, and cleanup fail closed whenever ownership or
repository state is ambiguous. The design is chapter
[57](../../design/v0.x/57-worktree-workers.vscode.md).

## Goals

1. Define a secure, bounded worktree lifecycle with explicit ownership and cleanup.
2. Route workers to worktrees and attribute every checkpoint and event to that isolation.
3. Require human review for merge/conflict outcomes and provide safe cleanup.
4. Apply one extension patch increment per user-visible delivery batch from the then-current
   `package.json`; milestone 0.57 is not a plugin patch number.

## Ordering

p_0.57.1 establishes ownership and lifecycle boundaries. p_0.57.2 may route work only through
that boundary. p_0.57.3 is last because review and cleanup require both lifecycle metadata and
worker attribution.

## Overall acceptance

1. Lifecycle tests reject paths outside the managed root, symlink/junction escapes, foreign
   worktrees, dirty ambiguous state, and forged ownership records before mutation.
2. Routing tests prove each worker uses its assigned worktree and that events, diffs, and
   checkpoints cannot be attributed to another worker or the primary tree.
3. Merge tests require explicit review, preserve conflicts for inspection, perform no automatic
   destructive resolution, and leave the primary worktree unchanged on any failed precondition.
4. Cleanup tests remove only proven-owned clean resources; uncertainty produces a visible blocked
   state and retains data.
5. `cd source && go test -count=1 ./...` and `cd editors/vscode && npm test` pass, including
   adversarial Git fixtures; each visible delivery verifies an exact one-patch version bump and
   synchronized declarations.

## Non-goals

- Automatic conflict resolution, automatic merge, or deleting unverified worktrees/branches.
- Running workers outside the local repository trust boundary.
- Treating Git commands, paths, refs, or ownership metadata supplied by a model as trusted.
