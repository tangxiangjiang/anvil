# Phase p_0.8.2 — Secret redaction

**Status:** done

## Goals

Reduce secret leakage into events, tool results shown to the model, and host logs (design 08).

## Scope

- Redact or truncate obvious patterns (API keys, `Bearer`, private key PEM headers) in tool_result content emitted on the stream (and optionally truncated store message bodies)
- Never persist `APIKey` in meta (already); add regression test
- Document that redaction is best-effort, not a DLP product

## Non-goals

- Encrypting the store at rest
- Scanning the entire cwd for secrets on Create

## Tasks

1. Shared redaction helper.
2. Apply at tool result emit boundary.
3. Tests with synthetic secrets.
4. Update design 08.

## Acceptance

- [x] Tool result containing a fake `sk-` / Bearer token is redacted in stream content.
- [x] Store meta regression: no api_key field.

## Depends-on

- 0.2 store; streaming events
