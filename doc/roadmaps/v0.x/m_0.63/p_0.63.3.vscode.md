# p_0.63.3 — VS Code sandbox surface and release gates

**Status:** planned
**Milestone:** [m_0.63_container_sandbox.vscode.md](../m_0.63_container_sandbox.vscode.md)
**Linked design:** [63-container-sandbox.vscode.md](../../../design/v0.x/63-container-sandbox.vscode.md)

## Goals

Make sandbox execution understandable and prove the boundary on supported platforms/runtimes.

## Scope

Profile selector, preflight, live resources/logs, stop/cleanup, setup diagnostics, evidence
projection, accessibility, Docker/Podman/rootless matrix, package/version gates.

## Tasks

1. Add explicit sandbox profile selection to eligible Worktree execution.
2. Preview image digest, mounts, network, resources, and secret names before start.
3. Show lifecycle/resources/logs and separate Worktree from process isolation.
4. Add runtime installation/rootless/image/policy diagnostics.
5. Run adversarial and packaged smoke suites across the supported matrix.

## Acceptance

- Opening/refreshing the surface starts no container.
- Confirmation binds the exact displayed spec digest.
- UI retains blocked cleanup/recovery details after reconnect.
- Platform/runtime packages advertise only tested capabilities.

## Non-goals

- Kubernetes/fleet UI or automatic sandbox selection that weakens policy.

## Depends-on

- p_0.63.1 and p_0.63.2.
