# p_0.63.1 — Runtime capability and policy boundary

**Status:** planned
**Milestone:** [m_0.63_container_sandbox.vscode.md](../m_0.63_container_sandbox.vscode.md)
**Linked design:** [63-container-sandbox.vscode.md](../../../design/v0.x/63-container-sandbox.vscode.md)

## Goals

Define runtime-neutral sandbox capabilities and fail-closed execution policy.

## Scope

Runtime discovery, image digest, mount/network/secret/resource specs, policy digest, unsupported
states, configuration, protocol/store schemas, and security tests.

## Tasks

1. Define sandbox runtime/spec/instance contracts and capability negotiation.
2. Resolve mutable image references to approved immutable digests.
3. Canonicalize and classify every mount; default project write access to one Worker Worktree.
4. Define network modes, opaque secret handles, process/resource limits, and no-downgrade rules.
5. Add fake runtime and adversarial path/policy fixtures.

## Acceptance

- Unsafe mounts, runtime sockets, mutable image drift, unsupported limits, and policy mismatches
  fail before instance creation.
- Secrets and host credentials are absent from specs, logs, and model data.
- Capability reports distinguish unavailable from weaker isolation.

## Non-goals

- Launching real workload containers or VS Code UI.
