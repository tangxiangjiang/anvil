# p_0.63.2 — Container lifecycle, execution, and recovery

**Status:** planned
**Milestone:** [m_0.63_container_sandbox.vscode.md](../m_0.63_container_sandbox.vscode.md)
**Linked design:** [63-container-sandbox.vscode.md](../../../design/v0.x/63-container-sandbox.vscode.md)

## Goals

Run a routed Worker inside the approved sandbox and recover safely across cancellation/crash.

## Scope

Container adapter, Worktree mount, non-root process, network/secrets, resource enforcement,
durable lifecycle, logs, process-group stop, checkpoint boundary, orphan reconciliation, cleanup.

## Tasks

1. Implement the first runtime adapter behind the p_0.63.1 contract.
2. Bind instance to Worker/execution/run and mount/policy/image digests.
3. Enforce limits and cancel the whole process tree.
4. Reconcile runtime and durable facts without adopting unknown instances.
5. Remove only proven-owned instances/profiles/volumes and retain blocked details.

## Acceptance

- Escape, host-read, secret, network, resource, fork-bomb, timeout, and orphan fixtures fail closed.
- Cancellation and restart have one durable terminal/recoverable outcome.
- Checkpoints contain Worktree files only, never layers/caches/secrets/runtime metadata.
- Cleanup is idempotent and ownership-bound.

## Non-goals

- Remote scheduling, whole-container snapshots, or host-home compatibility mounts.

## Depends-on

- p_0.63.1 and 0.60.
