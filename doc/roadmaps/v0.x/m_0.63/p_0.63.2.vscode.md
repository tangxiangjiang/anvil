# p_0.63.2 — Supervised browser verification

**Status:** planned

## Goals

Add separately gated browser read, interaction, and external-write evidence.

## Scope

- Add supervised generated-profile browser lifecycle, origin/network/resource/download bounds.
- Capture ordered DOM/accessibility/screenshot/console/network evidence.
- Resolve model target hints to fresh fingerprints; reject stale/hidden/ambiguous/cross-origin targets.
- Separate `browser_read`, `browser_interact`, and action-specific `browser_external_write`.
- Quarantine downloads; bind uploads to exact approved file/origin.
- Add opaque credential handles approved for one destination origin/field; values stay outside
  model-visible data, traces, logs, and exports.
- Make profile retention explicit/ephemeral-by-default and export ordered secret-redacted traces.

## Tasks

1. Implement supervised browser lifecycle, evidence capture, policy, and target fingerprints.
2. Add permission tiers, opaque credential handles, quarantine, upload, and profile retention.
3. Test injection, stale targets, secret exclusion, trace export, crash, and restart.

## Acceptance

- Read-only sessions cannot interact or persist unsafe downloads.
- Page/prompt injection cannot alter permissions, policy, origins, tools, or secrets.
- External writes require fresh approval and before/after evidence.
- Stop/crash/restart leaves no uncontrolled browser.
- Profile deletion/retention and trace export obey the displayed policy.

## Non-goals

- Desktop input, CAPTCHA bypass, or unattended high-impact action.

## Depends-on

- p_0.63.1 and 0.62 sandbox policy where available.
