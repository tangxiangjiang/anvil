# Milestone 0.63 — Container sandbox workers

**Status:** planned

Add an OS-level execution tier for selected Workers and tools with explicit mount, network,
secret, process, and resource policy. Design:
[63](../../design/v0.x/63-container-sandbox.vscode.md).

## Goals

1. Define a runtime-neutral sandbox capability and policy contract.
2. Deliver container lifecycle, Worktree mounts, network/secrets, resource bounds, and recovery.
3. Integrate sandbox selection/evidence into VS Code and cross-platform release gates.

## Overall acceptance

- The sandbox cannot read host home, primary/sibling Worktrees, runtime sockets, or ungranted
  secrets.
- Default network deny and resource/process limits are enforced.
- Runtime/image/policy/mount/Worker identities are immutable and restart-safe.
- Unsupported isolation never silently downgrades.
- Generated changes return only through reviewed Worktree commits/artifacts.

## Non-goals

- Claiming container/VM equivalence, Kubernetes scheduling, or mounting the host workspace/home.
