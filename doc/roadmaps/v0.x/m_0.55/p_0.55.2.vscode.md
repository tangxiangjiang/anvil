# p_0.55.2 — Partial approval and dependencies

**Status:** done
**Milestone:** [m_0.55_structured_plans.vscode.md](../m_0.55_structured_plans.vscode.md)
**Linked design:** [55-structured-plans-and-workflow-control.vscode.md](../../../design/v0.x/55-structured-plans-and-workflow-control.vscode.md)

## Goals

Allow explicit approval or denial of plan subsets while enforcing dependencies and preserving a
durable, auditable transition history.

## Scope

Approval commands, dependency readiness, denied/blocked states, optimistic concurrency,
idempotency, execution gates, audit events, and restart behavior.

## Tasks

1. Define item and batch approval/denial transitions with expected plan revision.
2. Compute readiness only from approved items whose dependencies completed successfully.
3. Persist actor, revision, decision, timestamp, and reason in the journal.
4. Reject stale, duplicate-conflicting, or dependency-invalid commands before worker start.
5. Follow the exact one-patch policy from the then-current extension version for any visible batch.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestPlan(PartialApproval|Dependencies|Revision|Restart)'`.
- Tests prove approving a dependent alone starts nothing; completing its approved prerequisites
  makes it ready; denying a prerequisite blocks dependents with a stable reason.
- Concurrent commands with the same expected revision yield one accepted transition and one
  conflict; replay produces no duplicate worker start.
- Failure does not invoke a reviewer or create/rewrite a plan automatically.

## Non-goals

- Automatic approval, reviewer agents, automatic retry, or autonomous re-planning.
- VS Code layout and interaction details.
- Dependency inference by a model.
