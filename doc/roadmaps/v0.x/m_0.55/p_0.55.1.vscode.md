# p_0.55.1 — Unified plan schema

**Status:** done
**Milestone:** [m_0.55_structured_plans.vscode.md](../m_0.55_structured_plans.vscode.md)
**Linked design:** [55-structured-plans-and-workflow-control.vscode.md](../../../design/v0.x/55-structured-plans-and-workflow-control.vscode.md)

## Goals

Define one versioned plan representation shared by SDK, host protocol, persistence, and VS Code.

## Scope

Plan/item identity, descriptions, status, dependencies, acceptance evidence, approval state,
schema versioning, validation, wire encoding, and JSONL/SQLite persistence.

## Tasks

1. Specify required fields, stable IDs, enums, and canonical dependency references.
2. Validate cycles, missing dependencies, duplicate IDs, and unknown schema versions.
3. Add lossless protocol/store round trips and migration boundaries.
4. Publish shared fixtures for Go and TypeScript tests.
5. Apply a package patch bump only for a user-visible delivery, exactly once from the current
   extension version and synchronized everywhere required.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestPlan(Schema|Validate|RoundTrip|Store)'` proves
  valid fixtures round-trip through wire, JSONL, and SQLite with equivalent semantic content.
- `cd editors/vscode && npm test -- --runInBand` consumes the same fixtures without editor-only
  fields or coercion.
- Duplicate IDs, cycles, missing dependencies, malformed approval state, and unknown schema
  versions are rejected before execution.
- Version tests do not map roadmap 0.55 to an extension version.

## Non-goals

- Approval execution, plan generation quality, automatic review, or automatic re-planning.
- A general-purpose workflow language.
- Editing plans concurrently.

## Depends-on

- Milestone 0.54 durable records.
- Existing workflow and delegation identities.
