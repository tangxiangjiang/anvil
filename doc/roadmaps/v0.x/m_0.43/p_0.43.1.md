# p_0.43.1 — A context budget in the SDK

**Status:** done (2026-10-19)
**Milestone:** [m_0.43_context_management.md](../m_0.43_context_management.md)
**Linked design:** [42-context-management.md](../../../design/v1.0/42-context-management.md) §2,
[03-runtime-loop.md](../../../design/v1.0/03-runtime-loop.md),
[09-extensibility.md](../../../design/v1.0/09-extensibility.md)

## Goals

1. **A budget in tokens with a declared window.** `Options.Context` names the window, the fraction
   at which to compact and how much tail to keep; the runtime estimates the conversation against
   it. `HistoryMaxChars` keeps working unchanged for embedders that use it.
2. **Compaction that cannot break a turn.** The cut is a user-message boundary, so a tool result
   never loses the assistant call that produced it, and compaction also runs between steps of a
   long run instead of only before it.
3. **Compaction on demand.** `Agent.Compact` compacts an idle agent, persists the same summary
   marker Resume already reads, and returns counts; `Agent.ContextUsage` answers the meter.
4. **A visible compact.** The runtime emits `EventCompact`; the reader projection gains a
   `summary` entry so a replayed conversation shows the same divider a live one did.

## Scope

`source/internal/compress/budget.go` (new), `source/internal/compress/compress.go` (shared
helpers), `source/internal/runtime/loop.go`, `source/context.go` (new public types and,
optionally, methods), `source/agent.go`, `source/options.go`, `source/types.go`,
`source/transcript.go`, `source/internal/store/store.go` (no schema change expected), tests.

## Tasks

1. **The estimate** (`internal/compress`):

   ```go
   func Estimate(messages []llm.Message) int
   ```

   Per message: `ceil(chars/4) + 4`; `+85` when it carries tool calls (name + arguments
   included in chars); `+EstimateImageTokens` (1600) per image part. Documented as an estimate,
   never called "tokens used".

2. **Budget compaction** (`internal/compress/budget.go`):

   ```go
   type BudgetOptions struct {
       MaxTokens int
       KeepRecent int
       Force bool
   }
   func Compact(ctx context.Context, completer llm.Completer, model string,
       messages []llm.Message, opts BudgetOptions) (Result, error)
   ```

   - Trigger when `Force`, or `MaxTokens > 0 && Estimate(messages) > MaxTokens`.
   - System messages are kept and never summarized (as in `Apply`).
   - The tail begins at the earliest `user` message at or after the `KeepRecent` mark, so the
     first tail message is a user turn and no tool result is orphaned. If there is no such
     boundary, keep the last user message and everything after it; if there is no user message at
     all, keep the last `KeepRecent` non-system messages.
   - Summarization reuses `summarize` (completer, then deterministic fallback). The summary
     message keeps today's shape: role `user`, name `anvil.summary`, content
     `[conversation summary]\n…`.
   - `Result` gains `Before`, `After` (estimates) and `Summarized` (number of messages folded);
     `DidCompress` keeps its meaning.

3. **The options** (`source/options.go`):

   ```go
   type ContextOptions struct {
       WindowTokens  int     // 0 = unknown; auto-compaction off
       AutoCompactAt float64 // fraction of WindowTokens; default 0.8
       KeepRecent    int     // messages kept verbatim; default 8
   }
   ```

   Normalization: `AutoCompactAt` outside `(0, 1]` becomes 0.8; `KeepRecent < 2` becomes 8 (at
   least one user message and one reply). The threshold is
   `int(window × fraction)`, floored at 1.

4. **The runtime** (`internal/runtime/loop.go`): `Config.Context ContextOptions` plus the model's
   `Provider` is irrelevant here. Replace the single run-start compression block with a helper
   called at two points:

   - before the loop (after the new user message is appended), and
   - at the top of each step, before building the request.

   When it compacts: replace `messages` with the result, `sink` the summary marker and the
   returned tail exactly as today, and `emit` an `EventCompact` carrying before/after/summarized
   and the window. Compaction is skipped when `WindowTokens == 0`. The trigger uses the estimate
   of the messages about to be sent, so the check inside the loop is exact for that request.

5. **The public surface** (`source/types.go`, `source/context.go`):

   ```go
   const EventCompact EventType = "compact"

   type CompactInfo struct {
       Reason string // "auto" or "manual"
       Before, After, Summarized, Window int
   }
   type ContextUsage struct {
       EstimatedTokens int
       WindowTokens    int
       CompactAtTokens int
       Messages        int
   }
   type CompactResult struct {
       Compacted bool
       Before, After, Summarized int
       Summary string
   }
   ```

   `Event.Compact *CompactInfo` is set only on `EventCompact`.

6. **Manual compaction** (`source/agent.go`):

   ```go
   func (a *Agent) Compact(ctx context.Context) (CompactResult, error)
   func (a *Agent) ContextUsage() ContextUsage
   ```

   - `Compact` locks, refuses while `a.running` (`a run is in progress`), and uses the budget
     compactor with `Force: true` over `a.history`. When there is at most one non-system turn it
     returns `Compacted: false, nil`.
   - On success it persists one `store.TypeSummary` record (run id empty) and replaces
     `a.history` with the compacted slice. The tail is already stored, so no messages are
     re-persisted.
   - `ContextUsage` estimates `a.history` plus `a.systemPrompt`, applies the same threshold
     computation, and reports the message count. It is safe to call while idle or running (it
     reads a copy under the mutex).

7. **Replay** (`source/transcript.go`): add `TranscriptSummary = "summary"` and project
   `store.TypeSummary` records as entries carrying `Content` (the summary text) and `RunID`. The
   model's history rule does not change.

8. **Tests.** Pure estimate tests; budget trigger under/over; tail-boundary tests including a
   history whose `KeepRecent` mark lands inside a tool exchange; mid-run compaction with a
   scripted provider (cross on step 2, assert the second request's first non-system message is
   the summary and the first tail message is a user turn); manual compact idle / running /
   nothing-to-do; resume after compact; transcript summary projection.

## Acceptance

- [x] `Estimate` is monotonic, counts tool-call names and arguments, and adds the image cost;
  an empty conversation is zero.
- [x] A conversation below `AutoCompactAt × WindowTokens` is sent unchanged; one above it is
  summarized before the first request.
- [x] A run that crosses the threshold between steps compacts once, emits one `compact` event,
  and finishes with the same final answer it would have produced otherwise.
- [x] The first message after a summary is a `user` message; no tool result is separated from its
  tool call.
- [x] `Agent.Compact` persists exactly one summary record and returns before/after/summarized;
  it is refused while a run is in flight and is a no-op on a single-turn history.
- [x] Resume after either compaction loads the summary plus the messages after it; the transcript
  still shows the pre-summary turns and a `summary` entry.
- [x] `ContextUsage` reports the estimate, the window, the threshold and the message count.
- [x] `go test ./...` green; `gofmt`/`go vet` clean.

## Implementation notes

Written back in the same commit; chapter 42 §2 is the contract.

- **The estimate counts runes, not bytes.** `runeTokens` uses `utf8.RuneCountInString`, so a CJK
  conversation is not under-counted by a factor of three (one rune is usually one token, while
  its three UTF-8 bytes would suggest three quarters of one). `Estimate` is a budget trigger and
  a meter, never the provider's count.
- **Step 0 is not checked twice.** The pre-loop call runs on exactly the slice step 0 would send,
  so the in-loop check starts at step 1. Repeating it at step 0 could only compact twice: the
  second summary would fold the first, and the client would see two dividers where one turn
  crossed the budget.
- **The tail rule moves forward, never backward.** `tailStart` takes the first `user` message at
  or after the `KeepRecent` mark; if there is none (a long tool exchange with no new user turn)
  it falls back to the last user message, which keeps the whole current turn. When that fallback
  lands at index 0 there is nothing older to fold, so `Compact` returns unchanged instead of
  writing an empty summary. This is also the honest limit of mid-run compaction: it folds prior
  turns of the same run, not the current turn's own steps.
- **Manual compaction re-sinks the tail.** `historyFromRecords` resumes from the last marker
  forward, so a marker with no records after it would resume into a summary alone. `Agent.Compact`
  therefore writes the marker and then the kept messages through `persistMessage`, exactly as
  the runtime's sink does; the append-only file gains a re-anchored copy of turns it already
  held, which Resume ignores because they precede the marker.
- **One compaction at a time.** `Agent.Compact` sets `compacting` under the lock, releases the
  lock for the summarizer call, and `Send` refuses with `a compaction is in progress` while it
  is set. The summarizer is a model call; holding the lock across it would stall every reader.
- **The public threshold mirrors the runtime's.** `contextThreshold` in `source/context.go` is
  the same arithmetic as `runtime.ContextBudget.threshold`; `ContextUsage` reports the
  normalized options so the SDK and the runtime cannot disagree about where the mark is.
- **The transcript gains a boundary, not a deletion.** `transcriptFromRecords` projects
  `store.TypeSummary` as `TranscriptSummary`, carrying the text and the run id. Pre-summary
  messages are still entries, which is what lets a replay draw both the turns and the divider.

## Non-goals

- An exact tokenizer, a model-window table, or pixel-accurate image costing.
- Compacting the system prompt, compacting children, or hierarchical memory.
- Deleting or rewriting pre-summary records.
- A background compactor or a compaction triggered from a tool.
