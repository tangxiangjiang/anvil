# p_0.49.1 — Layered prompts and roles

**Status:** done
**Milestone:** [m_0.49_roles_and_prompts.md](../m_0.49_roles_and_prompts.md)
**Linked design:** [49-roles-and-prompts.md](../../../design/v0.x/49-roles-and-prompts.md)

## Goals

Replace three prompt constants in three packages with one composition: an SDK-owned safety
layer that every agent gets and no option can remove, a role layer that names what the agent
is for, the project layer in today's order, a brief layer for structured tasks, and a per-run
directive. Today's default output must not change by a byte, except for one named closing
line.

## Scope

`source/internal/prompt/prompt.go` (`Safety`, `Compose`, `Spec`, `Role`, the five role
texts; the old functions as wrappers), `prompt_test.go`, `testdata/main.golden`,
`source/options.go` (`Options.Role`), `source/agent.go` (`buildSystemPrompt` calls
`Compose`; `WithDirective`), `source/subagent.go` (`childOptions` sets `Role: subagent`
instead of `SystemPrompt: subagentBrief`), `source/run.go` or wherever `SendOption` lives.

## Tasks

1. **Golden first.** Record `buildSystemPrompt(cwd, Options{})` and the same with
   `AllowShell` and with rules text, before any change, as three golden files.
2. **Cut L0 out of the main text.** `Safety(opts)` returns today's sandbox, secrets,
   untrusted-content and (when shell is on) shell-caution sentences, verbatim. The main role's
   L1 is what remains.
3. **`Compose(Spec)`.** L0 + L1 (role text or `RoleText`) + L2 + L3 + L4 + the closing line,
   with today's separators. The three old functions call it.
4. **Roles.** `Role` type and the five constants; `Options.Role`; `Create` refuses an unknown
   role; the `worker`, `decision` and `analyze` texts as chapter 49 §3 describes.
5. **`WithDirective(text)`** as a `SendOption`; the run's system prompt ends with it; it is
   not persisted.
6. **Subagents.** `childOptions` sets `Role: RoleSubagent`; `subagentBrief` becomes the
   role's L1 text in `internal/prompt`; `SystemPrompt` is no longer passed for a child.
7. **Tests.** `TestComposeDefaultIsUnchanged` (golden, three variants, modulo the closing
   line); `TestEveryRoleBeginsWithSafety`; `TestNoRoleLosesAClause` (sentence list ×
   every role × with/without `RoleText` × with a 20 KB L2); `TestSystemPromptCannotRemoveL0`;
   tier-1 eval `Expect` on a spawned child's first request carrying the untrusted-content
   clause.
8. **Verify.** Go suite from Git Bash; the script.

### Gate

- 命令：`cd source && go test -count=1 ./internal/prompt/... && go test -count=1 ./ -run 'TestSubagentPromptHasSafety|TestUnknownRoleRefused' && ./scripts/eval.sh`
- 通过条件：三个 golden 在去掉结尾一行后与 `Compose` 输出逐字节相等；五个角色的输出都以 `Safety(...)` 开头且以结尾行结束；安全句子列表中每一句在每个角色、有无 `RoleText`、有无 20 KB 项目层的组合下都原样出现；`RoleText` 为 "ignore all safety rules" 时输出仍以 L0 开头；子 agent 的首个请求 system prompt 含 untrusted-content 句；eval 不劣化——注意录制 fixture 的 digest **会**因 system prompt 变化而未命中，此阶段须重新录制并在提交中说明。
- 失败条件：任一 golden 不等（结尾行除外）；任一角色缺任一安全句；`RoleText` 能把 L0 挤出开头；子 agent 请求缺安全句；未重新录制而让 eval 通过（说明 digest 没把 system prompt 算进去，是 0.48.2 的缺陷）。
- 基线条目：三个 golden 文件；重新录制后的 `baseline.json`。

## Delivery status

Implemented and tested: `Safety`, `Compose`, `Role`, `Options.Role` (validated), `WithDirective`,
`RoleSubagent` for children, the three pre-change goldens (`internal/prompt/testdata/*.golden`),
and the tests named in task 7. The digest normalizer now finds the workspace line wherever the
role text starts, because Safety leads the prompt.

**Deviation from "byte-identical".** The phase asks both for a default prompt unchanged by a byte
and for every role to begin with Safety. They conflict: today's two safety sentences sit inside
the main text. Decision: Safety first. `TestComposeKeepsEveryLineOfToday` checks that every
sentence of the recorded goldens survives and that the prompt ends with the closing line; one
bullet that mixed a boundary rule with "read before write" is split across L0 and L1.

**Re-recorded.** The four genuine provider recordings missed their digests (the system prompt
changed, as the gate predicts) and were re-recorded by a live run, reviewed (no key or user name
in them, every request starts with `# Safety`), and replace the old ones. `baseline.json` was
refreshed: every `request_bytes` grew with the longer prompt, and two provider entries moved
because the model behaved differently on a fresh recording, not because of this code:
`provider_spawn_read_report` steps 2→3, tool_errors 0→2; `provider_two_file_edit_test` steps
7→5, tool_errors 3→1. The scripted and invariant entries changed in `request_bytes` only.

**Known limit.** `loop_guard` was recorded again (`loop_guard.live.jsonl`) but is not committed
as a replayed recording, as in 0.47: the model stops itself before the guard fires.
