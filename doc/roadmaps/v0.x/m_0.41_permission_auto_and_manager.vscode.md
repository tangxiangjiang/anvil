# Milestone 0.41 — Auto mode and a permissions manager

**Status:** done (2026-10-19)  
**Product version:** 0.41.x

0.36 made the rule shape strong — an effect, a tool glob, a command line, a path glob, a token
prefix, the shell analyzer behind `readonly`. 0.37 made the mode ladder complete. What neither
finished is the part a person uses every day: **a rung between "edits are fine" and "nothing
asks"**, and **a way to see and change a rule without opening JSON**.

Claude Code has both, differently: an `auto` mode driven by a model classifier, and a unified
Permissions dialog. This milestone takes the same two user-facing promises and keeps them with
what Anvil already has — a deterministic analyzer and a rule file the SDK can validate — rather
than adding a model call to the permission path.

## Goals

1. **An `auto` rung.** Read-only shell commands, in-workspace writes and edits, and the
   operator-configured test/build commands run without a card; everything else still asks.
   Written rules outrank the classifier, including a rule whose effect is `ask`.
2. **One classifier, in the SDK.** `AutoApproveCall` is a pure function over the same call facts
   the registry matches rules on, so "auto allowed this" and "rule 4 allowed this" cite the same
   evidence. No model call, no filesystem read, no new trust boundary.
3. **A permissions manager.** A webview document that lists the workspace's rules, edits effect,
   tool, pattern and reason, adds and deletes rows, and sets `defaultMode` — with validation in
   the host and an atomic write, and with hand editing still one click away.

## Overall acceptance

1. The composer offers six modes, in one order, on both sides of the wire; a workspace may
   declare `"defaultMode": "auto"` and a new session starts in it.
2. In `auto`: `git status` runs without a card, `go build ./...` asks, `rm -rf` asks, a
   `write_file` runs, `web_search` and an MCP call ask. A rule of effect `ask` still opens a card.
3. The classifier has no I/O and no model call; its tests feed it the same arguments the registry
   sees.
4. "Anvil: Open Permission Rules" and the composer's Permissions button open the manager. The
   manager lists the file's rules, saves an edit and a deletion through the host, changes
   `defaultMode`, refuses a malformed file instead of overwriting it, and opens the JSON on
   request.
5. `cd source && go test ./...` green; `cd editors/vscode && npm test` green; packaging and the
   packaged smoke test green.

## Non-goals

- A model-driven classifier, or any extra request on the permission path.
- User/global rule scopes, importing Claude Code's rule syntax, or managing MCP servers and hooks
  from this panel.
- Rule reordering, rule search, or a rules marketplace.
- Changing how `deny` is enforced, or how `defaultMode` is honoured; both stay where 0.36/0.37
  put them.
