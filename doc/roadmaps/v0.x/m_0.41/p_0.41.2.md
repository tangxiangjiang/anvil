## Goals

1. **A surface for the rule shape.** List `.anvil/permissions.json`'s rules, edit effect, tool,
   pattern and reason, add and delete rows, and set `defaultMode` — without knowing JSON.
2. **One writer, one validator.** The panel sends the whole list to the host; the host compiles
   it with the same parser a session uses and writes it atomically. A list the reader would
   refuse never reaches the disk.
3. **A malformed file stays a file to fix, not one to overwrite.** When the file cannot be read,
   the manager shows the problem and the place, disables structured editing, and offers the JSON.
4. **No dead-end.** Hand editing remains one click away, both from the panel and from a command.

## Tasks

1. **`SavePermissionRuleFile`.** New public function in `source/permissionrules.go`:

   ```go
   // SavePermissionRuleFile replaces the workspace rule file with exactly these
   // rules and this declaration.
   func SavePermissionRuleFile(cwd string, rules []PermissionRule, defaultMode string) error
   ```

   Build `permissions.File{Version: 1, DefaultMode: (nil unless non-empty), Rules: ...}`, marshal
   it with `MarshalIndent` plus a trailing newline, run it through `permissions.Parse` and return
   the same `*PermissionRuleError` shape `AddPermissionRule` returns, then write through the
   existing `writeRuleFile` (temporary file plus rename, `0644`). Do not read the existing file:
   the caller has the version it showed the user, and this function's contract is replacement.

2. **`permissions.set`.** New host method and types:

   ```go
   type PermissionsSetParams struct {
       Rules       []RuleSpec `json:"rules"`
       DefaultMode string     `json:"default_mode,omitempty"`
   }
   ```

   Handler order:
   1. decode; reject a rule with an empty trimmed `tool` with `errInvalidParams`;
   2. default an empty effect to `allow` (the panel always sends one, but the rule file's own
      default is the same);
   3. when `default_mode` is non-empty, require `honouredMode(default_mode) != ""` and refuse
      `bypass` in the words `refusedMode` already uses;
   4. `anvil.LoadPermissionRuleFile(cwd)` first: if it returns an error, refuse with
      `CodeInvalidRequest` and the problem in words — **never** overwrite a file this build
      could not read;
   5. call `SavePermissionRuleFile`; on a `*PermissionRuleError`, return the message and place as
      an invalid-request error;
   6. answer with the same `PermissionsResult` `permissions.get` builds, so the panel renders
      what the file now says rather than what it sent.

   Register `MethodPermissionsSet` in the dispatcher beside `get` and `add`. No
   `ProtocolVersion` bump.

3. **Client plumbing.** `protocol.ts` gains `PermissionsSet: 'permissions.set'` and
   `PermissionsSetParams`; `hostManager.ts` gains
   `savePermissionRules(params): Promise<PermissionsResult>`; `hub.ts` gains
   `savePermissionRules` (delegating) and an instance of the panel.

4. **The panel.** New `src/permissionsPanel.ts`, modelled on `ReviewPanels`:
   - one document per window (`anvil.permissions` view type), revealed rather than duplicated;
   - `enableScripts`, `retainContextWhenHidden` is not needed — reopening re-reads;
   - on `ready`, calls `permissions.get` and posts `{ type: 'state', path, exists, defaultMode,
     rules, problem, loadPermissions }`;
   - on `save`, validates shape (`rules` is a list, each tool a string, effect one of the three)
     and calls `hub.savePermissionRules`; posts back `{ type: 'saved', state }` or
     `{ type: 'error', message }` and never closes the document on failure;
   - on `openFile`, runs the existing file-opening path — extracted from `hub.openPermissionRules`
     into `hub.openPermissionRulesFile()` — which creates the file when missing, opens it, reports
     the problem against it, and warns when `anvil.permissions` is off;
   - trusted workspaces only: `HostManager.assertTrusted()` before the first host call, with the
     same error notice the chat panel uses.
   - `permissionsPanel.test.ts` checks the wiring by text, the way `inputAffordances.test.ts`
     does: `permissions.set` is the only write verb, the webview script uses `textContent`, the
     `defaultMode` select excludes `bypass`, and a `problem` disables Save.

5. **The document.** New `media/permissions.js` and `media/permissions.css`:
   - a row per rule: effect `<select>`, tool `<input>`, pattern `<input>`, reason `<input>`,
     its one-based number, and Delete;
   - Add rule appends an `allow` row with an empty tool, focused;
   - Save sends all rows, trimming whitespace; Reload re-fetches; Open JSON posts `openFile`;
   - the problem banner names the line and column and the controls are disabled while it stands;
   - the `anvil.permissions`-off warning is rendered when the host or settings says so;
   - every value is written with `textContent`; no `innerHTML`.

6. **Entry points.** `hub.openPermissionRules()` opens the panel; `extension.ts` registers
   `anvil.openPermissionRules` (manager) and `anvil.openPermissionRulesFile` (the old behavior);
   `package.json` contributes both, and the composer's **Permissions** button keeps its message
   (`openPermissions` → the manager). The chat panel's unrelated **Rules** button is untouched.

7. **Docs and version.** Update the extension README's permissions paragraph, chapter 36's
   "where a rule is edited" sentence if it names only the file, and chapter 40 if the
   implementation diverges.

## Acceptance

- [x] The manager lists a file's rules in file order, with the one-based numbers a denial quotes.
- [x] Adding, editing and deleting a rule and changing `defaultMode` survive a Reload and are
  visible in the JSON file.
- [x] A rule with an empty tool or a bad effect is refused by the host with a message the panel
  shows; the file is unchanged.
- [x] `defaultMode: "bypass"` cannot be written from the panel, and the refusal is the host's
  sentence.
- [x] A file that will not parse leaves the panel read-only with its problem and place, and Save
  cannot overwrite it.
- [x] With `anvil.permissions` off, the panel says the file is not read.
- [x] The composer's Permissions button and `Anvil: Open Permission Rules` open the manager;
  `Anvil: Open Permission Rules File` and the panel's Open JSON open the file.
- [x] `go test ./...` and `npm test` are green; packaging and the packaged smoke test are green.

## Non-goals

- Reordering rules, search, undo history, or a rule wizard for shell prefixes.
- A user/global rule file or importing Claude Code's rule syntax.
- Editing `permission_groups`, hooks or MCP configuration from this panel.
- Live conflict detection against a hand edit made while the panel is open. Reload re-reads; Save
  is a replacement, and the document says so once.
