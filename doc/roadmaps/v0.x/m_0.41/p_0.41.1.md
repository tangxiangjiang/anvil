## Goals

1. **A rung between `accept_edits` and `dont_ask`.** A session in `auto` runs work it can prove
   harmless without a card, and asks about everything else.
2. **The proof is the one Anvil already has.** A shell line is auto-approved only when
   `shellcmd.Analyze` proves the whole line read-only — the analyzer behind the `readonly` rule
   pattern. Writes, edits and patches are auto-approved because the sandbox confines them to the
   workspace.
3. **One classifier in the SDK, one callback in the host.** `AutoApproveCall(tool, args)` is a
   pure function over `tools.CallFactsFor`; the host's `autoHook` consults it and otherwise falls
   through to the ordinary approval card.
4. **Written rules still outrank the mode.** A `deny` never reaches the hook; a rule of effect
   `ask` opens the card, as it does in `bypass`.

## Tasks

1. **`AutoApproveCall`.** New public function in `source/autoapprove.go`:

   ```go
   // AutoApproveCall reports whether auto mode may run this call without asking.
   func AutoApproveCall(tool string, args json.RawMessage) bool
   ```

   Read the call's facts with `tools.CallFactsFor` — the function the registry matches rules
   with. Then:
   - a fact set with a command (the shell): true only when
     `shellcmd.Analyze(facts.Command, runtime.GOOS) == shellcmd.ReadOnly`;
   - a fact set with paths: true for `write_file`, `edit_file`, `apply_patch` (the SDK sandbox
     refuses any path outside the workspace before the tool runs);
   - neither: true for `run_tests` and `build`, whose argv is fixed by the operator and whose
     model-supplied arguments are validated tokens, not a shell;
   - anything else, including a shell call whose command could not be read: false.

   It must not touch the filesystem, the environment, or a model. Doc comment says why each row
   is safe and what it does *not* claim (a read-only command may still read outside the
   workspace, exactly as a `readonly` rule allows).

2. **The mode constant and the ladder.** `proto.go` gains `ModeAuto = "auto"` with the comment
   style of its neighbours, and `PermissionModes` becomes
   `{ModeAsk, ModeAcceptEdits, ModeAuto, ModePlan, ModeDontAsk, ModeBypass}`. `honouredMode`
   needs no change — it reads the list. `groupsForMode` needs no change: `auto` gates the default
   six like `ask`.

3. **The hook.** `permissionHookForMode` gains `case ModeAuto: return s.autoHook(sess, timeout)`.
   `autoHook` is:
   - `req.Rule != nil && req.Rule.Effect == anvil.PermissionEffectAsk` → the ordinary hook;
   - `anvil.AutoApproveCall(req.ToolName, req.Args)` → allow;
   - otherwise → the ordinary hook.

   The session allowlist is consulted by the ordinary hook, so it still wins on a call it covers.

4. **The client.** `protocol.ts` `PermissionModes` gains `'auto'` in the same position;
   `chatPanel.ts` gains `auto: 'Auto'` and `auto`, and a `modeNotice` sentence; the select gains
   `<option value="auto">Auto: safe actions</option>` after *Accept edits*; `media/chat.js`
   repeats the label. The pinned order in `permissionModes.test.ts` is updated with the rest.

5. **Tests.**
   - SDK: `autoapprove_test.go` — read-only true; `git status && rm -rf x` false; a mutating
     command false; an unlexable command false; `write_file`/`edit_file`/`apply_patch` true;
     `run_tests`/`build` true; `web_search`, an MCP tool and an unknown tool false.
   - Host: `approval_test.go` — the six-mode list; `groupsForMode(ModeAuto, nil)` is the default
     six; a read-only shell runs without a card in `auto`; a mutating shell opens one; an `ask`
     rule opens one; a `write_file` runs.
   - Extension: the pinned ladder, the label tables, and the select options.

6. **Docs.** Add the `auto` row to chapter 37's mode table and its text where it describes the
   ladder; update chapter 40 if implementation changed a claim; update the extension README's
   mode sentence and the root README only where it lists modes.

## Acceptance

- [x] `auto` is in `PermissionModes` on both sides, in the same position, with a label and a
  select entry; `permissionModes.test.ts` pins `ask, accept_edits, auto, plan, dont_ask, bypass`.
- [x] In `auto`, `git status` runs without a card; `go build ./...` opens one; a `write_file`
  runs; `web_search`, an MCP tool and an unknown tool open one.
- [x] A rule of effect `ask` opens a card in `auto`; a `deny` is still refused in the registry.
- [x] `AutoApproveCall` has no I/O and no model call, and its tests use the same argument shapes
  the registry receives.
- [x] `go test ./...` and `npm test` are green (383 extension tests).

## Non-goals

- A model classifier, a second request per call, or a confidence score.
- Auto-approving `fetch_url` or any egress.
- Auto-approving a shell line the analyzer cannot prove, even if it *looks* harmless.
- Changing `accept_edits`, `plan`, `dont_ask` or `bypass`.
