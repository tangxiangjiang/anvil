# p_0.57.1 — Worktree lifecycle and security

**Status:** done
**Milestone:** [m_0.57_worktree_workers.vscode.md](../m_0.57_worktree_workers.vscode.md)
**Linked design:** [57-worktree-workers.vscode.md](../../../design/v0.x/57-worktree-workers.vscode.md)

## Goals

Create and manage worker worktrees within a proven repository boundary, with explicit ownership,
bounded resources, and fail-closed cleanup.

## Scope

Repository eligibility, managed root, canonical path checks, ref naming, ownership records,
creation/adoption refusal, quotas, locks, lifecycle states, crash discovery, and safe cleanup.

## Tasks

1. Define trusted repository/worktree identities independently of model-provided strings.
2. Validate canonical paths against traversal, symlink, junction, and case-folding escapes.
3. Create worktrees and refs with collision-safe names and atomic ownership records.
4. Remove only resources proven owned and clean; otherwise retain and report blocked cleanup.
5. Apply the exact one-patch VS Code bump from the current package version only for visible delivery.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestWorktree(Lifecycle|Security|Ownership|Cleanup)'`.
- Adversarial fixtures cover `..`, absolute paths, symlinks, Windows junctions, case variants,
  forged ownership, branch collisions, dirty state, lock contention, and interrupted creation.
- Every uncertain ownership or repository-state case fails before mutation and preserves data.
- Cleanup never runs `git clean -fdx`, force-deletes an unverified branch, or modifies the primary
  worktree.

## Non-goals

- Worker routing, checkpoint attribution, merge UI, or automatic conflict resolution.
- Worktrees outside the local trusted repository.
- Trusting model-generated paths, refs, or shell commands.

## Depends-on

- Milestones 0.51–0.56, all complete.
- Existing Git tool and workspace trust boundaries.
