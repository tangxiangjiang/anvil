# p_0.57.2 — Worker routing and checkpoint attribution

**Status:** done
**Milestone:** [m_0.57_worktree_workers.vscode.md](../m_0.57_worktree_workers.vscode.md)
**Linked design:** [57-worktree-workers.vscode.md](../../../design/v0.x/57-worktree-workers.vscode.md)

## Goals

Route an eligible worker into its assigned worktree and bind every event, diff, task, and
checkpoint to the worker/worktree identity without fallback to the primary tree.

## Scope

Routing policy, worker launch context, cwd/repository verification, identity propagation,
checkpoint namespace, event/wire fields, restart reconciliation, cancellation, and mismatch
handling.

## Tasks

1. Resolve routing from trusted plan and lifecycle records, never prompt text.
2. Verify repository/worktree identity immediately before worker start and each restore.
3. Namespace checkpoints by root run, worker, worktree, and base revision.
4. Fail the worker closed on identity loss, attribution mismatch, or unavailable worktree.
5. Use the current extension package version for any exact one-patch visible delivery bump.

## Acceptance

- `cd source && go test -count=1 ./... -run 'TestWorktreeWorker(Routing|Attribution|Checkpoint|Restart)'`.
- Two-worker fixtures prove writes, events, diffs, and restores remain in their assigned worktrees
  and cannot cross worker namespaces.
- Removing/swapping ownership metadata or changing repository identity before start/restore
  blocks the operation and leaves the primary tree unchanged.
- Restart reconciliation never silently reroutes a worker to the primary worktree.

## Non-goals

- Merge/conflict review or cleanup UI.
- Dynamic worktree reassignment while a worker runs.
- Automatic retry in another worktree after a security failure.
