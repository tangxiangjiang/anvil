# p_0.46.21 — A mark you can see, and a word that turns

## Goals

The working line of p_0.46.20 answered "is it alive?" but read as one more muted fact: a
14px mark in the description colour, too small to notice beside the 0.85em text, and a single
word that never changed. On a long step it becomes scenery.

This phase makes the line something the eye lands on, in the shape Claude Code gives one.

1. **The mark is large enough to read and coloured so it is found first.** The anvil-and-hammer
   grows from 14px to 18px, and the hammer and its spark are drawn in the theme's orange while
   the anvil stays in the description colour, so the swing is what the eye catches.
2. **The word turns.** While the host sends no step, the line cycles through forging verbs —
   `Forging…`, `Hammering…`, `Tempering…`, `Striking…`, `Quenching…`, `Shaping…` — one every
   three seconds, the way the CLI's spinner changes its gerund. A host step text still wins
   and stays.
3. **The line sits clear of the composer.** The root line and the working line gain a little
   room above the input, so the facts of the run are read as a line of their own rather than
   pressed against the card.

## Scope

`editors/vscode/media/chat.js` (the verb list and its pacing inside the existing one-second
tick; the host word; the seed word), `media/chat.css` (the mark's size and colour, the dock's
spacing) and `test/unit/working.test.ts`. The milestone page and the design chapter record the
change. No protocol field, no host change, no setting, no new message type, no second timer.

## Tasks

1. **Grow the mark.** `.working-glyph` is 18px square; the view box is unchanged, so the pivot
   stays `12px 9px` and both shapes scale together.
2. **Colour the hammer.** The hammer group and the spark take
   `--vscode-charts-orange` (fallback `#e8912d`); the anvil keeps the description colour.
3. **Turn the word.** `WORKING_WORDS` holds the six verbs; `renderWorkingMeta` picks
   `WORKING_WORDS[floor(seconds / 3) % length]` while the host has sent no word, so the turn
   is pinned to the clock the line already runs and adds no interval.
4. **Let the host win.** A progress event with text sets `workingHostWord`; the rotation stops
   and the host's word stays for the rest of the run. `startWorking` resets it.
5. **Give the dock room.** `.root` and `.status` take 10px below their text instead of 6px.
6. **Test.** Source assertions for the list, the pacing, the host override and the reset;
   stylesheet assertions for the 18px mark, the orange hammer and spark, and the 10px foot.
7. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Decisions (before any change)

- **Size first, then colour.** A mark smaller than the text it labels reads as decoration; at
  18px beside 0.85em text it is a glyph. Orange is the one accent the transcript does not
  already use for state (`done` is green, `stopped` the warning colour), so the hammer cannot
  be mistaken for a status.
- **The rotation rides the clock that exists.** A second `setInterval` would be a second
  lifetime to own, and the renderer deliberately keeps one interval per fact (see the clock
  note in p_0.46.20). Deriving the verb from elapsed seconds makes the turn deterministic,
  replayable in a test's eye, and free.
- **The host's word is not outvoted.** A step text is a fact; the rotation is a placeholder
  for the absence of one. Once a run says what it is doing, it keeps saying it.
- **Three seconds, six words.** Long enough to be read, short enough that a run of thirty
  seconds shows that the line is alive. The first word stays `Forging…`, so a run's first
  impression is the product's own.
- **Room above the input, not a border.** The dock's lines are separated by space, as the
  rest of the transcript is; a frame around the working line would make it a card again.

## Implementation notes

### The mark

`.working-glyph` is 18px square; the 16-unit view box is untouched, so the anvil, the head and
the pivot scale together and the stylesheet's only geometry (`transform-origin: 12px 9px`,
`transform-box: view-box`) still points at the anvil's edge. The `.hammer` group and the
`.spark` group both take `--vscode-charts-orange` with `#e8912d` as the fallback; the anvil
path keeps the glyph's `--vscode-descriptionForeground`. The shapes use `currentColor`, so
the two rules are the whole change.

### The word

`WORKING_WORDS` holds six gerunds, `Forging…` first. `renderWorkingMeta` already computes the
elapsed seconds for the parenthetical, and on the same tick writes
`WORKING_WORDS[Math.floor(seconds / 3) % WORKING_WORDS.length]` while `workingHostWord` is
empty — so the verb changes at 3s, 6s, 9s and so on, with no timer of its own, and a hidden
tab skips the write as it already skipped the meta. `startWorking` resets the host word and
seeds the first verb; a `progress` event with text sets `workingHostWord` and the word, and
the rotation never overwrites it again for that run.

### The dock

`.root` and `.status` take 10px below their text instead of 6px. The dock is bottom-anchored,
so the change lifts both lines rather than growing the card, and it holds whether the working
half or the run's summary occupies `#status`.

## What was not walked

No real window here. The orange under the light, dark and high-contrast themes, its weight
beside the green of `done` and the warning yellow of `stopped`, and the reading rhythm of a
word that changes while a long tool runs were reasoned from the declarations.

## Non-goals

- Token counts while a run is in flight; only the terminal usage the meter already shows.
- A user-chosen or localized verb set; the six words ship with the product.
- A setting for the animation; `prefers-reduced-motion` is the only switch.
- A protocol change, a host change, a version bump, a branch, or a push.
