# p_0.46.50 — Durable failures and bounded editor context

**Status:** done

## Goal

Prevent long VS Code conversations from silently growing until a provider call
fails, and preserve the exact terminal failure so reopening the conversation
still explains why work stopped.

## Scope

- Give editor sessions a conservative context budget when the user has not
  configured the model's real window; an explicit zero continues to disable
  automatic compaction.
- Persist a run's terminal error and code in the append-only session record.
- Project the persisted failure through run metadata, transcript RPC and replay.
- Show a replayed failure reason using the same terminal information as a live
  run.

## Acceptance

- [x] A fresh VS Code installation sends a non-zero context budget and
  auto-compacts before unbounded history reaches the provider.
- [x] A user can still override the budget or explicitly set it to zero.
- [x] Provider and empty-response failures retain `err` and `code` after host
  restart.
- [x] Replaying a failed run displays its stored reason.
- [x] Focused Go and extension regression tests pass.
