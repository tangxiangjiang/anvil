# p_0.46.1 — LSP and test/build wiring

**Status:** done (2026-10-20)
**Milestone:** [m_0.46_editor_polish.md](../m_0.46_editor_polish.md)
**Linked design:** [46-editor-polish.md](../../../design/v0.x/46-editor-polish.md) §2–§3

## Goals

1. **A configured language server becomes tools.** `session.new` carries an `lsp` block, the
   host maps it to `anvil.LSPOptions`, and the session registers `lsp_*` tools. A language
   server that cannot start is a missing tool, not a failed conversation. The workspace's
   `.anvil/lsp.json` keeps working; this list is appended to it.
2. **A configured test or build command becomes a tool.** The extension sends the
   `test_command` and `build_command` the protocol has accepted since 0.18.
3. **Nothing configured changes nothing.** With empty settings, the wire message and the tool
   list are exactly what they are today.

## Scope

`source/internal/editorhost/proto.go`, `server.go`; `editors/vscode/package.json`,
`src/settings.ts`, `src/protocol.ts`, `src/hostManager.ts`; tests on both sides;
`editors/vscode/README.md`.

## Tasks

1. **Protocol.** Add `lsp: {enabled, servers: [{language, pattern, command, args}]}` to
   `SessionParams`. Keep `Required` unset (the host passes `false`); reject a server entry
   with an empty command or with neither language nor pattern.
2. **Host.** In `buildOptions`, map the block to `anvil.LSPOptions` with `Required` false;
   the SDK merges `.anvil/lsp.json` underneath. Validate `test_command` / `build_command`
   shape (a non-empty first word; empty array = unset) and keep the existing `opts.Test` /
   `opts.Build` mapping. Refuse an LSP entry with no command or no language/pattern, naming
   its index.
3. **Settings.** `anvil.lsp.enabled` (default `false`), `anvil.lsp.servers` (array of
   objects), `anvil.testCommand` and `anvil.buildCommand` (string arrays) in `package.json`.
4. **Extension.** Read and shape-check the settings in `src/settings.ts`; add the fields to
   `SessionNewParams`; send them from `hostManager.startSession` only when enabled or
   non-empty, so the unset case stays byte-identical.
5. **Docs.** `editors/vscode/README.md`: settings table, one paragraph on the trust posture
   (workspace values are accepted because the extension refuses untrusted workspaces; commands
   and arguments are never joined into a shell string), and what to do when a server fails.
6. **Tests.** Go: the mapping, an unstartable server not failing the session, and the command
   tools appearing. Extension: an integration test pinning the exact wire message with
   nothing configured (must match today) and with each setting configured.

## Acceptance

- [x] With no settings, `session.new` params deep-equal today's (integration test).
- [x] `lsp.enabled` with one server yields `lsp_*` tools in the session's tool list; a bad
      command leaves the session alive with the other tools.
- [x] `test_command` / `build_command` yield `run_tests` / `build`.

## Non-goals

- Discovering language servers automatically, or pushing LSP diagnostics to the Problems
  panel.
- Lazy start per file, or multiple servers per language.
- A `Required` setting in the editor.

## Implementation notes

- **The SDK already read `.anvil/lsp.json`.** `configureLSP` merges a project file underneath
  `opts.LSP` whenever the project setting source is loaded. What was missing was the client's
  path, not the engine, and the milestone and chapter say so rather than claiming LSP was
  absent from the editor.
- **`Required` is not on the wire.** A server that cannot start is a missing tool. The SDK
  starts servers lazily when nothing requires them, so a broken command surfaces on the first
  `definition` call rather than at `session.new`; the host test pins that a session opens with
  a nonexistent binary configured.
- **Two filters, on purpose.** `lspParams` drops an entry with no command or with neither
  language nor pattern, because one bad row in a settings array must not refuse a
  conversation. The host refuses the same shapes from a client that sends them directly,
  naming the entry's index.
- **Unset means absent.** `lsp`, `test_command` and `build_command` are added to
  `session.new` only when they have a value. The integration tests pin the configured message
  and the unconfigured one, which is the byte-identical case the phase promised.
- **What was not walked.** No real language server was started in a VS Code window. The engine
  side is covered by the SDK's `fakels` tests, the mapping by the host tests, and the wire by
  the fake-host tests; a manual gopls pass is left for when someone configures one in a
  workspace.
