# p_0.46.45 — TextMate code highlighting with Shiki

**Status:** done
**Milestone:** [m_0.46_editor_polish.vscode.md](../m_0.46_editor_polish.vscode.md)
**Linked design:** [46-editor-polish.vscode.md](../../../design/v0.x/46-editor-polish.vscode.md) §48

## Goals

Render completed fenced code with TextMate grammar quality instead of a small regular-expression
tokenizer.

## Scope

- Vendor an offline Shiki browser bundle in the VSIX.
- Permit bundled Oniguruma WebAssembly compilation in the Webview CSP without permitting JavaScript `eval`.
- Lazily initialize common language grammars and VS Code light/dark themes.
- Conservatively infer common languages for unlabelled, `text` and `plaintext` fences.
- Keep open streaming fences as plain text, then highlight once the fence closes.
- Build token spans through DOM APIs; never assign model text through `innerHTML`.
- Fall back to plain text for unknown languages or renderer failures.

## Acceptance

- [x] C/C++ and common editor languages use Shiki TextMate tokens.
- [x] An unlabelled C++ interface using `enum class`, `virtual` or access labels is inferred as C++.
- [x] Dark and light webviews select the matching VS Code theme.
- [x] Streaming remains synchronous plain text and stale asynchronous results are discarded.
- [x] The packaged extension contains Shiki, its license and version provenance.
- [x] Compile, lint, 628 tests, package and packaged smoke pass.
