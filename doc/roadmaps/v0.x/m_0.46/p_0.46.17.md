# p_0.46.17 — A summary for the run that finished

**Status:** done (2026-10-20)
**Milestone:** [m_0.46_editor_polish.md](../m_0.46_editor_polish.md)
**Linked design:** [46-editor-polish.md](../../../design/v0.x/46-editor-polish.md) §19,
[35-vscode-extension.md](../../../design/v0.x/35-vscode-extension.md) (the chat view)

## Goals

p_0.46.16 gave a finished answer an ending. A reader who finished a live turn saw none, then
reopened the same conversation from history and saw the ending there.

The live renderer decided whether a run had finished by testing the *absence* of a failure:
`if (!failure) markSummary(round)`. The extension never omits the failure — `classifyDone`
always returns one, and a clean finish is `{kind: 'none', message: '', isError: false}` — so
the test was never true and a live run never marked a summary. The replay read the stored
status (`done.status !== 'error' && done.status !== 'cancelled'`) and worked, which is why
the same turn had an ending only after it was reopened.

1. **Say finished by its kind.** `finishRun` marks the summary when `failure.kind === 'none'`
   (or when no failure arrived at all), the same fact the replay's status test expresses.
2. **Pin the fact that the object is always present.** The summary test asserts the kind
   test and refuses the old object test, so the next reading of `finishRun` does not undo it.

## Scope

`editors/vscode/media/chat.js` (`finishRun`) and `test/unit/summary.test.ts`. The milestone
page and the design chapter record the finding. No protocol field, no host change, no CSS,
no setting.

## Tasks

1. **Fix the test.** `if (!failure || failure.kind === 'none') markSummary(round)`.
2. **Test.** Replace the source assertion for `finishRun` with the kind test, and assert that
   the object test is gone.
3. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Acceptance

- [x] A live run that finishes cleanly marks its final answer as the summary, exactly as the
      replay of the same run does.
- [x] A failed or stopped run marks nothing, and a clean run whose last block is a tool call

- [x] Compile, lint, `npm test`, the Go triple, `package:vsix` and `smoke:vsix` green.

## Decisions (before any change)

- **The bug is a predicate, not a rendering.** The summary block, its colours and its rail
  were drawn correctly in the replay; only the guard in the live path was wrong. The fix is
  one expression, and the design and the CSS stay as p_0.46.16 wrote them.
- **Test the kind here, because the two paths speak different grammars.** The live path has
  a `RunFailure` whose `kind` is `none` for a clean finish; the replay has a stored status
  whose word is `finished`. Both ask "did this run end normally?" in the vocabulary each
  one has; neither should learn the other's.
- **Keep the absent-failure guard.** `finishRun` is fed `msg.failure` from a message; a
  malformed or older message that omits it means the run ended, and treating that as clean
  is better than a `TypeError` in the middle of the turn's ending.

## Implementation notes

`finishRun` now reads:

```js
if (!failure || failure.kind === 'none') markSummary(round);
```

`summary.test.ts` matches that line and asserts `if (!failure) markSummary` is absent, so the
old spelling cannot come back unnoticed. Nothing else changed: `endRound` still copies the
whole answer, `markSummary` still requires the round to be the last block, and the replay
still uses the stored status.

**What the test pins.** `summary.test.ts` matches `if (!failure || failure.kind === 'none')
markSummary(round)` in `finishRun` and asserts that `if (!failure) markSummary` is absent.
That is the whole defect: the first spelling tested an object that is never missing, and the
second tests the one field that says the run ended normally.

## What was not walked

The fix was found by reading the two paths side by side after a reader reported the difference
in a real window; the live ending itself was not watched here. The screenshots that reported
the difference showed a live turn without an ending and the same turn's replay with one, so
the live path's new ending is inferred from the fix and pinned by the source test rather than
seen.

## Non-goals

- A summary for a failed, stopped or tool-ending run.
- A summary generated from anything but the answer's own text.
- Any change to the replay, the protocol, the host, the stylesheet or the settings.
