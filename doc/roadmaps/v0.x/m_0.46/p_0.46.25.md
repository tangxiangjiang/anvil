# p_0.46.25 — A line that cannot grow or overlap

**Status:** done (2026-10-21)
**Milestone:** [m_0.46_editor_polish.md](../m_0.46_editor_polish.md)
**Linked design:** [46-editor-polish.md](../../../design/v0.x/46-editor-polish.md) §28,
[35-vscode-extension.md](../../../design/v0.x/35-vscode-extension.md) (the chat view)

## Goals

p_0.46.24 moved the footprint into the transcript and reserved its first line with
`min-height: 1.5em`, which was the height of the text and not of the mark beside it. The
working mark is 18px, so a turn starting grew the line from 16.57px to about 18px and moved
everything below it; the reserve only covered the empty-to-summary case. The composer's
actions row and the status line have two more ways to misbehave at a narrow width: a button
that shrinks under its own label, and a long parenthetical that has no box to ellipsise in.

1. **The status line is exactly one height.** It becomes a flex row whose `min-height` is the
   taller of the text line and the 18px mark — `max(1.5em, 18px)`. A run starting or ending,
   and the mark's own height, no longer change the block.
2. **Each half has its own truncation box.** The summary is a flex item with `min-width: 0`
   and an ellipsis; the working half keeps its mark and word and ellipsises the
   parenthetical. A long summary or a long step count truncates instead of overflowing.
3. **The actions row cannot squeeze a button.** Select and buttons become `flex: 0 0 auto`;
   the meter stays the row's only flexible child, so the total truncates and the controls
   keep their size and place.

## Scope

`editors/vscode/media/chat.css` (the status line's box and the actions row's flexibility) and
`test/unit/working.test.ts`. No template change, no renderer change, no protocol, no setting.

## Tasks

1. **Make the line a row.** `.status` gets `display: flex`, `align-items: center` and
   `min-height: max(1.5em, 18px)`; it keeps `nowrap` and `overflow: hidden`.
2. **Give the summary a box.** `.status-text` becomes `flex: 0 1 auto` with `min-width: 0`,
   `overflow: hidden` and an ellipsis.
3. **Give the parenthetical a box.** `.working` becomes a flex item with `min-width: 0`;
   `.working-word` does not shrink; `.working-meta` ellipsises.
4. **Fix the controls.** `.composer .actions > button` and `> select` get `flex: 0 0 auto`.
5. **Test.** The line's `min-height` is the mark's height when the text is smaller, the two
   halves truncate, and the buttons do not shrink.
6. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Decisions (before any change)

- **Reserve the taller of the two, not a round number.** `1.5em` is the text's box; 18px is
  the mark's. `max(1.5em, 18px)` follows `anvil.chatFontSize` in both directions: at a large
  size the text decides, at a small one the mark does, and the working line's natural height
  is that same maximum in both cases.
- **A flex row rather than a block of inline boxes.** With inline content the line box height
  is the strut's plus whatever the inline-flex baseline adds below it — a number the stylesheet
  cannot state and a test cannot pin. Aligned flex items have no baseline to add.
- **The summary truncates, the mark does not.** A clipped hammer reads as a broken icon; a
  clipped summary reads as a long summary, and the tooltip is not needed because the same
  numbers are in the transcript and the meter.
- **Buttons are fixed, the total flexes.** The meter's text is the only thing in the row that
  can be long for a legitimate reason; the controls are a known size, and a shrunk button
  loses its label before it loses its importance.

## Implementation notes

### The line

`.status` is now `display: flex; align-items: center; gap: 6px` with
`min-height: max(1.5em, 18px)` and `overflow: hidden`. That minimum is the exact natural
height of either half: the summary's text line is `0.85em × 1.5`, which follows
`anvil.chatFontSize`; the working half is 18px of mark plus the word's line, and a flex row's
height is the taller child. The block is therefore the same height before a turn, during one,
and after its summary — at the default size and at both ends of the text-size setting.

### The boxes

`.status-text` became a flex item with `flex: 0 1 auto`, `min-width: 0` and its own ellipsis:
`text-overflow` on the row does not reach text across a flex-item boundary. `.working` is the
other flex item with `min-width: 0`; inside it the glyph keeps its existing `flex: 0 0 auto`,
`.working-word` is `flex: 0 0 auto` and `.working-meta` is `flex: 0 1 auto` with `min-width: 0`
and the ellipsis. The mark therefore cannot clip and the parenthetical is the only thing that
shortens.

### The controls

`.composer .actions > button` and `> select` are `flex: 0 0 auto`. A flex item's default
`flex-shrink: 1` would have squeezed a button's label before the meter — the row's only
`flex: 1 1 auto` child — gave up any width. With this, a long session total truncates in its
own box and every control keeps its size and position; the meter's `title`/`aria-label` keep
the whole string reachable.

## What was not walked

No real window here. The heights are reasoned from the stylesheet's own numbers (0.85em,
1.5, 18px) rather than measured in a browser, and the flex-row claim about the line's height
is the specification, not an observation. Where a given panel width starts truncating the
summary or the total was not seen; the point of the change is that it truncates rather than
overlaps, and that no text can leave its box.
