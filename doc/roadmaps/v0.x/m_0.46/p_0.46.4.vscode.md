# p_0.46.4 — Reading: focus view, formulas, export

**Status:** done (2026-10-20)
**Milestone:** [m_0.46_editor_polish.vscode.md](../m_0.46_editor_polish.vscode.md)
**Linked design:** [46-editor-polish.vscode.md](../../../design/v0.x/46-editor-polish.vscode.md) §6

## Goals

1. **Focus view.** One toggle keeps the narrative and collapses tool cards and thinking
   blocks; the state survives a webview reload and never enters settings.
2. **Formulas.** `$…$` and `$$…$$` render with a locally bundled renderer under the existing
   CSP; malformed input stays literal.
3. **Export.** `/export` writes the conversation as Markdown through a save dialog.

## Scope

`editors/vscode/media/chat.js`, `media/chat.css`, `src/chatPanel.ts`, `src/commands.ts`,
`package.json` (command + keybinding), bundling for the math renderer; tests; README.

## Tasks

1. **Focus toggle.** Toolbar button and `Ctrl+Alt+F`; hide tool cards and thinking blocks,
   keep user and assistant prose; store the flag in `vscode.getState()`; keep scroll position.
2. **Formulas.** Add a local renderer (KaTeX or equivalent) bundled into `media/`; parse
   inline/display delimiters before the Markdown inline pass; build DOM, never assign
   `innerHTML` from host text; leave unclosed delimiters as text; document the bundle cost.
3. **`/export`.** Builtin command; render the transcript (prose + tool-call summaries) to
   Markdown; `showSaveDialog` with a sensible default name; write through
   `vscode.workspace.fs`.
4. **CSP.** Keep `default-src 'none'`; if the renderer needs a stylesheet, serve it from
   `media/` through `webview.asWebviewUri`.
5. **Tests.** Source assertions (no `innerHTML`, CSP unchanged, state key), a Markdown export
   fixture, and the delimiter parser's edge cases.

## Implementation notes

- **The document owns the focus flag.** The toolbar button and `Ctrl+Alt+F` are two ways to
  send one message; the palette command sends the same one, so there is no path that writes
  the view from the host. `chat.js` keeps the flag in `vscode.setState`, merged rather than
  replaced because the agent id is written at another moment, and reads its initial value
  from the `focus-view` class the host renders. The host learns it from the serializer and
  passes it to `renderHtml` and `createPanel`, so a restored tab comes back as it was left —
  and a conversation opened later starts in the ordinary view, because the state belongs to
  the tab rather than to the agent.
- **What focus hides, and what it must not.** Only `.tool` and `.think`. The approval card
  is a question to the reader, and the stylesheet says so in its own comment; the unit test
  reads both the rule and its absence for `.approval`. The scroll anchor skips elements the
  view is hiding: measuring a `display: none` node gives a zero rect, and re-anchoring to it
  would jump the reader to the top. A reader who was pinned to the bottom stays pinned.
- **Formulas are MathML, and that choice is the CSP's.** KaTeX's HTML output writes inline
  `style` attributes on its spans, which `default-src 'none'` with no `'unsafe-inline'`
  blocks; MathML output writes none and needs no stylesheet, so nothing is loosened and
  nothing is fetched. The vendored bundle is one `katex.min.js` (272,868 bytes) plus its MIT
  licence, committed under `media/vendor/katex/` and checked by `npm run vendor:katex`, which
  refuses a version other than the pinned one and refuses a bundle that assigns `innerHTML`.
  `output: 'mathml'`, `trust: false` (no `\href`, `\htmlClass`), `throwOnError: true`, and a
  refusal falls back to the source in monospace rather than to an error box.
- **The parser's rules are prose rules.** `$…$` is read after code spans (a `$` between
  backticks is a character) and before emphasis; the first `$` after the opener decides, so
  `$a $b$` is not a formula over text the author closed earlier; no space after the opener,
  no space before the closer, no digit after it — that last one is what keeps `$5 and $6`
  money. A line starting with `$$` opens a display block that closes on `$$` alone on its own
  line, keeping the body's newlines for aligned derivations; a closer with text after it is
  not one, and an unclosed `$$` stays a paragraph, which is the ordinary state of a formula
  that is still streaming. `MATH_OPEN` joins the paragraph boundaries for that reason, and the
  paragraph branch takes its first line unconditionally so an unclosed opener cannot leave the
  index where it was.
- **Export is a pure function and a dialog.** `src/export.ts` folds the store through
  `replayOf`, so only the first `user` record of a run is the reader's turn and the loop's own
  notes are not put in their mouth. Tool calls become the tool's name plus the paths
  `toolCallPaths` already knows how to read (`write_file`, `edit_file`, `apply_patch`);
  arguments, output and ids never travel. The panel reads `hub.transcript(agentId)`, not the
  screen, passes the store's `dropped` count so a truncated history says so, opens
  `showSaveDialog` on `anvil-conversation-<date>.md` in the workspace folder, and writes
  through `vscode.workspace.fs`. Cancelling writes nothing; a write failure is a notice, and
  *Open* is offered after the file exists. `/export` takes no argument, so text after it
  cannot steer where a file lands.
- **Tests.** `npm test` is 508 green (from 488): `export.test.ts` (7), `reading.test.ts` (8),
  five delimiter tests in `markdown.test.ts`, and the built-in list and routing in
  `commands.test.ts`. The reading tests read the source and the bundle as text, since no
  webview runs here.
- **What was not walked.** No part of this phase was seen in a running window: the visual
  result of MathML, the scroll anchoring when the first visible block is a hidden tool card,
  the save dialog's default name on a machine with no workspace folder, and the restored-tab
  case all rest on the assertions above. A manual pass in a real window — toggle with a turn
  running, reload with focus on, export and open the file in the preview — is still worth
  doing.
