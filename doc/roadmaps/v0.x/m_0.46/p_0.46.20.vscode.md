## Goals

While a turn is in flight the panel shows nothing of the agent's own state: the stop button
is the send button, the composer is disabled, and the one line that could speak — the status
line — is hidden from the moment the prompt is sent until the run's summary replaces it. A
reader who looks at the panel during a long step cannot tell a working agent from a hung one.

Claude Code answers the same question with one animated mark and one line of text beside it.
This phase gives the panel that line, with the mark this product can honestly draw: an anvil
and a hammer.

1. **The working line.** While a run is in flight the status line carries a small animated
   hammer and anvil, the word for what the agent is doing (`Forging…`), and — the way the
   CLI says it — a dim parenthetical: `esc to interrupt`, the elapsed time, and the step when
   the host reports one.
2. **The animation is drawn, not typed.** A character has no hammer that keeps its shape in
   every font; the mark is an inline SVG, and the head swings with the Web Animations API so
   `chat.css` stays free of at-rules.
3. **It ends when the turn does.** The line disappears with the run, and the run's summary
   takes its place in the same element. Stopping, failing or finishing all stop the clock and
   the animation together.
4. **It respects a reader who asked for less motion.** With `prefers-reduced-motion`, the
   mark is drawn still and the line stands.

## Scope

`editors/vscode/media/chat.js` (the line's nodes, the SVG, the clock and the meta text; the
status helpers; `setRunning`, the progress event, `finishRun` and `clearTranscript`) and
`media/chat.css` (the line's layout and the hammer's pivot); a new `test/unit/working.test.ts`.
The milestone page and the design chapter record the change. No protocol field, no host
change, no setting, no new message type.

## Tasks

1. **Build the line once.** `#status` gains a `.working` span — an `.working-glyph` SVG, the
   `.working-word` and the `.working-meta` — and a `.status-text` span that the summary and
   progress notes keep using.
2. **Draw the mark.** `hammerGlyph()` builds the SVG with `createElementNS` (never markup):
   an anvil, a hammer group with its pivot at the anvil's right edge, and a spark where the
   head lands.
3. **Move it.** The head swings on a 900ms loop through the Web Animations API; the spark
   flashes on the strike. `prefers-reduced-motion` leaves both still.
4. **Run the clock.** `setRunning(true)` starts the line and a one-second timer;
   `setRunning(false)` stops both. The meta is rebuilt each tick from the start time.
5. **Take the host's step.** A `progress` event with a step updates the meta; one with text
   becomes the line's word, so a host that names its step is shown rather than guessed at.
6. **Hand the line over.** `finishRun` writes the run's summary through `setStatus`, which
   hides the working half and shows the summary in the same element.
7. **Test.** Source assertions for the SVG, the animation, the timer, the meta and the
   handover; stylesheet assertions for the line's layout, the pivot and the hidden states.
8. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Decisions (before any change)

- **The status line is the place.** It already answers "what is happening" for a finished
  run; Claude Code's mark sits at the foot of the conversation in the same way. A row inside
  the transcript would be history (and would have to be removed from it), while this line is
  the one thing on screen that describes the run and not the conversation.
- **One element, two states.** The working line and the run's summary never show together.
  Building both into `#status` once means the SVG nodes are not replaced every second by a
  re-render of the line, which would restart the animation and lose the clock.
- **SVG plus the Web Animations API.** A hammer has no character that renders the same in
  every font, and `chat.css` may not carry an `@keyframes` (the layout tests parse it as
  text). The element is drawn from nodes and moved from script; the stylesheet only says
  where the pivot is.
- **The word is the product's own.** `Forging…` names what the anvil does; a host sentence
  for the step, when one arrives, is shown in its place rather than invented over.
- **The parenthetical follows the CLI.** `esc to interrupt · 12s · step 2/40`: the escape
  first because it is the actionable part, then the clock, then the step the host reported.
  Tokens are not there because a live run's usage arrives with the terminal event; a number
  that only appears at the end is not a progress fact.

## Implementation notes

### The line

`#status` holds `.working` and `.status-text`. `.working` is an SVG, `.working-word` and
`.working-meta`; it starts hidden. `startWorking()` unhides it, resets the word to `Forging…`,
records the start time and starts a one-second `setInterval` that rebuilds the meta;
`stopWorking()` clears the timer and hides the half. `setStatus(text)` writes the other span
and hides the line only when both halves are empty, so a progress note never blanks the
working mark.

The SVG is built by `svgNode` from `createElementNS`: an anvil path, a `.spark` group of
three rays, and a `.hammer` group holding the handle and the head. The stylesheet pivots the
group at `12px 9px` in the view box; the head swings from upright to `-72deg` over 900ms,
with the spark keyed to the strike and hidden otherwise.

The tick returns early on a hidden tab, as the cache clock does: a panel nobody is looking at
does not rebuild its meta every second, and the first tick after the tab returns catches the
elapsed time up. The renderer now has exactly two intervals, each one second and each owned
by a different lifetime — `renderMeter` while a live cache is on a visible tab, and
`renderWorkingMeta` while a turn is in flight — so `usageMeter.test.ts`'s "one interval"
assertion was widened to both by name rather than relaxed.

`setRunning` starts and stops the clock; `finishRun` hands the line to the summary; a
`progress` event updates the step and may replace the word; `clearTranscript` stops the clock
because the conversation the line described is gone.

## What was not walked

No real window here. The mark's size beside the 0.85em text, the hammer's arc and the
spark's timing, the animation's cost on a long run, and the line in high contrast and at
`anvil.chatFontSize` sizes were reasoned from the declarations. A webview that does not
support `Element.animate` would show a still mark rather than throw at load; that path is
guarded but not watched.

## Non-goals

- Token counts while a run is in flight; only the terminal usage the meter already shows.
- A rotating set of words, a second working mark in the transcript, or per-tool animations.
- A setting for the animation; `prefers-reduced-motion` is the only switch.
- A protocol change, a host change, a version bump, a branch, or a push.
