# p_0.46.86 — Single API and gateway model connections

**Status:** done

## Goal

Separate fixed-model API connections from gateway model discovery so each
workspace has one unambiguous model source.

## Scope

- Require Provider and an HTTP(S) Base URL in both modes.
- Single API mode requires one Model ID and exposes only that model.
- Gateway mode preserves Model Manager discovery, allow-list, and default model.
- Add a dynamic model connection configuration panel.
- Keep existing installations in Gateway mode.
- Validate the effective configuration before starting a session.

## Non-goals

- Storing API keys outside VS Code SecretStorage.
- Changing host provider protocols.
- Removing Subagent Profiles from Model Manager.

## Tasks

- [x] Add the model mode schema, validation, and backward-compatible resolution.
- [x] Build the dynamic model connection configuration panel.

## Acceptance

- [x] Single API mode requires and uses exactly one Model ID.
- [x] Gateway mode opens Model Manager and retains its current list workflow.
- [x] Invalid configuration cannot silently start a host session.
