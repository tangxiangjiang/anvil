# p_0.46.28 — Token counts below the working line

**Status:** done (2026-10-22)
**Milestone:** [m_0.46_editor_polish.vscode.md](../m_0.46_editor_polish.vscode.md)
**Linked design:** [46-editor-polish.vscode.md](../../../design/v0.x/46-editor-polish.vscode.md) §31

## Goals

Put the current conversation's reported input, output and cached-token counts directly below
the hammer's working line. Keep each count as its own animated node, so a changed value pulses
once while an unchanged redraw and the cache clock do not.

## Scope

The chat webview markup, layout and focused unit tests. The existing usage arithmetic,
protocol and reduced-motion behaviour remain unchanged.

## Non-goals

- Streaming token estimates before the host reports authoritative usage.
- A protocol, host, setting or product-version change.
- Changing the context-window facts on the root line.

## Tasks

1. Move the existing meter from the composer's actions into the transcript footprint,
   between the working/status line and the root line.
2. Style it as a stable, truncating footprint line and retain one inline box per count.
3. Keep the footprint visible when the meter is the only fact available.
4. Update layout and usage-meter tests, then compile, lint and run the unit suite.

## Acceptance

- [x] `in`, `out` and `cache` appear on the line immediately below the hammer/status line.
- [x] A changed count pulses once; unchanged values and cache-clock ticks do not pulse it.
- [x] The line follows the transcript's reading-column alignment and truncates safely.
- [x] Compile, lint and unit tests pass (519 tests).
