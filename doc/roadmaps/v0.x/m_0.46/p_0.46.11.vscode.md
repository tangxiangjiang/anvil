## Goals

p_0.46.10 calmed the transcript. The four manager panels were not part of that change, and
they each carry their own copy of the same document chrome: `body`, `#root`, the title, the
path line, the banner, the inputs and the buttons, with four different sets of local tokens.
Opened one after another they read as four products, and a fix to one of those shared pieces
has to be made four times. This phase gives every webview the same grammar.

1. **One document shell.** A new `media/panel.css` owns the chrome all four managers share,
   loaded after `media/tokens.css` and before each panel's own stylesheet.
2. **Sections are separated, not framed.** A scope, a task row, an MCP server and a review
   hunk stop being cards; consecutive items are divided by a hairline, and hover is the
   affordance.
3. **Colour means something.** A finished thing is muted; only running and failed carry
   colour — the same rule the transcript now follows.
4. **No local copies.** The `--perm-*`, `--tasks-*`, `--mcp-*` and `--review-*` tokens go
   away in favour of `--ui-*`, and no panel redeclares the base elements.
5. **Nothing else changes.** Every panel keeps its markup, its script and its behaviour. The
   chat panel already links `tokens.css` (p_0.46.10) and is not touched by this phase; the
   four managers gain the two links they were missing.

## Scope

New `editors/vscode/media/panel.css`; restyled `permissions.css`, `tasks.css`, `mcp.css`,
`review.css`; the `<head>` of `src/permissionsPanel.ts`, `src/tasksPanel.ts`,
`src/mcpPanel.ts`, `src/reviewPanel.ts` (two links each); new
`test/unit/panelStyle.test.ts`. The design chapters and the milestone page are updated by
this phase.

## Tasks

1. **The shell.** `panel.css` declares the box model, `body`, `#root`, `.title`, `.path`,
   `.hint`, the banner with a semantic left bar, form controls, the button variants, the
   status line and the focus ring, all from `--ui-*` and theme variables.
2. **Link it.** Each manager's `renderHtml` loads `tokens.css` → `panel.css` → its own CSS.
3. **De-card the four panels.** Permissions: a hairline between scopes, a frameless rule
   list without zebra striping. Tasks: frameless rows with a hover, a top hairline over the
   output. MCP: a frameless server list, hairlines between servers, the form on a hairline.
   Review: frameless hunks with a divided header, keeping the added/removed line backgrounds.
4. **Consolidate the tokens.** Delete the four local token blocks; replace their uses with
   `--ui-*`; keep each panel's own layout values (widths, columns) where they are local.
5. **Status colour.** A finished run is muted; running and failed keep their semantic colour;
   the MCP connection dot keeps its own.
6. **Tests.** A new `panelStyle.test.ts` pins the link order, the tokens, the absence of
   duplicated base rules and card borders, and the review diff backgrounds.
7. **Verify.** Compile, lint and tests; the Go triple from Git Bash; VSIX packaging and the
   packaged smoke test.

## Decisions (before any change)

- **Share the shell, not the sections.** The four panels' inner content really is different;
  what was accidental was that each one re-declared the page around it. `panel.css` takes only
  what was duplicated four times.
- **Keep the markup.** This is a stylesheet phase. Changing class names to fit a shared rule
  would touch four scripts and their tests for a visual result the CSS can reach alone.
- **Hairlines over frames.** The transcript's phase made the same choice: a frame around
  every item stacks into noise, while a rule between items says "these are siblings" once.
- **A finished thing is not an event.** Green on every completed row was the transcript's
  mistake and the panels had it too. Colour is reserved for what needs attention.
- **The manager link order is load-bearing.** `panel.css` must come after `tokens.css` and
  before the panel, because the panel is meant to override the shell, never the reverse.

## Implementation notes

### The shell

`media/panel.css` owns the box model, `body` (20px/16px, tight line height, theme foreground
and background), `#root`'s centring, `h1`/`h2.title`, `.path`, `.hint`, the banner, the form
controls and the button variants (`.primary`, `.secondary`, `.ghost`, `.delete`,
`.delete.armed`, `.link`), `.status`, `.spacer` and the high-contrast focus ring. The heading
rule is scoped to `h2.title` because tasks uses `span.title` inside a row and an `h1` in its
toolbar; only the managers' page heading is the shell's. Controls match
`input:not([type='checkbox'])` so the permissions panel's attribute-less inputs are covered.
The banner is a 3px semantic left bar over a faint validation background, the same shape the
transcript uses, instead of a frame.

### The panels

Each manager now links `tokens.css` → `panel.css` → its own CSS. The four local token blocks
are gone and every use is a `--ui-*`. Permissions: `.scope + .scope` is separated by a top
hairline; the rules list has no frame, no zebra and a hover, with a rule between rows. Tasks:
rows lost their frame and widget background and gained a hover; a finished status is muted,
and the output is opened by a top hairline rather than boxed. MCP: the server list is
frameless with a rule between servers, and the form is a top hairline over a transparent
background. Review: hunks are frameless, the head carries the rule, and the added/removed line
backgrounds are unchanged. Each panel keeps its own columns, widths and spacing.

### What was not walked

No real window, theme or screen reader here. Every panel should still be opened by hand in
light, dark and high contrast, at a wide and a narrow width, and the fixed footers checked
against the new body padding; the source-level tests can only pin the agreement between
files. The review panel's diff colours and the banner tints in a high-contrast theme are the
two spots most likely to need a follow-up after that pass.

## Non-goals

- Changing any panel's markup, wording, script or behaviour.
- A shared component framework, a build step for the stylesheets, or a new dependency.
- Restyling the transcript again (p_0.46.10) or the session list in the activity bar.
- A version bump.
