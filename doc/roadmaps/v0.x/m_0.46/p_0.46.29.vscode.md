# p_0.46.29 — Live rolling token estimates

**Status:** done (2026-10-22)
**Milestone:** [m_0.46_editor_polish.vscode.md](../m_0.46_editor_polish.vscode.md)
**Linked design:** [46-editor-polish.vscode.md](../../../design/v0.x/46-editor-polish.vscode.md) §32

## Goals

Make input and output token numbers move while a model response streams. Running values are
explicit estimates; the provider's terminal usage remains authoritative. Cached tokens update
only from terminal provider usage.

## Scope

Runtime stream events, the additive editor-host event fields, VS Code protocol types, the chat
meter renderer, and focused Go/TypeScript tests.

## Non-goals

- Claiming per-chunk values are provider measurements.
- Estimating cache reads or writes.
- Changing persisted usage, billing, context compaction, or protocol version.

## Tasks

1. Estimate the request input at each model round and streamed output as chunks arrive.
2. Attach cumulative run estimates to existing progress/assistant/reasoning events.
3. Project the additive estimate marker through the editor-host protocol.
4. Overlay the live run estimate on completed conversation totals in the webview.
5. Roll changed input/output numbers; replace estimates with terminal usage and update cache
   only at run completion.
6. Compile, lint, test, package and smoke the VSIX.

## Acceptance

- [x] A first turn shows input and `0 out` as soon as its model request starts.
- [x] Output increases while text/reasoning chunks stream.
- [x] Terminal usage replaces estimates without being counted twice.
- [x] Cache changes only from terminal provider usage.
- [x] Reduced-motion users receive immediate number updates without rolling animation.
- [x] Go and VS Code verification pass.
