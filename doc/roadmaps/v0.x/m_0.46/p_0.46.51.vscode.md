# p_0.46.51 — Empty completion recovery

**Status:** done

## Goal

Keep a productive tool-using run alive when an otherwise successful provider
response contains neither assistant text nor a tool call.

## Scope

- Treat an empty completion as a recoverable invalid provider result, not as an
  API-key or model-id rejection.
- Retry a bounded number of times without persisting the rejected responses or
  counting them as agent steps.
- Use the non-streaming completion path for recovery so an SSE assembly failure
  does not repeat through the same parser.
- Preserve cancellation and terminal failure behavior when every recovery
  attempt is empty.

## Acceptance

- [x] One or two empty completions followed by useful output complete the run.
- [x] Recovery attempts do not enter history and do not increment agent steps.
- [x] A streaming empty response retries through the non-streaming path.
- [x] Three consecutive empty completions end with an accurate actionable
  message rather than API-key guidance.
- [x] Runtime and extension tests, packaged smoke and local VSIX install pass.
