## Goals

The milestone was accepted on its tests and its documents, and its first real use found three
gaps. This phase closes them. It is the only phase in the milestone whose scope was written
after the milestone was called done, and it changes no engine and no public SDK shape.

1. **A pasted image reaches the model without being asked for twice.** The editor asks for
   vision by default; the setting remains the one switch that turns it off.
2. **A refused turn is visible.** A host refusal that only reached the log looked exactly like
   a turn that vanished, which is how the default-off setting above went unnoticed.
3. **The plan block can be closed.** The checklist under the composer had no way out, so a
   finished plan stayed on screen for the rest of the conversation.

## Tasks

1. **Default on.** `anvil.vision` defaults to `true`; `readSettings` falls back to `true` when
   the setting is absent; the description says what turning it off means.
2. **Say why.** `sendQuestion` catches the host's refusal and posts it as an error notice,
   then republishes the state, instead of leaving the optimistic echo as an errorless turn.
3. **Close the plan.** A head above the scrolling list carries a labelled close control;
   closing hides the block for that plan in that turn, and a different plan or a later turn
   brings it back.
4. **Docs.** Chapter 35's two "off by default" statements, chapter 19's SDK note, chapter 39's
   task-list contract, both READMEs, and the 0.35 phase page are corrected or annotated.
5. **Verify.** Extension compile, lint and tests; the Go triple; `package:vsix` and
   `smoke:vsix`.

## Decisions (before any change)

- **The editor defaults vision on; the SDK does not.** `Options.Vision.Enabled` is the SDK's
  opt-in and stays off, because enabling it changes what the SDK accepts for every consumer of
  the public package. The editor is a different contract: a person pasting a screenshot into a
  chat expects it to be sent. `anvil.vision` therefore defaults to `true` in the extension and
  the session still asks explicitly, so the wire and the host's refusal are unchanged.
- **`read_image` comes with it.** The host advertises `read_image` to a vision session, so the
  default-on session has one more tool than before. It reads inside the sandbox and only
  queues bytes for the next turn, so it is in the ungated part of the default set, like
  `read_file`; a client that wants it gated adds the `vision` group.
- **A close is about one plan, not the feature.** No setting is added: closing is a local act
  on what is on screen. The signature of the plan (its row texts, not their statuses) plus the
  turn it was closed in is what keeps it closed; anything else is a new plan and appears. A
  permanent switch would be a preference, and there is no evidence anyone wants the checklist
  gone for good rather than for now.
- **The refusal is reported where the turn was drawn.** The webview draws the user's message
  before the host answers; a refusal that only reached the log left that message looking sent.
  The notice is an error, not a warning, because the turn did not happen.

## Implementation notes

### Vision default

`package.json` declares `anvil.vision` with `"default": true` and a description that says what
turning it off means; `settings.ts` uses `true` as its fallback, so a session started before
anyone opened the settings UI asks for vision too. The SDK is untouched: `Options.Vision.Enabled`
still defaults off, and the host still builds `Vision: anvil.VisionOptions{Enabled: p.Vision}`
from what the client sent. The consequence the doc states is that a default-on session also
advertises `read_image`; it reads inside the sandbox and queues bytes, and the default gated set
does not include it (`vision` is a group a client can add).

### The refusal

`sendQuestion` already awaits the session; the change is what happens on the rejection. The
webview drew the user's bubble before the host answered, so the catch now posts
`{type: 'notice', level: 'error', message: 'The turn was not sent: …'}` and calls `postState()`
to take the composer out of the running state. The message the host produced is carried
verbatim, because it is the one that names `anvil.vision`.

### The plan block

The dock's markup is now a `#todos` wrapper with a `.todos-head` (title and a `×` button,
labelled *Hide the task list*) above `#todoList`, which keeps `role="list"` and carries the
scrolling `max-height`. `setTodos` computes a signature from the row texts — not their
statuses — and hides the block when the signature and the turn both match what was dismissed.
The composer's submit handler bumps `todoEpoch` after its guards, so `/tasks`, an empty box and
a submit while running do not count as a new turn. Closing moves focus to the send button,
because the button that had it is inside the block that just disappeared. An empty list clears
the signature and the dismissal.

### Docs

- Chapter 35's two statements are rewritten: the session param is still opt-in *on the wire*,
  and the editor is the client that asks by default.
- Chapter 19 keeps the SDK default as off and adds the client-side exception.
- Chapter 39's task-list contract gains a fourth detail describing the close.
- Chapter 44 §14 gains the phase row and the sentence about what the manual passes would have
  caught.
- Root `README.md` and `editors/vscode/README.md` say which side defaults on.
- p_0.35.5 is annotated rather than rewritten, the same way p_0.46.8 treated superseded text.

### What was not walked

Still no real window, no screen reader and no theme in this environment. The three fixes are
pinned at the source and over the fake host; seeing them — a pasted screenshot going out, an
error line where the bubble was, a closed plan staying closed while its rows move — is the
manual pass this phase cannot perform.

## Non-goals

- Changing the SDK's public default for `Options.Vision.Enabled`.
- A second switch for the checklist, per-turn persistence of its dismissal, or reordering it.
- Any of the manual passes this environment cannot run (a real window, a screen reader, a
  dark or high-contrast theme); they remain recorded in the phases that named them.
