# p_0.46.55 — Model management and selection

**Status:** done

## Goal

Make the models a workspace can use explicit, manageable, and selectable from
both configuration and a conversation.

## Scope

- Group the native Anvil settings by function.
- Add a curated available-model list and a default-model selector.
- Add models manually or discover them from a configured OpenAI-compatible
  `/v1/models` endpoint using the existing Anvil API key.
- Require an explicit add before a discovered model becomes available.
- Select an available model per conversation from the composer.
- Preserve existing `/model <id>` and session-resume behavior.

## Non-goals

- No automatic model routing, benchmarking, or context-window inference.
- No second API-key store or provider-specific catalog adapter.
- No automatic addition of every model returned by a gateway.

## Tasks

- [x] Add grouped settings, model settings, manager command, and panel.
- [x] Add endpoint normalization and curated-list persistence.
- [x] Add the composer selector and transactional session re-open.
- [x] Add focused unit and integration coverage.
- [x] Package, smoke-test, and install the VSIX.

## Acceptance

- [x] Manual and gateway models can be added once and removed.
- [x] Gateway discovery uses the configured exact endpoint and existing key.
- [x] The default is chosen only from available models or Host default.
- [x] The composer changes the current conversation model without losing history.
- [x] A failed model change leaves the previous model selected.
- [x] Extension tests, packaged smoke, and local install pass.
