# Phase p_0.45.3 — Confirm, retire dialogs, guard renders, real dialog

**Status:** done

## Goals

Stop the two things that make the console feel unsafe, and fix the three interaction defects that
do not depend on anything else: destructive actions that do not say what they destroy, native
dialogs, and responses that paint a route they did not start in.

## Scope

- Typed confirmation for the remaining destructive actions, stating the counts involved.
- Every `alert` / `confirm` / `prompt` in the web UI replaced by the in-app notice / modal.
- A render token so a late response cannot paint the wrong page.
- The modal becomes an actual dialog: semantics, Esc, focus in and back.

## Non-goals

- Optimistic patching, single-flight actions, the sticky job bar (p_0.45.4).
- Any change to what an action *does* — only to how it is confirmed, reported and painted.
- Server-side confirmation tokens. p_0.45.3 keeps the existing endpoints; the typed confirmation is
  a client-side gate.

## Tasks

1. **Typed confirmation for the destructive set.** Milestone delete
   (`openDeleteMilestoneModal`), design delete (`openDeleteDesignModal`), design-version delete
   (`openDeleteDesignVersionModal`), requirement-version delete (`openDeleteVersionModal`) and
   major seal (`openAdvanceMajorModal` when advancing to `sealed`) each open a modal that names what
   is removed — milestone title and its phase count, design title and its version count, version
   `M.m.p` — and require typing the confirmation word before the submit button enables. The counts
   come from the snapshot that is already loaded, so the warning is specific rather than generic.
2. **Retire native dialogs.** Replace the 17 `alert()` calls and the 1 `prompt()` in
   `delivery.js`, the 5 `alert()` calls and 1 `prompt()` in `clusters.js`, the 2 in `ai_chat.js` and
   the 1 in `nodes.js` with `showNotice` / `showUiModal`. "New folder name" becomes an input inside
   the modal rather than a browser prompt. `clusters.js` currently has no notice helper of its own —
   the shared one from p_0.45.5 is the destination, so p_0.45.3 adds a thin local wrapper that
   p_0.45.5 replaces with the shared module.
3. **Render token.** Add `_renderToken` to the delivery feature. An action captures
   `const token = ++this._renderToken` before its first `await`, and `render()` accepts the token it
   was called with and returns without painting when the token is stale. Apply to the ~50
   `await this.reload(); this.render();` sites; sites that intentionally re-render after a route
   change pass no token.
4. **Modal semantics.** `showUiModal` sets `role="dialog"`, `aria-modal="true"` and
   `aria-labelledby` on the card; Esc closes; focus moves to the first focusable element on open and
   returns to the invoking element on close; Tab is trapped inside the card. `closeUiModal` clears
   every surface key it owns (`_citeBySurface`, `_msgsBySurface`, `_chats`) rather than the two
   hard-coded keys `add-major` / `edit-major`.

## Acceptance

- [ ] `grep -rn "alert(\|confirm(\|prompt(" source/internal/web/static/js` returns nothing.
- [ ] Deleting a milestone with 3 phases shows "Delete <title> and its 3 phases" and the submit
      button stays disabled until the confirmation word is typed.
- [ ] Sealing a major states that the major becomes read-only and cannot receive new milestones.
- [ ] Navigating to another route during a slow mutation leaves the new route's paint intact (a
      request settled after navigation produces no DOM change in the new view).
- [ ] An open modal traps Tab, closes on Esc, and returns focus to the button that opened it.
- [ ] Opening an AI-assist modal, closing it, then opening another modal on the same surface starts
      with empty chat state.
