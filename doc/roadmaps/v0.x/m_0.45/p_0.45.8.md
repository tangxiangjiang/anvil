# Phase p_0.45.8 — AI assist: one endpoint, structured patches, no silent writes

**Status:** done

## Goals

Turn the seven per-surface mocks into one real assistant, and give it a contract that cannot corrupt
a record.

The audit behind this phase: every assistant in the console is a local string template. Roadmap
answers with `"(mock polish) Clarify acceptance: "`, Test with a `Case:/Given/When/Then` skeleton,
the major and milestone assists echo the prompt back into form fields, and the design and version
assists appended the operator's own text into the ADR, a Gate and Completion criteria until p_0.45.3
stopped them. There is no AI endpoint in anvil-web at all.

## Scope

- `POST /api/v1/delivery/assist` — one server-side entry, auth-gated like the rest of the API.
- A prompt builder that turns the current surface state and its `@` cites into a request.
- A **structured patch response**: the model returns proposed field edits, not prose.
- One client component that every surface uses, replacing seven ad-hoc `onSend` handlers.
- A mock/real switch so a deployment without a key keeps working, honestly labelled.

## Non-goals

- Streaming tokens into the assistant dock. A patch is small; a spinner is enough (streaming belongs
  to p_0.45.9, which is about the agent conversation, not about editing a field).
- Fine-tuning, tool use, or multi-turn planning. One request, one set of proposals.
- Replacing the scheduler or agentd as the execution path. This edits *planning documents*; running
  work still goes through jobs.
- Autonomy: nothing the model returns is applied without an accept.

## Tasks

1. **The endpoint.** `POST /api/v1/delivery/assist` takes
   `{surface, field?, instruction, target?, cites[]}` where `target` and every cite are stable
   record references (`{type,id,parent_id?,major?,minor?,patch?,field?}`)
   and returns `{proposals:[{field, value, rationale}], model, usage}`. It reuses the provider
   configuration the gateway already has (`anvil-gateway` / `OPENAI_*` in anvil-web's config) rather
   than inventing a second one. Model and prompt live server-side so a client cannot choose them.
2. **Resolve the boundary that design 23 set.** That chapter says agentd is not an LLM reverse proxy
   and the *worker* owns cognition. anvil-web calling a provider directly to draft planning text is a
   different act and has to be written down as such: a new short design section stating that web may
   call the provider for **drafting assistance only**, never for execution, and that the key stays in
   anvil-web's secret config. p_0.45.8 is not done until that chapter exists.
3. **A prompt builder per surface**, server-side: Requirements version (Detail/Goals/Completion),
   Design (ADR sections, per-Version Gate/Sub-architecture/Class design), Roadmap (polish note),
   Test (case bodies). Each gets the field's current value, the `@` cites resolved to their real
   text, and one instruction. The cite payload is what makes the assistant useful rather than
   generic, and it is why this cannot be a single "write me a design" button.
4. **Structured patches, not prose.** The response shape is enforced: an assistant that returns
   prose is an error, not a fallback. A `field` outside the surface's allowlist is rejected
   server-side — the client cannot be trusted to limit where a patch lands.
5. **One client component.** `js/features/delivery/assist.js` replaces the seven `onSend` bodies:
   it sends, renders each proposal as a **diff against the current value** (old → new, with the
   rationale), and offers Apply / Edit / Discard per proposal. Apply is a normal save through the
   existing PATCH endpoint; Discard removes it. The dock never writes anything by itself — the
   p_0.45.3 invariant becomes structural rather than a note in three files.
6. **Mock mode stays, labelled.** With no provider configured the endpoint returns `available:false`
   and the client says "AI assist is not configured" instead of producing a fake reply that looks
   like one. This replaces the `(mock)` prefixes entirely: a demo is honest by being absent.
7. **Tests.** The patch allowlist per surface (a patch for a field the surface does not own is
   rejected); the cite resolver; the client's Apply path writing exactly the proposed value; and a
   regression asserting no assistant handler contains a write call.

## As built

**`internal/web/assist_api.go`** — one endpoint for every surface. Five surfaces have allowlists
(`requirement_version`, `design`, `design_version`, `roadmap_polish`, `test_case`), each field with a
*hint* that says what belongs in it. The hint is doing the real work: it is the difference between
"write me a design" and "write the Completion criteria, which is what the agent is told done means".
That is why the mocks were useless and why a generic prompt would be no better.

Three refusals, all server-side:

1. **Prose instead of patches** → `502`. Accepting prose is how the old mock ended up writing a
   sentence into an ADR.
2. **A field the surface does not own** → `502`, and the request's own `field` is validated before
   the call too, so the allowlist is enforced on the way in and on the way out.
3. **An empty request** → `400`, rather than a pointless provider call.

**Off is stated.** With no `assist` block the endpoint answers `available:false` with a reason. It does
not invent a reply, because a demo that looks real is exactly how the previous generation of these
surfaces became untrustworthy.

**`js/shared/assist.js`** is one component that renders each proposal as before → after with its
rationale, Apply / Discard per card, and a footer saying that nothing is saved until you apply. It has
no write call of its own: `onApply` is supplied by the surface and is where the existing save happens.
That is what makes "the assistant cannot write" structural rather than a promise.

**Nine surfaces, not four.** The first pass wired only the four that edit a persisted record
(requirement version ×2, design, design version) and left five answering with a template: roadmap
polish, test-case drafting, the two major modals, the create wizard, and the project README in
Clusters. A review caught it. All nine now go through the component, and the two template helpers
(`applyMajorChatAssist`, `applyMilestoneChatAssist`) are deleted rather than orphaned — an unused mock
is a mock waiting to be re-wired by accident.

Three surfaces were added to the server allowlist to make that possible: `major` (title, summary),
`milestone` (title, goals, completion) and `project_readme` (readme). Each proposal lands in a form
field the operator then submits, so the propose-then-accept rule holds identically for a field that is
persisted and one that is only staged.

**`doc/design/v0.x/45-web-editor-polish.md`** states the boundary this crosses. Chapter 23 says agentd does
not proxy LLM HTTP and the worker owns cognition; that rule is about *execution*. A drafting call has
no tools, no filesystem, no conversation and no ability to write, and it is a different act with
different privileges. Amending the rule silently would have been worse than either option.

**Server-resolved citations.** The endpoint no longer accepts `cites:[]string` or client-supplied
`current`. A persisted edit sends a `target`; the server uses that record for the proposal's
`before` value. Each cite names one allowlisted field (or the bounded requirement-version `overview`
identifier), and only the server places resolved text into the provider prompt. Unsaved create forms
send no draft body as context: their instruction remains operator input, but no client-composed record
text can masquerade as an authoritative citation.

The resolver reads only these surfaces: requirement version (`title`, `problem`, `goals`,
`non_goals`, `constraints`, `success`), design ADR fields, design-version
(`title`, `gate`, `sub_architecture`, `class_design`), and generation (`title`, `summary`). It never
reads worker metadata, project/workspace ids, relative paths, status/audit fields, secrets, or files.
Deleted/obsolete ids return `404`; malformed or non-citeable refs return `400`; scope violations
return `403`; context limits return `413`. Resolution preserves cite order.

## Correction

This phase's first delivery claimed "the seven per-surface handlers" were replaced. That was wrong:
four were, five were not, and the five still answered with a local template — the same shape the phase
exists to remove, just without the writes. The mistake was reporting the change from the plan rather
than from a grep over the result; `grep "onSend:"` would have shown nine call sites and only four
calls into `AnvilUI.assist.ask`.

Everything is wired now, and the check is mechanical: `grep -rn "(mock" source/internal/web/static/js`
returns nothing, and every `onSend` in the tree calls the component.
