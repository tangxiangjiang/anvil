# Phase p_0.45.14 — Reachable: phone and flaky network

**Status:** done (2026-10-22)

## Goals

Make the console usable where an operator actually is when a fleet goes wrong: on a phone, on a train,
on a network that drops. Today the console assumes a wide, stable, desktop connection.

This is not a redesign for mobile. It is the smaller, load-bearing set: the two things an operator does
away from a desk (see state, stop a runaway job) must work on a 375 px screen and survive a dropped
connection.

## Scope

- Responsive layout down to 375 px for the four Delivery sections and the Workbench.
- Connection awareness: a dropped SSE stream reconnects and says so.
- A compact "ops" view: health + running jobs + stop, sized for a phone.

## Non-goals

- Native apps, offline data entry, push notifications. The Flutter app (0.26) is the native story.
- Editing long-form content on a phone: the ADR and requirement editors stay desktop-first and say so
  rather than pretending to be usable at that width.
- Touch gestures beyond tap; the canvas drag editor is explicitly desktop-only.

## Tasks

1. **A breakpoint pass with a real target.** The existing `@media` rules are ad-hoc (840 / 900 / 960 /
   1080 px) and the shell's fixed `--sidebar: 220px` squeezes content to nothing below 900. Rework:
   the sidebar collapses to an icon rail under 900 and to an overlay under 600; `.del-split` stacks;
   the job bar and scope strip wrap without truncating the action labels.
2. **A stated desktop-only list.** Surfaces that genuinely do not work small (canvas, ADR editor,
   version card drag) render a short "better on a wider screen" note instead of a broken layout. Naming
   the limit is more useful than a layout that half works.
3. **Connection state, honestly shown.** The SSE consumer already has reconnect semantics on paper;
   make the UI reflect them: a disconnected banner, the last event time, and automatic resume that
   does not duplicate events (dedupe by `seq` from p_0.45.12). A stale stream that *looks* live is
   worse than a visible disconnection.
4. **The ops view.** `#/ops` — health strip, running jobs with stop, and the readiness list in a
   single-column layout. This is the screen for a phone, and it is deliberately one screen.
5. **Slow-network behaviour.** The snapshot fetch gets a stale-while-revalidate cache so a route shows
   its last known content with a "refreshing" marker instead of a blank body — the skeleton from
   p_0.45.6 already provides the shape.
6. **Tests.** The reconnect/dedupe reducer (pure: frames with gap, replay, overlap); and a responsive
   smoke test in the jsdom harness asserting the desktop-only surfaces declare themselves at 480 px.

- [x] Real headless Chrome at 375px verifies the Ops Stop CTA, 44px touch target, keyboard focus,
      no document overflow, and each Delivery section has reachable actions. Exact 600/601px checks
      verify overlay-to-rail behaviour; exact 900/901px checks verify wide-only notes and content.
- [x] The two surfaces that genuinely need width now say so: the roadmap canvas and the ADR editor
      render a `.desktop-only` note below 900px and the wide element carries `.needs-wide`. The note
      names what is lost and what is not — the milestone cards below the canvas carry every action, and
      the design's Markdown is still readable through *View*, so nothing becomes unreachable.
- [x] The Workbench now follows with a resumer: capped backoff (6 attempts, ~40s), a visible banner
      (`live` / `reconnecting…` / `disconnected` / `ended`), and dedupe on `seq` so a replay does not
      redraw the conversation. `stream.test.js` proves the backoff cap, the reset on open, the dedupe,
      and that a frame without `seq` is accepted rather than dropped.
- [x] `#/ops` — health, running jobs and transition readiness in one column, with Stop per Job and
      repair navigation for blocked records. Stop calls the unified Job cancel endpoint; the server
      selects Workbench cancellation or the phase-job milestone lever by Job kind.
- [x] Delivery, Ops and Workbench use one bounded volatile stale-while-revalidate primitive. A route
      paints the last successful snapshot with its age and `refreshing…`, atomically replaces it only
      with the newest in-scope response, and keeps it with `disconnected` + Retry on failure. Auth
      changes clear every cache; Ops/Workbench projections exclude prompts and event content.

## As built

**`js/shared/stream.js`** — `createResumer`, pure and tested. It decides when to retry (exponential
backoff, six attempts, capped, and a reset on a successful open so a flaky connection that keeps
recovering never gives up), and it deduplicates on `seq`. The dedupe is the part that matters: the
Workbench stream replays from the beginning, so a reconnect without it redraws the whole conversation.
A frame with no `seq` is accepted rather than dropped — losing content is worse than drawing a
duplicate.

**The Workbench follows instead of stopping.** It used to catch a dropped read, print "stream ended",
and stop. It now loops: on a drop it waits the backoff and re-opens; the banner says which state it is
in, and it stops retrying once the session has ended (retrying a finished job forever is a busy loop
with extra steps).

**Responsive shell.** Under 900px the sidebar becomes an icon rail and under 600px a fixed overlay
behind a floating button, toggled by click, closed by Escape and by choosing a destination. The shell
goes to one column, `.del-split` stacks, the generation scope scrolls rather than truncating, and the
modal width becomes a percentage. `.desktop-only` / `.needs-wide` exist so a genuinely wide-only surface
can name its limit instead of rendering half-broken.

**`#/ops`** — one screen: health per Fleet, running Jobs with a Stop each, and the authoritative
transition-readiness list with blocked count and repair link. It polls only while the tab is visible,
because a phone left on this screen should stay current and a background tab should not keep a network
loop alive.

**Bounded stale-while-revalidate.** `js/shared/swr.js` is memory-only, LRU-bounded (surface stores use
at most two entries) and age-bounded (five or ten minutes). Exact scope keys prevent cross-scope reads;
per-key request generations reject out-of-order completions; logout/login invalidates all entries.
Delivery caches planning snapshots only. Ops keeps health and minimal Job identity; Workbench keeps
Session id/Worker/state only, so prompts, event content, credentials and provider data are not cached.

**Browser evidence.** `npm run test:browser-smoke` starts anvil-web with a temporary SQLite database and
drives local Chrome through CDP. It measures 375px and both sides of the 600/900px breakpoints, exercises
the phone Stop action and focus/touch target, checks Delivery overflow/actions and wide-only notes, then
uses a local fake stream to force drop → visible reconnect → 400ms backoff → overlap replay → deduped
resume. It also forces a failed Ops refresh and verifies stale content remains with Retry. No external
Fleet, Node or provider is contacted.
