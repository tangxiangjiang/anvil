# Phase p_0.45.15 — Production toolchain wiring

**Status:** done (2026-10-22)

## Goals

Close the production wiring gaps left behind the 0.45 close-out. A browser-started
Workbench or Delivery run must use the authenticated scheduler path, execute on the
acquired daemon Worker through `EmbeddedRunner`, retain enough durable history to
recover honestly after process restart, and apply the workspace's tools and policy
without exposing secrets.

## Scope

- Wire the production web server to the scheduler-backed job runner for start,
  stream, result, approval and cancel.
- Make cancel remote-first, idempotent, ownership-safe and observable for Workbench
  and generic Jobs without regressing Delivery Pause/Stop.
- Preserve the acquired Worker identity in both direct and cluster daemon paths,
  apply its dynamic LLM settings, and persist/reload those settings.
- Load project permission rules, hooks and MCP configuration inside the daemon
  runner. Interactive Workbench may wait for a bounded user approval; unattended
  Delivery fails closed when policy requires an approval.
- Persist every phase/campaign/fix/regress/polish/Workbench Job and event, including
  session-to-Agent mapping, so history and resume survive a web restart.
- Define scheduler restart behaviour: nodes reconnect; in-flight jobs, approvals,
  waiters and cancellation are failed closed rather than represented as live;
  durable non-secret configuration is restored and secret material remains in
  environment/config secret sources.
- Add a local loopback end-to-end test that traverses web, scheduler, cluster
  transport, agentd `EmbeddedRunner`, a fake provider and fake MCP without
  `force_stub`.
- Audit advertised capabilities against the paths that actually implement them.

## Non-goals

- Starting 0.46 or adding unrelated product capability.
- A distributed consensus system or transparent continuation of an LLM request
  across scheduler/daemon process death.
- Persisting API keys, browser auth tokens, approval payload secrets, or MCP
  credentials in Job/event history.
- Contacting a real provider, node, MCP server, or user repository in tests.

## Tasks

1. Wire web construction and cancellation through `schedclient`.
2. Carry Worker identity through cluster execution and persist Worker LLM metadata.
3. Build daemon runtime options from bounded, workspace-scoped permissions, hooks
   and MCP configuration with distinct interactive/unattended approval policy.
4. Unify durable Job/event writes and add durable Workbench resume metadata.
5. Add explicit restart reconciliation for volatile scheduler/daemon state.
6. Add loopback E2E and restart/security tests; remove unsupported capability claims.
7. Update design/protocol documentation and run the complete acceptance suite.

## Acceptance

- [x] Production `anvil-web` start/stream/result/cancel uses `schedclient`; no test
      fake or nil fallback is required.
- [x] Stop/cancel calls scheduler first, reports remote errors, is idempotent, and
      cannot cancel another user's/session's Job.
- [x] Cluster and direct jobs use the acquired Worker ID and `LLMFor(workerID)`;
      Worker LLM survives daemon restart without persisting API-key values.
- [x] Workspace permissions, hooks and MCP load in daemon execution. Workbench has
      bounded approval; unattended Delivery fails closed instead of bypassing or
      waiting forever. Secret-bearing configuration is absent from web/events.
- [x] All Job kinds have durable headers/events/terminal state and replay after web
      restart; state projection failures use an explicit compensation/error record.
- [x] Workbench Session ↔ SDK Agent ID is durable and resumable with user/session
      ownership, expiry, not-found and concurrent-resume checks.
- [x] Scheduler restart makes volatile running/approval/cancel state explicitly
      unavailable while nodes reconnect and durable non-secret configuration reloads.
- [x] A repeatable local acceptance suite proves tool call, MCP, permission/hooks
      and stream through `EmbeddedRunner` and a loopback provider without
      `force_stub`, plus approval routing, cancel, resume, campaign history and
      provider-backed component restart in focused integration tests.
- [x] Request/event/config limits, auth, scope, ownership, idempotency, expiry and
      error semantics have executable tests.
- [x] `gofmt` on changed Go files, relevant tests, `go test ./...`,
      `go build ./...`, `npm test`, JS syntax, browser smoke when UI changes,
      repeated restart E2E, and `git diff --check` all pass.

## As built

- Production construction installs a fleet-aware `schedJobRunner`; Workbench,
  Delivery and generic cancellation share authenticated scheduler clients.
- Cluster and direct daemon paths retain the acquired Worker ID and call
  `RunOn(..., LLMFor(workerID), ...)`. Non-secret Worker LLM overrides survive
  daemon restart.
- `EmbeddedRunner` loads project permissions, hooks and MCP. Interactive jobs use
  the bounded approval broker; unattended jobs require an explicit allow rule and
  otherwise deny immediately.
- Workbench identity is durable and owner/Worker scoped. The browser resumes by
  prior Workbench Session ID, while the server atomically resolves the SDK AgentID.
- Job history now covers phase, run, fix, regress, polish and Workbench. Restart
  reconciliation fails leftover live projections closed; scheduler nodes reconnect,
  and web periodically restores workspace-token leases without logging tokens.
- `TestE2EConfigureJoinJobModels` traverses scheduler cluster transport and
  `EmbeddedRunner` with a loopback streaming provider, a real `read_file`, local
  stdio MCP, project permission allow and hook denial; it does not use
  `force_stub`. `TestSchedulerRestartNodeReconnectsAndRunsNewJob` restarts the
  scheduler, observes node reconnect, and runs against a loopback provider.
- Final evidence: `go test ./...`, `go build ./...`, 104 JS tests, Chrome browser
  smoke, E2E/restart repeated three times, JS syntax and `git diff --check`.
