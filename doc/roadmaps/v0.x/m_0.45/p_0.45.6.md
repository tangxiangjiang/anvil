# Phase p_0.45.6 — One generation scope, breadcrumbs, skeletons, empty states

**Status:** done

## Goals

Make the four sections feel like one product. Today Requirements home concatenates two unrelated
components (the major index *and* the workspace picker) while Designs / Roadmap / Test show the
major index alone — four different entry experiences, and no persistent indicator of which generation
the user is inside once they have drilled in.

## Scope

- One **Generation scope** component, used by all four sections, with a persistent switcher.
- Breadcrumbs on the requirement → milestone → version and design → version walks.
- Skeletons for the first paint of the top-level lists; designed empty states.

## Non-goals

- Changing the routing scheme. Existing `#/delivery/{section}/m/{M}/…` hashes keep working, and
  bookmarks do not break.
- Redesigning the roadmap canvas or the control cards.
- A new navigation surface in the sidebar; the generation switcher lives in `.del-head`.

## Tasks

1. **Generation scope.** Extract the generation plan strip into one component that renders the
   majors, their status, and the counts of work under each (`majorWorkCounts` already computes these).
   Every section renders it in `.del-head` with the current major selected, and selecting a different
   major switches section scope without leaving the surface. Requirements home stops concatenating
   `viewMajorIndex` and `viewWorkspace`; the workspace picker becomes its own deliberate entry
   (`#/delivery/requirements/projects`, which `parseRoute` already understands).
2. **Breadcrumbs.** Generalise `createCrumbs` into a shared component and use it on requirement →
   milestone → version and design → version. Each crumb is a link; the current node is text. A
   requirement crumb shows the project Key, a milestone crumb its `M.m` and title, a version crumb its
   `M.m.p`.
3. **Skeletons.** A skeleton block for the major index, the worker home and the roadmap list — sized
   to the real card, so the transition does not shift layout. Detail views keep the instant path
   (the data is already in the snapshot) and need none.
4. **Empty states.** Each list gets a designed empty state naming the one action that resolves it
   ("No milestones in this generation — create one"), instead of a bare `.muted` sentence.
5. **Visible redirects.** `#/delivery` → `#/delivery/requirements` and `#/nodes` → `#/clusters` stop
   being silent: the redirect is reflected in a breadcrumb root, and the legacy `#/delivery/gates`
   mapping keeps its existing rewrite.

## Acceptance

- [x] All four sections show the same generation scope, and switching generation from inside any of
      them changes that section's scope.
- [x] Every detail route (requirement → milestone → version, design → version) shows a breadcrumb
      that walks back up, and each crumb navigates.
- [x] A first visit to a top-level list shows a skeleton rather than a blank body on a throttled
      connection.
- [x] Every empty list states what to do next, and that action works.
- [x] Existing deep links and bookmarks still resolve to the same views.

Evidence (2026-10-22): `npm run test:browser-smoke` uses a temporary SQLite database and local
headless Chrome. It delays the first Delivery snapshot to assert the skeleton, switches a synthetic
empty generation from each of the four scoped sections, walks requirement milestone/version and
design breadcrumbs, exercises every empty-state action and the Projects inventory error state, and
releases delayed inventory/action responses after navigation to prove they cannot repaint the new
route. Existing seeded deep links and the p_0.45.5 wizard/Clusters paths also render, with zero
console exceptions or errors and no external node connection.
